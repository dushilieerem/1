# FEAT-004：因子资产目录与回测结果缓存 — Product Requirements

- 状态：已规划
- 所属 Initiative：INIT-001 投研核心

## 1. 目标与范围

将因子库从 `ResearchEngine/factor/` 迁移至根目录 `Factor/libraries/`，并为
`POST /api/backtest/factor` 提供透明的本地结果缓存。缓存仅用于避免重复计算，不提供研究历史管理。

## 2. 用户故事

1. 作为研究员，我希望因子库与 `MarketData/` 同属项目级资产，以便统一管理源码和数据。
2. 作为研究员，我希望重复提交同一因子和配置时快速获得原结果，而非再次等待回测。
3. 作为研究员，我希望行情或参数变化后自动获得重新计算的结果，不被旧缓存误导。
4. 作为前端开发者，我希望能通过响应头判断本次结果是否命中缓存，但无需改变现有响应体解析逻辑。

## 3. 业务规则

### 3.1 目录规则

```text
Factor/
├── libraries/                 # 受版本控制：因子源码、index.yaml、因子文档
└── backtest_results/          # 运行时缓存：不受版本控制
```

- 默认因子库目录为 `<repo>/Factor/libraries`；环境变量 `SVQUANT_FACTOR_DIR` 可覆盖。
- 默认缓存目录为 `<repo>/Factor/backtest_results`；环境变量 `SVQUANT_BACKTEST_CACHE_DIR` 可覆盖。
- `Factor/backtest_results/` 必须加入 `.gitignore`。

### 3.2 缓存命中规则

仅当以下内容完全一致时才命中缓存：

- `factor_code`、`factor_name`；
- 全部因子回测请求参数；
- 因子回测算法版本；
- 本次回测会读取的 `MarketData/` 与目标基准文件的数据指纹。

数据指纹由相关 Parquet 文件的相对路径、文件大小和最后修改时间生成。任一文件变化即视为缓存失效；允许过度失效，不允许错误复用。

### 3.3 返回规则

- 命中：返回缓存中保存的完整 `FactorBacktestResponse`，HTTP 响应头为 `X-SVQuant-Cache: HIT`。
- 未命中：执行回测、写入缓存、返回结果，响应头为 `X-SVQuant-Cache: MISS`。
- 缓存不可读、过期或写入失败时：忽略该缓存并执行回测；缓存故障不能阻断回测。
- 因子代码执行错误不写入缓存。

### 3.4 清理规则

- 默认 TTL：30 天；默认容量上限：10 GB。
- 每次写入后触发轻量清理：先删除过期项，再按最近访问时间删除直到低于容量上限。
- 缓存是可再生数据，清理不需要用户确认。

## 4. 边界与异常

| 场景 | 预期行为 |
|------|----------|
| 已移除的 API 参数 | 与现有规则一致，返回 HTTP 422。 |
| 缓存目录不存在 | 自动创建。 |
| 缓存文件损坏 | 删除或忽略后重新回测。 |
| 同一缓存键并发请求 | 仅一个请求写入；其他请求等待写入完成后读取，超时则各自回测但不得读到半成品。 |
| 因子库迁移后旧路径不存在 | 内置因子列表、示例和文档均使用新路径。 |
| 多个 API 实例 | MVP 各实例使用各自本地缓存，不保证跨实例命中。 |

## 5. 非功能要求

- 缓存查询与键生成的额外延迟在本地磁盘环境下应低于 100 ms（不含首次读取操作系统冷缓存）。
- 缓存文件写入必须原子完成，不能暴露部分 JSON。
- 缓存键不可直接暴露因子源码；对外仅返回 `HIT` / `MISS`。
- 现有 `/api/backtest/factor` JSON 响应体字段保持兼容。

## 6. 验收标准

1. 使用迁移后的因子目录，`GET /api/factor-libraries` 能列出内置因子库，`GET /api/factors/{library_name}` 能列出指定库的内置因子。
2. 两次相同请求中，第二次返回 `X-SVQuant-Cache: HIT`，且不调用回测执行器。
3. 修改因子代码、任一回测参数、相关行情文件或基准文件后，请求返回 `MISS`。
4. 缓存中的响应与首次计算响应体一致。
5. 损坏缓存文件、只读缓存目录等异常不会导致 API 返回 500。
6. TTL 和容量清理有自动化测试；缓存目录不被 Git 跟踪。
