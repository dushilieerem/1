# Product Requirements：机器学习模型接入与预测回测

## 用户故事

1. 作为算法研究员，我希望按平台模板实现一个预测模型并声明所需特征，使其能够在 SVQuant 中训练和产生样本外预测。
2. 作为量化研究员，我希望将模型预测当作因子查看 IC/IR 与分层结果，并用相同预测进行策略回测，以判断模型是否具备投资价值。
3. 作为平台研发，我希望模型失败、预测错位或可能泄露未来数据时得到明确错误，而不是产生看似正常但不可信的回测结果。

## 主流程

```text
算法组提交模型类 + 模型配置
        ↓
ResearchEngine 校验模型元信息与数据需求
        ↓
DataEngine / FactorEngine 构造特征面板与标签面板
        ↓
按时间配置切分 train / validation / test
        ↓
模型 fit（仅 train，可选 validation）→ predict（仅 test）
        ↓
预测面板契约校验与运行清单落盘
        ↓
预测因子 → IC/IR、分层分析 → 选股组合 → 向量化回测
        ↓
返回模型运行信息、分析指标、净值和可追溯产物
```

## 业务规则

### 模型与数据

- 模型必须声明唯一 `model_id`、版本、所需特征名称、预测目标频率（MVP 仅支持日频）和预测方向（分数越高越看多或越看空）。
- 特征和标签均为以交易日为行、证券代码为列的 `pandas.DataFrame`；模型可在内部转换为长表、张量或其他框架输入。
- 特征列必须由已有数据字段或已注册因子提供。平台不接受模型内部静默读取任意文件、网络或未来日期的数据。
- 标签由研究配置明确声明，例如“未来 5 个交易日收益”；标签构造必须使用 `as_of_date` 规则，且标签值只可用于训练或离线评估，不能作为预测时输入。

### 时间与样本外规则

- `train_end < validation_start ≤ validation_end < test_start ≤ test_end`；未配置验证集时仍要求 `train_end < test_start`。
- 模型在测试区间的每个预测日期，只能使用该日期收盘前或研究配置指定可得时点的数据。日频 MVP 默认在 `t` 日收盘后计算分数，于 `t+1` 交易日执行调仓。
- `predict` 的输入只含测试区间特征；平台拒绝模型返回训练/验证日期的预测或测试区间之外的证券。
- 滚动训练、扩展窗口和 walk-forward 是同一契约下的后续编排方式，不属于 MVP。

### 预测输出与回测

- `predict` 必须返回单列预测分数或等价的 `Series`，平台规范化为 `DataFrame[date × instrument]`。不得返回买卖订单、持仓、成交价格或直接修改回测状态。
- 缺失预测允许存在；因子分析和组合构建按已有缺失值规则剔除。全空、全非有限值或重复索引的输出必须失败。
- 因子分析使用预测面板及与配置相符的未来收益；策略回测使用同一预测面板、现有股票池、调仓频率、交易成本和回测适配器配置。
- MVP 支持等权 Top-N 多头和多空分层研究；是否允许做空由既有回测市场/配置能力决定，A 股默认仅多头。

## 异常行为

| 情况 | 系统行为 |
|---|---|
| 模型类无法导入、依赖缺失或初始化失败 | 任务失败，返回模型标识、阶段和原始异常摘要；不产生成功结果 |
| 声明特征缺失 | 训练前失败，列出缺失字段/因子与可用范围 |
| 数据切片不连续、时间顺序非法 | 配置校验失败，不调用模型 |
| 预测日期、证券或形状不匹配 | 预测校验失败，保存诊断信息，不进入回测 |
| 预测含 NaN | 允许按既有缺失规则处理并记录覆盖率；全空或全无效时报错 |
| 模型训练或推理超时 / 内存不足 | 任务失败并释放本次运行资源；MVP 先使用进程内软超时，生产级隔离后续实现 |
| 模型尝试访问未声明数据 | MVP 不提供数据读取对象以外的入口；沙箱隔离不在 MVP，内部算法组须使用受信任代码 |

## 非功能要求

- 核心安装不新增 sklearn、PyTorch、TensorFlow 等强制依赖；参考模型只依赖 NumPy/Pandas。
- 同一数据快照、配置、模型版本和随机种子重复运行，应得到一致的预测与回测结果；框架自身非确定性须由模型声明。
- 每次运行落盘 `manifest.json`，至少含模型 ID/版本、代码标识、随机种子、数据范围、特征列表、标签定义、切片、预测覆盖率和回测配置摘要。
- 已有非模型因子/策略接口与 API 行为保持兼容。

## 验收标准

| 编号 | 可测试的验收条件 |
|---|---|
| AC-01 | 参考模型通过 `BasePredictiveModel` 契约校验，并在合成日频面板上完成训练和测试集预测 |
| AC-02 | 给定同一合成数据、配置和随机种子，连续两次运行的预测面板和核心回测指标一致 |
| AC-03 | 预测面板可进入现有指标引擎，返回 IC/IR 和分层结果；可进入向量化回测，返回净值与绩效指标 |
| AC-04 | `train_end >= test_start`、测试预测含训练日期、重复索引、全无效值等场景均在回测前失败，并给出可定位错误 |
| AC-05 | 模型声明的特征缺失时，系统在训练前列出缺失特征，不调用 `fit` |
| AC-06 | 运行产物含完整 `manifest.json`，可据此还原模型版本、时间切片和预测覆盖率 |
| AC-07 | 未安装可选深度学习框架时，核心包导入、已有因子研究和回测测试均正常运行 |
