# FEAT-014：策略调仓日志

- 状态：已完成
- 所属 Initiative：INIT-001 投研核心
- 所属能力：策略研究、策略回测 API

为策略回测记录目标权重变更，并允许 Web 端按需取得按调仓日聚合的日志。

## 1. 价值与范围

### 功能名称

策略回测调仓日志按需返回。

### 背景

现有策略回测只返回净值、指标和可选持仓快照。Web 用户无法直接解释策略为何在某个调仓日换入或换出标的。

### 用户价值

研究者可在回测结果中查看每个调仓日的标的和权重变动，快速核验策略行为。

### 商业价值

提升回测结果的可解释性和可信度，是策略研究 Web 工作台的基础审计信息。

### 竞品分析

主流量化平台通常展示交易/调仓明细。MVP 优先提供与当前向量化目标权重模型一致的日志，不伪造尚不存在的订单成交信息。

### MVP 范围

- 必须做：记录目标权重变化；Web 请求时按调仓日返回标的、方向和前后权重。
- 可以以后做：成交价、金额、手续费、订单状态和导出文件。
- 明确不做：事件驱动订单撮合与实盘成交回报。

## 2. 业务规则与场景

### 用户故事

作为研究者，我希望在请求策略回测时选择返回调仓日志，以便核验每次调仓的标的和权重变化。

### 业务规则

1. `POST /api/backtest/strategy` 增加可选布尔字段 `include_rebalance_logs`，默认 `false`。
2. 为 `true` 时，响应 `rebalance_logs` 按调仓信号日分组。
3. 每笔记录含 `symbol`、`side`、`previous_weight`、`target_weight`、`weight_change`。
4. 仅返回权重实际变化的标的；权重不变及非调仓日不返回。
5. 未请求时 `rebalance_logs` 为 `null`，既有调用不受影响。
6. 日志为目标权重变更，不承诺是订单或实际成交回报。
7. `include_execution_timeline=true` 时，API 返回供 Web 统一消费的时间线：向量化策略映射为目标权重变更，事件策略映射为订单、成交、账户快照和审计事件。

### 验收标准

1. Native 回测结果包含首建仓和后续调仓的买卖日志。
2. API 未传开关时不返回日志；传入开关时返回结构化日志。
3. 既有策略 API 测试继续通过。
4. 向量化与事件策略均可通过 `execution_timeline` 返回可展示的执行过程。

## 3. 方案设计

### 模块边界

`QuantCore.backtest` 从 `BacktestSignals.target_weights` 生成统一日志并存入 `BacktestResult.rebalance_logs`。NativeEngine 复用该生成逻辑。`ResearchEngine.api` 只负责按请求开关序列化。

`ResearchEngine.api` 同时提供按需的 `execution_timeline` 兼容层。向量化模式将 `rebalance_logs` 映射为 `type=rebalance`；事件模式按时间合并订单、成交、账户快照和审计事件。该字段不改变既有 `rebalance_logs` 语义，供 Web 作为唯一展示数据源。

### 数据规则

目标权重前向填充后与前一日有效目标权重比较。差值大于零为 `buy`，小于零为 `sell`；每条日志记录调整前后权重及差值。时间为策略产生目标权重的信号日。

### 兼容与回滚

请求字段默认关闭，响应新增可空字段，旧客户端兼容。出现问题时可停用 `include_rebalance_logs`，不影响回测计算、指标或持仓快照。

### 测试策略

单元测试验证首次建仓及换仓方向；API 测试验证按需返回和默认空值。

## 4. 验收与证据

- NativeEngine 单元测试覆盖首次买入和后续卖出/买入调整。
- 策略回测 API 测试覆盖默认不返回及 `include_rebalance_logs=true` 时返回日志。
- 已运行 QuantCore 与 ResearchEngine 相关测试。
