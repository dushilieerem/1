# Feature Proposal：AI 自然语言因子生成 API

## 功能名称

AI 自然语言因子生成 API。

## 背景

SVQuant 已具备因子函数源码提交和因子回测能力，但用户仍需理解 Python、平台字段和 `FactorLibrary` 写法，才能把“过去 20 日上涨且成交量放大”的研究假设变成可验证因子。这个门槛阻断了产品定位中“用自然语言与平台对话，生成策略、因子代码”的第一步。

本 Feature 在 Web 应用与现有 ResearchEngine 回测服务之间补充受控的 AI 生成能力：自然语言只发送给平台后端，后端调用已配置的第三方大语言模型，并返回受限、可审阅的因子函数草稿。生成服务不直接执行回测，也不保管用户资产或回测结果。

## 用户价值

- 非专业编程的研究员可将投资假设快速转化为可审阅、可回测的因子草稿。
- 专业量化研究员可节省字段查阅和样板代码时间，并保留修改、比较和复现的控制权。
- Web 应用可展示结构化解释、假设和警告，避免把模型输出误当成投资建议或已验证结论。

## 商业价值

这是 Wave 1 可演示的 AI 投研闭环入口，能直接放大既有数据、因子和回测能力，降低试用门槛并形成专业版 AI 调用额度的计费基础。若不做，平台的 AI 差异化仍停留在产品愿景，Web 用户必须自行编写代码或离开平台使用通用 AI 工具。

## 竞品分析

| 竞品 / 形态 | 常见做法 | 对 SVQuant 的启示 |
|---|---|---|
| 聚宽、米筐 | 提供研究 API 与代码编辑器，代码能力仍是主要入口 | 生成结果必须落回明确的平台函数契约，而非只给自然语言解释 |
| BigQuant | 用可视化模块和 AI/AutoML 降低建模门槛 | 应输出可检查、可复现的研究资产，而不是黑盒信号 |
| 通用 LLM | 可生成 Python，但不了解平台字段、时点和回测约束 | 必须以版本化字段目录、代码模板和结构化输出约束模型 |

差异化选择：SVQuant 首期只生成“单个日频因子函数”，并让用户显式确认后才进入回测；不以聊天机器人直接替用户下结论、下单或静默运行任意代码。

## MVP 范围

### 必须做

1. 提供服务端 `POST /api/ai/factor-generations`：接收自然语言、可选回测上下文和幂等键，调用一个由部署配置选定的第三方 LLM。
2. 维护版本化因子能力目录：允许字段、允许的 pandas 运算、内置库方法、频率和明确禁用项；仅向模型提供该目录与当前契约。
3. 强制 LLM 按 JSON Schema 返回 `factor_name`、只含函数定义的 `factor_code`、解释、假设、警告和所用字段；拒绝非结构化或不合规输出。
4. 用 AST 静态校验函数签名、禁用导入/文件/网络/动态执行、限制允许属性与调用；通过后返回 `validation` 结果，失败时不得标记为可回测。
5. Web 用户确认生成草稿后，复用既有 `POST /api/backtest/factor`，将 `factor_code` 和 `factor_name` 送入回测；生成 API 不自动回测。
6. 记录不含密钥的审计元数据：请求/能力目录/提示词模板/模型/输出哈希、校验结果、耗时和调用量；支持按租户实施额度和限流。

### 可以以后做

- 多轮追问、候选因子比较、自动修复和基于回测错误的受控迭代。
- 生成因子组合策略、新闻/行业/政策因子，以及模型自动优化。
- 异步生成队列、流式输出、因子资产保存、版本历史和团队协作审批。
- 多模型路由、A/B 质量评估、成本智能路由和私有化模型。

### 明确不做

- 不让浏览器持有第三方 LLM API Key，也不接受浏览器指定任意 API Base URL、模型或系统提示词。
- 不直接根据自然语言执行回测、创建交易订单、给出荐股或收益承诺。
- 不支持任意 Python、`import`、文件/网络访问或动态执行；也不以静态校验替代生产回测沙箱。
- 不在本 Feature 中建设用户、计费、因子资产目录或异步回测系统。

## 优先级评估

商业价值 5、用户价值 5、战略价值 5、开发成本 3，评分为 41.7。建议 P0：以中等投入使已有回测能力成为可感知的 AI 产品闭环。

## 管理层摘要

| 维度 | 结论 |
|---|---|
| 为什么做 | 将自然语言研究想法转为可验证因子，兑现 AI 投研入口 |
| 不做的影响 | 用户仍需自行编码或使用平台外通用 AI，平台的核心差异化不可见 |
| 为什么现在做 | 因子函数与回测 API 已具备，可在不改回测内核的前提下快速接入 |
| 投入 | 约 12–16 人天，2–3 个自然周；首期供应商已选定字节火山方舟 Coding API，仍需确认预算和数据保留条款 |
| 预计收益 | 降低试用门槛，增加 AI 调用频次，为订阅额度与后续 AI Agent 奠基 |
| 风险 | 幻觉、不安全代码、供应商成本与数据合规；通过能力目录、静态校验、人工确认、额度和沙箱缓解 |
| 下一步 | 使用已选定供应商完成连通性验证，评审可用字段目录、供应商合规与生产沙箱方案后进入开发 |
