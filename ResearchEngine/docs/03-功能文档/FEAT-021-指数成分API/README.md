# FEAT-021：股指与成分股查询 API

- 状态：已完成
- 所属 Initiative：INIT-001 投研核心
- 所属能力：数据、研究 API

为 Web 应用提供已发布股指列表，以及按股指代码查询最新一期成分股的只读 API。

## 1. 价值与范围

### 背景与价值

Web 工作台需要让研究者选择市场基准并查看其成分股；现有 API 只能查询股票列表和个股日线，无法复用已发布的指数元数据。该能力降低前端维护静态指数清单和成分数据的成本，并为基准选择、证券池浏览提供可信的数据入口。

### MVP 范围

- **必须做**：列出当前已发布的内置股指；按股指代码返回最新一期成分股和名称。
- **可以以后做**：指定历史日期、指数日线、权重、行业筛选、分页。
- **明确不做**：在线数据源调用、指数自定义、实时数据、用户鉴权和投资建议。

优先级：P1（商业价值 3、用户价值 4、战略价值 3、技术成本 2）。

## 2. 业务规则与场景

### 用户故事

作为 Web 端开发者，我希望取得可用股指列表，并按股指代码取得其成分股，以构建基准选择器和成分股展示。

### 业务规则与验收

1. `GET /api/market-data/indices` 返回已发布且可读取的上证50、沪深300、中证500、中证1000，按代码升序。
2. `GET /api/market-data/indices/{code}/constituents` 返回该指数最新一期成分、证券名称和未映射数量；成分按代码升序。
3. 股指代码使用 `000016.SH`、`000300.SH`、`000905.SH`、`000852.SH`，并兼容对应内部标识。
4. 未知代码返回 `404`；成分文件、证券主数据或市场数据不可用时返回 `503`；不返回伪造数据。
5. 成分股是最新快照，不可表述为历史时点成分或当前实时成分。

## 3. 方案设计

`ResearchEngine.api.market_data` 保持 HTTP 适配层职责：复用按数据目录缓存的 `DataEngine(FieldParquetProvider)`；通过既有 `get_index` 判断已发布股指可用性，通过既有 `get_universe` 读取最新一期成分。证券名称继续从发布版 `stock_info.parquet` 映射，路由与 Pydantic 模型只负责契约和 JSON 序列化。

新增 GET 端点，不改动既有回测或个股行情契约。数据目录读取失败立即以 `503` 失败；回滚时移除两条路由即可。测试覆盖可用股指、最新快照、未知代码及现有 API 回归。
