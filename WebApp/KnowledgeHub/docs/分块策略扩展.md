# 分块策略扩展指南

KnowledgeHub 的分块与「知识库类型 / pipeline」分离：

- **pipeline（知识库类型）**：创建库时的文档模板（通用 / 问答 / 手册 / 表格 / 论文 / 法规），只决定**默认**分块策略。
- **chunk strategy（分块方法）**：真正把正文切成片段的算法，可单独选择，也可后续新增。

## 在哪加

| 位置 | 作用 |
|------|------|
| [`../backend/knowledge_hub/chunking/strategies.py`](../backend/knowledge_hub/chunking/strategies.py) | 实现并 `@register(...)`（相对本 docs） |
| [`../backend/knowledge_hub/chunking/registry.py`](../backend/knowledge_hub/chunking/registry.py) | 登记表；`list_strategies` / `chunk_text` |
| 前端 | 通过 `GET /api/kh/meta` 拉取，**无需**再写死一份 |

> 后端包目录：`WebApp/KnowledgeHub/backend/knowledge_hub/`（与前端同属 KnowledgeHub；由 `api_server` 挂载 `/api/kh`）


## 步骤

1. 在 `strategies.py` 复制一个现有函数（如 `plain_window`）。
2. 改 `strategy_id`、`label_zh`、`description` 与切块逻辑；返回 `[{ordinal, text, meta}, ...]`。
3. 重启 `api_server.py`。
4. 打开知识库「创建」对话框，分块方法下拉应出现新项；上传文档后检查切片。

## 一期内置

- `markdown_heading` — 按 Markdown 标题
- `plain_window` — 固定窗口
- `paragraph_merge` — 按段落合并（Word / 纯文本）
- `numbered_heading` — 按编号标题（纪要 / 方案：`1.` `一、` `第x章` / `姓名——主题`）
- `qa_pair` — 问答对
- `table_row` — 表格行

## 注意

- id 全局唯一，建议 `snake_case`。
- 大文件注意窗口与 overlap，避免切片过大拖慢检索。
- 新策略合入后同步改本文件「一期内置」列表。
