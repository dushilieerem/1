```text
Idea（人点「转成因子草稿」）
  → C 因子草稿：平台可回测的 def 代码 + 建议回测窗
  → 人确认
      ├─ 去检测页（手工细调）
      └─ D 回测报告：把草稿参数发给平台回测
  → 人确认
  → E 评价：只给「建议复核 / 不建议入库」，不写库
```

## C 因子草稿 · `/ai/factor`

- 输入：B 的一条可转假设（`factor_prompt` + `validity` 窗口跟着走）。
- 输出：一个 `def name(self, …)`，只用日频 `close/open/high/low/volume`。
- 校验不过则回退动量模板，并打警告。
- 下游按钮：去检测页；发给回测 Agent。

## D 回测报告 · `/ai/factor-backtest`

- 输入：C 的 `backtest_hint`（函数名、代码、区间、股票池）。
- 输出：指标摘要报告（给 E 用）。换区间结果可以差很多，必须人点「发送回测」。
- 耗时可能较长，页面会提示。

## E 评价入库 · `/ai/factor-eval`

- 输入：D 的报告。
- 输出：`review`（建议人工再看样本外）或 `reject`。`admit` 永远为否。
- 入库按钮以后再做，本步绝不改因子库。

## 人闸

| 步 | 必须人点 |
|----|----------|
| B→C | 「转成因子草稿」；`convertible=false` 禁用 |
| C→D | 「发给回测 Agent」再「发送回测」 |
| C→检测 | 「去检测页」 |
| D→E | 「送给评价 Agent」再「给出入库建议」 |
