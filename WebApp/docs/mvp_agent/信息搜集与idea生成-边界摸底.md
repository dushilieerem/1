# Agent 子模块摸底 · 信息搜集 ↔ Idea 生成

> **日期**：2026-08-17  
> **状态**：边界/场景摸底（**具体设计见** [`Agent设计-A-信息搜集.md`](./Agent设计-A-信息搜集.md)；Agent B 另篇）  
> **修订**：一期来源收敛为 **站内资讯 + 外网公开信息**；社区 / KH / 因子面板等不进一版

---

## 1. 关系：可以串，而且应该串

```text
用户意图 / 选题
       ↓
┌──────────────────┐
│  Agent A 信息搜集  │  产出：结构化「证据包 / 情报摘要」
└────────┬─────────┘
         ↓  （A 的输出 = B 的主输入）
┌──────────────────┐
│  Agent B Idea 生成 │  产出：可行动的 idea 列表（可再进人工或下游）
└──────────────────┘
```

- **默认主路径**：搜集 → idea（流水线）。  
- **也可单跑**：只搜集（只要情报、不要 idea）；或人工贴材料直接进 idea（跳过搜集）。  
- **不是互相独立的两个聊天框**：idea 若看不到搜集结果，容易空转或胡编。

---

## 2. 各自输入 / 输出（约定草案）

### Agent A · 信息搜集

| | 内容 |
|--|------|
| **职责** | 按主题/问题，从**已声明的来源**取材料，清洗、去重、溯源，打成「证据包」 |
| **输入（上游）** | ① 用户问题/主题（必填）② 时间窗、标的、题材等约束（可选）③ **来源开关**（资讯 / 外网）④ 上限（条数/字数） |
| **输入来源（关键）** | 见第 3 节 —— **一期只做资讯 + 外网** |
| **输出** | 结构化证据包：`items[]`（标题/摘要/链接/时间/来源/标的/题材）、`digest`、`citations`、`gaps` |
| **不做什么** | 不直接给交易建议；不发明未检索到的事实；不替代检测/回测 |

### Agent B · Idea 生成

| | 内容 |
|--|------|
| **职责** | 在证据包（+ 可选用户补充）上，生成**可验证方向**的 idea，并标明依据条目 |
| **输入** | ① **A 的证据包**（主输入）② 用户偏好（偏因子/策略/题材/风险偏好）③ 可选：平台能力边界 |
| **输出** | `ideas[]`：标题、一句话逻辑、依据（引用 A 的 item id）、建议下一步、置信/风险提示 |
| **不做什么** | 不编造证据包里没有的「新闻事实」；不直接下单；不保证收益 |

**串起来后的端到端：**

| 阶段 | 输入 | 输出 |
|------|------|------|
| 整条链路 | 用户主题 + 来源配置 | **idea 列表**（每条挂 citations） |
| 中间产物 | — | 证据包（可单独展示，供人审） |

## 3. 输入来源（一期定稿方向）

**来源比 Prompt 更决定成败**（质量 / 时效 / 口径 / 合规 / 可追溯）。

### 3.1 第一版只做这两类

| 优先级 | 来源 | 说明 |
|:------:|------|------|
| **P0** | **SVQuant 资讯**（`news_items`：要闻流 / 电报快讯 / 公告表） | 站内已有、可检索、有题材/标的标签；一期主战场 |
| **P0** | **外网公开信息** | 公开网页/资讯站等；须可追溯 URL；合规与稳定性单独评估 |

> 外网「具体白名单」不在摸底里拍脑袋定死，见 **§3.3 后续设计（官方源）**。

### 3.2 第一版明确不做（避免不标准 / 随意口径）

| 来源 | 原因 |
|------|------|
| 社区帖 | 观点杂、审核态不一，一版不作为情报主源 |
| 全局搜索「社区+资讯」打包 | 与「只做资讯」重复且易混入口径；检索可复用资讯侧 API，不必绑社区 |
| KnowledgeHub | 内部手册/方法论，不是市场情报主源；另线 |
| 行情 bars / 因子面板数值 | 试算走 RE；易触敏感/L3；**不是搜集 Agent 主输入** |

### 3.3 后续设计：官方信息源（待专项）

用户侧方向：在「外网」里再收一档 **官方 / 半官方**，比泛网页更可信。初步候选（**待调研后写进需求，本期不实现**）：

| 候选类型 | 举例（待核实可用性与许可） | 备注 |
|----------|---------------------------|------|
| 交易所披露 | 上交所 / 深交所 / 北交所公告、停复牌 | 与站内「公告表」可能重叠，需定主从 |
| 监管与政策 | 证监会、交易所规则、央行/部委公开稿 | 偏政策类 idea |
| 上市公司法定披露 | 巨潮等（站内 cninfo 源已部分覆盖） | 优先复用站内资讯管道 |
| 指数与公司行动 | 中证指数、公司官网 IR | 慎用爬虫；能 API 则 API |

**设计原则（写需求时遵守）：**

1. 每条证据必须有 **source_type**（`sv_news` / `web_public` / 日后 `exchange_official`…）与可点开的 URL 或站内 id。  
2. 外网默认 **只读公开页**；禁止把未授权付费库、个人隐私、L3 数值当搜集输入。  
3. 「官方源」单独一章白名单，上线前法务/合规过一眼。

**结论：** 需求文档必须单列「数据源与权限」；没有白名单就不该开搜集 Agent。

## 4. 典型场景（摸底 · 按新来源）

1. **题材跟踪**：「最近算力相关公告/快讯」→ 站内资讯证据包 → idea（因子/标的方向，需人工）  
2. **外网补强**：同一主题拉取白名单外网页 → 与站内资讯去重合并 → idea  
3. **只搜不生成**：只要材料包，关掉 idea  
4. **人工材料进 idea**：粘贴纪要/研报摘要 → 跳过 A，直接 B

## 5. 与现有模块边界

| 已有 | 关系 |
|------|------|
| **资讯** | **A 的一期主取数**；不是竞品页 |
| 全局搜索 | 可复用其资讯检索能力；一版 UI/契约不绑社区结果 |
| 外网抓取 / 只读代理 | 新能力（或后置工具）；须进白名单 |
| SV 助手多模型聊天 | 通用对话；本子模块是**固定 I/O 流水线** |
| 社区发帖 Writer/Critic | 改稿审帖；与本子模块分流 |
| 因子/策略 AI 生成 | idea 的**下游可选动作**，不在本子模块一次做完 |
| 因子面板 / RE 试算 | **不进搜集输入** |

---

## 6. 本周文档要写清的三句话

1. A→B 默认串联；证据包是合同格式。  
2. **一期来源 = 站内资讯 + 外网公开信息**；官方交易所等源后续专项设计。  
3. B 输出 idea + 引用，不输出「假新闻」和「必赚承诺」。
