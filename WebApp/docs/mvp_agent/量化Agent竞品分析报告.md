# 量化 Agent 竞品分析报告

## 一、报告概述

### 1.1 分析范围

本报告聚焦 AI Agent 在量化投研、因子研究、策略回测、组合管理、风险控制和交易执行等环节的应用。

资料主要来自截至 2026 年 8 月的公开产品、平台和研究资料。产品功能以公开信息为准，未对其实际投资收益和实盘表现进行验证。

### 1.2 核心结论

当前量化 Agent 的主流模式不是让大模型直接预测价格或直接控制资金，而是：

> **大模型负责理解意图、拆解任务和编排流程；确定性引擎负责数据计算、回测、风控和下单。**

市场主要形成三层产品结构：

1. **策略研发层**：自然语言生成策略、因子挖掘、代码生成和回测。
2. **投研运营层**：数据质检、研究实验、风险审查、报告和知识沉淀。
3. **交易执行层**：组合调仓、订单执行、实时监控和反馈学习。

目前最成熟的是“研究助手”和“自然语言策略构建”；最具潜力的是“自动化因子研究”和“量化研究运营”；真正完全自主、直接管理资金的 Agent 仍处于早期阶段。

## 二、市场分类

### 2.1 自然语言策略构建型

用户用自然语言描述交易逻辑，Agent 将其转换为结构化策略，包括：

- 标的池；
- 买卖条件；
- 因子和指标；
- 持仓与再平衡规则；
- 止盈止损；
- 仓位和风险约束。

随后系统自动生成策略图或代码，并调用回测引擎进行验证。

代表产品包括 [Pyon](https://www.pyon.io/)、[Kvants Studio](https://www.kvants.ai/) 和 [QuantConnect Strategy Builder](https://www.quantconnect.com/live/)。

这类产品最接近当前市场的主流商业形态，目标用户主要是个人投资者、初级量化用户和希望提高研究效率的策略开发者。

### 2.2 因子与 Alpha 自动挖掘型

这类 Agent 以研究假设为起点，自动完成：

`研究假设 → 因子设计 → 代码实现 → 回测 → 评分 → 样本外验证 → 失败归因 → 继续迭代`

重点不只是生成因子，而是建立可重复的研究循环，并控制未来函数、过拟合、幸存者偏差和数据泄露。

[QuantGPT](https://www.quant-gpt.com/) 已公开展示因子研究、自动回测、Walk-forward 验证、OOS 检测和信号存证等能力。[WorldQuant BRAIN](https://www.worldquant.com/brain/?next=%2Fdashboard) 则代表了较成熟的“数据、Alpha 生成、模拟验证和研究社区”平台模式，虽然不完全属于 LLM Agent。

### 2.3 多智能体投研型

系统将投研流程拆分给多个专业 Agent，例如：

- 基本面 Agent；
- 技术面 Agent；
- 新闻和情绪 Agent；
- 宏观 Agent；
- 组合管理 Agent；
- 风控 Agent；
- 交易员 Agent。

多个 Agent 分别完成分析，再由协调 Agent 进行汇总、辩论和形成结论。

[FinRobot](https://github.com/AI4Finance-Foundation/FinRobot) 和 [2025 年 EMNLP 的多智能体量化金融研究](https://aclanthology.org/2025.emnlp-industry.55/)，都采用了专业角色分工、动态代码生成和结果反思机制。

这类产品适合投研报告、个股分析、组合建议和投资委员会模拟，但其输出不一定等同于可执行的量化策略。

### 2.4 量化研究运营型

这类产品关注的不是“预测下一根 K 线”，而是提高专业量化团队的工作效率：

`数据质检 → 研究假设 → 特征构建 → 回测 → 风险复核 → 人工审批 → 报告与监控`

[DQT](https://dataquant.tech/zh/) 公开展示了这种模式，强调内部数据、可追溯实验、确定性回测、人工审批和审计记录。

这类产品更适合机构和专业团队，商业价值主要体现在：

- 缩短研究周期；
- 减少重复性工作；
- 提升实验可复现性；
- 降低研究和上线风险；
- 沉淀团队知识。

### 2.5 交易执行与闭环学习型

这类 Agent 位于策略和交易系统之间，负责：

- 组合资金分配；
- 仓位调整；
- 交易时机选择；
- TWAP/VWAP 等订单执行；
- 滑点和成交概率估计；
- 实时风险监控；
- 根据实盘结果调整参数。

实际生产系统通常会将 Agent 的权限限制在策略建议和参数调整范围内，风险引擎、限仓、熔断和 OMS 仍拥有最高权限。

例如，Interactive Brokers 在 2026 年推出了 AI 接入账户和交易指令的能力，但交易指令仍需用户确认后提交。[Interactive Brokers AI Integration](https://www.interactivebrokers.com/en/general/about/mediaRelations/6-1-26.php)

## 五、行业共性技术架构

目前较合理的量化 Agent 架构通常包括六层：

1. **交互层**：接收自然语言研究目标、投资约束和策略需求。
2. **任务编排层**：将目标拆分为数据查询、因子构建、代码生成、回测和风控任务。
3. **工具调用层**：连接行情数据、财务数据、研究数据库、Notebook、回测引擎和券商接口。
4. **确定性计算层**：负责因子计算、收益统计、组合优化、回测、风险计算和成本建模。
5. **治理层**：负责权限、审批、限仓、熔断、版本、审计和人工复核。
6. **记忆与反馈层**：保存研究假设、实验结果、代码版本、参数变化和实盘反馈。

核心流程可以概括为：

`研究意图 → Agent 拆解 → 工具执行 → 回测验证 → 风险审批 → 模拟/实盘 → 监控反馈`

## 六、主要竞争壁垒

### 6.1 数据壁垒

量化 Agent 的能力高度依赖数据质量，包括：

- 点时数据；
- 公司行为处理；
- 停牌、退市和股票池变动；
- 财务数据发布时间；
- 交易成本和市场冲击；
- 另类数据和新闻数据。

仅依靠通用大模型和公开行情数据，很难形成稳定竞争优势。

### 6.2 验证壁垒

真正有价值的系统必须能够自动检查：

- 未来函数；
- 数据泄露；
- 幸存者偏差；
- 过度参数优化；
- 样本外稳定性；
- 换手率和策略容量；
- 滑点、手续费和冲击成本；
- 不同市场环境下的表现。

### 6.3 工程壁垒

量化 Agent 不是聊天机器人，必须具备：

- 可执行代码；
- 稳定的任务调度；
- 可恢复的长流程；
- 失败重试；
- 研究版本管理；
- 结果存档；
- 模拟盘和实盘一致性。

### 6.4 风控与治理壁垒

机构客户尤其关注：

- Agent 能做什么、不能做什么；
- 谁审批了策略；
- 使用了哪一版数据和代码；
- 为什么产生某个交易信号；
- 是否可以回放完整决策链；
- 发生异常时能否自动停止。

## 七、市场机会与产品建议

### 7.1 以“研究闭环”作为核心，而不是简单聊天

重点建设：

`数据 → 假设 → 因子 → 回测 → OOS → 风控 → 报告 → 版本管理`

这比单纯提供“输入一句话生成策略代码”更容易形成长期壁垒。

### 7.2 采用“Agent 编排 + 确定性引擎”架构

大模型适合：

- 理解研究意图；
- 拆分任务；
- 生成候选方案；
- 解释结果；
- 归纳失败原因。

确定性程序适合：

- 计算因子；
- 执行回测；
- 计算风险；
- 管理订单；
- 执行限仓和熔断。

### 7.3 优先做受控自动化

推荐采用分级权限：

- **研究模式**：Agent 可自主生成和测试；
- **模拟模式**：Agent 可自动运行，但不能动真实资金；
- **生产模式**：Agent 只能生成建议，必须经过风控和人工审批；
- **自动执行模式**：仅允许在白名单策略、额度和交易时段内运行。

### 7.4 强化中国市场适配

面向 A 股市场时，可以重点建设：

- T+1；
- 涨跌停；
- 停牌与复牌；
- ST 和退市规则；
- 复权和公司行为；
- 交易费用；
- 融资融券；
- 北向、行业和主题数据；
- 组合换手与容量约束。

### 7.5 把“可验证性”作为产品卖点

每个策略都应能够回答：

- 使用了哪些数据？
- 使用了哪个时间窗口？
- 代码和参数是否发生变化？
- 是否经过样本外测试？
- 是否加入交易成本？
- 回测结果能否复现？
- 实盘信号是否可以独立验证？

## 八、结论

当前量化 Agent 市场仍处于快速演进阶段，但主流方向已经比较清晰：

> **从“AI 帮我分析市场”逐步发展为“AI 帮我完成可验证的量化研究和交易流程”。**

短期竞争焦点是自然语言建策略、多智能体投研和自动回测；中期竞争焦点是因子自动挖掘、研究记忆和策略验证；长期竞争焦点则是数据、执行、风险治理和实盘反馈闭环。

因此，一个有竞争力的量化 Agent 不应只是“大模型加行情接口”，而应成为具备：

> **数据能力、量化计算能力、Agent 编排能力、验证能力、风控能力和审计能力的完整研究系统。**

*注：本报告中的竞品功能均基于公开资料整理，公开宣传内容不代表实际投资收益或实盘稳定性。*
