# 可测步骤表 · 因子检测回测

> **产品入口：** `/factor/detect/:projectId`（`FactorDetectPage`）  
> **用途：** 按步骤测；哪一步挂就查哪一层。  
> **关联地图：** [`WebApp结构地图-GitNexus.md`](./WebApp结构地图-GitNexus.md) §4.2  
> **日期：** 2026-08-19

---

## 0. 总览（一眼）

```
[浏览器 FactorDetectPage]
    │ ① 保存项目配置（可选）
    │ ② 点「检测」→ ygBacktestFactor
    ▼
[Vite :9530]  /api/* 代理
    ▼
[本机 api_server :8766]
    │ ③ POST /api/factor/re-backtest → submit_factor_backtest（立刻返回 job_id）
    │ ④ 前端轮询 GET /api/factor/re-backtest/{job_id}
    │ ⑤ 池内 _run_job → forward_factor_backtest
    ▼
[同事 RE 192.168.3.64:9527]
    │ ⑥ POST /api/backtest/factor（真正算）
    ▼
[浏览器拿到 result]
    │ ⑦ 若 result.error 非空 → 失败，不跳转
    │ ⑧ 否则 saveDetectRun → POST /api/detect/runs
    ▼
[报告页] /factor/detect/report/:runId
```

**两条链别混：** 检测因子回测走 **本机队列 BFF**；策略回测多走 `/yg-api` 直连 RE。

## 1. 前置条件

| # | 条件 | 怎么确认 |
|---|------|----------|
| P1 | 已登录（sessionStorage JWT） | 顶栏有用户；未登录会跳 `/login` |
| P2 | 前端 `:9530`、后端 `:8766` 在跑 | `GET /api/health` → `ok: true` |
| P3 | 同事 RE `192.168.3.64:9527` 可达 | 浏览器或本机 curl；Clash 勿拐局域网 |
| P4 | 检测项目已存在 | `/factor/detect` 列表能点进项目 |
| P5 | 有可跑因子（库因子或本地源码） | 入口 `factor_name` 非空；自定义需有 `factor_code` |

## 2. 逐步执行表

### 步骤 1 · 打开检测台

| 项 | 内容 |
|----|------|
| **页面** | `FactorDetectPage` · 路由 `/factor/detect/:projectId` |
| **动作** | 从列表点进，或新建项目 |
| **前端函数** | `listProjects` / `getProject`（`detectStore.ts`） |
| **接口** | `GET /api/detect/projects` · `GET /api/detect/projects/{id}` |
| **后端** | `api_server.do_GET` → `detect_store` · **PG** |
| **成功** | 看到配置区、因子选择、可点检测 |
| **失败点** | 401 登录；列表空/404 项目；整站 API 502（见步骤 3 说明） |

---

### 步骤 2 · 点「检测」组装请求

| 项 | 内容 |
|----|------|
| **页面动作** | 点击开始检测（内部 `runDetect` 一类逻辑） |
| **前端函数** | `FactorDetectPage` 内：`resolveBacktestRange(cfg)` → 组装 `YgBacktestRequest` → **`ygBacktestFactor(req, signal)`** |
| **关键文件** | `frontend/src/pages/FactorDetectPage.tsx`（约提交处）· `frontend/src/lib/ygApi.ts` |
| **请求体要点** | `factor_name`；可选 `factor_code` / `library_name`；`start`/`end`；`universe`；`benchmark`；费率与 `analysis_level` 等 |
| **UI 日志** | 「开始检测 · 已提交排队…」 |
| **失败点** | 「因子代码为空」——本地源码路径未填；未进入网络 |

---

### 步骤 3 · 入队（本机立刻响应）

| 项 | 内容 |
|----|------|
| **HTTP** | `POST /api/factor/re-backtest`（带 `Authorization: Bearer`） |
| **前端函数** | `ygBacktestFactor` → `fetch("/api/factor/re-backtest", …)` |
| **后端入口** | `api_server.do_POST` 匹配该 path |
| **服务函数** | **`submit_factor_backtest(payload, user_id=…)`** · `re_backtest_jobs.py` |
| **行为** | 写内存 job：`status=queued`；`ThreadPoolExecutor` 提交 `_run_job`；**马上**返回 |
| **响应关键字段** | `async: true` · `job_id` · `queued` / `running` / `max_inflight`（默认 inflight=**8**，环境变量 `SVQUANT_RE_BACKTEST_INFLIGHT`） |
| **成功** | HTTP 200 + 有 `job_id`（通常 <1s） |
| **失败点** | 401；400 参数；若仍「同步干等」旧逻辑会堵死 Vite → **短接口也 502**（当前设计已避免） |

---

### 步骤 4 · 轮询任务状态

| 项 | 内容 |
|----|------|
| **HTTP** | 每 ~1.5s：`GET /api/factor/re-backtest/{job_id}` |
| **前端函数** | `ygBacktestFactor` 内 while 循环 |
| **后端函数** | **`get_factor_backtest_job(job_id, user_id=…)`** |
| **状态** | `queued` → `running` → `done` / `error` / `cancelled` |
| **取消** | Abort → `DELETE /api/factor/re-backtest/{job_id}` → **`cancel_factor_backtest_job`** |
| **超时** | 前端 deadline 约 **1800s**；job TTL **3600s** |
| **成功** | `status === "done"`，带上 `result` |
| **失败点** | 404「任务已过期」；`status=error` 抛错；跨用户 `forbidden` |

---

### 步骤 5 · 本机 BFF 打 ResearchEngine

| 项 | 内容 |
|----|------|
| **后台函数** | **`_run_job`** → **`forward_factor_backtest(payload)`** · `re_backtest_bff.py` |
| **清洗** | 去掉 `_svquant_ui` / `_svquantDraftFactor*` 等仅本站字段 |
| **出站** | `lan_http.post_json` → **`http://192.168.3.64:9527/api/backtest/factor`**（超时默认 1800s） |
| **注意** | **不经** Vite `/yg-api`；绕过 Clash（`NO_PROXY` + 无代理 opener） |
| **成功** | RE 返回 JSON；job → `done`，`result=…` |
| **失败点** | 连不上 RE / 代理 502 → job `error`；RE 线程池打满；本机 inflight 排队久 |

**GitNexus 核对调用边：**  
`do_POST` → `submit_factor_backtest`；`_run_job` → `forward_factor_backtest`。

---

### 步骤 6 · 解读 RE 业务结果

| 项 | 内容 |
|----|------|
| **位置** | 仍在前端 `FactorDetectPage`，`ygBacktestFactor` resolve 之后 |
| **判据** | HTTP 已是 200 **不够**；必须看 **`res.error`** |
| **失败** | `res.error` 有值 → 日志「检测失败（代码/执行错误）」→ **不跳转报告** |
| **成功** | `error` 空/null → 继续落库 |
| **失败点** | 因子未来函数、缺字段、组合函数写错；帮助 FAQ（3） |

---

### 步骤 7 · 落库检测 run

| 项 | 内容 |
|----|------|
| **前端函数** | **`saveDetectRun({…})`** · `detectStore.ts` |
| **HTTP** | `POST /api/detect/runs` |
| **body** | `projectId` · `factorName` · `request`（含 `_svquant_ui` 等）· `result` · `elapsedSec` |
| **后端** | `api_server` → `detect_store` · **PG**（结果可较大） |
| **成功** | 返回 `run.id` |
| **失败点** | 401；PG 挂；极旧浏览器配额错误（已迁 IndexedDB，见页面提示） |

---

### 步骤 8 · 跳转报告页

| 项 | 内容 |
|----|------|
| **路由** | `navigate(/factor/detect/report/${rec.id})` |
| **页面** | `FactorDetectReportPage` |
| **读数** | **`getRun(runId)`** → `GET /api/detect/runs/{id}` |
| **成功** | 报告图表/指标可见 |
| **失败点** | 白屏 / 空数据：run 未写入或 getRun 失败；iframe 占位未写 loading（历史问题） |

## 3. 现象 → 卡在哪一步

| 现象 | 优先怀疑步骤 | 动作 |
|------|--------------|------|
| 点检测瞬间整站 `/api` 也 502 | 3（旧同步堵死）或 8766 挂了 | 看后端日志；确认走 async job |
| 一直转圈、排队日志在 | 4～5 | 看 `queued/running`；RE 是否卡死；inflight |
| 「ResearchEngine 回测失败」 | 5 | ping `192.168.3.64:9527`；Clash；RE 日志 |
| 「代码/执行错误」有文案 | 6 | 改因子代码；看 `res.error` |
| 完成但不跳转 | 6 | `res.error` 非空 |
| 跳转了报告空白 | 8 | `GET /api/detect/runs/{id}` |
| 建项目都失败、回测却在跑 | 3/线程 | 确认队列已上；别同步打 RE |

## 4. 手工冒烟清单（最短路径）

1. 登录 → `/factor/detect` 进一项目  
2. 选一个官方库小因子 + 短区间（或试算级区间）  
3. 点检测 → Network 应看到：  
   - `POST .../re-backtest` 很快 200 + `job_id`  
   - 多次 `GET .../re-backtest/{id}`  
4. 结束后 `POST .../detect/runs` → 跳转报告  
5. 故意空代码 / 错函数名 → 应停在步骤 6，不跳转
