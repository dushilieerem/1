# SVQuant 本地启动与试用口（9532）

> **路径**：`WebApp/docs/启动与试用口9532.md`  
> **更新**：2026-08-14  
> **机器约定**：开发前端 `:9530` · 试用前端 `:9532` · API `:8766` · RE `192.168.3.64:9527`

---

## 一、端口分工（一眼）

| 用途 | 地址 | 怎么起 | 说明 |
|------|------|--------|------|
| **开发前端** | `http://127.0.0.1:9530` | `npm run dev` | 改代码热更新；同事试用别用这个 |
| **试用前端** | `http://本机局域网IP:9532` | `build:dist` + `preview:stable` | 冻住的包；要更新须重新 build 并重启 |
| **后端 API** | `http://127.0.0.1:8766` | `python -u api_server.py` | 开发 / 试用 **共用** 同一后端 |

局域网示例：`http://192.168.3.32:9530`（开发）· `http://192.168.3.32:9532`（试用）。

```powershell

cd E:\quant-lab\SV\SVQuant\WebApp\backend

# 首次：复制并编辑 .env（DATABASE_URL / JWT 等）

```

依赖：本机 Postgres、`.env` 已配好、能访问 RE `192.168.3.64:9527`。

## 三、开发前端如何启动（9530）

另开终端：

```powershell

npm install

```

打开：`http://127.0.0.1:9530`  
API 经 Vite 代理到 `127.0.0.1:8766`，**须先起后端**。

## 四、试用口 9532：build + 预览

**可以 build。** 推荐用 `build:dist`（只打前端包，不跑全量 `tsc`；仓库里若有历史类型报错不会拦构建）。

### 4.1 打包装试用

```powershell
cd E:\quant-lab\SV\SVQuant\WebApp\frontend

# 1）打包 → 生成 frontend/dist
npm run build:dist

# 2）若 9532 已有旧 preview，先关掉（见下文「端口占用」）

# 3）预览冻住包
npm run preview:stable
```

同事打开：`http://192.168.3.32:9532`（换成你机器局域网 IP）。

### 4.2 更新试用版

改完开发口、确认 OK 后：

```powershell
npm run build:dist
# 停掉旧的 preview:stable，再执行：
npm run preview:stable
```

同事 **强制刷新** 页面即可。只改源码、不重新 build，**9532 不会变**。

### 4.3 和 `npm run build` 的区别

| 命令 | 行为 |
|------|------|
| `npm run build:dist` | 仅 `vite build` → **试用口用这个** |
| `npm run build` | `tsc && vite build`；类型检查失败会整体失败 |

## 五、端口被占用了怎么处理

Windows PowerShell（管理员非必须）：

### 5.1 查谁占了端口

```powershell
# 例：查 9530 / 9532 / 8766
netstat -ano | findstr ":9530"
netstat -ano | findstr ":9532"
netstat -ano | findstr ":8766"
```

看 `LISTENING` 那一行最右侧的 **PID**。

### 5.2 结束进程

```powershell
# 把 12345 换成上面的 PID
taskkill /PID 12345 /F
```

或一次清掉某端口的监听进程：

```powershell
$port = 9532
Get-NetTCPConnection -LocalPort $port -State Listen -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force -ErrorAction SilentlyContinue }
```

### 5.3 常见场景

| 现象 | 处理 |
|------|------|
| `Port 9530 is already in use` | 关掉旧的 `npm run dev`，或按上面杀 PID 后再起 |
| `Port 9532 is already in use` | 关掉旧的 `preview:stable`，再 `build:dist` + `preview:stable` |
| `Port 8766 is already in use` | 关掉旧的 `api_server.py` 再起；**不要**同时起两个后端抢同一库连接也不要紧，但端口只能一个听 |
| 电脑打开 `http://127.0.0.1:9530` 空白/`ERR_EMPTY_RESPONSE` | 多半 9530 被 HTTPS 进程占着，却用 HTTP 访问 → 杀掉后重新 `npm run dev`（HTTP） |
