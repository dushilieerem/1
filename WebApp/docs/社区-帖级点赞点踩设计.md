# 社区 · 帖级点赞 / 点踩 设计

> 状态：**已落地**（2026-07-30）  
> 日期：2026-07-30  
> 背景：Feed / 详情只有浏览·评论·收藏，**帖子不能赞踩、无统计**；评论侧已有完整赞踩。  
> 对照：[`COMMUNITY_DESIGN.md`](./COMMUNITY_DESIGN.md)「帖级点赞」；评论实现见 `comment_votes` + `set_comment_vote`。

---

## 1. 结论（一句话）

帖子赞踩 **对齐评论**：一人一票（赞 / 踩 / 取消互斥）；**点赞发消息**、**点踩不发**；列表与详情都露出统计。

---

## 2. 现状缺口

| 能力 | 评论 | 帖子 |
|------|------|------|
| 数据表 | `comment_votes` | ❌ 无 |
| API | `POST .../comments/{id}/vote` | ❌ 无 |
| 详情操作 | 👍 / 👎 + 数 | 仅「收藏」 |
| Feed 统计 | — | 👁 💬 ⭐，无赞踩 |
| 消息 | `type=like` + `comment_id` →「赞了你的评论」 | ❌ |

`notifications.type` 已含 `like`；个人中心「收到的赞」可直接复用，只需区分帖 / 评。

---

## 3. 产品规则

1. **一人一帖一票**：`1` 赞 / `-1` 踩 / `0` 取消；再点同态 = 取消；赞↔踩直接切换。  
2. **点赞 → 消息**：首次（或从无/踩切到赞）通知**帖作者**；自己赞自己不通知（沿用 `_insert_notification` 的 `user_id == actor_id` 跳过）。  
3. **点踩 → 不消息**。  
4. **取消赞 / 改踩**：不删历史消息（与评论一致；避免已读态纠缠）。  
5. **游客**：只看数，点按钮跳登录。  
6. **不可赞自己的帖**（同收藏）：详情页自己的赞/踩为灰色只读；后端亦静默忽略。与收藏正交。  
7. **排序（本版可选）**：Feed 增加「点赞最多」；不做也可，列表先出数字即可。

### 消息文案

| 条件 | 文案 |
|------|------|
| `type=like` 且 `comment_id` 有值 | 「赞了你的评论」 |
| `type=like` 且 `comment_id` 为空 | 「赞了你的帖子」 |

跳转：帖赞 → `/community/post/{id}`；评赞 → 原逻辑带 `?comment=`。

铃铛未读数、按类型筛选「收到的赞」**不用改类型枚举**。

## 4. 数据

```sql
CREATE TABLE IF NOT EXISTS post_votes (
  user_id    BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  post_id    BIGINT NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  value      SMALLINT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (user_id, post_id),
  CONSTRAINT post_votes_value_chk CHECK (value IN (-1, 1))
);
CREATE INDEX IF NOT EXISTS idx_post_votes_post ON post_votes (post_id);
```

计数：**不落 posts 冗余列**，列表/详情用 `COUNT` 聚合（同 `favorite_count`）。

通知插入：

```text
type = 'like'
post_id = <帖>
comment_id = NULL          -- 与评赞区分
```

运营仓近 7 日「赞」：`comment_votes` + `post_votes` 合并（现只算评论）。

---

## 5. API

`POST /api/community/posts/{id}/vote`  
Body：`{ "value": 1 | -1 | 0 }`（需登录）

响应：

```json
{
  "ok": true,
  "post_id": 12,
  "like_count": 3,
  "dislike_count": 1,
  "my_vote": 1
}
```

读接口扩展（Feed item / 详情 `post`）：

| 字段 | 说明 |
|------|------|
| `like_count` | 赞数 |
| `dislike_count` | 踩数 |
| `my_vote` | 登录用户：`1`/`-1`/`0`；游客省略或 `0` |

## 6. UI

### 6.1 Feed 卡片（`PostCard` 底栏）

现有：👁 浏览 · 💬 评论 · ⭐ 收藏  

追加：**👍 like_count · 👎 dislike_count**（只读数字，点击进详情再操作；避免列表误触刷票）。

### 6.2 帖详情顶栏

在「收藏 N」旁加两组按钮（样式对齐收藏）：

- `👍 赞 N`（已赞高亮）  
- `👎 踩 N`（已踩高亮）  

交互同评论组件：点已选 = 取消；点另一侧 = 切换。

### 6.3 消息 / 个人中心

- Tab「收到的赞」：帖赞 + 评赞混排（已按 `type=like`）。  
- `typeLabel`：按是否有 `comment_id` 分支文案（见上）。

### 6.4 排序（可选，同迭代若顺手）

Feed：`views` / `favorites` / `newest` / **`likes`**。  
实现：`ORDER BY like_count DESC`。

## 7. 实现切片（建议顺序）

1. DB：`post_votes` + ensure  
2. `set_post_vote`（抄 `set_comment_vote`，赞时 `comment_id=None`）  
3. 列表/详情 SQL 挂 `like_count` / `dislike_count` / `my_vote`  
4. API 路由 + `communityApi.votePost`  
5. 详情按钮 + Feed 统计  
6. 消息文案分支  
7. （可选）Feed「点赞最多」+ 运营 `likes_7d` 合并帖赞  

预估：半日～一日内可收口。

---

## 8. 验收

- [ ] 详情可赞 / 踩 / 取消；数正确；刷新后 `my_vote` 仍在  
- [ ] Feed 露出赞、踩数  
- [ ] A 赞 B 的帖 → B「收到的赞」出现「赞了你的帖子」，铃铛 +1  
- [ ] A 踩 B 的帖 → B **无**新消息  
- [ ] 自己赞自己的帖 → 无数异常、**无**消息  
- [ ] 游客点赞 → 跳登录  
- [ ] 评赞文案仍为「赞了你的评论」，互不串

## 9. 不做（本版）

- 赞踩排行榜 / 成就  
- 踩的负向权重进热门算法（热门仍可继续用浏览等）  
- 取消赞时撤回通知  
- 把「收藏」改成赞（二者保留）
