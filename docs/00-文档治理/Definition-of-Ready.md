# Definition of Ready

Feature 只有完成准入检查后才能进入开发。检查深度跟随决策权重：平台级 / P0 / 跨模块走完整清单，普通 FEAT 走轻量清单，小改动（Bug 修复、重构、不改公共行为的单文件改动）不要求文档。

## 轻量清单（普通 FEAT）

- [ ] 价值一句话：解决谁的什么痛点，不做有什么影响。
- [ ] 范围冻结：本次做什么、明确不做什么（MVP 边界）。
- [ ] 影响面：涉及的模块、接口、数据已列明，确认不跨模块。
- [ ] 业务规则：关键规则、异常与兜底已写清。
- [ ] 验收标准：可测试的通过条件明确。
- [ ] 风险与依赖：技术风险、外部依赖和回退方式已记录。
- [ ] 状态与回链：已进入需求池，包 README 标明上下游。

## 完整清单（平台级 / P0 / 跨模块）

### 需求层

- [ ] 所属 Initiative、目标用户和具体业务痛点明确。
- [ ] 价值目标和可测试指标明确。
- [ ] MVP、以后再做和明确不做项已冻结。
- [ ] 优先级、时间约束、外部依赖和主要风险已记录。

### 业务层

- [ ] 用户故事或业务场景覆盖正常路径、分支和异常路径。
- [ ] 角色、职责、权限边界和交接点明确。
- [ ] 核心业务规则、数据校验、状态变更和闭环标准明确。
- [ ] 业务验收标准可由产品或业务人员独立判断。

### 架构层

- [ ] 模块边界、职责、数据所有权和接口依赖已评估。
- [ ] 数据结构、兼容策略、性能、安全和可观测性影响已评估。
- [ ] 关键技术风险已有验证结论或缓解方案。
- [ ] 重大长期技术选择已记录 ADR；迁移和回滚边界明确。

### 功能层

- [ ] 功能清单、操作入口、字段、枚举、状态和权限规则明确。
- [ ] 空态、加载态、错误态、重试和越权提示明确。
- [ ] 每个业务场景和验收标准都有对应功能或用例。
- [ ] 用户文档、API 契约、原型或示例已同步到可评审状态。

### 实现准入

- [ ] 任务、依赖、复杂度、负责人和里程碑已拆分。
- [ ] 开发自测、联调、回归、性能/安全测试策略已定义。
- [ ] 发布、监控、权限、数据迁移和回滚方式已定义。
- [ ] 没有阻塞性未决问题；未决事项有负责人和截止时间。
