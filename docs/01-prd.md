## 0. 文档说明

本文档定义 YGQuant 平台的产品需求，是后续架构设计（`03-architecture.md`）、技术方案与排期的输入。

- **优先级约定**：`P0` MVP 必备 → `P1` 早期重要 → `P2` 中后期 → `P3` 远期
- **阶段约定**：`阶段一` 研究引擎（CLI/SDK，无 AI、无 SaaS）→ `阶段二` 实盘交易（CLI/SDK，无 AI、无 SaaS）→ `阶段三` AI 完整平台（Web SaaS，多租户）。优先级表示"必要性"，阶段表示"实现顺序"，二者不完全等同。
- **接口先行（API-first）**：阶段一/二引擎暴露 Python API + CLI + 预留 HTTP 适配层，阶段三 AI 平台通过这些接口调用引擎。
- **标注约定**：`TBD` 表示待与产品/业务确认；`[AI]` 标记 AI 对话研究助手相关需求（阶段三引入）
- **关联文档**：`02-domain/`（领域建模）；`03-architecture.md`（引擎分层架构）

## 1. 产品概述

### 1.1 一句话定位

YGQuant 是一个**以 AI 对话研究助手为核心交互的一站式 A 股量化投研 SaaS 平台**，让个人量化研究者用自然语言完成策略研发、回测、分析，并能向组合风控与实盘交易平滑延伸。

### 1.2 背景与问题

当前个人量化研究者面临三重痛点：

1. **门槛高**：传统量化平台以代码 IDE 为主，新手需先掌握 Python + 数据 API + 回测框架才能跑通第一个策略。
2. **链路割裂**：数据获取、因子计算、策略回测、绩效归因散落在不同工具，研究者在数据搬运上耗时多于策略思考。
3. **AI 渗透浅**：现有平台（聚宽、米筐、优矿、BigQuant）虽有 AI 元素，但多停留在「代码补全」或「可视化建模」层面，缺少以自然语言驱动的端到端研究助手。

### 1.3 产品愿景

让每一位有想法的研究者，都能在与 AI 的对话中把投资直觉变成可验证的量化策略——**"说人话，做量化"**。

### 1.4 核心价值主张

| 价值点 | 说明 |
|---|---|
| 对话即研究 | 用自然语言描述策略思路，AI 生成可运行代码并自动回测、解读结果 |
| 一站式闭环 | 数据 → 因子 → 策略 → 回测 → 分析 → 报告，单平台完成，无数据搬运 |
| 研究友好 | 引擎层按机构级标准设计（风控/组合/执行），但交互层对个人友好 |
| 平滑演进 | 从研究到模拟盘再到实盘，能力随用户成长而解锁 |

## 2. 市场与竞品分析

### 2.1 目标市场

A 股个人量化研究市场，逐步向中小私募/券商投研团队延伸。市场特征：用户基数大但付费意愿分化明显，需要免费档引流 + 付费档变现的分层模型。

### 2.2 竞品对标

| 平台 | 市场范围 | 核心特色 | AI 能力 | YGQuant 差异化点 |
|---|---|---|---|---|
| 聚宽 JoinQuant | A 股 | 回测+模拟+实盘、社区因子 | 弱（代码补全级） | AI 对话研究助手为核心交互，非代码优先 |
| 米筐 RiceQuant | A 股 | RQAlpha 开源引擎、机构+个人 | 弱 | 同上；纯商业 SaaS 体验更聚焦 |
| 优矿 UQER | A 股 | 通联数据、偏研究 | 弱 | 端到端对话闭环 + 交易延伸 |
| BigQuant | A 股 | AI/机器学习、可视化建模 | 中（偏 AutoML 建模） | 我们走"对话助手"路线而非"拖拽建模"，交互更轻 |
| QuantConnect | 国际多市场 | Lean 开源引擎、社区 | 弱 | A 股本土化 + 对话式研究 |
| Alpaca | 美股 | API 券商、交易优先 | 弱 | 我们研究优先、交易为延伸 |

### 2.3 差异化总结

**核心差异化 = AI 对话研究助手**。竞品的 AI 多为「锦上添花」（补全/可视化），YGQuant 将 AI 对话作为「主交互通道」，承担代码生成、回测调度、结果解读、报告生成的端到端职责。

## 3. 目标用户与角色

### 3.1 用户画像

| 画像 | 占比预期 | 特征 | 核心诉求 |
|---|---|---|---|
| 量化入门者 | 高 | 有投资经验、缺编程能力 | 用自然语言跑通策略、学习量化 |
| 量化进阶者 | 中高 | 会 Python、有策略想法 | 高效回测、因子研究、AI 辅助 debug |
| 量化教学者 | 低 | 高校/培训讲师 | 教学演示、分享案例、班级管理 |
| 机构投研团队 | 低（中后期） | 私募/券商研究员 | 协作、权限、合规审计、模拟→实盘 |

### 3.2 用户角色与权限（RBAC）

| 角色 | 说明 | 关键权限 |
|---|---|---|
| 免费用户 | 注册即得 | 公开数据、限额 AI、限额回测、公开分享 |
| 个人付费用户 | 订阅个人档 | 私有策略/因子、更多额度、分钟数据 |
| 团队成员 | 团队档席位 | 团队空间共享、协作编辑 |
| 团队管理员 | 团队档所有者 | 席位管理、配额分配、权限配置 |
| 机构用户 | 机构档 | 实盘、风控规则、合规审计、数据隔离 |
| 平台运营 | 内部 | 用户管理、计费、内容审核、运营看板 |

> `TBD`：是否设置「量化教学者」专属教育档（免费或低价、班级管理能力）。

### 3.3 典型用户旅程

**旅程 A（阶段一 · 研究引擎，CLI/SDK）：研究员策略与因子研究**
1. 在策略 py 文件中编写双均线策略（调用引擎 Python API）
2. 命令行运行回测 → 输出收益曲线与标准绩效（控制台/文件）
3. 调整参数 → 再回测 → 对比结果
4. 在因子库 py 文件中定义因子 → 运行 IC/IR/分层分析
5. （阶段三后）通过 AI 平台界面分享到社区

**旅程 B（阶段三 · AI 完整平台）：AI 对话式研究**
1. 输入"帮我写一个双均线策略，回测沪深300过去3年"
2. AI 生成策略代码 → 一键回测 → 返回收益曲线与关键指标
3. 追问"为什么2024年5月回撤这么大？"→ AI 归因解读
4. AI 辅助因子分析、自动生成投研报告

## 4. 产品目标与成功指标

### 4.1 产品目标

- **G1（阶段一 · 研究引擎）**：研究员能用平台完成策略开发、因子研究、回测与绩效分析的完整闭环。
- **G2（阶段二 · 实盘交易）**：研究产出的策略能安全部署到实盘，打通研究→模拟→实盘链路。

## 6. AI 能力专题

> 本章定义平台核心差异化的详细需求。AI 对话研究助手定位为**端到端研究主交互通道**，而非代码补全工具。
> **实现时序**：AI 在阶段三引入，前两阶段（研究引擎、实盘交易）不含 AI。AI 能力建立在已成熟的研究引擎与实盘交易系统之上。

### 6.1 能力清单

| ID | 能力 | 阶段 | 说明 |
|---|---|---|---|
| F1 | 自然语言 → 策略/因子代码生成 | 阶段三 3a | "写一个低估值高股息策略"→ 可运行代码 |
| F2 | 回测结果解读与归因 | 阶段三 3a | 解释收益来源、回撤成因、关键拐点 |
| F3 | 策略 debug 与优化建议 | 阶段三 3a | 报错解读、逻辑修正、防过拟合提示 |
| F4 | 量化知识问答 | 阶段三 3a | 市场规则（T+1/涨跌停）、API 用法、量化概念 |
| F5 | 投研报告自动生成 | 阶段三 3a | 自然语言生成图文报告 |
| F6 | Agent 多步研究 | 阶段三 3b | 规划→生成→回测→解读→报告，自主完成研究任务 |
| F7 | 对话式因子分析与对比 | 阶段三 3b | "比较动量因子和价值因子近期表现" |

### 6.2 交互模式

- **嵌入式对话面板**：在工作台右侧常驻，与编辑器/回测区联动（对话→代码→回测→结果回流对话）。
- **指令式快捷命令**：`/backtest`、`/factor`、`/report` 等斜杠命令快速触发。
- **Agent 模式**（P2）：用户给出研究目标，AI 自主规划多步并执行，关键节点可暂停人工确认。

### 6.3 安全与护栏（硬性约束）

| 约束 | 说明 |
|---|---|
| 沙箱执行 | AI 生成代码必须在隔离沙箱运行，禁止直接访问生产/实盘环境 |
| 实盘二次确认 | 任何影响实盘资金的操作必须人工二次确认，AI 不得自主下单 |
| 合规边界 | AI 仅作研究辅助，**不提供投资建议/荐股**，全程展示免责声明 |
| 数据保密 | 用户私有策略/因子不得进入他人上下文，禁止用于跨租户训练 |
| 可追溯 | AI 生成的代码须标注依据（因子库引用、API 版本） |
| 防幻觉 | 涉及市场规则、数据口径时以平台规则库为准，不臆造 |

### 6.4 模型策略

## 8. SaaS 平台需求（阶段三 · AI 平台）

> SaaS 层（多租户、计费、登录、Web UI）在阶段三 AI 平台引入。阶段一/二为 CLI/SDK 引擎，无 SaaS 层。

### 8.1 多租户模型

- **共享池**（个人档）：共享计算与数据资源，逻辑隔离用户数据。
- **专属隔离**（机构档）：独立数据库 Schema / 独立算力配额，满足合规与性能要求。

### 8.2 计费分层（草案，价格 `TBD`）

| 档位 | 价格 | 数据 | AI 额度 | 回测 | 交易 | 协作 |
|---|---|---|---|---|---|---|
| 免费档 | ¥0 | 日线公开 | 限额（如 20 次/日） | 限额 | 无 | 公开分享 |
| 个人专业版 | `TBD`/月 | 日线+分钟 | 高额度 | 长时长 | 模拟盘 | 私有策略 |
| 团队版 | `TBD`/席位/月 | 同上 | 团队共享 | 高并发 | 模拟盘 | 团队空间 |
| 机构版 | 联系销售 | 全量+另类 | 定制 | 专属算力 | 实盘 | 权限/审计/合规 |

### 8.3 配额与限流

按档位对 AI 调用次数、回测并发与时长、数据下载量设置软/硬配额，超额引导升级。

### 8.4 部署形态

- **公有云 SaaS**（默认）：多租户共享。
- **专属/私有部署**（机构档可选）：`TBD` 是否支持。

## 9. 范围边界（Out of Scope）

> "首期"指阶段一（ResearchEngine）。实盘交易（阶段二）与 AI（阶段三）属后续阶段，非永久排除。以下为各阶段均不做或远期才考虑的边界。

- 港美股、期货、期权的实盘交易（多市场扩展点，远期）
- 高频/Tick 级策略研究（算力成本过高）
- 投顾/荐股服务（合规边界，AI 明确不提供投资建议）
- 移动端 App（Web 优先）
- 自研行情数据源（依赖第三方授权数据）

## 10. 里程碑与发布计划（Roadmap）

> **实现路径：先研究、后实盘、再 AI 结合**。先把量化研究基础设施与实盘交易系统做扎实（阶段一、二，不含 AI），最后用 AI 对话助手将两者结合成完整平台（阶段三）。AI 在阶段三才引入。

### 阶段一 · ResearchEngine（策略与因子研究引擎）

**形态**：CLI/SDK（无 Web 界面、无 SaaS 层）。研究员在因子库/策略 py 文件中写代码，命令行运行。
**目标**：完成策略开发、因子研究、回测、绩效分析的完整研究闭环（**不含 AI、不含实盘、不含 SaaS**）。

| 子阶段 | 核心交付 | 对应功能 ID |
|---|---|---|
| 1a 研究闭环核心（向量化） | A 股日线/基本面数据 + 策略 py 文件 + 向量化回测 + 市场规则 + 标准绩效 | A1, A2, C1, C2, C3, G1 |
| 1b 因子研究 | 因子表达式引擎 + 内置因子库 + 因子分析(IC/IR/分层) + 归因分析 | B1, B2, B3, G2 |
| 1c 研究增强（事件驱动） | 事件驱动回测引擎（复杂策略）+ 另类数据 + 报告导出（社区分享延后到阶段三） | A3, G3 |

**涉及模块**：QuantCore（数据/因子/策略/回测/分析/报告/市场规则）+ ResearchEngine（CLI/SDK，不含 AI）
**接口预留**：所有引擎能力暴露 Python API + CLI + 预留 HTTP 适配层，供阶段三 AI 平台调用。

### 阶段二 · 实盘交易系统（策略上实盘）

**形态**：CLI/SDK（无 Web 界面、无 SaaS 层）。研究员/交易员通过命令行/脚本部署策略到实盘。
**目标**：研究产出的策略能部署到实盘，含风控与组合管理（**不含 AI、不含 SaaS**，手动操作）。

| 子阶段 | 核心交付 | 对应功能 ID |
|---|---|---|
| 2a 模拟盘 → 实盘接入 | 模拟盘(实时行情) + 券商 API 接入 + 订单管理 + 实盘持仓 | C5, E1, E2 |
| 2b 风控与组合 | 风控规则引擎 + 风险指标 + 组合构建与再平衡 | D1, D2, D3, E3 |

**涉及模块**：TradingEngine + QuantCore（Execution/Portfolio/Risk Engine）
**接口预留**：订单/风控/组合能力暴露 Python API + CLI + 预留 HTTP，供阶段三 AI 平台调用。

### 阶段三 · 完整平台（AI 结合研究引擎与实盘）

**形态**：Web SaaS（多租户、登录计费、AI 对话界面）。
**目标**：用 AI 对话研究助手把 ResearchEngine 与实盘交易系统结合，形成 AI 量化投研 SaaS 平台，达成产品愿景。

| 子阶段 | 核心交付 | 对应功能 ID |
|---|---|---|
| 3a AI 研究助手 + SaaS 基础 | SaaS 层(登录/计费/多租户) + AI 研究助手(代码生成/解读/debug/问答/报告) + 社区分享 | I1, I2, F1, F2, F3, F4, F5, H1 |
| 3b AI Agent 与实盘护栏 | 多步研究 Agent + 对话式因子分析 + 实盘二次确认护栏 | F6, F7 |
| 3c 平台成熟 | 团队协作 + 合规审计 + 多市场扩展 + 机构计费 + 用量统计 | H2, I3, I4, A4, A5, A6, 多市场 |

## 11. 风险与依赖

| 风险/依赖 | 影响 | 缓解 |
|---|---|---|
| A 股数据源合规与授权 | 高 | 优先签订授权；免费档仅用公开/延迟数据 |
| AI 幻觉导致错误策略 | 高 | 沙箱执行、护栏、可追溯、防过拟合提示 |
| 实盘交易安全 | 高 | 二次确认、风控前置、与持牌券商合作 |
| 监管：量化工具 vs 投顾资质 | 中 | 明确产品边界为研究工具，不提供投资建议 |
| 大规模回测算力成本 | 中 | 档位限流、向量化优化、结果缓存 |
| 商用大模型 API 成本与可用性 | 中 | 多模型兜底、用量计费转嫁、缓存常见问答 |
