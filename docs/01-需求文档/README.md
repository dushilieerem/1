# 需求文档

本层回答“为什么做”与“业务怎么跑”：锁定真实问题、用户价值、量化目标、范围边界、优先级和风险，并在同层维护业务流程、角色、规则和领域边界。这里的结论是架构层和功能层的输入，不是开发任务清单。

> 业务层不再单独设目录：0-1 阶段业务设计与需求定义是同一批人在同一时刻完成的工作，业务结论就近落在产品文档、Initiative 领域设计和功能包「业务规则与场景」中，但“脱离系统业务能否独立跑通”的自检要求不变。

## 进入下一层的最低条件

- 明确要解决的业务问题和目标用户。
- 有可衡量的成功指标或可验证的判断标准。
- 写清必须做、可以以后做和明确不做的范围。
- 标注优先级、风险、依赖和时间约束。
- 能说明“不做这个需求”会造成什么影响。
- 业务流程、角色规则和状态闭环已定义，不得用页面或接口设计替代业务定义。
