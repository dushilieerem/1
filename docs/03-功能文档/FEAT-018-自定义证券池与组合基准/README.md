# FEAT-018：自定义证券池与组合基准

- 状态：开发中（ResearchEngine 快照契约已完成；WebApp CRUD 待交付）
- 所属 Initiative：INIT-001 投研核心
- 所属能力：数据、因子研究、策略回测
- 宏观影响：L1（在既有研究能力中补充可复用研究资产，不改变产品模块边界）

## 1. 价值与范围

### 背景

当前因子和策略回测可传入固定股票池名称，并只能选择少数内置指数作比较基准。研究员常见的研究对象却是自己维护的一组证券，例如“消费龙头 30 只”“排除 ST 的高股息候选池”或团队关注名单；他们也需要把自选篮子、固定权重组合或多指数配比作为比较对象。

现有 `universe` 与 `benchmark` 只是请求中的字符串：无法保存成分和权重、无法记录版本，也无法让两类回测复用同一对象。固定指数股票池按最新一期成分筛选，历史样本内存在幸存者偏差，不能作为动态池的正确实现基础。

### 用户与商业价值

- 研究员可一次定义、多次复用自己的证券范围，不必在每次回测中修改代码或粘贴代码列表。
- 研究员可用自己的投资机会集作为因子截面，并将策略收益与真正相关的被动组合比较。
- 回测结果明确记录股票池、基准、成分、权重及版本，使同一研究可复现、可审计。
- 自定义研究资产是从“演示型回测工具”走向个人专业用户和团队工作台的基础门槛；用户沉淀的研究范围和比较口径会随项目保存，并可复用到团队共享、权限隔离、策略发布和模拟盘组合管理。

### MVP 范围

**必须做**：WebApp 的用户级证券池与组合基准 CRUD、鉴权与版本解析；静态证券池（显式股票清单）；静态组合基准（显式股票权重）；WebApp 将不可变快照提交给因子与向量化策略回测；运行结果写入资产版本、内容哈希和实际成分/权重快照；保留已有固定指数参数兼容。

**可以以后做**：历史日期×证券成分和权重、定期调仓、指数历史成分、等权/市值权重自动生成、规则型股票池、CSV 导入导出、在线编辑、团队共享与权限。

**明确不做**：Wave 3 多租户资产服务；任意数据源的实时选股；实盘组合执行；用最新成分近似历史成分；为基准静默补齐缺失价格或忽略不可交易证券。

| 类型 | 风险 | 缓解 |
|---|---|---|
| 产品 | 用户混淆股票池与基准 | API、页面与结果分别标记“研究/交易范围”和“业绩比较对象”。 |
| 研究正确性 | 最新指数成分造成幸存者偏差 | MVP 只承诺用户静态清单；历史指数池另行以日期掩码实现。 |
| 数据 | 自定义基准成分缺少价格 | 执行前严格校验，拒绝静默前填或删减。 |
| 架构 | 用户数据库直接耦合回测内核 | 保持 `WebApp Asset → Snapshot → ResearchEngine` 边界，ResearchEngine 不读取用户数据库。 |
| 项目 | WebApp CRUD 与研究 API 的职责混淆 | WebApp 负责所有用户数据与权限，ResearchEngine 只保留快照校验、回测和结果元数据。 |

## 4. 当前结论

WebApp 负责用户资产的 CRUD、鉴权、数据库存储、版本解析和快照生成；ResearchEngine 只校验并消费快照。历史逐日成分、规则选股和事件驱动接入作为后续增量。现有固定指数代码继续兼容。

## 5. API 摘要

- `POST /api/backtest/factor`、`POST /api/backtest/strategy`：使用
  `universe_snapshot` 和 `benchmark_snapshot` 接收 WebApp 已解析的资产快照。
  各引用不能与旧的 `universe`、`benchmark` 参数同时传入。
