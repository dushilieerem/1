# FEAT-025：免费数据源补齐日频基本面与证券状态 MVP

- 状态：待批准
- 所属 Initiative：INIT-001 投研核心
- 所属能力：数据 / 研究基础设施
- 优先级：P0
- 关联 Feature：FEAT-010、FEAT-024
- 提案日期：2026-08-14

> 当前边界（2026-09-17）：免费数据源采集、候选 release 和活动 `marketdata/` 不属于 SVQuant；由独立数据发布项目生成并供 ResearchEngine 使用。本 Feature 在 SVQuant 仅保留数据契约、产品需求和跨仓库验收说明。

## 1. 价值与范围

### 目标

使用可公开获取的免费数据源，补齐以下两个活动数据资产：

- ResearchEngine 配置的 `marketdata/panels/daily_basic.parquet`
- ResearchEngine 配置的 `marketdata/panels/security_status.parquet`

MVP 的成功标准是：两张表追平 `market_data.parquet` 的最大交易日；沪深股票的核心估值、ST 和停牌字段可用于研究；每个缺口和口径差异均可审计。MVP 不承诺免费数据源与 iFinD 全字段、全市场、全历史等价。

### 背景

当前 `daily_basic.parquet` 和 `security_status.parquet` 没有追平行情数据：前者结束于 2026-08-04，后者只有 141 个交易日；`security_status.is_st` 仍全部为空。现有市场行情已到 2026-08-12，因此研究面板存在最新六个交易日缺口。

现有数据底座已经规定了两张表的字段契约和不可变 release 机制。继续等待单一商业源全量完成，会阻塞基本面因子和交易状态相关策略。需要一个成本低、可重复执行、能明确披露缺口的免费源 MVP。

### 用户与商业价值

- 研究员可以使用最近交易日的市值、股本、估值、ST 和停牌状态进行因子研究。
- 策略回测可以识别沪深股票的 ST 和停牌约束，减少把不可交易股票当作可交易股票的错误。
- 数据维护者可以在无商业数据授权的开发环境中重建候选 release，并定位每个字段的来源和缺失原因。
- 未来切回 iFinD 时，上层字段和 Provider 接口无需变化。
- 本能力是基本面因子、经典价值策略和事件驱动回测的共同前置数据；降低早期开发对商业数据授权的依赖，缩短从数据采集到内部 Demo 的周期，并为后续付费数据源切换保留标准字段和审计链路。

### 竞品与替代方案分析

| 方案 | 优点 | 局限 | 本 MVP 取舍 |
|---|---|---|---|
| AkShare | 接口覆盖面广，适合快照和公开市场数据 | 接口口径依赖具体站点，历史稳定性和授权需自行评估 | 用于 CNINFO 股本和快照校验，不直接承担所有历史字段 |
| BaoStock | 免费、适合沪深历史日频估值和交易状态 | 北京市场和部分字段覆盖有限，需处理限流及数据口径 | 作为沪深历史核心源 |
| Tushare Pro | 字段体系成熟，部分接口易用 | 免费额度、权限和频率限制会影响全市场历史回补 | 不作为本 MVP 的唯一依赖 |
| 商业数据源 | 口径和服务通常更完整 | 需要授权、成本和供应商绑定 | 保留 iFinD 字段语义，后续显式切源 |

### MVP 范围

**必须做**：

- 将两张表补到 `market_data.parquet` 最大交易日。
- 保留既有 release 中 2026-08-04 及以前的非空值。
- 使用 BaoStock 补沪深 `pe_ttm`、`pb`、`ps_ttm`、`is_st`、`is_suspended`。
- 使用 AKShare/CNINFO 股本变动补 `total_shares` 和 `float_shares`。
- 使用未复权收盘价和股本计算 `total_mv`、`float_mv`。
- 生成字段级来源 manifest、质量报告和文件哈希。
- 对候选 release 进行 Provider 和代表性回测回归后切换活动数据。

**可以以后做**：北京市场历史估值和交易状态的专门适配器；有效日期完整的申万行业变更历史；历史涨停、跌停、停牌原始状态文本；免费源与 iFinD 的系统性差异校准及数据源切换工具。

**明确不做**：用最新申万行业静态截面反填历史；用动态 PE 或静态 PE 填充标准字段 `pe`；将缺失值填零或静默使用另一来源逐单元格兜底；在未完成授权评估前承诺数据可对外商业再分发。

### 优先级评估与决策请求

按“商业价值 × 用户价值 × 战略价值 ÷ 开发成本”评估：商业价值 4、用户价值 5、战略价值 4、开发成本 3，优先级评分约 26.7，属于 P0。

决策请求：批准 7～9 个工作日、1 名数据工程师的 MVP；先发布开发和内部回测使用的数据版本，待授权和质量审查完成后再决定是否用于对外服务。

| `security_status` 构建器 | ST、停牌、行业/涨跌停边界处理 | 3 | 高 | BaoStock、旧 release | 1 |
| 质量检查和 manifest | 覆盖率、重叠期、哈希和异常报告 | 3 | 中 | 两个构建器 | 1.5 |

预计 7～9 个工作日；公共接口全量回补的网络运行时间另计，不占用开发人天承诺。

里程碑：

- M1：100 只股票样本通过，字段口径和市场范围获评审确认。
- M2：原始数据可断点采集，重复运行不会产生重复记录。
- M3：候选 release 追平行情最大日期，质量报告完整。
- M4：沪深 ST/停牌回归通过，因子和策略读取不改接口。
- M5：内部环境完成一次 release 切换和回滚。

| 角色 | 责任 |
|---|---|
| 数据工程 | 采集器、标准化、发布和质量检查 |
| 量化研究 | 估值口径、停牌/ST 样本和回测结果验收 |
| 平台维护 | release 切换、Provider 回归和运行配置 |
| 产品/负责人 | 确认 MVP 是否仅限内部研究，批准后续商业化范围 |

| 风险类型 | 具体风险 | 触发条件 | 应对 |
|---|---|---|---|
| 技术 | 公共接口限流、字段变更 | 连续请求失败或 schema 改变 | 退避、缓存原始响应、固定版本并停止发布 |
| 数据 | 估值口径与现有 iFinD 不一致 | 重叠区间差异显著 | 标记来源切换，禁止静默覆盖，重新评估因子 |

| 产品 | 用户误解为全字段免费替代 | 请求 `pe`、行业或完整涨跌停 | 在 manifest/API 能力声明中标记 partial/blocked |
| 合规 | 免费源缓存和再分发授权不清 | 准备对外展示或 SaaS 化 | 先完成授权审查，MVP 限内部研究 |

Definition of Done：

- 文档包和 backlog 已更新。
- 采集原始数据、标准化表和候选 release 可定位。
- 两张目标表满足 schema 和日期契约。
- 质量报告明确覆盖率、异常、来源和未完成字段。
- 旧 release 可回读，新 release 可切换和回滚。
- 测试和代表性回测通过，未引入隐式填充或未来函数。

## 4. 核心结论

1. BaoStock 负责沪深历史 `pe_ttm`、`pb`、`ps_ttm`、`is_st` 和交易状态。
2. AKShare/CNINFO 负责股本变动；市值由未复权收盘价乘以对应股本计算。
3. 现有 `pe` 保持 iFinD 语义，MVP 不用免费源的动态 PE 冒充。
4. 申万历史行业和完整历史 `limit_status` 暂不回填，避免引入未来信息或口径伪装。
5. 采用新 release 构建、质量检查、哈希登记和原子切换，禁止直接修改活动数据。
