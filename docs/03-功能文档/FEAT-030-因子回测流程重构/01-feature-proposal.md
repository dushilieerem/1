# FEAT-030：因子回测流程重构 — Feature Proposal

- 状态：开发中（实施中）
- 日期：2026-08-28
- 所属 Initiative：INIT-001；建议优先级：P0
- 审核人：用户（已批准开工）；实施责任：ResearchEngine 实施者

> 实施状态（2026-08-28）：用户已明确批准按本方案开始重构；四引擎主链及入口切换已完成，
> 当前进入专项验收，尚未宣布 Feature 最终交付。

## 背景与用户问题

架构纠偏（2026-08-28）：用户指出 QuantCore 并无多个实际消费者，并明确采用常规 FastAPI
services/models 分层。取消共享库假设，将引擎业务归 ResearchEngine，内部模型单独提取。
该修订已授权实施，详见 [目录与职责修订](06-app-layout.md)；原方案中的 QuantCore 归属不再适用。
预计追加约 3 人天完成目录迁移和验证，不改变用户功能、商业目标或计算口径。

重构前因子入口曾统一经过 FactorBacktestExecutor，但实际计算继续委托
_FactorBacktestAlgorithm，过滤、预处理、组合构造、基准、分层评价与结果处理仍分散在
多个应用辅助模块。NativeEngine 的含义仅是底层向量化收益计算，与团队希望的
“BacktestEngine 表示完整回测流程”不一致。

这增加了定位默认参数、理解时序、修改共同计算步骤和比较单次/批量结果的成本。
批量 Profile 还强制开启停牌及涨停过滤，不能满足“处理可选且默认关闭”的统一要求。

## 用户价值、商业价值与战略价值

| 维度 | 本次价值 | 验证方式 |
|---|---|---|
| 用户价值 | 同一显式配置在 API、批量、Python 中产生一致结果，过滤是否生效可见 | 跨入口数值测试、过滤告警验收 |
| 开发价值 | 读取/筛选、因子加工、组合、评价分别有明确责任方 | 架构测试、依赖审查 |
| 商业价值 | 降低研究结果解释和维护成本，提高交付可靠性，支持已有投研闭环 | 结果可复现、现有接口回归，不承诺未经验证的收入增长 |
| 战略价值 | 为后续筛选、中性化和组合方法演进提供边界 | 后续需求能归入既有引擎，无须本期建设占位层 |

## 竞品与替代方案

本次是内部架构重构，不据此声称优于竞品。外部参考仅用于理解职责分离：
[Qlib 的 Portfolio Strategy 文档](https://qlib.readthedocs.io/en/latest/component/strategy.html)
展示了从预测到组合决策、再进入回测与评价的组织方式；不推断任何闭源商业平台的内部架构，
也不引入 Qlib 依赖或复制其执行层。

| 方案 | 优点 | 代价与本次判断 |
|---|---|---|
| 保持 Executor + 旧算法 + adapter | 近期迁移成本小 | 无法完成已确认的职责整理 |
| 单一 BacktestEngine 编排四引擎 | 入口直观，各阶段可独立测试，复用既有基础能力 | 需要数值基准和跨入口回归；本次选择 |
| BacktestEngine 接口 + Native 实现 + Simulator | 便于多实现替换 | 目前没有对应需求，增加概念和迁移成本；不采用 |
| 同时统一因子与策略 | 可一次清理全部旧组件 | 牵连策略资产及事件语义，超出首期范围；延期 |

本期差异化重点是 SVQuant 自身的统一配置、可追溯结果及简单职责边界，不新增用户界面功能。

## MVP 范围

### 必须做

- 单一具体 BacktestEngine，组织 DataEngine、FactorEngine、PortfolioEngine、MetricEngine。
- 单次 API、批量任务及 Python 门面统一接入，保持 Manager 的 FIFO 和生命周期。
- 已有过滤/预处理能力迁入责任引擎，全部默认关闭；批量允许显式配置。
- 保留请求范围内的行情时间轴、因子/分组/权重分离和评价时序；不由系统补读预热历史。
- 缺失过滤状态数据时跳过并在当次结果、缓存和日志中告警。
- 保留公式与展示口径，升级执行/缓存身份，完成跨入口、并发和策略回归。

### 可以以后做

- 跌停、北交所、上市天数过滤，以及中性化的回测配置入口。
- 策略回测迁移、真实成交限制模拟和更丰富的组合构建。
- 过滤诊断的批量历史持久化。
- 因子数据库来源切换，由 FEAT-029 单独管理。

### 明确不做

- BacktestEngine 接口继承体系、模拟器层、插件框架或通用工作流引擎。
- 改动 WebApp、数据库 schema、历史数据清理、行情发布格式迁移。
- 将目标持仓变化包装成真实成交。
- 同期重写既有收益/费用公式或以更新测试期望掩盖差异。

## 成功指标

1. 所有因子入口最终调用同一 BacktestEngine，主链不再依赖旧 Executor/算法/adapter。
2. 同一显式规格及 release 下，跨入口因子截面、组合、收益和评价一致。
3. 四项可选处理默认关闭；单独开启、缺失数据告警和缓存回放均可验证。
4. 现有策略及调度测试无新增回归；历史数据库保留可查询。
5. 只允许已确认的行为差异，其他差异返回审核。

## 初步优先级与资源

评分是评审估计，不是已测商业收益：

| 维度 | 分数（1–5） | 理由 |
|---|---:|---|
| 商业价值 | 3 | 支持交付可靠性，非直接收费功能 |
| 用户价值 | 4 | 提高配置透明性及结果可比性 |
| 战略价值 | 4 | 稳定投研核心的责任边界 |
| 开发成本 | 4 | 涉及共享计算、入口及数值回归 |

优先级分数 = (3 × 4 × 4) ÷ 4 = 12；建议 P0，按高价值且高成本事项分阶段交付。
一名实施者预计 12 人天，包含 M0 文档 1 人天，不含用户审核等待。

## 宏观影响与老板决策摘要

本次改变 ResearchEngine 内部编排、业务服务与数据模型的职责边界，按 L2 影响提交 INIT-001 下评审；
不改变六大产品业务模块、目标用户、商业模式或 Wave 顺序。不新增 Initiative，也不更新
产品能力地图中的已交付状态。

| 议题 | 结论 |
|---|---|
| 为什么做 | 降低研究计算的理解、修改和结果核对成本 |
| 不做有什么影响 | 过滤配置及计算职责继续分散，后续能力更难一致接入 |
| 为什么现在做 | 引擎边界已经讨论清楚，且因子数据库迁移尚未开始 |
| 投入多少资源 | 约 12 人天；M0 后有明确用户审核关卡 |
| 预计收益 | 同配置跨入口一致、过滤可解释、责任可测试 |
| 风险 | 数值漂移、策略共享依赖、覆盖现有改动；通过基准、隔离和审查控制 |
| 下一步计划 | 完成 M5 专项验收、差异说明和交付状态更新 |

## 建议决策

本方案及 ADR-028 已获用户批准并进入实施；在 M5 专项验收完成前，Feature 保持“开发中”，
不提前标记为已完成。
