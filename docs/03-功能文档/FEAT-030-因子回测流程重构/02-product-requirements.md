# FEAT-030：因子回测流程重构 — Product Requirements

- 状态：开发中（实施中，待专项验收）
- 日期：2026-08-28
- 关联：[技术设计](03-technical-design.md)、[验收矩阵](05-verification.md)

## 用户故事

1. 研究员希望单次、批量和 Python 回测采用同一计算流程及参数含义。
2. 研究员希望按需启用筛选或预处理，并能知道哪些过滤实际生效。
3. 维护者希望每类计算只由其责任引擎维护，不在入口、批量和绘图中复制。
4. 运维人员希望调度、取消、重试和历史查询不因计算重构而退化。
5. 审核人希望先看到完整方案、行为变化及回归条件，再批准代码重构。

## 业务流程

```text
入口读取参数并形成 FactorBacktestSpec
  → ExperimentManager 排队并提供固定 release 上下文
  → 因子 Experiment 调用 BacktestEngine
  → 数据与筛选条件 → 因子加工 → 组合与评价数据 → 效果计算
  → 完整结果
  → 当次响应 / 缓存 / 按现有策略保存和绘图 / 批量标量投影
```

批量继续维护两个未完成因子的业务窗口，每个因子独立提交同一个 Manager。
CLI 仍通过 HTTP 触发批量任务，不自行执行计算。Python 兼容门面保留现有构造方式和
ResultManager 返回行为。

## 可选处理与默认值

| 参数 | 首期含义 | 目标默认值 | 责任引擎 |
|---|---|---|---|
| filter_suspended | 从当日研究样本中排除已知停牌标的 | false | DataEngine |
| filter_limit_up | 从当日研究样本中排除已知涨停标的 | false | DataEngine |
| winsorize | 0 不处理；1 MAD；2 标准差；3 四分位 | 0 | FactorEngine |
| standardize | 0 不处理；1 原始值标准化；2 rank 标准化；3 极差标准化 | 0 | FactorEngine |

四项在单次、批量、Python 中含义一致。去极值/标准化沿用已有 0–3 编码及具体公式；
显式参数生效，未配置时关闭。旧部署配置若显式开启，仍视为用户配置，不能被新默认覆盖。

批量原有固定股票池、基准、组数、调仓间隔和分析级别本期不变，只解除强制过滤约束并
开放以上四项。后续过滤及中性化不进入本期公开请求字段。

## 数据、筛选与因子规则

- 筛选输出有效性掩码，行情面板及原始价格精度不因筛选而改变。
- `start/end` 就是本次因子计算、组合及评价的数据范围；系统不补读 start 前历史。省略 end 时使用 release 的实际最后交易日。
- 顺序为按请求范围计算因子 → 当日有效池 → 去极值 → 标准化。
- 因子值不能被分组编号覆盖；因子、分组和权重分别保留。
- 过滤是研究样本规则，不表示订单一定可以买入或卖出，不新增真实交易限制。
- 非调仓日延续既有持仓，不因筛选状态变化自动清仓。
- 缺失字段与数据格式损坏应区分：可选状态缺失可跳过；必要 close 缺失、无有效区间、
  无共同股票等仍沿用现有领域错误分类。

## 过滤失效及告警

| 情况 | 处理 | 对外说明 |
|---|---|---|
| 过滤关闭 | 不应用过滤，不要求对应状态字段 | 记录未启用，无缺字段告警 |
| 过滤开启且状态完整 | 按状态生成有效掩码 | 记录已应用 |
| 过滤开启但整个状态字段缺失 | 跳过该项，其他处理继续 | 记录未生效、缺失字段和原因 |
| 状态仅部分日期/股票缺失 | 已知状态生效，未知状态沿用放行 | 记录覆盖不足、范围/数量 |
| 状态字段存在但格式无法解释 | 沿用数据错误边界，不伪装成正常缺失 | 返回可定位的错误 |

当次单因子响应元信息、缓存及运行日志保留过滤状态与告警。批量当次任务结果可汇总这些
诊断，但 SQLite 批量历史不增加诊断字段；任务过期或缓存清理后，不能从批量历史重建告警。
命中缓存不得丢失告警，也不得把 requested=true 表述为已经完整应用过滤。

## 组合与效果规则

- PortfolioEngine 负责分组、选股、权重、持仓与调仓记录；沿用 Q1 最高组及既有重复值规则。
- 对同一分组依据只计算一次分组，组合与分层评价复用；full 分析有不同分组依据时单独构建。
- 在完整价格索引上计算 close[t+h] / close[t] - 1，再按日期、股票对齐；默认 h=1。
- 远期收益只用于评价，不参与选股或权重生成；不能因未来价格缺失而提前排除当期候选股票。
- MetricEngine 负责收益、成本扣减、净值、基准、IC/RankIC/ICIR、分组和 core/full 效果计算。
- 收益序列保留首个信号到次日的收益；展示净值在首个输出日归一为 1，之后沿用现有累计口径。
- 不改变既有费用、缺失值和扩展分析公式；新发现的公式缺陷单独记录和审核。
- 调仓记录表示组合调整意图，不标为真实成交；不新增事件撮合。

## 兼容性与非功能要求

- 保留 Manager FIFO、队列容量、任务状态和原有取消语义，不承诺本期增加强制中断能力。
- 保留批量窗口、错误分类、重试、幂等和断点续跑；新版本不得续用旧执行版本的计算结果。
- 现有 HTTP 路径、响应主体、因子来源及源码契约保持；新增字段采用兼容扩展。
- DataEngine/provider 继续共享只读行情；各任务的因子、掩码、组合和结果不得互相污染。
- 不改动 WebApp、因子库内容、策略执行模式及批量历史 schema。
- 不新增每只股票的重复行情加载；分组复用且不额外复制完整行情。M1 在固定环境记录耗时、
  读次数与内存基线，M5 报告差异，不凭经验宣称性能提升。

## 验收标准

结构修订新增 AC-13：五个 Engine 在 services；Panel、MetricContext、回测规格/结果和实验
上下文在 models；models 不运行服务、访问存储或导入 HTTP DTO。取消 quantcore/core/repositories
运行时包，按职责进入 services/database/utils/config.py。所有入口和动态代码模板使用新导入；
HTTP、存储格式、公式、调度和执行/缓存版本不因目录调整改变。细则见 [结构修订](06-app-layout.md)。

| ID | 可测试标准 |
|---|---|
| AC-01 | 三类因子入口均进入同一个 BacktestEngine；主链无旧 Executor/算法/adapter 调用 |
| AC-02 | 四项默认关闭且可独立开启；批量无强制开启过滤校验 |
| AC-03 | 掩码不破坏请求范围内时间轴或原始行情；end 之后数据修改不影响本次结果 |
| AC-04 | 缺状态时处理符合告警表，缓存回放保留诊断，关闭时不依赖状态字段 |
| AC-05 | 掩码、去极值、标准化顺序固定，缺失/常数/重复值截面结果可重复 |
| AC-06 | 分组、调仓、持仓、费用、远期收益和 IC 与手算样例或冻结基准一致 |
| AC-07 | 同一显式规格和 release 跨入口数值一致，忽略任务 ID、耗时及保存状态 |
| AC-08 | 并发任务不串数据，Manager/批量行为和策略回归无新增失败 |
| AC-09 | 新执行/缓存版本不命中旧结果，历史数据库可读且不迁移/清理 |
| AC-10 | core/full 结果和原有输出行为保留；序列化及绘图不另算一套评价结果 |
| AC-11 | 所有非预期数值差异说明原因并重新审核，不直接覆盖期望值 |
| AC-12 | 文档如实标注当前/目标状态；代码仅在用户明确批准后开工，当前实施状态可追溯 |

允许的行为差异只有：默认过滤关闭、有效池先于预处理、新增告警。它们不构成任意修改
收益公式或删除现有功能的授权。
