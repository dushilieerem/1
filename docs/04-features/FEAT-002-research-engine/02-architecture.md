# ResearchEngine 架构

> 文档版本：v2.0
> 最后更新：2026-07-15

---

## 1. 定位

ResearchEngine 是 SVQuant 的**纯计算服务层**——无状态、水平可扩展、不管理策略/因子/因子库。

**核心职责**：接收前端提交的因子代码 + 策略代码 + 参数 → 跑回测 → 返回指标 + 净值。

**不做的事**：
- ❌ 不管理策略库、因子库、因子文件
- ❌ 不持久化回测结果（结果由前端或外部存储服务处理）
- ❌ 不加载本地因子文件（因子代码由前端提交）
- ❌ 不依赖本地配置文件（所有参数通过请求传入）

### 部署模型

```
┌──────────────────────────────────────────────────┐
│  应用层（前端 / AI Agent）                        │
│  - 管理策略、因子库、因子定义                      │
│  - 组装因子代码 + 参数 → 提交给 RE                │
│  - 接收结果，决定存储策略                          │
│  - 可独立部署、独立扩展                            │
└──────────────────────┬───────────────────────────┘
                       │ HTTP (FastAPI)
                       ▼
┌──────────────────────────────────────────────────┐
│  ResearchEngine 集群（N 个无状态实例）              │
│  - 接收代码 → 执行回测 → 返回结果                   │
│  - 不存储任何状态                                  │
│  - 实例间无通信（shared-nothing）                   │
└──────────────────────┬───────────────────────────┘
                       │ Python API
                       ▼
┌──────────────────────────────────────────────────┐
│  QuantCore                                        │
│  - 数据读取（从共享存储 / 对象存储）                │
│  - 因子计算 + 回测 + 指标计算                       │
│  - 纯计算，无状态                                  │
└──────────────────────────────────────────────────┘
```

## 4. 无状态设计要点

### 4.1 实例间无共享状态

| 组件 | 状态管理 | 说明 |
|------|---------|------|
| HTTP 路由 | 无状态 | 请求处理完即释放 |
| 回测运行器 | 无状态 | 代码在内存中编译执行，结果序列化返回 |
| 异步回测（可选） | 外部存储 | `run_id` → 结果存 Redis / DB，实例重启不影响 |
| 数据读取 | 只读 | 从共享存储读取 MarketData，不改写 |

### 4.2 部署扩展

```yaml
# docker-compose 示例
services:
  re-api:
    image: svquant/researchengine:latest
    environment:
      - SVQUANT_DATA_DIR=/data/market
    volumes:
      - /mnt/shared-data:/data/market   # 只读挂载共享存储
    ports:
      - "8000"
    deploy:
      replicas: 5          # 水平扩展
      resources:
        limits:
          cpus: '4'
          memory: 8G
```

### 4.3 请求路由

- 同步回测：负载均衡器直接分发，任意实例可处理
- 异步回测：负载均衡器分发 + 结果存外部存储（Redis / DB），轮询时可路由到不同实例

## 5. 与 QuantCore 的关系

```
ResearchEngine                  QuantCore
    │                              │
    │  (接收前端代码)               │
    │                              │
    ├── 编译因子代码 ────────────►  │ FactorLibrary (动态执行)
    ├── 编译策略代码 ────────────►  │ Strategy (动态执行)
    ├── 请求数据 ───────────────►  │ DataEngine / FieldParquetProvider
    ├── 跑回测 ─────────────────►  │ NativeEngine / VectorBTEngine
    ├── 计算指标 ────────────────►  │ MetricEngine
    │                              │
    │  (序列化结果返回前端)         │
```

ResearchEngine 只做编排 + 序列化，所有计算委托 QuantCore。

## 6. 与前端 / AI Agent 的分工

| 职责 | 归属 |
|------|------|
| 策略/因子库管理 | 前端 / 应用层 |
| 策略版本管理 | 前端 / 应用层 |
| 因子元数据管理 | 前端 / 应用层 |
| 代码提交与回测调用 | ResearchEngine |
| 回测执行 | ResearchEngine → QuantCore |
| 结果存储与查询 | 前端 / 外部存储服务 |
| 结果可视化 | 前端 |
| AI 分析解读 | AI Agent（调用 ResearchEngine 结果） |

## 7. 通信协议

### 7.1 同步模式（默认）

```
POST /api/backtest
Request:  factor_code + strategy_code + 参数
Response: metrics + equity_curve + 序列化结果
适用：回测时间 < 30s 的场景
```

### 7.2 异步模式（可选）

```
POST /api/backtest/async
Request:  factor_code + strategy_code + 参数
Response: { run_id }

GET /api/backtest/{run_id}
Response: { status, result(完成后) }
适用：回测时间 > 30s 或需要轮询的场景
```

### 7.3 结果存储（由前端决定）

```
方式 A：直接返回，前端存自己数据库
方式 B：返回结果时前端指定 callback URL，RE 回调推送
方式 C：RE 写结果到共享外部存储（S3 / MinIO），前端异步拉取
```

## 8. 与 v1 的关键差异

| 维度 | v1（旧） | v2（新） |
|------|---------|---------|
| 因子管理 | FactorLoader 加载本地 `factor/` 目录 | 因子代码由前端提交，无本地依赖 |
| 策略管理 | 无明确策略概念 | 策略代码由前端提交，可单独编译执行 |
| 配置管理 | ConfigManager + config.yaml | 所有参数通过请求传入 |
| 结果管理 | ResultManager 本地持久化 | 结果返回前端，不本地存储 |
| 部署模型 | 单进程 | 多实例水平扩展 |
| 状态 | 有状态（本地文件依赖） | 无状态（shared-nothing） |
| 可扩展性 | 单机 | 集群部署 |

## 9. 数据依赖

ResearchEngine 唯一的外部依赖是**只读的市场数据**：

```
MarketData/             # 共享只读存储（NFS / S3 / MinIO）
├── stock_daily/        # A 股日线 parquet
├── stock_minute/       # 分钟数据（可选）
└── fundamentals/       # 基本面数据（可选）
```

所有实例挂载同一份数据，只读不写。
