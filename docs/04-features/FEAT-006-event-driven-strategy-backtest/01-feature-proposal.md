# FEAT-006：事件驱动策略回测引擎

## 功能名称

事件驱动策略回测引擎（EventEngine）。

## 背景

当前 `POST /api/backtest/strategy` 接收策略生成的“日期 × 标的”目标权重矩阵，再由向量化后端统一计算净值。它适合因子选股、动量排序和批量参数研究，但无法表达聚宽示例中的以下行为：

- `initialize` 初始化状态、维护持仓与止损原因；
- `run_daily` / `run_weekly` 在指定时点调度；
- 根据当时的组合现金、持仓、昨日涨停和订单成交结果做后续决策；
- `order_target_value` 下单，并受现金、最小佣金、停牌、涨跌停、T+1 和整手约束；
- 使用历史行情、当期行情与时点化基本面数据选股；
- 盘中检查涨停打开、止盈止损等时序规则。

仓库虽已有 `BacktestEngine`、`Portfolio`、`MatchingEngine`、`Order` 和 `Fill` 的演示实现，但它只按日线 close 推进，缺少策略运行时、调度器、市场规则、订单生命周期、可复现数据快照与 ResearchEngine API 编排，因此不能承载真实策略研究。

## 用户价值

- 量化研究员可把“选股 + 调仓 + 风控 + 下单”写成可读的策略程序，而非强行压缩为权重矩阵。
- 前端/AI 可在同一平台支持简单因子策略和复杂事件策略，并明确提示该使用哪个引擎。
- 回测结果能解释“何时下单、为何拒单、何时成交、何时触发止损”，提升研究可信度与可调试性。

## 商业与战略价值

这是“基础量化设施不低于竞品”的 P0 补齐项。没有事件回测，平台难以承接现成的聚宽/米筐策略，也无法为 Wave 2 的模拟盘和实盘建立可复用的策略运行、订单与市场规则基座。

## 聚宽样例差距分析

| 聚宽样例能力 | 当前 SVQuant | 本 Feature 处理 |
|---|---|---|
| `initialize`、全局状态 `g` | 无 | 策略实例状态 + `context.state` |
| `run_daily` / `run_weekly` | 无 | 可复现调度器 |
| `get_price` / `history` | 仅面板读取 | 受限的时点化数据查询 API |
| `get_fundamentals` | 无策略运行时接口 | 日频时点化基本面查询（MVP） |
| `order_target_value` | 仅低层 `Order` | 订单服务、校验、成交与拒单原因 |
| 涨跌停、停牌、T+1、整手 | 无/演示级 | A 股规则配置与执行 |
| 14:00 分钟级检查 | 无 | 分钟事件作为后续增量，不纳入首个日频 MVP |

## MVP 范围

### 必须做

- 新增日频 EventEngine 和策略运行时：`initialize(context)`、日/周/月调度、策略私有状态、日志。
- 提供只读 `context`：时间、组合、行情历史、时点化基本面查询、市场规则和策略参数。
- 提供订单命令：按目标市值、按目标数量、平仓；返回订单回执与拒单原因。
- 实现 A 股日频最小规则：现金约束、100 股整手买入、卖出印花税、最小佣金、停牌、涨跌停、T+1。
- 记录订单、成交、持仓快照、净值和结构化事件日志；通过独立 API/SDK 提交事件策略。
- 保持现有 Native 向量化接口与因子回测数值不变。

### 通用性原则与能力画像

EventEngine 的内核不按“GARP”“西蒙斯”或任何平台策略名称分支，而是由策略声明的能力画像（`StrategyRequirements`）与运行环境声明的能力画像（`EngineProfile`）匹配。只有所有能力均满足时才允许启动；否则返回缺失能力，而不是静默降级。

| 能力画像 | 频率/资产 | 关键能力 | 金标策略 |
|---|---|---|---|
| `cn_equity_daily_v1` | A 股股票、日频 | 现金多头、T+1、公告日财务、历史行业、日频成交 | GARP |
| `cn_etf_t0_minute_v1` | T+0 ETF、分钟 | 1 分钟事件、T+0、日内平仓、ETF 成本和滑点 | 统计套利 ETF 子策略 |
| `cn_index_future_minute_v1` | 股指期货、分钟 | 双向、保证金、合约乘数、平今费率、主力合约映射 | 统计套利期货子策略 |
| `cn_multi_asset_intraday_v1` | ETF + 股指期货、分钟 | 多子账户/资金账本、跨资产数据与统一净值 | 西蒙斯风格统计套利 |

首期编码只交付 `cn_equity_daily_v1` 的最小垂直链路；其余画像共享内核契约，按数据和规则准备情况逐个启用。这样“覆盖所有策略”的含义是覆盖所有**已发布能力画像**中的合规策略，而不是承诺直接运行任意第三方平台源码。

### 可以以后做

- 分钟/Tick 数据与盘中事件（支持样例中的 14:00 涨停打开检查）。
- 限价单、部分成交、成交量约束、复权/除权、融资融券、ETF/基金细则。
- 完整基本面 DSL、审计意见/分红等扩展数据集、参数优化、异步队列与结果持久化。
- 聚宽代码迁移助手、兼容层和 AI 自动转换。

### 明确不做

- 逐函数复制聚宽 API、全局 `g` 对象或直接执行不受限第三方平台代码。
- 实盘下单、券商接入、实时行情和账户风控；这些属于 TradingEngine / INIT-002。
- 将策略资产、用户权限、计费、版本管理放入 ResearchEngine。

## 优先级评估

| 维度 | 评分 | 说明 |
|---|---:|---|
| 商业价值 | 5 | 解除复杂策略研究的核心阻塞，增强竞品替换能力。 |
| 用户价值 | 5 | 覆盖现有量化用户最常见的回调式策略表达。 |
| 战略价值 | 5 | 是双引擎与模拟/实盘演进的共享基础。 |
| 技术成本 | 5 | 跨策略运行时、数据、订单、组合与规则，需要严格验证。 |
| 优先级指数 | 5.0 | `(5 × 5 × 5) ÷ 5`，建议以受控日频 MVP 立项。 |

## 风险与结论

风险在于“假精确”：若没有真实的时点化数据、交易规则和执行模型，复杂策略的结果会误导用户。因此首版必须明确日频边界和所有近似规则，并以订单/拒单日志可审计为验收标准。建议批准进入详细设计后实施。
