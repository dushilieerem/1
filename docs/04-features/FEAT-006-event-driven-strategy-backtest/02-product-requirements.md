# 事件驱动策略回测引擎：产品需求

## 1. 用户故事

1. 作为量化研究员，我希望在初始化时注册每周调仓、每日风控等任务，使策略逻辑按真实时间顺序运行。
2. 作为量化研究员，我希望读取当时可见的行情、基本面、持仓和现金，并用目标市值下单，以验证策略而非仅验证因子。
3. 作为量化研究员，我希望在订单失败时知道是现金不足、停牌、涨跌停、T+1 还是整手限制，以便调试策略。
4. 作为前端用户，我希望同时看到净值和订单/成交/持仓时间线，理解回测结果来源。

## 2. 核心流程

```text
提交策略代码 + 配置
  → 编译并校验策略接口
  → initialize(context) 注册任务
  → 对每个交易日按时间顺序派发事件
      → 更新时点可见数据与组合估值
      → 执行到期调度任务
      → 策略读取 context 并提交订单
      → 市场规则校验、撮合、成本与持仓更新
      → 写入订单/成交/持仓/日志快照
  → 计算绩效并返回结构化结果
```

## 3. 策略接口

策略使用 SVQuant API，不使用聚宽全局函数：

```python
def initialize(context):
    context.state.stock_num = 4
    context.schedule.weekly(rebalance, weekday=2, time="10:00")
    context.schedule.daily(stop_loss, time="10:00")

def rebalance(context):
    candidates = context.data.fundamentals.query(...)
    for symbol in context.portfolio.symbols_not_in(candidates):
        context.orders.target_value(symbol, 0)
    for symbol in candidates:
        context.orders.target_value(symbol, 250_000)
```

| 对象 | 可做 | 不可做 |
|---|---|---|
| `context.state` | 保存可序列化的策略状态 | 访问其他策略或服务状态 |
| `context.data` | 查询截至当前事件可见的数据 | 查询未来日期、读任意文件 |
| `context.portfolio` | 查询现金、持仓、成本、估值 | 直接修改现金或持仓 |
| `context.orders` | 提交订单、查询订单状态 | 直接修改成交结果 |
| `context.schedule` | 仅在 `initialize` 注册任务 | 在运行中动态改写历史调度 |

## 4. 业务规则与边界

### 4.1 时间与防未来函数

- 每个事件有唯一 `current_dt`；数据 API 只能返回 `as_of <= current_dt` 的数据。
- 日频 MVP 的行情执行价为配置的 next-open 或 close；默认使用 next-open，避免“用收盘价生成信号又以同一收盘价成交”。
- 基本面必须按公告日期可见性过滤，不得按报告期直接提前使用。

### 4.2 订单与 A 股规则

- 买入需满足可用现金、最小佣金和 100 股整手；卖出不受整手限制。
- 当日买入的股票在 T+1 前不可卖出；卖出征收印花税。
- 停牌、涨停买入、跌停卖出必须拒单并记录原因；持仓股票即使涨停也不会被过滤出当前组合。
- 订单回执必须包含 `submitted`、`rejected`、`filled`、`partial`、`cancelled` 之一及原因码。

### 4.3 调度

- 支持 `daily`、`weekly`、`monthly`；同一时间点按注册顺序执行。
- 日频 MVP 只允许配置的日内时点作为逻辑排序，不宣称使用分钟行情。
- 缺少可用交易日时，周/月任务顺延至下一交易日并记录。

## 5. 非功能要求

- 可复现：同一策略、配置、数据快照和引擎版本应得到相同订单与净值。
- 可解释：每个拒单、成交、持仓变化均可追溯到策略回调和规则判定。
- 隔离：生产部署必须在子进程或容器中运行用户代码，限制 CPU、内存、运行时间、文件和网络权限。
- 性能：日频 3 年、5000 标的、每周调仓的基础策略在 60 秒内完成（以目标硬件基准测试）。

## 6. 验收标准

| 编号 | 可测试验收标准 |
|---|---|
| AC-1 | 策略可在 `initialize` 中注册周调仓和日止损任务，回测按时间顺序执行并输出调用日志。 |
| AC-2 | 策略可读取时点化日线/基本面、当前持仓和现金，提交目标市值订单。 |
| AC-3 | 现金不足、停牌、涨跌停、T+1、整手不符订单均被拒绝，结果返回机器可读原因码。 |
| AC-4 | 日频信号默认在下一可交易时点成交，测试证明不会使用同一 bar 的未来价格。 |
| AC-5 | 回测返回净值、指标、订单、成交、持仓快照和事件日志；前端可区分成功、拒绝与未成交。 |
| AC-6 | 现有 `/api/backtest/factor` 与 `/api/backtest/strategy`（向量化模式）测试和数值基线不退化。 |
| AC-7 | 不可信代码不能访问宿主文件系统或网络，且超时/资源耗尽能终止该次运行而不影响服务进程。 |

## 7. 未决项

- 指数成分、停复牌、涨跌停和基本面公告日期数据的权威来源与数据 schema。
- 日频首版的成交时点选择是否固定 next-open，还是允许每次请求配置。
- 策略代码沙箱的技术路线（子进程、Docker 或微虚拟机）与资源配额。
