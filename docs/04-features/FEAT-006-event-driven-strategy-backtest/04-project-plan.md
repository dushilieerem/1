# 事件驱动策略回测引擎：项目计划

## 1. 任务拆解

| 编号 | 任务 | 复杂度 | 风险 | 依赖 |
|---|---|---:|---|---|
| T1 | 明确日频行情、停复牌、涨跌停、指数成分和基本面公告日数据契约 | 4 | 高 | 数据源确认 |
| T2 | 实现策略运行时、受控 `context`、状态容器与调度器 | 4 | 中 | T1 |
| T3 | 实现事件时钟、next-open 成交时序和订单生命周期 | 5 | 高 | T2 |
| T4 | 实现 A 股规则与成本：T+1、整手、停牌、涨跌停、印花税/最低佣金 | 5 | 高 | T3、T1 |
| T5 | 扩展组合、订单、成交、持仓/事件日志结果模型 | 4 | 中 | T3、T4 |
| T6 | 增加事件回测 SDK/API、序列化与前端契约样例 | 3 | 中 | T5 |
| T7 | 建立金标策略、单元/组件/回归/安全测试 | 5 | 高 | T1-T6 |
| T8 | 加入子进程沙箱、资源和超时控制 | 5 | 高 | T2、T6 |

## 2. 建议排期（6 周，1 名后端 + 1 名量化/数据协作）

| 周期 | 目标 | 产出 |
|---|---|---|
| Week 1 | 数据与规则技术验证 | 数据契约、日频成交口径、金标样例、风险结论 |
| Week 2 | 策略运行时与调度 | `initialize/context/state/schedule` 单元测试 |
| Week 3 | 事件循环与订单 | next-open、订单状态、组合快照 |
| Week 4 | A 股规则与数据查询 | T+1、整手、涨跌停、停牌、公告日过滤 |
| Week 5 | API、结果与沙箱 | 事件 API、审计结果、受限执行 |
| Week 6 | 金标验收与灰度 | 回归、性能、安全验证、Feature Flag 灰度 |

## 3. 里程碑

- M1（Week 1）：数据可用性和日频成交口径通过技术验证；否则停止开发并调整范围。
- M2（Week 4）：本地 SDK 可运行周调仓、止损、目标市值订单和 A 股规则样例。
- M3（Week 6）：HTTP API 在 Feature Flag 下可供内部用户使用，验收标准全部通过。

## 4. 资源与风险管理

| 风险类型 | 风险 | 缓解与决策点 |
|---|---|---|
| 数据 | 没有带公告日期的基本面/交易状态数据 | M1 前确认；不满足则从 MVP 移除基本面 API，不伪造时点准确性。 |
| 技术 | 事件引擎性能或复杂度吞噬向量化优势 | 双轨而非替换；大规模因子研究继续走向量化。 |
| 产品 | 用户误以为与聚宽完全一致 | 文档与 UI 明确“SVQuant 事件策略 API”，提供迁移表和差异说明。 |
| 安全 | 任意策略代码危及服务 | 生产发布以 T8 完成为门槛；未完成仅本地可信开发。 |

- [x] Feature Proposal、MVP 与明确不做项已定义。
- [x] 用户流程、边界、验收标准、模块影响和测试策略已定义。
- [x] 任务、依赖、复杂度、排期和里程碑已拆分。
- [ ] M1 数据契约与公告日期可用性验证完成。
- [ ] 沙箱方案与资源配额确认。

**结论：暂不进入编码。** 先完成 M1 数据验证与沙箱方案决策；两项均不阻塞设计评审，但任一失败时不得按当前范围实施。
