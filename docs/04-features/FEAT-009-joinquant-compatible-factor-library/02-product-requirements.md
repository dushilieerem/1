# Product Requirements：聚宽兼容因子库

## 用户故事

1. 作为从聚宽迁移的量化开发者，我希望按聚宽因子名或分类找到 SVQuant 对应项，以便迁移研究代码。
2. 作为研究员，我希望在使用因子前看到数据依赖、公式口径和验证状态，以便判断结果是否可用于研究。
3. 作为数据负责人，我希望系统阻止缺失授权字段或存在未来数据风险的因子计算，以便保持数据合规与回测可信。

## 业务流程

```text
合法账号导出目录快照 → 生成并人工审核 manifest
       → 字段映射与点时规则审核 → 原生 FactorLibrary 实现
       → 单元测试 + 参考样本回归 → 标记为已验证
       → index/API/研究回测可发现和计算
```

## 业务规则

- `manifest.yaml` 是目录事实来源；每项的状态只能为 `planned`、`blocked_by_data`、`implemented`、`verified`、`not_supported` 之一。
- 公开调用名使用稳定的 `jq_<原始因子名小写>`；因子原始名、中文描述和分类仅作为元数据保留，禁止通过重命名覆盖现有因子。
- 每项必须声明 `required_fields`、`availability_rule`、`formula_reference`、`source_snapshot` 与 `verification`；字段未就绪时必须抛出明确的缺字段错误。
- 财务类字段以公告/可见日为准，报告期结束日不得直接作为交易日可见日；禁止回填到公告日之前。
- 无法确认公式或数据口径的目录项保留在 manifest，但状态为 `not_supported` 或 `blocked_by_data`，不可被计算 API 当作可用因子返回。
- “已验证”要求至少一个固定证券池、连续交易日窗口和冻结后的容差阈值通过；若数据源无法提供可比样本，最多标为 `implemented`。

## 非功能要求

- 不新增聚宽运行时依赖；计算仅依赖 SVQuant 及已授权的数据 provider。
- 任一因子在 API 可发现结果中必须可追溯到目录快照和实现版本。
- 单因子计算应保持现有向量化面板模型，不逐标的 Python 循环。
- 目录解析或一个可选因子的失败不得阻止已有因子库加载。

## 可测试验收标准

1. 给定冻结目录快照，可生成唯一版本号和目录哈希；manifest 中每个原始因子名恰好一条记录。
2. 每个 `verified` 因子具有原始名、字段依赖、可见性规则、公式来源、实现文件/方法和回归证据。
3. 对至少一个行情、估值、财务、成长、质量、风险和动量因子，各有确定性公式测试；并验证全部返回日期×标的宽表。
4. 财务测试数据中，公告日前因子不可见，公告日及之后才可见。
5. 缺少依赖字段时计算失败并列出缺失字段；不会以零值、未来值或静默降级代替。
6. `/api/factors`（或其后续目录接口）仅把 `implemented` / `verified` 因子标为可运行，并返回兼容元数据与状态。
7. 在获得合法的同源参考样本后，`verified` 因子的值在约定容差内一致；差异超过阈值会使测试失败并降级状态。
