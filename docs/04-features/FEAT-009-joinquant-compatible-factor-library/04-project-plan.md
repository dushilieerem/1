# Project Plan：聚宽兼容因子库

## 任务拆解

| 任务 | 复杂度（1-5） | 风险 | 依赖 | 完成条件 |
|---|---:|---|---|---|
| 导出并冻结聚宽目录快照 | 2 | 中 | 合法聚宽账号与授权 | 已收到 260 项文本目录；仍需补齐原始 CSV/JSON、抓取日期、版本/哈希和许可记录。 |
| 建立 manifest、导入和校验工具 | 3 | 中 | 目录快照 | 一源清单可生成草稿，名称与字段校验可自动执行。 |
| 财务数据点时契约与 provider | 5 | 高 | 授权财务数据、字段字典 | 公告日可见性、修订记录和日频面板测试通过。 |
| 实现行情/技术/动量/风险子集 | 3 | 低 | OHLCV、复权规则 | 因子按原生 `FactorLibrary` 实现并通过公式测试。 |
| 实现估值/财务/成长/质量子集 | 5 | 高 | 财务契约、市值字段 | 字段映射、点时性与回归测试通过。 |
| 实现行业/风格/情绪/预期/资金流子集 | 5 | 高 | 行业和替代数据授权 | 每一类别的数据许可与对比样本通过评审。 |
| 接入索引/API 和可观测性 | 3 | 中 | manifest、FactorLoader | 可发现、状态可见，异常信息可读。 |
| 参考样本回归与发布 | 4 | 高 | 合法参考值样本 | 容差、覆盖率、已验证清单和遗留项发布。 |

## 建议排期

```text
Week 1：取得授权与目录快照；确认数据字段、复权和财报可见性；完成 manifest 原型。
Week 2：落地导入/校验工具和 OHLCV 类兼容因子；完成确定性与未来数据测试。
Week 3-4：接入点时财务数据；实现估值、成长、质量、每股等因子；开展样本回归。
Week 5+：按已授权数据逐类补齐行业、风格、情绪、预期、资金流；每批独立验收发布。
```

## 里程碑

- M1：目录边界、数据授权和 manifest 获批。
- M2：行情/技术/动量/风险子集可运行且可追溯。
- M3：财务点时契约与估值/成长/质量子集通过参考回归。
- M4：按冻结目录的支持率、验证率和数据可用率发布兼容性报告。

## Sprint 建议

目标：完成可验证的第一批原生兼容因子，不承诺未经数据验证的“全量”。

| 任务 | 负责人 | 风险 |
|---|---|---|
| 目录快照和许可证确认 | 数据负责人 | 账号权限、许可边界。 |
| 字段映射与点时性设计 | 数据工程 / 架构 | 财务公告日和复权口径。 |
| 导入、manifest、OHLCV 因子 | 量化开发 | 名称规范与性能。 |
| 夹具、回归与覆盖率报告 | QA / 量化研究 | 参考样本可获取性。 |

## 风险管理与发布门槛

| 风险类型 | 风险 | 缓解措施 |
|---|---|---|
| 合规 | 第三方数据或受限定义被不当复制/分发 | 仅保存可合法保存的元数据与自研代码；法务/数据负责人确认许可。 |
| 技术 | 同名因子数值不一致或含未来数据 | 版本化公式、点时契约、参考样本回归和失败即降级。 |
| 项目 | “全部”范围随目录变化而无限扩大 | 冻结快照，按类别发布支持率，不以模糊全量作为完成条件。 |
| 性能 | 大量财务字段和滚动计算影响批量研究 | 懒加载、按需计算、基准测试；热点再优化。 |

## Definition of Ready 检查

- [x] 所属 Initiative 和产品能力明确。
- [x] Feature Proposal 已批准（仅限第一批技术因子）。
- [x] MVP 范围和明确不做项已定义，待批准后冻结。
- [x] 用户流程、业务规则、边界和验收标准已定义。
- [x] 架构边界、接口和数据影响已评估。
- [x] 任务、依赖、复杂度、测试和回滚已拆分。
- [ ] 已收到 260 项名称与分类文本，但目录版本/哈希、数据授权及点时字段契约尚未确认；其阻塞全量实现，不阻塞第一批仅依赖收盘价的技术因子。

结论：第一批技术因子可进入编码；取得目录快照版本与数据授权确认后，按本计划补齐其余类别并复审 DoR。
