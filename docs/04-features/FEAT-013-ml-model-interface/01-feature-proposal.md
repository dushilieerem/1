# Feature Proposal：机器学习模型接入与预测回测

## 功能名称

机器学习模型接入与预测回测。

## 背景

SVQuant 已具备面板数据、因子计算、因子分析和向量化回测能力，也已提供 Qlib Alpha158/Alpha360 等机器学习特征基线；但算法组产出的机器学习、深度学习模型没有统一交付和调用入口。模型开发者需要自行拼接数据、训练、预测、因子评估与策略回测，容易造成数据时点、股票池、调仓频率和交易成本口径不一致，也难以复现或横向比较模型效果。

本 Feature 建立“模型输出即预测因子”的研究接入层：算法组只需实现明确的模型契约，平台负责生成无未来信息的训练/验证/测试切片，接收预测结果，并复用既有因子分析与回测能力。

## 用户价值

- 算法研究员：可将 sklearn、PyTorch、TensorFlow 等框架实现的模型封装后接入，不必重写回测逻辑。
- 量化研究员：可在同一数据和交易假设下，比较传统因子与模型预测因子的 IC、分层表现和策略绩效。
- 平台研发：模型框架与 QuantCore/ResearchEngine 解耦，避免把第三方训练框架渗入核心数据与回测代码。

## 商业价值

这是 AI 驱动投研闭环的基础能力：平台可承接算法组的模型资产，缩短“模型原型到可验证策略”的周期，并为后续模型目录、算力任务、模型版本治理和 AI 自动优化建立统一入口。没有该能力，平台的 AI 优势只能停留在代码生成和解释，无法形成可复用的模型研究生产力。

## 竞品分析

| 竞品 / 框架 | 常见做法 | 对 SVQuant 的启示 |
|---|---|---|
| Qlib | DataHandler、Dataset、Model、RecordTemplate 解耦，预测结果可进入回测记录 | 训练与评估解耦，模型输出须有明确索引和时间语义 |
| BigQuant | 将特征、模型、预测和回测编排成可视化工作流 | 平台应承担编排与复现，不要求算法组关心回测细节 |
| 聚宽 / 米筐 | 以策略 API 与回测为中心，模型训练通常由用户自行组织 | SVQuant 应把模型预测标准化后复用现有因子/策略两条研究路径 |

差异化选择：首期不建设封闭式 AutoML 或可视化训练平台，而是提供开放、框架无关的 Python 模型插件契约，优先服务内部算法组和专业量化开发者。

## MVP 范围

### 必须做

1. 定义并实现 `BasePredictiveModel` Python 契约：模型元信息、`fit`、`predict`、可选的保存/加载钩子。
2. 提供研究编排入口：按配置构造时间切片，调用训练和样本外预测，产出“日期 × 标的”的预测面板及运行清单。
3. 校验预测面板的索引、标的、数值、时间可得性和样本外边界；不符合契约时失败并给出可定位错误。
4. 将预测面板作为因子输入接入现有 IC/IR、分层分析和向量化策略回测；支持按分数选股的基础组合配置。
5. 提供一个不依赖深度学习框架的参考线性模型和一个算法组可复制的模型模板、端到端自动化测试。

### 可以以后做

- PyTorch、TensorFlow、LightGBM、XGBoost 的官方适配包与可选依赖组。
- GPU 调度、分布式训练、超参数搜索和实验队列。
- 模型资产目录、模型注册审批、版本比较、模型监控和在线推理。
- 分钟级/事件驱动模型推理、在线特征服务及实盘部署。
- 模型融合、概率校准、风险暴露约束和 AutoML。

### 明确不做

- 不在核心包中强制安装任何机器学习或深度学习框架。
- 不替算法组设计模型结构、标签定义或训练目标。
- 不承诺模型收益、不提供投资建议，也不将研究模型直接下发实盘。
- 不改变既有因子代码、回测适配器或事件驱动策略 API。

## 优先级评估

商业价值 5、用户价值 5、战略价值 5、开发成本 3，评分为 41.7。建议列为 P0：它以中等成本补齐 AI 模型研究闭环，并直接放大已有数据、因子和回测基础设施的价值。

## 管理层摘要

| 维度 | 结论 |
|---|---|
| 为什么做 | 让算法组模型从离线原型进入统一、可复现的因子与策略验证闭环 |
| 不做的影响 | 模型研究继续依赖个人脚本，口径不一且无法稳定比较、复用和沉淀 |
| 为什么现在做 | 数据、因子分析和向量化回测已具备，当前是以较低增量成本打通模型能力的窗口 |
| 投入 | 约 10–13 人天，2 个自然周；需 1 名算法组成员配合提供参考模型 |
| 预计收益 | 缩短模型验证链路，提升 AI 研究能力的可演示性和后续机构客户的扩展空间 |
| 风险 | 标签泄露、框架依赖冲突和深度学习训练耗时；通过时点校验、可选依赖和异步扩展边界缓解 |
| 下一步 | 评审 MVP 契约并由算法组提交参考模型与依赖清单，然后进入开发 |
