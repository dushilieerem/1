# 个股日线行情 API：Product Requirements

## 用户故事

作为 Web 端开发者，我希望先取得可选股票代码列表，再按股票代码和日期范围取得结构化 OHLC 日线，以便构建选择器并直接渲染日线图。

## 业务流程

1. Web 调用 `GET /api/market-data/symbols`，取得可选股票代码。
2. Web 选择代码后调用 `GET /api/market-data/daily/{symbol}`，可选传递 `start`、`end`。
3. 服务从当前已发布的市场数据版本读取四个标准字段。
4. 服务按日期和代码对齐，过滤任一 OHLC 缺失的交易日，按日期升序返回。
5. Web 使用 `bars` 渲染日线，并使用 `date_range` 展示实际覆盖区间。

## 接口契约

```http
GET /api/market-data/daily/000001.SZ?start=2024-01-01&end=2024-06-30
```

```json
{
  "symbol": "000001.SZ",
  "bars": [
    {"date": "2024-01-02", "open": 10.1, "high": 10.5, "low": 10.0, "close": 10.3}
  ],
  "date_range": {"start": "2024-01-02", "end": "2024-06-28"}
}
```

## 业务规则与边界

1. `GET /api/market-data/symbols` 返回 `{"symbols": [{"symbol": string, "name": string}, ...]}`；代码按字典序去重排序，仅包含当前数据面板中实际可查询的代码。
2. 股票列表和个股日线响应均返回证券主数据中的 `name`；行业、实时状态和数据版本仍不在本 Feature 范围。
3. 数据目录、证券主数据或股票代码面板不可读时，股票列表接口返回 HTTP 503。
4. `symbol` 必填，按数据文件中的列名精确匹配；服务不猜测、不转换证券代码。
5. `start`、`end` 可选，格式为 `YYYY-MM-DD`，均为包含边界；省略时使用可用全量区间。
6. `start` 晚于 `end` 为无效请求，返回 HTTP 422。
7. 返回仅含 `open`、`high`、`low`、`close` 均为有效数值的行；结果始终按日期升序。
8. 标的不存在或筛选后无完整 OHLC 日线，返回 HTTP 404。
9. 市场数据目录、证券主数据、必需字段文件或读取过程不可用，返回 HTTP 503；不以零值、其他字段或猜测名称替代。
10. 日线响应不含成交量、复权模式、数据源或数据版本；这些属于后续范围。

## 非功能要求

- 只读、无状态；复用 `FieldParquetProvider` 的进程内字段缓存。
- 数据仅来自 `SVQUANT_DATA_DIR` 指定的已发布历史版本（或默认 `MarketData`），不访问网络。
- 数值采用 JSON number，日期采用 `YYYY-MM-DD`。

## 验收标准

1. 股票列表返回 200、去重且排序的代码数组，与测试 Parquet 面板列一致。
2. 给定存在的代码与日期范围，返回 200、升序 OHLC 数组，字段和数值与 Parquet 测试数据一致。
3. 未传日期时返回全部可用完整 OHLC 日线；传日期时边界为包含关系。
4. 不存在的代码、无完整日线和倒置日期范围分别得到明确的 404、404、422。
5. 数据目录、股票代码面板或任一 OHLC 字段缺失时返回 503，不返回伪造数据。
6. 现有 API 回归测试全部通过。
