# Project Plan：AI 自然语言因子生成 API

## 任务拆解

| ID | 任务 | 复杂度 | 风险 | 依赖 | 完成条件 |
|---|---|---:|---|---|---|
| T1 | 冻结 API、响应 JSON Schema、错误码和 Web 交互 | 2 | 中 | 产品/前端评审 | OpenAPI 与示例经前后端确认 |
| T2 | 建立能力目录、函数模板与 AST 白名单 | 4 | 高 | QuantCore 字段/因子库 | 正负代码样例覆盖且仅允许受控子集 |
| T3 | 实现火山方舟 Provider 适配器、服务端密钥、超时和错误映射 | 3 | 高 | 火山方舟访问权限、密钥管理 | 假 Provider 与 `ark-code-latest` 连通性验证均通过合约测试 |
| T4 | 实现生成编排、幂等、限流/额度和脱敏审计 | 4 | 高 | 应用层认证与存储 | 重试不重复计费，审计字段完整 |
| T5 | 实现 Web 草稿审阅、编辑后再校验和“确认回测”衔接 | 3 | 中 | T1、既有回测 API | 已确认代码可无转换提交回测 |
| T6 | 部署回测执行隔离、端到端安全与质量评估 | 5 | 高 | 容器平台、T2–T5 | 无网/只读/资源限制有效，验收集达到阈值 |
| T7 | 文档、监控告警、灰度与验证记录 | 2 | 中 | T1–T6 | 运行手册、仪表板、回滚演练和验收证据齐备 |

## 排期与里程碑

| 周期 | 计划 | 里程碑 |
|---|---|---|
| Week 1 | T1–T2；完成字段目录、AST 白名单和安全负样例评审 | M1：生成契约与受控代码边界冻结 |
| Week 2 | T3–T4；接入批准的供应商沙箱环境、幂等/额度/审计 | M2：后端可稳定产生并校验草稿 |
| Week 3 | T5–T6；打通 Web 审阅与隔离回测，执行端到端测试 | M3：内部 Demo 完成“自然语言→确认→回测” |
| Week 4（缓冲） | T7；灰度、质量评估、性能/安全修复与验收 | M4：满足 DoD 后扩大可用范围 |

## 建议 Sprint

- Sprint 目标：上线受控的单因子生成内测，研究员无需写模板代码即可提交现有回测 API。
- 负责人：后端/AI 1 人、前端 1 人、平台/安全支持 1 人；量化研究员负责能力目录和样例验收。
- 外部依赖：火山方舟数据保留条款与账户预算、已轮换且可用的服务端密钥、应用层认证/配额存储、受限执行环境。

## 风险与发布管理

| 类型 | 风险/触发信号 | 缓解与决策 |
|---|---|---|
| 产品 | 生成代码可读但实际字段/方法不可用 | 首期仅开放小目录；以“可编译率、回测可运行率”作为灰度门槛 |
| 安全 | 当前 ResearchEngine 进程内执行用户代码 | 在 T6 前禁止对外开放确认回测；仅允许内部受信任环境验证 |
| 项目 | 火山方舟账户权限、区域或预算未落实 | T3 开始前完成 `ark-code-latest` 的最小连通性验证与预算确认；否则以假 Provider 完成开发但不得上线 |
| 成本 | 单次调用 token 或重试异常增长 | 强制额度、长度限制、幂等和按模型别名监控成本 |

发布采用功能开关和内部租户白名单。严重安全、成本或质量问题时关闭生成入口；不回滚既有手写因子与回测功能。进入开发前须完成供应商合规确认、应用层身份/配额归属和隔离回测环境验证，满足 Definition of Ready。
