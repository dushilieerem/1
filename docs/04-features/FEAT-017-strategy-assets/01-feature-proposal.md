# 策略资产目录与版本化持久化：Feature Proposal

## 1. 功能名称

策略资产目录与版本化持久化。

## 2. 背景

现有 `/api/backtest/strategy` 只接受临时提交的 `strategy_code`。代码离开请求后没有项目级归档入口，回测结果也无法稳定关联到某个策略版本。因子已经通过 `Factor/libraries/*.py + index.yaml` 作为项目资产管理；策略需要采用同样轻量、可由 Git 审计的方式补齐研究闭环。

## 3. 用户价值

研究员可以保存、枚举和复用策略；同一策略的旧版本不被后续编辑覆盖，回测可以明确使用的策略 ID、版本与源码哈希。

## 4. 商业价值

策略是从研究走向模拟盘/实盘的核心资产。先建立可追溯的源码版本边界，可降低结果不可复现和未来迁移至资产管理服务的成本。

## 5. 竞品分析

主流量化平台通常提供云端策略编辑、版本和运行记录。SVQuant 当前是 CLI/SDK 到 Web 的过渡阶段，MVP 选择与既有因子库一致的 Git 管理文件目录，保留后续 SaaS 资产服务替换空间。

## 6. MVP 范围

**必须做**：`Strategy/libraries/index.yaml` 索引、版本化 `.py` 源码、目录读取/校验、策略列表 API、回测按 `strategy_id + strategy_version` 引用源码并返回内容哈希。

**可以以后做**：在线编辑、保存 API、回测运行历史、策略版本对比、团队权限、发布审批、对象存储和数据库资产目录。

**明确不做**：事件策略执行、用户不可信代码沙箱、实盘/模拟盘部署、将策略源码或回测产物自动写入数据库。
