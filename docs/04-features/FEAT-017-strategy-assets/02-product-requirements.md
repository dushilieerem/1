# 策略资产目录与版本化持久化：产品需求

## 用户故事

1. 作为研究员，我希望把可复用策略以项目文件保存并由 Git 追踪。
2. 作为研究员，我希望查看已登记策略的当前版本，并指定历史版本回测。
3. 作为研究员，我希望从结果中得知所执行的策略版本和源码哈希。

## 核心流程

```text
新增 strategy_vN.py → 在 index.yaml 登记版本 → Git 提交
→ GET /api/strategies 查看目录 → POST /api/backtest/strategy 引用 ID/版本
→ 读取指定源码、校验入口、运行既有向量化回测 → 返回版本与哈希
```

## 业务规则与边界

- 索引格式当前为 `version: 2`；每个策略有唯一 ID、业务 `strategy_type`、执行 `execution_mode`、当前版本和版本映射。
- 策略版本源码文件必须是策略目录根下的 `.py` 文件，不允许绝对路径或目录穿越。
- 已被引用的版本不得覆盖；逻辑变更必须新增版本并更新 `current_version`。
- 回测请求在 `strategy_code` 与 `strategy_id` 间二选一；提供 `strategy_version` 时必须提供 `strategy_id`。
- MVP 仅运行 `execution_mode: vectorized` 的条目；`execution_mode: event` 策略可登记但不能由现有端点运行。

## 非功能要求

- 列表 API 不导入或执行策略源码。
- 错误索引、缺失版本、缺失文件和入口不匹配返回可读业务错误，不产生半成品。
- 内联 `strategy_code` 的既有 API 行为保持可用。

## 验收标准

| 编号 | 标准 |
|---|---|
| AC-1 | 合法索引可列出策略 ID、名称、业务类型、执行模式、当前版本、入口和标签。 |
| AC-2 | 以 ID 和指定版本请求回测时，执行对应 `.py` 文件，并返回 ID、版本和 SHA-256。 |
| AC-3 | 未指定版本时使用 `current_version`。 |
| AC-4 | 缺失索引、版本、源码，或非法文件路径均不会执行代码并返回明确错误。 |
| AC-5 | 内联源码回测与既有结构化策略回测测试不回归。 |
