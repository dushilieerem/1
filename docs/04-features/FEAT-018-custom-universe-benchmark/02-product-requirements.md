# 自定义证券池与组合基准：产品需求

## 用户故事

1. 作为研究员，我希望保存一组明确的股票代码为证券池，并在因子与策略回测中引用它。
2. 作为研究员，我希望保存一组带权重的股票为组合基准，用它计算净值、超额收益和报告对比。
3. 作为研究员，我希望历史回测结果保留当时使用的证券池和基准版本，即使资产后来更新也不改变旧结果。

## 核心流程

```text
WebApp 创建或更新 universe / benchmark → WebApp 在数据库保留版本与归属
→ WebApp 鉴权并解析资产快照 → 回测请求传入快照
→ 证券池过滤因子面板或策略可交易范围
→ 基准组合按权重计算被动净值 → 结果返回并持久化资产快照
```

## 业务规则

- `InstrumentPool` 与 `BenchmarkPortfolio` 是不同资产。证券池决定可参与计算及可交易标的；基准不得自动扩大或缩小股票池。
- MVP 的证券池必须有一个非空、去重后的 A 股证券清单；每个代码必须存在于所选回测数据的 `close` 面板列中，否则请求失败并列出缺失代码。
- MVP 的组合基准必须有一个非空的 `symbol → weight` 映射；权重必须为有限非负数，总和在 `1 ± 1e-8` 内。基准成分可以不属于证券池。
- MVP 基准在回测起止区间内采用固定权重、每日收盘到收盘收益、无交易成本和无再平衡。任一成分在首个有效基准日没有价格，或其后缺失价格导致无法计算收益时，回测失败，不做前填或删减。
- 资产 ID、归属、版本、删除和访问权限由 WebApp 管理；ResearchEngine 不访问用户数据库。
- 回测请求中 `universe` 与 `universe_snapshot` 至多选一个；`benchmark` 与 `benchmark_snapshot` 至多选一个。两者均未传时维持既有默认值。
- 证券池资产可用于因子回测与向量化策略回测。事件驱动策略的可交易范围接入必须复用同一已解析快照，但不属于本 MVP。
- 结果元数据至少包含资产 ID、解析版本、内容哈希和有效成分数量；持久化结果还保存完整成分/权重快照。

## 边界与异常

| 场景 | 行为 |
|---|---|
| WebApp 无权访问、资产不存在或版本不合法 | WebApp 在调用 ResearchEngine 前拒绝。 |
| 股票池为空或含重复代码 | 空池拒绝；重复项在目录解析时拒绝，避免隐式行为。 |
| 权重和不为 1、负权重或非数值 | 拒绝；多空基准留后续版本定义。 |
| 基准价格缺失或与回测日期无重叠 | 拒绝，不产生误导性的超额收益。 |
| 用户同时传旧参数和资产引用 | 拒绝，要求只保留一种来源。 |
| 回测期间证券池更新 | 已启动运行使用开始时解析的不可变快照；新运行才使用新版本。 |

## 非功能要求

- 目录解析不执行用户策略代码；列表接口只返回元数据。
- 解析后的资产内容哈希使用规范化 JSON 计算，避免 YAML 排版差异改变语义却破坏审计。
- 同一请求、相同数据版本与相同资产版本必须得到相同的证券范围和基准权重。
- 旧有 `CSI300`、`CSI500`、`CSI1000`、`SSE50` 参数行为保持兼容。

## 验收标准

| 编号 | 标准 |
|---|---|
| AC-1 | 合法索引可列出证券池和组合基准的 ID、名称、版本、类型与成分数量。 |
| AC-2 | 因子回测引用静态证券池后，因子面板、分层和 IC 样本只包含该池的证券。 |
| AC-3 | 向量化策略回测引用同一证券池后，传入策略的数据及目标权重不包含池外证券。 |
| AC-4 | 引用固定权重组合基准时，响应的基准净值和超额收益与夹具中手工计算一致。 |
| AC-5 | 结果元数据和持久化快照包含实际使用的资产 ID、版本、哈希、成分与权重。 |
| AC-6 | 缺失代码、无效权重、重复来源参数与缺失价格均在执行前返回明确错误。 |
| AC-7 | 既有内置股票池和指数基准的 API 测试全部通过。 |
