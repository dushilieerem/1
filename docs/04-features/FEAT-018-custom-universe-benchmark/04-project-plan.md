# 自定义证券池与组合基准：项目计划

## 任务拆解

| 任务 | 复杂度 | 风险 | 依赖 | 完成条件 |
|---|---:|---|---|---|
| 实现 WebApp 用户资产 CRUD、鉴权与版本解析 | 4 | 中 | WebApp 用户体系、PostgreSQL | 用户只能管理自己的资产；每次修改形成可审计版本。 |
| 冻结 WebApp → ResearchEngine 快照契约 | 2 | 中 | 回测 API | 研究引擎不读取用户数据库，非法成分/权重在执行前失败。 |
| 实现静态组合基准净值计算器 | 3 | 中 | 收盘价面板 | 手算夹具的净值和超额收益一致。 |
| 接入因子与向量化策略回测 API | 3 | 中 | 既有 Runner、schema | 两个端点支持资产引用，旧参数回归通过。 |
| 结果元数据、配置快照与目录列表 API | 2 | 低 | 结果存储、API schema | 可查看资产摘要；运行结果保留全量快照。 |
| 自动化测试、使用文档与验证记录 | 2 | 中 | 前述任务 | AC-1 至 AC-7 有可重复证据。 |

## 排期与里程碑

- Week 1：WebApp 用户资产 CRUD、鉴权与版本化；M1：WebApp 可解析不可变证券池快照。
- Week 2：固定权重组合基准与 ResearchEngine 快照回测接入；M2：因子与向量化策略可使用用户资产。
- Week 3：补齐 WebApp 页面、结果快照、异常和全量回归；M3：满足验收标准，进入待验收。

预计投入：1 名研发约 10–15 人天；如同时建设 Web 编辑、CSV 上传或历史成分，需拆为后续 Feature，不能挤入本 MVP。

## 风险与缓解

| 类型 | 风险 | 缓解 |
|---|---|---|
| 产品 | 用户混淆股票池与基准 | API、页面与结果分别标记“研究/交易范围”和“业绩比较对象”。 |
| 研究正确性 | 最新指数成分造成幸存者偏差 | MVP 只承诺用户静态清单；历史指数池另行以日期掩码实现。 |
| 数据 | 自定义基准成分缺少价格 | 执行前严格校验，拒绝静默前填或删减。 |
| 架构 | 用户数据库直接耦合回测内核 | 保持 `WebApp Asset → Snapshot → ResearchEngine` 边界，QuantCore 和 ResearchEngine 均不读取用户数据库。 |
| 项目 | WebApp CRUD 与研究 API 的职责混淆 | WebApp 负责所有用户数据与权限，ResearchEngine 只保留快照校验、回测和结果元数据。 |
