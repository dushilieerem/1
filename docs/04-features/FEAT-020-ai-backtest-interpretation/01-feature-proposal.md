# Feature Proposal：AI 回测解读与优化建议

## 1. 功能名称

AI 回测解读与优化建议。

## 2. 背景与用户问题

SVQuant 已能返回净值、基准、年度收益、回撤、换手、因子 IC/IR、分层表现以及可选的持仓和调仓日志，但“拿到结果”不等于“完成研究”。用户仍需自行回答：

- 收益是否显著优于基准，还是由少数年份或阶段贡献？
- 最大回撤、换手、交易成本假设和样本长度暴露了哪些风险？
- 因子是否具有稳定 IC、分层单调性和跨行业一致性？
- 下一轮应该先验证数据和稳健性，还是调整调仓、持仓或信号参数？

通用大模型可以复述指标，但如果直接接收大量净值点，容易臆造因果、遗漏数据限制、把样本内调参包装成优化结论。SVQuant 需要把量化证据、AI 表达和研究纪律组合成一个可信的产品能力。

## 3. 用户价值

- **量化开发者**：在数十秒内得到结构化结论和下一轮实验清单，减少手工汇总指标与排查风险的时间。
- **非专业编程研究员**：用通俗语言理解夏普、回撤、换手、IC、分层等指标，并知道结论的证据来源。
- **投研团队**：统一回测评审口径，让建议具备证据引用、版本和审计记录，便于复核与协作。

## 4. 商业价值

本功能把已有数据、回测、指标和 AI 生成能力连接成完整闭环：

```text
自然语言生成因子/策略 → 用户确认 → 回测 → AI 解读 → 优化实验 → 再回测
```

它是专业版 AI 调用额度、团队研究工作流和后续多步研究 Agent 的直接基础。若不做，用户仍需把结果复制到平台外解释，SVQuant 的 AI 能力停留在“生成代码”，无法形成持续研究与留存。

## 5. 竞品与替代方案

> 核对日期：2026-07-31。以下只采用竞品官方资料，能力会随时间变化。

| 竞品 / 替代方案 | 已验证能力 | 对 SVQuant 的启示 |
|---|---|---|
| [QuantConnect Mia](https://www.quantconnect.com/docs/v2/ai-assistance/predefined-assistants/mia) | 可读取回测统计、订单和日志并总结表现，也可发起参数优化和敏感性测试 | AI 回测助手已经成为竞争基线；我们需要用证据引用、A 股语境和防过拟合流程建立差异 |
| [QuantConnect Optimization Results](https://www.quantconnect.com/docs/v2/cloud-platform/optimization/results) | 展示多参数净值、目标值和参数敏感性 | “最优参数”之外必须展示敏感性，避免只挑单点最佳结果 |
| [Composer Create with AI](https://help.composer.trade/article/108-create-with-ai) | 自然语言生成策略，可插入编辑器并直接回测 | 生成到回测的链路应顺畅，但用户仍需保留审阅和修改权 |
| [Composer Backtest Basics](https://help.composer.trade/article/67-backtest-basics) | 明确回测是假设性结果、受后见之明影响，不构成未来交易建议 | 免责声明、假设和局限必须成为结果本身的一部分，而非页面角落文案 |
| [BigQuant 平台能力](https://bigquant.com/square/codedev) | 提供因子分析、超参搜索、组合优化、滚动训练和归因分析 | 优化建议不能只覆盖参数，还要覆盖因子处理、稳健性、执行成本和归因 |
| 手工分析 / 通用 LLM | 灵活但耗时；通用 LLM 缺少平台指标定义和结果来源约束 | 用版本化证据与建议目录约束模型，比单纯提示词更可靠 |

### 差异化选择

1. **证据可追溯**：每条判断引用确定性证据 ID，数值由服务端渲染，不由模型生成。
2. **研究纪律优先**：样本外、成本、样本长度、参数敏感性存在缺口时，先建议验证，不急于提升收益。
3. **A 股语境**：逐步纳入 T+1、涨跌停、停牌、交易成本、行业与政策阶段等本地约束。
4. **建议可实验**：建议不是一句“降低回撤”，而是一个可执行、可验收的下一轮实验。

## 6. MVP 范围

### 必须做

1. 提供 `POST /api/ai/backtest-interpretations`，接收一个成功的因子或向量化策略回测结果快照、原回测上下文、可选关注点和幂等键。
2. 由确定性 `EvidenceBuilder` 复算并输出版本化证据包：身份与口径、收益与基准、风险与回撤、年度稳定性、换手/持仓覆盖、因子分析、数据充分性和缺失项。
3. 由版本化 `DiagnosticCatalog` 根据证据生成诊断与候选实验；首期覆盖短样本、缺少样本外验证、成本假设不足、高换手、深回撤、年度不稳定、因子 IC/分层弱等场景。
4. LLM 仅对候选诊断和实验做选择、排序与通俗表达；严格结构化输出，所有引用必须存在，所有数值由服务端从证据包渲染。
5. 返回表现总览、主要优势、主要风险、数据局限、最多 5 条优化实验建议和研究免责声明；每条建议包含证据、假设、预期方向、权衡、验证步骤和通过标准。
6. 记录结果指纹、模型别名、提示词/证据/诊断目录版本、输入输出哈希、引用校验、耗时和调用量；不记录密钥。
7. 因子与策略两类结果共用一个公共解释模型，但保留各自特有证据；输入不足时返回 `insufficient`，不得凑出建议。

### 可以以后做

- 事件驱动回测的订单、成交、拒单、现金和 A 股交易规则专项解释。
- 通过持久化 `backtest_id` 读取结果、历史解读、团队评论和多个回测对比。
- 用户确认后自动创建实验分支、修改参数、运行候选回测和比较敏感性。
- 行业/风格/政策归因、市场状态识别、压力测试、Walk-forward 和 Deflated Sharpe 等高级稳健性证据。
- 多轮问答、报告导出、策略上线前研究门禁和模拟盘偏差监控。

### 明确不做

- 不自动改写策略、自动运行优化、自动挑选样本内最优参数或下单。
- 不输出个股买卖建议、收益承诺或“可以实盘”的结论。
- 不把时间相关性描述成未经数据支持的回撤成因；没有行业、持仓或事件证据时只陈述现象。
- 不把原始策略源码、完整持仓明细、订单明细或完整净值曲线发送给第三方模型。
- 不为缺失指标、缺失成本或失败回测补造数据。

## 7. 成功指标

| 类别 | MVP 目标 |
|---|---|
| 正确性 | 证据复算黄金用例 100% 通过；响应中的证据引用 100% 可解析 |
| 可信度 | 评测集中不得出现无证据数值、收益承诺或伪造因果；不合规输出必须被拒绝或降级为确定性报告 |
| 有用性 | 专业评审认为“结论清晰且至少一条建议值得验证”的样本占比 ≥ 80% |
| 可执行性 | 至少 90% 的建议包含明确实验变量、对照方法、权衡和通过标准 |
| 性能 | 不含供应商故障时 P95 ≤ 12 秒；供应商超时上限 20 秒 |
| 成本 | 发送给模型的上下文体积相比完整回测 JSON 降低 ≥ 80% |
| 产品 | 上线后统计“回测完成 → 请求解读”和“解读 → 发起下一次回测”的转化率，目标值在 Beta 后设定 |

## 8. 优先级评估

| 维度 | 评分 | 说明 |
|---|---:|---|
| 商业价值 | 5 | 形成可计费 AI 闭环，直接增强转化与留存 |
| 用户价值 | 5 | 解决结果难理解、下一步不明确的高频问题 |
| 战略价值 | 5 | 产品定位中 P0 AI 能力，也是多步研究 Agent 的基础 |
| 技术成本 | 3 | 可复用回测结果与 LLM 接入，但需可靠证据层和评测体系 |
| 综合评分 | 41.7 | `(5 × 5 × 5) ÷ 3`，建议 P0 |

## 9. 初步投入与风险

- 预计投入：20–24 人天；量化/后端与 AI/API 两条工作流部分并行，约 3 个自然周。
- 关键依赖：FEAT-002 回测结果契约、FEAT-016 的 LLM Provider/幂等/审计基础；FEAT-014 调仓日志为增强依赖。
- 主要风险：指标口径误读、模型幻觉、建议诱导过拟合、结果数据过大、第三方数据合规。
- 缓解：确定性复算、引用校验、受控诊断目录、最小化上下文、专业评测集、失败时降级为无 LLM 的结构化报告。

## 10. 宏观影响

- 影响等级：L1。
- 是否改变能力地图：否，能力地图已包含“AI 研究助手：生成、解读、优化”。
- 是否改变路线图：否，Wave 1 已包含 AI 回测解读。
- 是否改变架构边界：否，AI 治理仍属于 SaaS 应用层，ResearchEngine 负责确定性研究计算。

## 11. 管理层摘要与建议决策

| 章节 | 结论 |
|---|---|
| 为什么做 | 把生成、回测和下一轮实验连成完整闭环，解决“指标很多但不会分析”的核心门槛 |
| 不做的影响 | 用户把结果带到平台外解释；AI 差异化停留在代码生成，难形成留存和计费 |
| 为什么现在做 | 回测 API、结构化指标和 LLM 接入已具备，改动不要求重写回测内核 |
| 投入多少 | 20–24 人天，约 3 周，建议量化/后端与 AI/API 各 1 人部分并行 |
| 预计收益 | 提升 AI 使用率、回测后的继续研究率，为团队评审和后续 Agent 奠基 |
| 风险 | 幻觉、错误因果、过拟合和合规；以证据先行、建议目录、人工确认和降级报告缓解 |
| 下一步 | 批准 Proposal 与 MVP 边界；冻结证据字段和首批诊断阈值；建立 30–50 个黄金评测样本后开发 |

**建议：批准为 P0，但以“证据与诊断层先通过黄金用例”作为 LLM 接入开发的前置门禁。**
