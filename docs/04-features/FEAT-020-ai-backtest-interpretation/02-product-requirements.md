# Product Requirements：AI 回测解读与优化建议

## 1. 目标与非目标

### 目标

1. 让用户在一次成功回测后，用一次操作获得可追溯、易理解的结果解读。
2. 把“优化建议”定义为下一轮可验证实验，而不是未经验证的策略改写。
3. 在样本、成本、基准或数据质量不足时明确降低结论置信度。
4. 为因子回测和向量化策略回测提供一致的交互与输出结构。

### 非目标

- 不判断策略是否适合投入真实资金。
- 不替代完整归因、参数优化、Walk-forward 或压力测试引擎。
- 不在 MVP 建设回测结果资产库、多轮 Agent 或自动执行链。

## 2. 用户角色与用户故事

1. 作为量化开发者，我希望快速看到收益、风险、稳定性和执行假设中的主要问题，并获得下一轮实验优先级。
2. 作为投研新手，我希望每个判断都能展开查看对应指标和含义，而不是只得到一个黑盒评分。
3. 作为团队评审者，我希望知道解读基于哪个结果快照、使用哪个规则和模型版本，并能复现证据。
4. 作为平台管理员，我希望控制模型密钥、调用额度、审计和数据发送范围。

## 3. 主流程

```text
用户完成因子或向量化策略回测
              ↓
点击“AI 解读”并可选择关注点 / 填写问题
              ↓
服务校验结果与上下文 → 生成结果指纹
              ↓
确定性 EvidenceBuilder 复算证据与数据覆盖
              ↓
DiagnosticCatalog 产生诊断与候选实验
              ↓
LLM 选择、排序并组织通俗说明
              ↓
引用与合规校验 → 返回解读 / 降级报告 / 数据不足
              ↓
用户查看证据并手动选择下一轮实验
```

## 4. 功能需求

### FR-01 触发与关注点

- 成功回测结果页提供“AI 解读”入口；失败回测不显示可用入口。
- MVP 关注点取值为 `overall`、`risk`、`robustness`、`factor`、`execution`；默认 `overall`。
- 用户问题可选，1–500 字；问题只能改变排序和表述，不能绕过数据、能力和安全限制。

### FR-02 证据包

证据包至少包含以下分区，并为每个字段分配稳定的 `evidence_id`：

| 分区 | 内容 |
|---|---|
| `identity` | 回测类型、引擎、区间、股票池、基准、策略/因子与版本、结果指纹 |
| `coverage` | 有效交易日、可用字段、缺失字段、证据等级与限制 |
| `performance` | 总收益、年化收益、同期基准收益、区间超额收益 |
| `risk` | 波动率、夏普、Sortino、Calmar、最大回撤及主要回撤区间 |
| `stability` | 分年收益、正收益年份占比、最好/最差年份、阶段集中度 |
| `execution` | 换手、持仓/调仓覆盖、成本与滑点口径是否已知 |
| `factor` | IC/Rank IC、IC 波动、滚动 IR、分层收益和行业证据（仅因子） |
| `assumptions` | 样本内/样本外标记、复权、成本、可交易规则等已知假设 |

证据缺失必须标记为 `unknown`，不得用零替代。

### FR-03 结果解读

输出固定分为：一句话结论、表现亮点、主要风险、可靠性与局限、下一轮实验。每个发现必须包含：

- `finding_id`、类型和标题；
- 受控的 `candidate_id`；
- 一个或多个有效 `evidence_refs`；
- `confidence`（`high` / `medium` / `low`）；
- 通俗解释与明确局限。

页面中的数值、日期、策略名和基准名由服务端根据证据渲染；模型自由文本不得成为数值来源。

### FR-04 优化实验建议

最多返回 5 条，按优先级排序。每条必须包含：

- 研究假设，而不是收益承诺；
- 触发该建议的证据；
- 建议调整的单一主要变量；
- 预期影响方向（收益、风险、稳健性、成本或可解释性）；
- 可能代价和失效场景；
- 对照组、验证区间/方法、关键观察指标和通过标准；
- `manual_only=true`，用户确认后自行创建下一次实验。

当存在 `NO_OUT_OF_SAMPLE`、`SAMPLE_TOO_SHORT`、`COST_ASSUMPTION_UNKNOWN` 等研究有效性问题时，至少一条 P0 建议必须先处理该问题；不得把纯样本内收益调优排在其前。

### FR-05 证据展开与反馈

- 用户点击任一结论或建议可展开查看证据值、指标定义、来源和缺失项。
- 用户可标记“有帮助 / 无帮助”并选择原因；MVP 只记录反馈，不在线训练模型。

### FR-06 降级

- LLM 超时、输出不合规或引用无效时，返回由确定性模板生成的解读和候选实验，`mode=deterministic_fallback`。
- 有效净值点少于 60、结果包含业务错误、核心净值不可解析时返回 `insufficient` 或 `rejected`，不调用 LLM。

## 5. 公共 API 契约

### `POST /api/ai/backtest-interpretations`

该端点长期归属 SaaS 应用层 AI Research Service。当前独立 SaaS 服务未落地时，可在 `researchengine.api` 以过渡路由实现，但 LLM Provider、审计和配额不得进入 `QuantCore`。

**请求示例：**

```json
{
  "backtest_type": "strategy",
  "result": {"metrics": {}, "equity_curve": [], "drawdowns": [], "annual_returns": [], "meta": {}, "error": null},
  "run_context": {
    "validation_scheme": "in_sample",
    "commission_rate": 0.00025,
    "stamp_tax": 0.0005,
    "slippage_rate": 0.001,
    "price_adjustment": "unknown"
  },
  "focus": "overall",
  "question": "这套策略下一步最值得验证什么？",
  "idempotency_key": "8ecb2eb2-6f7f-4d64-93b2-7e63b34ff2a8"
}
```

| 字段 | 必填 | 规则 |
|---|---:|---|
| `backtest_type` | 是 | `factor` 或 `strategy` |
| `result` | 是 | 必须匹配现有对应回测响应；`error` 必须为空；最大请求体 2 MiB，单条曲线最多 10,000 点 |
| `run_context` | 否 | 补充原请求未返回的成本、复权和验证口径；未提供的字段按 `unknown` 处理 |
| `focus` | 否 | 枚举值，默认 `overall`；因子专属关注点用于策略结果时返回 `422` |
| `question` | 否 | 1–500 字；敏感信息过滤后才可进入模型上下文 |
| `idempotency_key` | 是 | UUID；同租户、同键、同内容 24 小时内复用结果 |

**响应骨架：**

```json
{
  "interpretation_id": "bi_01J...",
  "status": "ready",
  "mode": "llm_grounded",
  "evidence": {
    "schema_version": "1.0",
    "result_fingerprint": "sha256:...",
    "coverage": "partial",
    "warnings": ["NO_OUT_OF_SAMPLE"],
    "items": []
  },
  "interpretation": {
    "summary": "策略有正超额收益，但当前只有样本内证据，优先验证稳健性。",
    "findings": [],
    "experiments": []
  },
  "disclaimer": "本结果仅用于量化研究，不构成投资建议或收益承诺。",
  "meta": {
    "model_alias": "backtest-interpreter-default",
    "prompt_version": "v1",
    "diagnostic_catalog_version": "v1",
    "latency_ms": 1520
  }
}
```

### 状态与错误

| HTTP / 状态 | 场景 |
|---|---|
| `200 / ready` | 证据足够，返回经校验解读；`mode` 为 `llm_grounded` 或 `deterministic_fallback` |
| `200 / insufficient` | 数据不足，只返回缺失项和补充建议，不输出表现结论 |
| `200 / rejected` | 结果类型、来源或内容违反业务规则，不能进行解读 |
| `400` | 空问题、请求体超限或结果快照不可解析 |
| `409` | 幂等键复用但请求内容不同 |
| `422` | 枚举、类型或回测响应结构不符合契约 |
| `429` | AI 调用额度或速率超限 |
| `502/503/504` | 供应商错误；仅在确定性降级也失败时返回 |

## 6. 业务规则与边界条件

1. 解释的是“提交的回测快照”，不是对真实未来表现的判断。内联快照来源标记为 `client_supplied`；后续使用结果资产 ID 时可标记为 `server_verified`。
2. 有效净值点 `< 60` 时为 `insufficient`；`60–251` 点只允许低置信度描述并强制短样本警告。
3. 回测区间、基准或年度序列不重叠时，对应比较证据为 `unknown`，不得计算或陈述超额结论。
4. `run_context` 没有成本信息时标记未知；明确为零时标记零成本假设。两者语义不同。
5. 没有样本外、Walk-forward 或参数敏感性证据时，不得使用“稳健”“泛化良好”或同义结论。
6. 回撤“原因”只有在存在对应持仓、行业、基准或事件证据时才能作为低/中置信推断；否则只描述时间、幅度和同步性。
7. 因子结果缺少 IC、分层或行业序列时，输出范围自动收缩；不得用策略收益替代因子有效性。
8. 用户问题视为不可信输入；其中要求忽略规则、泄露提示词、输出投资建议或编造信息的内容均不执行。
9. 建议默认一次只改变一个主要变量；多变量方案必须拆分为多个实验，避免无法归因。
10. 不使用单一综合“策略评分”替代证据，防止用户误认为平台给出投资评级。

## 7. 非功能要求

- **正确性**：所有派生证据使用与现有指标一致的定义，并由黄金数据集验证。
- **隐私**：模型上下文仅含压缩证据、候选 ID 和脱敏问题；不含源码、证券明细、订单、密钥和完整净值序列。
- **可追溯**：证据、诊断目录、提示词和模型均版本化；同一结果可定位到输入/输出哈希。
- **性能**：确定性证据生成 P95 ≤ 500 ms（10,000 点以内）；整体 P95 ≤ 12 秒。
- **可用性**：供应商不可用时提供确定性降级，不阻塞用户查看原始回测结果。
- **可访问性**：颜色不是风险等级的唯一表达；结论、证据和建议均有文本标签。
- **合规**：固定展示研究免责声明；禁止收益承诺、荐股和自动下单语义。

## 8. 验收标准

| 编号 | 可测试条件 |
|---|---|
| AC-01 | 合法因子与向量化策略回测快照均能生成稳定结果指纹和版本化证据包；同一规范化输入得到相同证据。 |
| AC-02 | 服务复算的总收益、基准收益、最大回撤、年度统计与黄金数据集一致；缺失值保持 `unknown`。 |
| AC-03 | 有效净值少于 60 点、`error` 非空或核心日期乱序时不调用 LLM，并返回 `insufficient/rejected`。 |
| AC-04 | 每条 finding 和 experiment 至少引用一个存在的证据或诊断 ID；未知引用、模型新造数值或新造参数会触发拒绝并降级。 |
| AC-05 | 当仅有样本内结果、成本未知或样本过短时，响应包含对应警告，且首要建议优先验证有效性而非提高样本内收益。 |
| AC-06 | LLM 超时、非 JSON、Schema 不符、提示词注入或合规词命中时，用户仍能收到确定性降级报告，原始供应商异常不泄露。 |
| AC-07 | 发送给 Provider 的测试抓包不含策略源码、证券代码、订单/持仓明细、完整净值曲线、用户身份和密钥。 |
| AC-08 | 相同租户、幂等键和请求 24 小时内不重复调用 Provider；内容不同返回 `409`。 |
| AC-09 | 专业评测集覆盖正收益、负收益、深回撤、高换手、短样本、成本未知、因子弱单调等至少 30 个样本，并达到 Proposal 中正确性与有用性门槛。 |
| AC-10 | 移除 AI 路由或关闭 Feature Flag 后，原有因子/策略回测 API 与结果页面不受影响。 |

## 9. 已确定的评审口径

- MVP 不依赖持久化 `backtest_id`，使用内联结果快照；结果资产接入后再扩展引用模式。
- MVP 不支持事件驱动专项解读；事件模式返回明确的能力提示，不静默按向量化解释。
- MVP 不自动执行优化建议；自动实验必须另立 Feature 并单独评估成本、权限和过拟合风险。
