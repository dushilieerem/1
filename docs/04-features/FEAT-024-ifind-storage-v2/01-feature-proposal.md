# Feature Proposal：iFinD 宽表规范与渐进替换

## 1. 背景

现有 AkShare 数据已经能够支持研究验证，不需要等待 iFinD 全量基本面完成后一次性切源。当前目标是继续使用可用数据，将已经下载并验证的 iFinD 行情、估值和状态字段逐步写入新的 `current` 版本。

SVQuant 的回测数据是只读历史快照，并且价格、成交量、成交额和换手率通常一起加载。Parquet 本身支持列选择，因此没有必要为七个高度相关字段维护七个独立文件。现有 iFinD `market_data_hfq.parquet` 的业务分组方向正确，需要补齐文件边界、字段清单、版本和读取规范。

## 2. MVP

### 必须做

- 固定“一个业务域一个多字段宽表”的文件规格。
- `market_data.parquet` 保存后复权 OHLC、成交量、成交额和换手率。
- `daily_basic.parquet` 保存市值、股本和估值。
- `security_status.parquet` 保存行业、涨跌停状态、ST 和 `is_suspended`。
- `unadjusted_price.parquet` 独立保存未复权 OHLC。
- 支持 AkShare 与 iFinD 按字段渐进替换，并在 manifest 记录每个逻辑字段的来源。
- 发布版本和服务器内存快照只读；更新生成新版本，不原地修改旧数据。

### 明确不做

- 不统一供应商单位，不对 iFinD 数值做百分比、金额或股数换算。
- 不在存储层填充缺失值。
- 不等待全部财务和基本面数据完成。
- 不将行情、基本面、状态、指数和元数据塞进一个无边界的超级宽表。
- 不为了回测读取建设数据库。

## 3. 用户价值

- 研究员可以马上使用现有数据，不被 iFinD 下载进度阻塞。
- 回测常用字段集中读取，文件数量和服务启动 I/O 更少。
- 每个文件有清晰业务含义，后续基本面扩展不会污染行情表。
- 历史版本不可变，单次回测始终绑定一致的数据快照。

## 4. 决策

方案已于 2026-08-11 批准。优先完成三个研究宽表和一个展示宽表，再接入只读内存快照与共享回测进程池。
