# 本周工作计划：因子研究回测闭环与后续模块准备

> 周期：2026-07-20（周一）— 2026-07-24（周五）
>
> Sprint 目标：交付因子回测 API 与六类图表闭环；交付“编写策略 → 策略回测 → 结果展示”的策略 MVP；将内置因子从 92 个扩展至 300 个并完成质量验证；交付策略部可执行的因子/策略回测手册；完成社区模块的开发准入材料。
> 关联：`INIT-001`、`INIT-003`、`FEAT-002`、`docs/01-需求文档/产品能力地图.md`

## 优先级与承诺范围

| 优先级 | 工作项 | 本周完成定义（DoD） |
|--------|--------|---------------------|
| P0 | 因子研究：回测 API 与出图 | `POST /api/backtest/factor` 的请求、响应、错误和缓存契约冻结；返回六类图表数据；完成渲染/展示联调与自动化回归。 |
| P0 | 策略模块 MVP | 实现并验收“编写策略代码 + 参数 → 策略回测 → 指标、净值、错误响应 → 结果展示”的闭环；不包含策略保存、版本管理或社区发布。 |
| P1 | 因子库扩展 | 在 ResearchEngine 独立仓库登记并验证 300 个可加载因子。新增因子均具备分类、公式来源/说明、最小计算测试和批量加载校验；SVQuant 只同步目录并展示。 |
| P1 | 策略部回测手册 | 交付因子和策略回测的操作手册，含前置数据、代码模板、请求参数、结果解读、常见错误、验收样例和交接说明；由策略部按手册独立跑通一次。 |
| P2 | 社区模块 | 完成 Feature Proposal、PRD、技术设计和项目计划；本周不投入社区模块代码开发。 |

> 团队容量：**两名开发者**。开发者 A 负责因子回测六类图表数据/渲染与策略编写、策略回测结果展示的联调、测试和内部 Demo；开发者 B 负责因子库扩展至 300 个与质量验证、因子回测 API、策略回测 API，以及策略部因子/策略回测手册。项目/架构工作由项目经理推进，不占用两名开发者的代码容量。

## 验收与度量

| 指标 | 目标 |
|------|------|
| 因子/策略回测 API 自动化测试 | 相关测试全部通过；无 P0 回归 |
| 六类图表 | 每类均有真实回测数据演示；缺数据时有明确空态 |
| 因子库数量 | `index.yaml.total_factors = 300`，且批量加载成功 |
| 因子质量 | 新增因子 100% 具备唯一名称、分类、说明/来源、字段依赖和最小计算测试 |
| 策略 MVP | 策略代码编写入口、参数、策略回测 API、指标/净值/错误响应、结果展示和至少一个成功样例、一个错误样例均有自动化验证 |
| 策略部回测手册 | 策略部人员不依赖开发者口头协助，能依手册完成一次因子回测和一次策略回测，并取得预期结果 |
| 社区模块 | Definition of Ready 全项通过，或明确记录阻塞项并不进入开发 |

## 风险与应对

| 风险 | 影响 | 触发信号 | 应对 |
|------|------|----------|------|
| 因子库扩展与双回测 API 争抢开发者 B 容量 | 高 | 周三任一 API 未通过或因子批量校验失败 | 优先双回测 API；因子库按批次完成并每日报告缺口，不以未验证公式凑数 |
| 手册与实际系统不一致 | 中 | 策略部走读时无法复现样例或参数含义不清 | 使用 CI 通过的真实样例编写；周四由策略部独立走读，周五修订后交付 |
| 前端工程/图表库未就绪 | 高 | 周一无法确认联调入口 | 以 API mock、Swagger 和后端图表数据验收；前端渲染拆为独立任务 |
| API 口径持续变化 | 高 | 周二后仍新增/改名响应字段 | 锁定 v1 契约；新需求使用兼容新增字段 |
| P0 延期挤占新模块 | 中 | 周三 M1 未通过 | 暂停策略/社区代码，只保留设计和 DoR |
| 行业映射或行情数据质量不足 | 中 | 行业图为空、IC 序列异常 | 将数据问题列为数据模块缺陷，使用固定样本回归测试 |
