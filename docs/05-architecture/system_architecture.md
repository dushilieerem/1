## 1. 架构总览

```text
                              SVQuant
 ┌────────┬────────┬────────┬────────┬────────┬──────────────┐
 │ 用户   │ 数据   │ 新闻   │ 社区   │ 研究   │ 实盘 / 模拟盘 │   业务模块
 └────┬───┴──┬─────┴──┬─────┴──┬─────┴──┬─────┴──────┬───────┘
      │      │        │        │        │            │
      │      └───────┼────────┼────────┘            │
      │              ▼        ▼                     ▼
      │       QuantCore（数据、因子、指标、回测、市场规则）
      │              ▲                              ▲
      │       ResearchEngine                   TradingEngine
      │       （研究计算服务）                  （规划中）
      └──── SaaS 应用层（IAM、资产、计费、Web、社区；规划中）
```

### 设计说明（给老板）

SVQuant 先按六个**业务模块**定义产品边界，再用可演进的技术组件承载它们：

1. **用户模块**负责身份、组织、权限、额度、计费和资产归属；它是所有模块的访问控制入口。
2. **数据模块**负责标准化行情、基本面、指数和行业分类；新闻、研究和交易都从它获得统一数据。
3. **新闻模块**负责新闻、公告、研报和政策事件及其证券/行业关联；它提供研究可消费的事件与语义输入。
4. **社区模块**负责内容、协作和研究资产分享，不执行回测或维护行情。
5. **研究模块**负责因子与策略研究。`ResearchEngine` 是其中的回测计算服务，调用 `QuantCore` 完成数据读取、计算、回测和指标，并不管理用户因子库或前端页面。
6. **实盘/模拟盘模块**负责策略运行、账户、风控、模拟撮合和订单执行；`TradingEngine` 为其规划承载。

`QuantCore` 是跨数据、研究和交易模块复用的量化引擎层。六个业务模块不要求当前立即拆成六个进程或仓库；在 0-1 阶段可在同一应用中实现，但必须保持接口和数据所有权边界。

### 1.1 业务模块依赖

```text
用户模块 ─────────────→ 全部模块（鉴权、权限、额度、资产归属）
数据模块 ─────────────→ 新闻模块、研究模块、实盘/模拟盘模块
新闻模块 ─────────────→ 研究模块（事件信号、行业/政策分析输入）
研究模块 ─────────────→ 实盘/模拟盘模块（策略发布与研究结果）
社区模块 ─────────────→ 用户模块、研究模块（引用资产，不直接调用回测）
```

## 2. QuantCore 引擎分层

```
QuantCore
├── Data Engine         数据引擎（统一数据访问）
├── Factor Engine       因子引擎（因子计算）
├── Factor Library      内置因子库
├── Strategy Engine     策略引擎（研究/交易共享的策略定义）
├── Backtest Engine     回测引擎（双模式）
├── Portfolio Engine    组合管理（供实盘/模拟盘模块复用，Wave 2）
├── Risk Engine         风险控制（供实盘/模拟盘模块复用，Wave 2）
├── Execution Engine    订单执行（由 TradingEngine 编排，Wave 2）
├── Analyzer            绩效分析
├── Report Engine       报告生成
└── Market Rule         市场规则（多市场扩展点）
```

### 为什么这样分层

把量化研究的每一步拆成独立模块，原因是：

1. **可替换**：数据源从 CSV 换成 ClickHouse，只需要改 Data Engine，因子引擎不用动
2. **可测试**：每个引擎可以独立测试
3. **可扩展**：新增市场（如港股）只需新增 Market Rule，不用改回测引擎

## 3. 双引擎设计 ⭐

### 3.1 为什么需要两个引擎？

把回测引擎比作计算器：

- **向量化引擎**：就像按一个按钮算出整张表格——快，适合批量计算
- **事件驱动引擎**：就像逐行逐列计算，每一步都检查中间结果——慢但精确

### 3.2 各司其职

| | 向量化引擎 | 事件驱动引擎 |
|------|-----------|------------|
| 计算方式 | 矩阵运算（批处理） | 逐 bar 推进 |
| 速度 | 快（秒级） | 慢（分钟级） |
| 适用场景 | 因子计算、快速回测 | 复杂策略、模拟盘 |
| A 股规则支持 | 有限 | 完整 |
| 当前进度 | ✅ 已落地 | 🔧 框架已预留 |

### 3.3 适配层设计（已落地）

```
ResearchEngine（因子代码不变）
       │  Experiment.run() 委托给适配器
       ▼
IBacktestEngine ←── 契约接口
       │
  ┌────┴────────────┐
  │                  │
VectorBTEngine   NativeEngine
(wraps vectorbt)  (自研实现)
```

**给老板的解释**：研究员写的因子代码，通过一个"转接头"连接回测引擎。这个转接头有两个版本——一个快的（向量化），一个准的（事件驱动）。研究员换引擎只需要改一行配置，代码不用动。

## 4. 数据流

```
行情数据（MarketData/ 目录，Parquet 格式）
       ↓
DataEngine / IDataProvider（数据读取）
       ↓
FieldParquetProvider（按字段读取，内存友好）
       ↓
Factor Engine（因子计算 → 因子值矩阵）
       ↓
         ├── Metric Engine（IC/IR/分层分析）
         ├── Backtest Engine（策略回测）
         │        ↓
         │   Metric Engine（绩效指标）
         │        ↓
         │   Report（净值曲线/报告）
         │
         └── Experiment（ResearchEngine 编排）
                  ↓
             output/（回测结果）
```

## 5. 数据存储方案

| 数据类型 | 格式 | 说明 |
|---------|------|------|
| 行情数据 | Parquet | 按字段+日期分片存储，列式格式，查询快 |
| 因子值 | numpy array | 运行时内存管理，不落盘（可缓存） |
| 回测结果 | CSV/Parquet | ResearchEngine output/ 目录 |
| 基本面数据 | Parquet | 与行情类似，按字段存储 |
| 用户配置 | YAML | ResearchEngine config.yaml |
| 结果存储 | CSV/Parquet/SQLite/ClickHouse | 可选后端 |

## 6. 多市场扩展

```
新增市场 = 新增 MarketRule 实例 + 对应数据源
```

| 市场 | 规则 | 状态 |
|------|------|------|
| A 股 | T+1、10%/20% 涨跌停、100 股/手 | ✅ 已支持 |
| 港股 | T+0、无涨跌停 | 🔧 规划 |
| 美股 | T+0、无涨跌停 | 🔧 规划 |

**设计原则**：回测引擎不依赖任何市场的具体规则。规则从 MarketRule 注入，新增市场只需新增 MarketRule，无需改动引擎。

## 8. 架构决策索引

| 决策 | 选择 | 原因 |
|------|------|------|
| 计算引擎 | NumPy/Pandas 向量化 | 开发效率高，生态成熟 |
| 历史行情存储 | 文件 + Parquet | 批量研究读取，免部署；列式格式匹配面板计算 |
| 回测适配层 | 接口契约 + 可插拔后端 | 解耦策略代码和后端实现 |
| 包管理 | setuptools + pyproject.toml | 标准 Python 打包 |
| HTTP 框架 | FastAPI | 异步高性能，自动生成 OpenAPI 文档 |
| 业务模块边界 | 用户 / 数据 / 新闻 / 社区 / 研究 / 实盘模拟盘 | 分离产品职责与数据所有权，同时保留 0-1 阶段的渐进式部署 |
| 文档 | Markdown + AGENTS.md | 轻量，版本可控 |
