# ADR-011：为什么以 AkShare 为主历史数据源

- 日期：2026-07-27
- 状态：已接受
- 关联：ADR-003、ADR-010、FEAT-010

## 问题

SVQuant 需要可持续更新、可复现的 A 股历史行情，以生成本地 Parquet 发布版本。现有 Wind 账号为一个月试用，无法作为长期自动更新与历史发布的唯一依赖；项目已具备 AkShare / Baostock 原始历史库及日更脚本。

## 选择

1. AkShare 原始库为当前主历史数据源；其中由 Baostock 补齐的历史文件保留其真实来源，具体以 `data_provenance.csv` 为准。
2. 发布链路固定为 `IFind/data/akshare` → 质量门禁 → `IFind/data/releases/<version>` → `SVQuant/MarketData`。候选版本验证完成前不得覆盖 SVQuant 活动数据。
3. Wind 仅作为受限期内的小样本校验源，不承担日常更新或正式数据发布。
4. 首批发布字段限于可直接映射且在清单中标注为后复权的 OHLC、`volume`、`amount`、`turnover`。`adj_factor`、财务、证券状态与未验证字段必须保持 `blocked`，不得伪造或静默混源。
5. 单证券停更或缺少字段时，候选面板保留 `NaN`，并在清单记录受影响证券；禁止填零、前值填充或跨来源补值。

## 备选方案

### Wind 作为主历史数据源

不采用。试用账号有期限，且样本中 `float_mv` 映射返回全空，尚未具备可持续性和完整字段验证条件。

### 继续使用现有第三方 `current`

不采用为主发布源。其成交量额等字段与 Wind 样本一致，但没有发布清单、来源版本和复权公式；OHLC 与 Wind、AkShare 存在系统性倍率差异，无法审计或可靠拼接。

### 多来源按缺失值拼接

不采用。同一字段混用不同复权、单位或可得性规则会破坏回测可复现性；补源和切源必须形成新版本并在清单中声明。

## 后果

### 正面

- 可利用现有完整历史库和日更脚本，避免试用账号成为交付阻塞。
- 每个发布版本可记录来源、后复权口径、质量报告和文件哈希，便于回滚与复现。
- Wind 仍可在可用期内提供独立抽样对账。

### 负面与约束

- AkShare 原始文件存在停更和字段缺失，必须通过质量门禁；当前不能直接全量发布。
- 原始库含 AkShare 与 Baostock 历史补源，必须保留逐文件来源，不能统一标记为单一供应商。
- 后复权价不能替代 `adj_factor`；在补齐复权因子与公式前，价格相关扩展字段仍不可发布。
- 数据使用、缓存和产品展示仍须符合各来源的许可条款。
