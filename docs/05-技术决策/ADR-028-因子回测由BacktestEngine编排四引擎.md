# ADR-028：因子回测由 BacktestEngine 编排四引擎

- 日期：2026-08-28
- 状态：已采纳（实施中，待专项验收）
- 关联：[FEAT-030](../03-功能文档/FEAT-030-因子回测流程重构/README.md)
- 适用范围：因子回测；策略回测不在本期迁移范围

> 2026-08-28 修订：[ADR-029](ADR-029-研究服务采用services与models分层.md) 已采纳。
> 四引擎编排和业务规则保留，本文中的 QuantCore 包归属被 services/models 分层接替。
> 策略只随目录迁移，不改变其执行语义；本 ADR 的历史决定保留供追溯。

## 问题

现有完整因子流程由 FactorBacktestExecutor 和 _FactorBacktestAlgorithm 共同承担，
NativeEngine 只负责底层组合收益。团队希望 BacktestEngine 明确表示完整回测过程，
并使数据筛选、因子加工、组合构建和效果计算有各自的责任方。

单次/批量/Python 入口已统一，但过滤、分组和指标辅助计算仍分散；批量强制过滤也不符合
本次已确认的“所有过滤/预处理默认关闭、可分别开启”要求。

## 选择

1. 应用层只有一个具体 BacktestEngine，提供 run(spec, context)，组织 services 中的四个责任引擎。
   不增加接口继承、Native 实现层、模拟器、后端注册表或通用工作流。
2. DataEngine 负责行情、股票池、基准/辅助数据与筛选掩码；保留完整时间轴和价格精度，
   不通过删行情行实现过滤。
3. FactorEngine 负责加载/计算及可选加工，顺序为完整历史计算 → 有效池 → 去极值 → 标准化。
4. PortfolioEngine 负责分组、权重、持仓、调仓意图及评价数据对齐；未来收益不参与组合决策。
5. MetricEngine 负责收益、费用扣减、净值、基准、IC、分组和扩展评价，既有公共指标接口保持。
   API 模型、存储和绘图留在应用层。
6. Manager 和两个现有因子 Experiment 保持原有职责；单次、批量、Python 都调用同一新引擎。
   因子链路移除旧 Executor/算法/信号包装和 adapter 委托，策略依赖的旧组件暂时保留。
7. 首期仅迁移停牌/涨停过滤、去极值、标准化，全部默认关闭；新过滤和中性化入口后续再做。
   缺少可选过滤数据时跳过并告警，保留在当次结果、缓存和日志，不新增批量历史字段。
8. 保持现有收益、净值及分组指标公式；当前执行版本为 factor-execution-v4，缓存为
   factor-backtest-v10，指标公式版本保持 factor-scorecard-v2。批次身份隔离新旧执行版本。
9. 本期不修改 SVQuant、不迁移因子数据库、不改变批量历史 schema，也不清理历史数据。
10. 因子回测只保留调用方原始 `FactorBacktestSpec`；运行时实际数据终点记为 `actual_end`。
    不派生 `effective_spec`，因子主链不再把 Spec 转换为 `ConfigManager`。

## 备选方案

- 保留旧 Executor 兼容门面：没有当前调用方，反而继续制造错误的执行边界。
- BacktestEngine 接口 + NativeBacktestEngine + Simulator：当前没有多实现需求，概念和迁移成本过高。
- 因子与策略一次重构：影响策略资产及事件成交语义，超出首期范围。
- 缺少过滤数据立即失败：一致性更严格，但用户选择继续研究并明确告警。
- 将告警永久写入批量历史：可审计性更强，但用户选择本期不改 schema，后续另行评审。

## 后果

### 正面

- 完整流程入口与业务语义一致，四类计算职责清楚。
- 已有可选处理统一配置，批量和单次能共享显式规格与数值基准。
- 过滤状态可见，未来收益与组合决策分离。
- 策略旧接口和历史数据库保持，控制本次迁移范围。

### 代价与限制

- 默认关闭过滤及先有效池后预处理会改变部分旧请求结果，必须在版本和发布说明中标明。
- 保留现有首期收益/展示净值约定，不解决所有历史公式或费用接线问题。
- 当次告警不会进入批量历史；任务或缓存过期后无法从历史查询恢复过滤诊断。
- 策略迁移前新因子流程与旧策略流程并存，但因子本身不得长期保留双套计算路径。
- 共享引擎和指标迁移具有回归风险，需要数值、并发及策略验收。

## 生效与审核

用户已审核计划和文档并明确允许代码重构，当前四引擎主链已实施，旧 FactorBacktestExecutor
已删除。M5 专项验收完成后，
再把相关架构文档的“当前实现”基线更新为最终交付状态；在此之前本 ADR 标记为实施中。
