# ADR-003: 事件引擎替换演示回测

## 问题

旧 `BacktestEngine` 在策略读取当日收盘价后，以同一根日线的收盘价撮合，无法保证日频策略的防未来函数语义，也没有 A 股交易规则和可审计的订单生命周期。

## 选择

删除旧演示引擎及其订单、撮合、组合和成本实现，新增独立的 `quantcore.backtest.event.EventBacktestEngine`。

首期仅启用 `cn_equity_daily_v1` 的本地可信开发内核：策略在盘前读取截至前一收盘的日线数据，当日开盘按卖后买顺序执行，并校验现金、100 股整手、T+1、停牌与涨跌停。结果保留订单、成交、持仓快照和事件日志。

向量化 `NativeEngine` 及其 API 保持不变；事件策略不复用 `generate_signals()` 契约。

## 备选方案

1. 保留旧演示引擎并逐步改造：会同时存在两套名称相近、时序语义不同的事件回测，容易误用。
2. 仅扩展向量化回测：无法严谨表达 T+1、订单拒绝和状态机策略。

## 后果

正面后果是事件策略有明确的时间口径和 A 股规则基础，唐奇安等突破、止损、持仓状态策略可在此继续实现。

负面后果是旧 `BacktestEngine` 的 Python API 被移除；事件 API、点时基本面数据和生产沙箱尚未完成，因此当前内核仅限本地可信研究使用。
