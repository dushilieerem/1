# ADR-005：为什么保留向量化并新增事件驱动策略接口

- 日期：2026-07-21
- 状态：提议
- 关联：FEAT-006、ADR-001、ADR-002

## 问题

现有策略回测使用“策略生成目标权重矩阵”的向量化契约，速度快但无法表达聚宽式策略的定时调度、持仓状态、订单与 A 股规则。若直接把事件回调塞进现有向量化接口，将混淆成交时序、降低性能且破坏已验证的因子研究链路。

## 选择

保留 NativeEngine / VectorBTEngine 作为因子和批量策略研究的默认引擎；新增独立 EventEngine、`StrategyContext` 和事件策略代码契约。两个路径共享数据、市场规则、成本、结果和指标能力，但不共享策略代码 API。

## 备选方案

### 只增强现有目标权重接口

不采用。它无法准确表示订单失败、盘中回调、T+1 和状态机策略，并会把回测实现细节泄漏到策略矩阵。

### 用 EventEngine 替换向量化引擎

不采用。因子研究和大规模参数搜索会失去向量化性能优势，且迁移成本高。

### 一比一复刻聚宽 API

不采用。聚宽全局函数、数据授权、订单语义和运行环境不可直接复制；兼容层会扩大安全和维护范围。优先定义 SVQuant 自有、显式依赖 `context` 的 API。

## 后果

正面：复杂策略可审计地回测，向量化研究不退化，并为模拟/实盘复用策略运行时奠定基础。

负面：需要维护两套策略接口，用户必须选择引擎模式；事件策略数据、规则与沙箱成本较高。新增分钟级、融资融券和其他市场时必须以独立 Feature 扩展。
