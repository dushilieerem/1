# ADR-007：聚宽兼容因子采用版本化清单与原生复算

## 问题

SVQuant 需要降低聚宽研究员的因子迁移成本。聚宽因子目录会演进，且不同类别依赖行情、财务、行业、预期及资金流等不同来源和时点口径。直接调用第三方运行时或仅复制名称，都会使可用性、数值一致性、授权和未来数据风险不可控。

## 选择

采用“合法导出的目录快照 + 版本化 manifest + SVQuant 原生 `FactorLibrary` 复算”的方式：

- 目录快照仅保存名称、分类、描述、抓取日期、来源版本和哈希等可审计元数据；不保存或分发受限因子数值。
- 每个兼容项声明原始名称、SVQuant 名称、公式来源、字段依赖、数据许可、点时可得规则、实现位置和验证状态。
- 仅将 `implemented` / `verified` 项作为可运行因子暴露；财务数据以公告/可见日而非报告期结束日对齐。
- 不把聚宽 SDK/API 作为生产运行时依赖；实现继续使用现有面板向量化模型和可替换的数据 provider。

## 备选方案

1. **直接调用聚宽 API**：上线快，但依赖第三方账号、网络、配额和许可，无法作为平台基础设施。
2. **导入或缓存聚宽因子值**：看似可快速一致，但存在数据许可、可再分发和长期依赖问题。
3. **仅复制因子名称**：实现成本低，但会掩盖公式和数据口径差异，无法建立可信兼容性。
4. **只保留既有 Qlib 集合**：已具备通用机器学习基线，但不能满足聚宽 A 股研究迁移需求。

## 后果

正面影响：因子实现、数据来源与验证证据可追溯；不锁定第三方运行时；可按数据授权渐进扩展。

负面影响：首批交付慢于直接接 API；需要维护 manifest、数据字段契约和参考回归；在没有完全相同原始数据及口径时，不能承诺逐值一致。
