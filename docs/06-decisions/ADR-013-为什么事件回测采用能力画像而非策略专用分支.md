# ADR-013：为什么事件回测采用能力画像而非策略专用分支

- 日期：2026-07-28
- 状态：提议
- 关联：FEAT-006、ADR-002、FEAT-010

## 问题

GARP 日频基本面策略需要公告日财务、A 股 T+1 与现金账户；股指期货和 T+0 ETF 统计套利需要一分钟事件、保证金、双向、合约换月和多子账户。若引擎以策略名称或聚宽函数集为中心扩展，将持续产生 GARP、期货或 ETF 的专用分支，无法支撑新的资产和策略。

## 选择

EventEngine 采用策略声明的 `StrategyRequirements` 与运行环境发布的 `EngineProfile` 进行启动前能力匹配。内核只识别频率、资产类别、数据能力、交易能力、调度能力、市场规则和执行模型；策略公式、品种选择和风控阈值留在策略代码中。

首期按画像分阶段启用：A 股日频现金多头、T+0 ETF 分钟、股指期货分钟、ETF+期货多资产分钟。能力缺失时返回结构化失败，不执行或静默近似。

## 备选方案

### 为每类策略增加专用引擎

不采用。会复制事件循环、订单和账本逻辑，且新策略仍需新增专用分支。

### 完整复刻聚宽 API

不采用。平台 API、数据授权与订单语义不同，兼容面不可控，也无法自然表达内部能力边界。

### 一次性实现任意市场和频率

不采用。数据、市场规则与执行真实性无法一次验证；通过画像逐个发布能控制风险并保留统一内核。

## 后果

正面：同一内核可扩展日频、分钟、股票、ETF、期货和多账户；策略支持范围可被机器校验和准确说明。

负面：需要先定义能力契约和更多数据/规则适配器；“支持所有策略”必须表述为“支持所有已发布能力画像内的策略”。
