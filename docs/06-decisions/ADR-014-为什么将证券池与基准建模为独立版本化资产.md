# ADR-014：为什么将证券池与基准建模为独立版本化资产

- 日期：2026-07-29
- 状态：提议
- 关联：FEAT-018、FEAT-017、FEAT-007

## 问题

因子和策略回测都需要证券范围与业绩比较对象。若继续使用单个字符串或把基准当作股票池的附属字段，用户的自选组合无法复用，权重和版本也不会保留；历史结果会因后续配置修改而无法复现。股票池还会影响因子截面与可交易范围，基准则应只影响收益比较，二者业务语义不同。

## 选择

把 `InstrumentPool` 与 `BenchmarkPortfolio` 建模为独立的版本化研究资产，由应用层 Catalog 解析为不可变快照：

- `InstrumentPool` 输出日期范围内可研究/可交易的证券集合；MVP 为静态清单。
- `BenchmarkPortfolio` 输出带权重的被动组合；MVP 使用固定权重、收盘到收盘收益且不含成本。
- 回测以 `AssetRef` 引用资产，在运行开始时将其解析为带内容哈希的 Snapshot，并随结果保存。
- QuantCore 仅消费已解析的证券集合或基准净值/收益，不依赖目录、用户或权限。

## 备选方案

### 将股票池和基准继续限制为内置枚举

不采用。无法覆盖用户研究组合，也不支持版本和复现。

### 用一个“股票篮子”对象同时承担股票池和基准

不采用。它会混淆“能否参与选股/下单”与“如何计算比较收益”，也无法表达基准可含池外证券和权重。

### 在 QuantCore DataProvider 中保存用户资产

不采用。DataProvider 的职责是统一市场数据读取；用户/项目资产属于应用层。将文件和权限逻辑放入 QuantCore 会破坏模块边界。

### MVP 直接实现动态条件选股与历史指数成分

不采用。它依赖历史分类、上市状态和日期×证券成分数据；以最新成分近似会产生幸存者偏差。先交付语义明确的静态资产，再单独建设时间序列成员资格。

## 后果

正面：因子、策略和后续模拟盘可复用同一资产引用；结果可复现和审计；未来可把文件 Catalog 平滑替换为 SaaS 资产服务。

负面：需要维护版本、哈希与快照；MVP 不会自动满足“按行业、市值或历史指数成分动态选股”的需求，后续必须新增时间序列成员资格能力。
