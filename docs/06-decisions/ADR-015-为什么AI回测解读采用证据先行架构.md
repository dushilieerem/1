# ADR-015：为什么 AI 回测解读采用证据先行架构

- 日期：2026-07-31
- 状态：提议

## 问题

回测结果包含大量数值、曲线、指标和假设。若直接把完整 JSON 交给大语言模型，模型可能误读指标口径、创造不存在的数值、把时间相关性解释成原因，或为了“优化”而推荐样本内调参。与此同时，完全使用固定模板又难以满足不同用户关注点和通俗解释需求。

平台需要在可信度、表达能力、成本、隐私和后续 Agent 演进之间建立长期边界。

## 选择

采用“证据先行”的两阶段架构：

1. 确定性 `EvidenceBuilder` 从受控回测响应中复算并生成版本化证据包，明确事实、派生值、未知项、公式、来源和限制。
2. 版本化诊断目录和实验目录根据证据生成允许的诊断与候选实验。
3. 大语言模型只选择、排序和通俗表达已有候选，不创建新数值、新参数或新事实；最终数值由服务端从证据包渲染。
4. 所有模型输出经过引用、Schema、合规和隐私校验；失败时降级为确定性报告。
5. MVP 的建议为人工确认的研究实验，不自动修改、回测、优化或下单。

身份、密钥、配额、Provider 和审计继续遵循 ADR-012，归属 SaaS 应用层；ResearchEngine 可承载纯确定性的证据构建，QuantCore 不引入 LLM 依赖。

## 备选方案

1. **完整结果直接交给 LLM**：开发最快，但上下文大、成本高、不可稳定复算，幻觉和隐私风险最高。
2. **纯规则和模板**：可信且便宜，但难以针对用户问题调整语言和排序；保留为故障降级，而非唯一体验。
3. **让模型自由生成建议，事后做关键词检查**：表达灵活，但关键词无法可靠发现虚构数值、错误因果和过拟合建议。
4. **直接建设自动研究 Agent**：可自动改策略、回测和比较，但会同时引入执行权限、算力成本、循环终止、审计和选择偏差问题，超出当前阶段。

## 后果

### 正面

- 量化事实可测试、可复算、可引用，模型替换不改变证据口径。
- 发送给第三方模型的数据更少，不含源码和证券明细，成本与合规风险更低。
- 供应商失败仍可输出确定性报告，AI 不成为回测结果页的单点故障。
- 诊断与实验目录为后续自动研究 Agent 提供明确、可审计的工具边界。

### 负面

- 首期需要额外建设 Evidence Schema、诊断目录、黄金评测集和 Grounding 校验，投入高于简单 Prompt。
- 模型只能在候选范围内表达，可能显得保守；新增诊断需先扩展目录和测试。
- 内联结果快照只能证明“解释了这份输入”，不能证明输入来自可信服务器；需要后续结果资产 ID 完善来源。

### 演进约束

- 自动修改与回测必须另立 Feature，并默认采用样本外、Walk-forward、参数敏感性和预算上限。
- 任何新增证据、阈值或实验参数都必须版本化并补黄金测试；不得只改提示词。
- 历史解释按当时版本保留，不按新规则静默重写。
