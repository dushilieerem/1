# ADR-017：市场数据按业务域采用多字段宽表

- 日期：2026-08-11
- 状态：已接受
- 关联：FEAT-024、ADR-003、ADR-016

## 问题

原有 `FieldParquetProvider` 采用“一个字段一个 Parquet”的物理布局。该方式便于单字段懒加载，但价格、流动性、估值和证券状态等字段在研究与回测中通常成组读取。字段数量增加后，一字段一文件会带来文件数量膨胀、日期和证券轴重复存储、跨文件对齐复杂以及发布校验分散等问题。

SVQuant 的历史数据发布后只读，更新通过生成新版本完成，因此需要在读取效率、文件职责、schema 管理和渐进替换之间确定新的物理布局。

## 选择

1. 股票日频数据按业务域组织为多字段 Parquet 宽表，而不是一字段一文件，也不把所有数据放进一张总表。
2. 宽表行是唯一且升序的 `datetime`；列使用 `(symbol, field)` 两级结构。证券代码使用 iFinD 完整代码，字段名使用 SVQuant 逻辑字段名。
3. 验证期固定以下核心资产：
   - `panels/market_data.parquet`：`open/high/low/close/volume/amount/turnover`。
   - `panels/daily_basic.parquet`：`total_mv/float_mv/total_shares/float_shares/pe/pe_ttm/pb/ps_ttm`。
   - `panels/security_status.parquet`：`industry_sw/industry_sw_code/limit_status/is_st/is_suspended`。
   - `display/unadjusted_price.parquet`：未复权 `open/high/low/close`。
4. `is_suspended` 是独立逻辑字段。优先使用 iFinD 独立停牌字段；过渡期允许从 `limit_status` 的停牌状态生成，同时保留原始 `limit_status`。
5. 字段单位和值按数据源返回结果保存，存储层不换算；缺失值原样保留，由研究员在使用阶段决定处理方式。
6. 物理文件只负责持久化分组。Provider 对外继续暴露单字段“日期 × 证券”面板；服务器内存快照继续采用 `field → ndarray[date, symbol]`，不要求内存复制磁盘布局。
7. release 发布后不可修改。更新时读取上一版本、替换选定逻辑字段、重建受影响业务域宽表、完成校验后切换 `current`。

## 备选方案

### 一个字段一个 Parquet

不再作为目标物理布局。它的单字段读取简单，但会重复保存索引和证券轴，增加文件、对齐和版本管理成本。旧文件可在迁移期由兼容读取器继续使用。

### 所有字段放进一张总宽表

不采用。研究行情、日频基本面、证券状态和 Web 展示价格具有不同职责、更新节奏与数据类型，全部合并会扩大变更和校验范围。

### 长表或数据库

当前不采用为日频回测的默认持久化方案。长表需要在回测前透视为矩阵；数据库增加部署和查询链路。多服务器共享、实时写入、复杂在线查询或高频数据成为真实需求后再评估。

## 后果

### 正面

- 常用的相关字段集中在一个有明确职责的资产中，减少文件数量和重复轴数据。
- 字段来源可逐步从 AkShare 替换为 iFinD，而对外逻辑字段和回测接口保持稳定。
- 业务域之间仍然隔离，未复权展示价格不会与研究用后复权行情混用。
- Parquet 列投影和 Provider 字段映射仍支持按需读取；服务器加载后回测只访问字段级只读内存数组。

### 负面与约束

- 读取器需要识别两级列并维护 `field → 文件及物理列` 映射，不能直接用文件名推断字段。
- 替换单个字段时需要重建其所属业务域文件，但旧 release 保持不变，失败时可直接回退。
- 同一业务宽表内允许不同字段类型，写入和读取测试必须覆盖数值、布尔与分类字段。

## 对既有决策的影响

本 ADR 更新 ADR-003 中“一个字段一个文件”的物理组织方式，但不改变 ADR-003 关于“历史数据使用本地文件并以 Parquet 为标准格式”的决定。运行时访问方式由 ADR-016 定义。
