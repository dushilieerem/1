# ADR-018：因子计算区间与收益确认区间分离

- 日期：2026-08-12
- 状态：已接受
- 关联：FEAT-002、FEAT-011、FEAT-024、ADR-016

## 问题

不同因子的预热长度不同：移动平均、动量、波动率和更长窗口的复合因子，都需要回测起点之前的历史数据。如果直接用请求的 `start` 截断行情后再计算因子，回测起点会出现人为缺失，甚至把第一批有效信号推迟到几十个交易日之后。

## 选择

1. 因子回测请求中的 `start/end` 只定义收益确认区间。
2. 因子面板使用当前数据版本中可用的完整历史计算，包含收益确认区间之前的预热数据；指数因子依赖也使用完整指数历史。
3. 因子值、收盘价、远期收益、分层分析、指标和净值在因子计算完成后裁剪到收益确认区间。
4. 命名股票池仍按收益确认区间内的首个实际交易日解析一次，之后整个区间固定该成分列表。
5. 因子回测缓存版本随该语义变更递增，避免复用按旧区间计算的结果。

## 备选方案

### 为每个因子声明 warmup_days

不采用。因子库需要额外维护预热元数据，复合因子和用户自定义因子容易漏填或声明错误。

### 自动向前扩展固定天数

不采用。固定窗口无法覆盖不同因子的需求，且会把预热规则暴露给调用方。

### 只加载 `start` 之前的历史

不采用。因子计算面板统一使用完整可用数据，简化因子契约；最终收益与指标仍严格裁剪到请求区间。

## 后果

### 正面

- 因子不需要额外声明预热区间。
- 回测起点可以直接使用滚动因子的有效值。
- 研究员提交自定义因子时遵循同一套数据契约。

### 约束

- 回测会读取和计算完整历史，单次任务的计算量可能增加。
- 结果展示和指标只代表请求区间；完整计算历史不是收益样本。
- 因子实现仍必须自行避免使用未来数据，否则会产生前视偏差。
