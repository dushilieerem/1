# SVQuant 测试设计

## 1. 测试目标与范围

验证 SVQuant 自身后端、前端、鉴权和 ResearchEngine 网关适配。ResearchEngine 的计算逻辑、服务 API 契约测试和数据校验由 RE 仓库负责；SVQuant 的集成验证不能替代 RE 侧测试。

## 2. 当前可执行检查

### Python 后端静态检查

在项目 Conda 环境中，从仓库根目录运行：

```bash
conda activate svquant
python -m compileall -q backend KnowledgeHub/backend
```

该命令检查 Python 源码可编译，不等价于单元测试或数据库集成测试。

### 前端构建

```bash
cd frontend
npm run build
```

该命令执行 TypeScript 检查和 Vite 生产构建。

### 后端 HTTP 契约冒烟脚本

脚本位于 `backend/scripts/contract/`，需要目标 SVQuant 后端正在运行，并配置专用的开发/测试账号：

```bash
conda activate svquant
cd backend
python scripts/contract/test_auth.py
python scripts/contract/test_detect.py
python scripts/contract/test_modules.py
```

默认请求 `http://127.0.0.1:8766`；可通过 `CONTRACT_BASE` 指定其他测试地址。脚本会执行登录和只读 API 检查，其中部分场景依赖测试账号及示例数据。**不得对生产环境运行。** `test_modules.py` 在 RE 因子目录不可用时允许网关返回 `502`，因此该脚本通过不代表 RE 集成可用。

## 3. Feature 验收

功能专属的验收记录保留在 [模块详细设计](../03-模块详细设计/README.md) 对应 FEAT 包中。修改跨服务契约时，应结合 SVQuant 冒烟/集成验证和 RE 仓库的契约测试进行联合验收。

## 4. 当前限制

当前仓库可发现的自动化检查以源码编译、前端构建和依赖运行环境的 HTTP 冒烟脚本为主；没有发现独立的 pytest、Vitest 或 Jest 测试套件配置。性能目标、安全测试覆盖率及 CI 门禁尚未在本文件中设定，需在有明确项目决策后补充，不能将空白视为已达标。
