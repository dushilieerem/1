## 1. 计划目的与使用方式

本计划是 SVQuant 的**总控计划**：将产品路线图、Initiative、Feature、Sprint 和团队资源统一到同一套交付视图中。

它不替代 Feature 文档包中的需求、技术设计和项目计划，也不替代每周 Sprint。使用规则如下：

- Portfolio Backlog 是 Initiative 与 Feature 状态的唯一入口。
- 本文定义跨 Feature 的目标、顺序、依赖、资源、风险和里程碑。
- `sprints/current.md` 只承诺当前周的具体任务；实际完成情况以 Release 与 Verification 为准。
- 任何新增生产功能必须先通过 Definition of Ready；本计划中的“技术验证”不等同于获准上线开发。

## 2. 产品目标与当前边界

### 2.1 产品目标

SVQuant 的阶段一目标是建立面向 A 股量化研究者的最小研究闭环：

```text
标准化行情数据
  → 因子/策略编写
  → 因子与策略回测
  → 指标、图表与结果解读
  → 可复现的研究交接
```

阶段一的核心价值是让研究员能够独立完成一次可信、可解释、可复现的因子或策略研究，而不是只完成底层引擎代码。

### 2.2 当前范围

| 范围 | 本计划处理方式 |
|------|----------------|
| 因子研究、策略研究、回测 API、结果展示 | Wave 1 主线，按 P0 推进。 |
| 因子库和因子质量体系 | Wave 1 增强项，按 P1 推进，但不得以数量牺牲质量。 |
| 事件驱动策略回测 | 已有 Feature 设计，先完成数据与沙箱技术验证，再决定进入开发。 |
| AI Agent | 本周期只完成框架选型、架构与数据 Agent POC；生产化功能须独立 Feature 准入。 |
| 模拟盘、实盘、行业新闻 | Wave 2，不纳入当前开发承诺。 |
| 用户、社区、计费、多租户 Web SaaS | Wave 3，不纳入当前开发承诺。 |

## 7. 依赖与关键路径

```text
数据可用性与字段契约
          ↓
因子/策略回测 API 契约与实现
     ┌────┴───────────┐
     ↓                ↓
六类图表与展示      因子库质量验证、手册与交接
     ↓                ↓
内部 Demo       策略部可独立使用
     └────┬───────────┘
          ↓
Wave 1 研究闭环验收
          ↓
事件策略验证 / Agent POC 的后续 Feature 准入
```

关键路径为“数据 → API → 展示/交接 → Wave 1 验收”。Agent POC 不得阻塞此路径，也不得要求修改回测主链路的业务边界。

## 9. 质量、发布与回滚要求

### 9.1 质量门槛

- 所有新增 Python 功能必须补充对应 `test_*.py` 测试。
- API 变更必须同步更新契约、样例、手册和集成测试。
- 因子库新增项必须通过注册、最小计算、唯一性、批量加载与代表性回测校验。
- 图表必须验证真实数据、空数据、短区间和错误响应四类情形。
- 内部 Demo 必须可由非开发人员按说明复现。

### 9.2 发布与回滚

- API 使用向后兼容的字段新增；不得在同一版本无提示删除已公开字段。
- 回测和 Agent POC 均保留明确的功能开关或独立入口；验证失败时可停止入口而不影响既有研究能力。
- 生产执行用户代码前必须完成隔离、资源限制和审计方案；当前仅限可信内部环境。
