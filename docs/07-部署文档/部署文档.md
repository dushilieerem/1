# SVQuant 部署文档

## 1. 部署边界

本仓库提供 SVQuant 产品前后端的本地开发启动方式。PostgreSQL 和 ResearchEngine（RE）是独立依赖，需先由各自环境部署并可访问。本仓库目前没有定义生产环境的反向代理、进程守护、容器编排、高可用或自动回滚方案；生产部署按实际运维方案执行，不应将本地启动脚本视为生产部署器。

## 2. 环境准备

- Linux Bash 环境，具备 `setsid`、`curl` 和可用的 `conda`。
- 项目 Conda 环境 `svquant` 已安装后端依赖。
- `frontend/node_modules/` 已安装 Vite 依赖。
- PostgreSQL 可访问；RE 已独立启动并可从 SVQuant 后端访问。
- `backend/.env` 已从 `backend/.env.example` 创建并配置。

首次准备环境时，在仓库根目录执行：

```bash
cp backend/.env.example backend/.env
conda activate svquant
pip install -r backend/requirements.txt
npm --prefix frontend install
```

然后按部署环境编辑 `backend/.env`。如果 Conda 环境尚未创建，应按团队 Python 环境规范先准备环境；本项目不在启动脚本中自动安装依赖。

至少确认以下配置存在且值正确：

| 配置 | 用途 |
|---|---|
| `DATABASE_URL` | SVQuant PostgreSQL 连接 |
| `JWT_SECRET_KEY` | SVQuant 登录令牌签名密钥，部署时必须设置为随机密钥；缺失或弱值会导致后端启动失败 |
| `YG_RE_BASE` | ResearchEngine 服务地址 |

`.env.example` 中的地址、默认管理员信息和密钥仅供本地示例使用；首次部署前必须检查并替换不安全的默认值。`.env`、密码、Token 和密钥不得提交到 Git 或复制到文档中。

## 3. 一键启动

在仓库根目录运行：

```bash
./scripts/svquant.sh
```

脚本启动后端 `8766` 端口和前端 `9530` 端口，最多等待 60 秒进行健康检查。前端默认访问地址为 <http://127.0.0.1:9530>，后端 API 文档为 <http://127.0.0.1:8766/docs>。脚本将进程置于独立后台会话；关闭启动终端不会向服务发送中断信号。

```bash
./scripts/svquant.sh status    # 查看服务状态
./scripts/svquant.sh logs      # 跟踪日志；Ctrl+C 只退出日志查看
./scripts/svquant.sh restart   # 重启
./scripts/svquant.sh stop      # 停止脚本启动的服务
```

可通过 `SVQUANT_CONDA_ENV` 指定 Conda 环境名（默认 `svquant`）；找不到 Conda hook 时可设置 `SVQUANT_CONDA_HOOK`。运行日志和 PID 文件写入被 Git 忽略的 `backend/output/dev-services/`。

## 4. 手动启动

```bash
conda activate svquant
cd backend
python -u api_server.py
```

另开终端启动前端：

```bash
cd frontend
npm run dev
```

启动顺序为：PostgreSQL 与 RE → SVQuant 后端 → 前端。SVQuant 不启动或管理 RE。

## 5. 健康检查与故障定位

```bash
curl http://127.0.0.1:8766/api/health
./scripts/svquant.sh status
./scripts/svquant.sh logs
```

若服务无法就绪，先检查 `backend/output/dev-services/` 中的日志，再确认 PostgreSQL、`backend/.env`、Conda 环境、前端依赖和 RE 地址。浏览器不能直接访问 RE；RE 连接问题应从 SVQuant 后端日志和 RE 服务状态两侧排查。
