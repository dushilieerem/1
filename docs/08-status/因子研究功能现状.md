## 给老板看：技术概念通俗解释

> 以下用日常业务语言解释文档中出现的技术术语，方便向老板汇报。

### 1. 什么是"因子"？

**通俗说**：因子就是**选股的依据**。

- 比如"市盈率低的股票表现更好"——"市盈率"就是一个因子
- "最近涨得多的股票还会继续涨"——"动量"就是一个因子
- "大市值公司比小市值公司稳"——"市值规模"就是一个因子

**用户是怎么用因子的？**

```
研究员心里想："低估值的股票长期能跑赢大盘"
    ↓
写成因子代码："用市盈率 PE 的倒数作为选股信号"
    ↓
系统计算：过去 3 年每一天、每只股票的 PE 值
    ↓
验证：这个因子真的有效吗？→ 跑 IC/IR/分层回测
```

### 2. 什么是"因子引擎"？

**通俗说**：因子引擎就是一个**自动化计算工厂**。

```
研究员写好因子公式
    ↓
因子引擎自动拉取所有股票的历史数据
    ↓
一次性算出每只股票每天的因子值
    ↓
交给分析模块验证因子是否有效
```

**没有因子引擎之前**：

研究员手动拉数据 → 写循环一只股票一只股票算 → 拼接结果 → 再算指标。5000 只股票 × 3 年数据，手动做要几个小时甚至几天。

**有了因子引擎之后**：

研究员写好公式 → 引擎几分钟算完 → 直接出结果。

### 3. "注册因子"是什么意思？

**通俗说**：注册因子就是**把因子配方录入系统**。

就像开餐厅：
- 大厨（研究员）发明了一个新菜品（因子）
- 把菜品的做法（因子代码）录入菜单（注册到引擎）
- 之后客人点餐时（用户调用），厨师可以直接按菜单做

**不注册会怎样？**

不注册的因子，系统不知道它的存在，没法计算、没法分析、没法回测。就像菜不在菜单上，服务员没法下单。

**代码层面（给技术参考）**：

```python
# 注册前：引擎是空的
engine = FactorEngine()
engine.factors  # {}  空字典

# 注册一个动量因子
engine.register(MomentumFactor())
engine.factors  # {"momentum": <MomentumFactor对象>}

# 现在可以计算了
engine.compute("momentum", ...)  # ✅ 能找到因子
engine.compute("nonexistent", ...)  # ❌ 报错：未注册
```

### 4. "批量计算"是什么意思？

**通俗说**：批量计算就是**一次算完所有股票的数据，不逐个循环**。

**逐个计算（慢）**：
```
for 每只股票:          ← 循环 5000 次
    for 每一天:        ← 循环 750 次
        算这个因子     ← 算 375 万次
```

**批量计算（快）**：
```
把所有股票所有天的数据拼成一个大表格
    ↓
一次矩阵运算出结果    ← 算 1 次
```

**给老板的数据**：

| 方式 | 5000 只 × 3 年 | 代码量 |
|------|---------------|--------|
| 逐个循环 | 几十分钟到几小时 | 多（要写循环） |
| 批量计算（我们的方案） | 几秒钟到几分钟 | 少（写公式即可） |

这个就叫"面板计算"——把 5000 只股票 × 750 天的数据当作一个"面板"（大表格），一次算完，不用逐个循环。

### 5. "IC"和"IR"是什么？

**通俗说**：用来衡量**因子预测能力**的指标。

- **IC**（信息系数）：因子值和未来收益的相关性。**IC 越高，说明因子预测能力越强**。
  - IC = 0.1：有一定预测能力
  - IC = 0：纯随机，没有预测能力
  - IC < 0：反向指标

- **IR**（信息比率）：IC 的稳定性。**IR 越高，说明因子预测能力越稳定**。
  - IR = 0.5：一般
  - IR = 1.0：不错
  - IR = 2.0+：非常优秀

**举个例子**：

> IC 就像猜股票涨跌的准确率，IR 就像这个准确率有多稳定。
>
> 一个因子 IC = 0.08，IR = 1.5，意味着"这个因子长期有效，而且比较稳定，不是碰运气"。

### 6. "分层回测"是什么？

**通俗说**：把股票按因子值从高到低分成 N 组，看**最高组和最低组的收益差距**。

```
全市场 5000 只股票，按因子值排序：
┌──────────────────────────────────────┐
│  第 1 组（因子值最高 20% 的股票）    │  ← 收益 15%
│  第 2 组                              │  ← 收益 10%
│  第 3 组                              │  ← 收益 8%
│  第 4 组                              │  ← 收益 5%
│  第 5 组（因子值最低 20% 的股票）    │  ← 收益 2%
└──────────────────────────────────────┘

如果第 1 组到第 5 组收益单调递减 → 因子有效
如果各组收益杂乱无章 → 因子无效
```

### 7. "FF3 三因子归因"是什么？

**通俗说**：把策略的收益拆解到**市场贡献了多少、市值贡献了多少、估值贡献了多少**，看策略到底是真有本事，还是只是碰上了市场行情。

```
策略收益 20%
    ↓ 拆解
市场贡献：+12%    ← 大盘涨了，被动收益
市值贡献：+5%     ← 买了小盘股，小盘行情好
估值贡献：+2%     ← 买了低估值股票
超额收益：+1%     ← 真正的选股能力
```

### 8. "分行业 IC/IR"是什么？

**通俗说**：同一个因子，在**不同行业的表现可能完全不一样**。

| 行业 | IC | 说明 |
|------|----|------|
| 银行 | 0.12 | 动量因子在银行板块有效 |
| 医药 | -0.03 | 动量因子在医药板块无效 |
| 科技 | 0.08 | 动量因子在科技板块一般 |

**意义**：研究员不会盲目在所有行业用同一个因子，而是分行业调权重。

## 2. 已实现功能（✅ 完整交付）

### 2.1 因子表达式引擎

| 组件 | 位置 | 说明 |
|------|------|------|
| `FactorEngine` | `QuantCore/quantcore/factor/engine.py` | 面板因子计算引擎，支持注册和批量计算 |
| `BaseFactor` | `QuantCore/quantcore/factor/base.py` | 因子基类，定义 compute 契约 |
| `ComputeBackend` | `QuantCore/quantcore/factor/backend.py` | 计算后端抽象（python/numba） |
| `Panel` | `QuantCore/quantcore/factor/base.py` | 面板数据结构，按字段访问 |

**能力**：注册因子 → 通过 DataEngine 获取面板数据 → 一次向量化计算因子值 → 返回日期×标的宽表。

**关键设计**：
- Panel 模式：所有字段一次性取回，多个因子共享同一面板，避免重复 I/O
- 后端可插拔：通过 `ComputeBackend` 切换计算后端（当前支持 python，可扩展 numba）
