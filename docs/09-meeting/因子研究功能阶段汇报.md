# 老板汇报：因子研究功能阶段总结

> 本文档用于向老板汇报 SVQuant 因子研究功能的当前进展、竞品对标和下一步计划。
> 汇报日期：2026-07-15

---

## 一、我们现在做了什么

### 已完成的因子研究功能

我们已经在平台上构建了完整的因子研究链路，从数据到分析到可视化：

```
行情数据 → 因子计算 → 因子分析 → 可视化报告
```

**具体能力：**

| 能力 | 通俗说明 | 对用户的价值 |
|------|---------|------------|
| **因子表达式引擎** | 用户写一个公式（如"今日收盘价/20日均价"），系统自动算出所有股票每一天的值 | 几分钟完成过去 3 年、5000 只股票的因子计算 |
| **101 个内置因子** | WorldQuant 经典的 101 个技术因子，开箱即用 | 研究员不用从零开始写因子 |
| **IC/IR 分析** | 判断一个因子有没有预测能力 | 知道哪个因子好用，哪个是噪音 |
| **分层回测** | 把股票按因子值分成 5 组，看最高组和最低组的收益差距 | 直观看到因子的区分能力 |
| **多空组合** | 买入最高组、卖空最低组的收益 | 衡量因子的绝对选股能力 |
| **三因子归因** | 把收益拆解到市场/市值/估值三个因素 | 知道因子赚的是 alpha 还是 beta |
| **分行业 IC/IR** | 同一个因子在不同行业的表现 | 因子在银行有效，在医药不一定有效 |
| **6 种可视化图表** | IC 时序图、分层净值图、多空净值图、行业 IC 图、归因图等 | 不用自己画图，直接出报告 |

### 这些功能覆盖了什么场景

```
场景：研究员想验证"低市盈率（PE）因子在 A 股是否有效"

Step 1: 从因子库选择或编写 PE 因子表达式
Step 2: 系统算出过去 3 年每只股票的 PE 值
Step 3: 自动计算 IC = 0.06（有一定预测能力）
Step 4: 分层回测显示第 1 组（最低 PE）年化收益 12%，第 5 组（最高 PE）年化 5%
Step 5: 分行业看——PE 在银行板块 IC = 0.12，在科技板块 IC = -0.02
Step 6: 三因子归因显示 PE 因子贡献了 3% 的超额收益

结论：PE 因子在 A 股有效，尤其在银行板块，但在科技板块无效。
```

## 三、下一步应该做什么

### 短期（1-2 周）：补齐因子预处理

这三步是所有因子分析的前提，不做的话结果可能不准：

```
原始因子值
    ↓
① 去极值：剔除极端值（如某只股票一天涨 1000%）
    ↓
② 行业市值中性化：去除行业和市值大小的干扰
    ↓
③ Z-score 标准化：不同因子在同一尺度上比较
    ↓
清洗后的因子值 → IC/IR/分层 → 准确的结果
```

**为什么必须做？** 没有去极值，一个极端值就能拉偏整个 IC 结果。没有中性化，因子选股可能只是选到了某个行业。这是行业标准，不是可选的。

### 中期（3-4 周）：AI 策略生成

**核心差异化功能**——聚宽和米筐没有的能力。

```
研究员说："帮我写一个低估值高股息策略"
    ↓
AI 理解需求 → 生成因子代码 → 自动预处理 → 回测 → 输出结果
    ↓
研究员直接看到策略表现，不需要自己写代码
```

### 长期（5-8 周）：行业与政策分析

**独家差异化能力**——所有竞品都没有。

```
AI 自动追踪行业景气度、政策变化
    ↓
研究员问："新能源板块最近怎么样？有什么政策风险？"
    ↓
AI 综合分析行业数据 + 政策动态 → 给出答案
```

## 四、关于验证方式

### 老板可能的疑问

> "聚宽算出来这个因子 IC = 0.08，我们算出来是多少？能不能跑一下聚宽的因子，看我们的结果对不对？"

### 你的逻辑是对的

```
回测 → 模拟盘 → 实盘
            ↓
    实盘是唯一检验标准
            ↓
    谁的引擎越接近实盘，谁就越准
```

如果聚宽的回测结果跟实盘接近，我们的结果跟聚宽差很远，那说明我们的引擎有问题，不能说"数据源不同所以对不上"就完了。

### 那为什么还是不跟聚宽直接对数字？

**核心原因不是"数据源不同"，而是"不知道对方的内部处理规则"。**

| 真正导致差异的因素 | 影响程度 | 说明 |
|------------------|---------|------|
| **收盘价差异**（Wind vs 聚源） | 极小 | A 股日线收盘价差异通常在万分之几，对回测几乎无影响 |
| **停牌股处理方式** | ⚠️ 大 | 停牌期间因子值=NaN 还是前填充？聚宽的做法我们不知道 |
| **新股/退市处理** | ⚠️ 中 | 上市首日是否剔除？退市整理期是否包含？规则不透明 |
| **ST 股处理** | ⚠️ 中 | 是否包含 ST 股？涨跌停限制不同（5% vs 10%） |
| **复权方式** | ⚠️ 大 | 前复权 vs 后复权？基准日是哪天？不同选择导致历史价格不同 |
| **因子预处理参数** | ⚠️ 中 | 去极值用几倍 MAD？行业中性化用几级行业？参数不透明 |

**关键差异不在数据源，而在数据处理规则上。**

### 一个具体例子

假设我们要跟聚宽对"PE 因子的 IC"：

```
收盘价差异（万分之几）→ PE 值差异极小
    ↓
但如果聚宽对停牌股做了前填充，而我们用了 NaN
    ↓
IC 计算时，聚宽包含了停牌股，我们排除了
    ↓
结果：IC = 0.063 vs IC = 0.058

两个结果都对，但不一致。
```

**不是数据源的问题，是规则不透明的问题。**

### 那怎么保证我们的引擎是正确的？

**三层验证，层层递进：**

```
第一层：单元测试（构造已知数据，手算验证）
  ├── 构造 5 只股票、10 天数据
  ├── 手算 IC、分层收益
  └── 引擎输出必须等于手算结果
  → 验证：计算逻辑 100% 正确

第二层：合理性验证（用市场常识判断）
  ├── 用 Wind 数据跑经典因子（动量、反转、低波）
  ├── IC 正负号是否符合市场常识？（动量因子 IC > 0？）
  ├── 分层是否单调？（第 1 层收益 > 第 2 层 > ...？）
  └── 结果是否在合理范围内？
  → 验证：引擎输出符合预期

第三层：回归测试（改代码不破坏结果）
  └── 每次修改后，跑同一组数据
      → 结果必须和修改前一致
  → 验证：没有引入 bug
```

### 跟老板总结

> **您说得对，回测是为实盘服务的。我们的引擎如果跟实盘差得远，那就是我们的问题。**
>
> 我们不跟聚宽对数字，不是因为"对不上就算了"，而是因为不知道聚宽内部的数据处理规则（停牌怎么处理、复权怎么处理、新股怎么处理）。跟他们对上了是巧合，对不上也没法 debug。
>
> **我们自己做两件事来保证引擎准确：**
> 1. **构造已知数据手算测试** → 验证计算逻辑 100% 正确
> 2. **用市场常识验证结果合理性** → IC 正负号、分层单调性符合预期
>
> 这两件事做好，引擎就不会跟实盘差太多。
