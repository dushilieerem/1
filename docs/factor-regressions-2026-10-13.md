# 因子测试四项 Fail 修复

对应《测试报告-因子与因子库》的 FT-007、FT-011、FT-012、FT-013。

| 用例 | 修复行为 | 部署后复测 |
| --- | --- | --- |
| FT-007 | 用户因子增加编辑入口，可保存名称、说明和代码；检测页保存同时保存编辑源码，单个用户因子同步写回库 | 将测试因子改名、改说明，公式由 `pct_change(5)` 改为 `(10)`；保存、刷新、重新打开检测应保持修改；取消编辑不改变原记录 |
| FT-011 | 明确清空代码不会回退到旧公式，页面和提交接口阻止空代码 | 清空编辑器后检测，应提示代码不能为空，无新任务/报告；空白和纯注释也不能执行 |
| FT-012 | 自定义因子提交前加入返回值检查，在计算服务执行到入口返回时，拒绝全空/全无穷因子矩阵；历史配置按当次请求还原源码 | 用 `pct_change(100000)` 检测，应出现无有效数值/历史行情不足提示，不生成成功报告；`pct_change(5)` 正常；合法零值不误判 |
| FT-013 | 历史重跑优先使用当次 `factor_code` 与库依赖，不从已删除因子拼接自调用；没有可执行快照的旧记录明确阻止 | 先成功检测，删除因子，再打开历史配置并运行；应还原原公式。无源码旧记录应提示重新添加，不得 RecursionError |

## 本地验证

前端（`frontend/`）：

```sh
node --import tsx --test tests/factorRegressions.test.tsx tests/backtestFilters.test.tsx
npm run build
```

后端（`backend/`，svquant 环境）：

```sh
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -p "test_factor_*.py" -v
```

页面回归使用真实 React/CodeMirror 组件和模拟接口；后端用合成 pandas 行情验证实际计算返回值，数据库权限/重复名与代理请求使用 mock，不写线上数据。

## 验收边界

- 本次修复包含前端和 SVQuant 后端，需同时部署；计算服务仓库不在本项目中。FT-012 的检查代码由后端加入自定义因子入口，须部署后复核与当前计算服务的兼容性。
- 有效数值检查针对实际返回矩阵全空/全无穷，不能替代所有行情缺失、覆盖率或统计显著性的完整检测；不会以零收益判断数据无效。
- 改名不重写历史报告，也不自动替换其他组合中旧名称的依赖；这些组合需重新选取因子，有历史源码的记录仍按原快照运行。
- 不修改上证50选项，不增加历史报告保留天数。不将线上原始 Fail 记录提前改成 Pass；合并由 mentor 审批并手动部署后再验收。
