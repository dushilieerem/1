## 1. 结论先说

六个维度各有一个独立 Agent，但 **六个 Agent 拿到的是同一份数据 payload**（`_agent_payload` 对六个 key 返回同一结构），差异只在：

- 各自的 system prompt；
- `business_model`、`governance` 两个维度额外带一条输入说明；
- AI 不可用时的规则兜底模板按维度取不同数据。

也就是说，当前实现是「同一份数据 + 六套提示词」，不是「每个维度单独裁剪数据」。如果要让每个维度只喂相关数据，需要修改 `_agent_payload`。

## 2. 六个 Agent 共用的数据

`_build_research` 组装 facts（`inst_service.py:589`、`:780`），`_agent_payload` 再裁剪为发给模型的 JSON（`:853`）。

| 数据块 | 来源表 / 计算 | 关键字段 |
|---|---|---|
| company | `inst_company` | `symbol / name / market / industry / data_status / ref_price` |
| price / as_of | `md_daily_bar`（未复权，缺失回退后复权） | `close / trade_date` |
| valuation | `md_valuation_daily` 最新一行 | `pe_ttm / pb_mrq / pcf_ocf_ttm / dividend_yield_ttm / float_mv / total_mv / total_shares` |
| percentile | 用 `md_valuation_daily` 近 3 年同日频序列计算 | `pe_percentile / pb_percentile` |
| risk | `md_daily_bar`（后复权）近 252 日 + `md_index_bar`（A 股用 `000300.SH`） | `annual_vol / max_drawdown / beta` |
| industry | `ref_security_industry`（`level=1`） | `industry_code / effective_from / effective_to` |
| financials | `fin_income_statement` + `fin_balance_sheet` + `fin_cash_flow` + `fin_indicator` 按 `report_date` 合并，只取已公告，最近 8 期 | 营收/净利/营业利润/毛利、总资产/负债/权益/现金/存货/应收、经营/投资/筹资现金流/FCF/capex、ROE/毛利率/净利率/同比 |
| data_gaps | 规则判断（无财务数据时为「财务三表未接入或未公告」） | `string[]` |

`_agent_payload` 实际发给模型的结构：

```json
{
  "company": {
    "symbol": "...",
    "name": "...",
    "market": "CN",
    "industry": "...",
    "data_status": "real|partial|missing",
    "ref_price": 0
  },
  "as_of": "YYYY-MM-DD",
  "market_data": {
    "price": 0,
    "pe_ttm": 0,
    "pb_mrq": 0,
    "pe_percentile": 0,
    "pb_percentile": 0,
    "max_drawdown": 0,
    "annual_vol": 0,
    "total_mv": 0,
    "float_mv": 0,
    "total_shares": 0
  },
  "industry": {
    "industry_code": "...",
    "effective_from": "YYYY-MM-DD",
    "effective_to": null
  },
  "financials": ["最近 8 期，按 report_date 合并"],
  "data_gaps": ["..."]
}
```

按维度额外追加的字段：

| 维度 | 追加字段 | 内容 |
|---|---|---|
| `governance` | `governance_note` | 输入不含公告正文、管理层履历或关联交易明细，必须据此列 `data_gaps` |
| `business_model` | `business_model_note` | 输入没有分部收入、客户集中度和渠道数据，只能从财务结构推断并标注缺口 |

其余四个维度没有额外字段。

## 3. 六个维度的 TaskSpec

定义在 `backend/ai/router/tasks/institution.py:223`，六个任务共用同一组参数（`:233` 注册）。

| 维度 | Task ID | 说明 |
|---|---|---|
| 商业与产业 | `inst.dim.industry` | 行业与产业 Agent：规模、竞争结构、供需与周期 |
| 公司商业模式 | `inst.dim.business_model` | 商业模式 Agent：收入结构、客户价值、单位经济性 |
| 护城河 | `inst.dim.moat` | 护城河 Agent：品牌、成本、网络、转换成本与侵蚀路径 |
| 财务质量 | `inst.dim.financial` | 财务质量 Agent：三表勾稽、ROIC/FCF、会计风险 |
| CEO 与治理 | `inst.dim.governance` | 治理 Agent：资本配置、承诺兑现、关联交易 |
| 估值与价格 | `inst.dim.valuation` | 估值 Agent：PE/PB 分位、DCF 假设、安全边际 |

共同参数：

- `temperature=0.2`
- `max_tokens=4096`
- `timeout_sec=120`
- `executors=("local",)`
- `response_format={"type": "json_object"}`
- `validator=validate_dimension`（`institution.py:68`）

`validate_dimension` 的校验：

- `summary` 必须非空；
- `checks / counter / open_questions / data_gaps` 统一转为字符串数组；
- `evidence` 只保留同时有 `title` 与 `quote` 的条目；
- `confidence` 截断到 0–1，缺失时默认 0.5。

## 4. 六个维度的系统提示词

> 2026-11-04：提示词已升级到 `inst-dim-v2`，补充数据纪律、分析框架、结论先行与证伪要求。完整提示词以 `backend/services/institution/inst_service.py` 的 `_DIMENSION_PROMPTS` 为准；本节以下短提示词仅保留历史对照，不再作为运行配置。

在 `backend/services/institution/inst_service.py:819`，每条提示词末尾都会拼接统一的 `_DIM_OUTPUT`（`:810`）。

### 4.1 商业与产业

```text
你是旸谷资本机构研究部的产业研究 Agent，服务巴菲特式价值投资。
只依据输入的公司、行情、行业与财务数据，分析行业规模、竞争结构、供需与周期、产业链位置与行业吸引力。
没有行业规模/份额数据时必须列入 data_gaps，不得编造。
```

### 4.2 公司商业模式

```text
你是旸谷资本机构研究部的商业模式 Agent，服务巴菲特式价值投资。
只依据输入数据分析：公司靠什么赚钱、客户价值、收入结构、单位经济性、资本强度与可复制性。
没有分部收入、客户集中度、渠道数据时只能做财务结构推断，并在 data_gaps 明确标注。
```

### 4.3 护城河

```text
你是旸谷资本机构研究部的护城河 Agent，服务巴菲特式价值投资。
只依据输入数据分析品牌、成本优势、网络效应、转换成本、规模与可持续性；
毛利率、ROE、增速只是线索，不等于护城河；必须给出可检验的护城河证据、侵蚀路径与反证条件。
```

### 4.4 财务质量

```text
你是旸谷资本机构研究部的财务质量 Agent，服务巴菲特式价值投资。
只依据输入财务数据分析三表勾稽、ROE/ROIC、自由现金流、应收存货、资本化与会计风险；
指出利润与现金流是否互相印证，以及需要回原始公告核验的项目。
```

### 4.5 CEO 与治理

```text
你是旸谷资本机构研究部的 CEO 与治理 Agent，服务巴菲特式价值投资。
只依据输入数据分析资本配置、承诺兑现、关联交易、分红回购与治理结构；
输入若没有公告、管理层履历或治理数据，必须把缺口写入 data_gaps，禁止编造人名、履历或违规事实。
```

### 4.6 估值与价格

```text
你是旸谷资本机构研究部的估值与价格 Agent，服务巴菲特式价值投资。
只依据输入数据分析 PE/PB 分位、DCF 假设与局限、安全边际与估值风险；
不给目标价或买卖点，必须说明估值口径、数据缺口与哪些假设会推翻结论。
```

### 4.7 六维统一输出契约（`_DIM_OUTPUT`）

```text
只输出 JSON，不要 markdown：{"summary":"...","checks":["..."],"counter":["..."],
"evidence":[{"title":"...","quote":"...","source":"..."}],"open_questions":["..."],
"confidence":0.6,"data_gaps":["..."]}。
结论先行，summary 前 200 字直接给判断；每个判断给数字、区间或明确方向；
区分【事实】【推断】【不知道】；数据不足写“在补到 X 之前，我的判断是 Y，置信度低”；
禁止编造数字、人名、公告或事实；禁止“建议进一步研究/有待观察”这类空话；
summary≤200字，checks≤5条，counter≤3条，evidence≤5条，open_questions≤3条，data_gaps≤5条，
总输出不超过1800字；不给买卖点、目标价、涨跌预测或收益承诺；不改变业务状态。
```

### 4.8 CIO 一页纸输出契约（`inst.research_memo`）

```text
{"summary":"...","decision":"proceed|watch|avoid",
 "six_dim_scores":[{"key":"industry","score":1-5,"confidence":0-1,"note":"..."}],
 "conflicts":["..."],"key_variables":["..."],"evidence":["..."],
 "risks":["..."],"open_questions":["..."]}
```

- `decision` 是研究建议（推进辩论/观察/回避），不是买卖指令；非法值回落为 `watch`。
- `six_dim_scores` 只接受六个合法维度，分值必须在 1-5；非法项丢弃。
- 规则兜底（AI 不可用）返回 `decision=watch`，不伪造评分、矛盾和关键变量。

## 5. 规则兜底时按维度使用的数据

AI 不可用或三次重试失败时，`_merge_agent_results`（`inst_service.py:981`）回退到 `_build_research` 里按维度生成的确定性模板。

| 维度 | 规则模板主要用到的数据 |
|---|---|
| 商业与产业 | `ref_security_industry` 行业代码、公司行业名、参考价 |
| 公司商业模式 | 营收、净利、毛利率、净利率、营收同比、净利同比、自由现金流 |
| 护城河 | 毛利率；无毛利数据则标记 partial |
| 财务质量 | 营收、净利、经营现金流、ROE、净利率、自由现金流 |
| CEO 与治理 | 只有核验框架（治理结构/关联交易/分红回购均写「待补充」），不落事实 |
| 估值与价格 | PE_TTM、PB_MRQ、3 年分位、参考价、近一年最大回撤 |

规则兜底的维度会标记 `engine=rule`，并写入 `agent_error`；其余维度不受影响。

## 6. 编排方式

`_run_dimension_agents`（`inst_service.py:934`）：

- 默认 6 个 Agent 并发，`INST_AGENT_CONCURRENCY` 可调；
- 每个维度独立重试 3 次，间隔 1.2s / 2.4s；
- 单维失败只影响该维，回退规则模板；
- 每维完成后写 `inst_research_task` 进度，前端每 2 秒轮询；
- 六维完成后生成 AI 一页纸（`POST /api/inst/cases/{id}/ai/memo`）。

## 8. 当前限制

- 六个 Agent 的数据 payload 完全相同，只有提示词不同；如果希望「产业只看行业、财务只看三表」，需要按 `key` 裁剪 `_agent_payload`。
- `governance` 维度目前没有公告正文、管理层履历、关联交易明细数据，因此只能给核验框架，不能给事实判断。
- 美股/港股缺少基本面与公告数据，相关维度会大量落入 `data_gaps` / 「待补充」。
- `evidence` 由模型返回后再落 `inst_evidence`，按 `hash` 去重；无证据的论点不参与后续裁决。
