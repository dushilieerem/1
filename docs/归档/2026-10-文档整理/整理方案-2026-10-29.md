## 1. 结论

当前 docs 不是「没有规则」，而是**一次目录迁移做了一半**：

- 目标结构其实已经写在 [`docs/README.md`](../../README.md) 里：以非编号目录（`需求文档/`、`架构文档/`、`模块详细设计/`…）作为当前版本。
- 但实际内容被移动回了 `01-需求文档` 至 `08-使用文档`，并在里面多套了一层 `*新/`。
- 结果：非编号当前目录全部不存在，旧编号目录里同时混着「当前版」「旧版」「带新后缀的当前版」。

建议**按 README 已声明的目标收敛**，而不是再发明第三套结构。

## 3. 整理原则

1. **一个主题只有一个当前版本**：当前版放非编号目录；旧版进 `99-历史归档/`，不删除。
2. **编号只保留给“横切/流程”目录**：`00-文档治理`、`09-技术决策`、`10-项目管理`、`99-历史归档`。
3. **01–08 不再作为当前文档入口**：其中的有效内容迁出后，空壳归档。
4. **文件名不出现「新」「最终」「v2」**：版本信息写在文档头或 Git 历史里。
5. **移动必须同时修链接**：每次移动后跑相对链接检查，目标为 0 条死链。
6. **FEAT 功能包保留**：它们是可复用的交付单元，不按旧文档处理，统一放到 `模块详细设计/FEAT-*`。

## 8. README 重构建议

`docs/README.md` 改为「唯一入口」，不再维护两套路径。建议结构：

1. **快速入口**：PRD、机构端 PRD、系统架构、模块设计、数据库、API、测试设计、部署、使用说明。
2. **按角色阅读**：
   - 产品/需求：需求文档 → 机构端 PRD → 项目倡议
   - 研发：架构文档 → 模块设计 → 数据库/API → FEAT

3. **文档地图**：00 治理、09 ADR、10 项目管理、99 历史归档。
4. **维护规则**：
   - 当前版只写非编号目录；
   - 旧版进 `99-历史归档/YYYY-MM-主题/`；
   - 文件名不带「新/最终/v2」；
   - 移动文档必须同步修链接并跑链接检查。

同时在 `00-文档治理/README.md` 中把「01 至 08」改为新的目录名，避免规则与实际结构再次脱节。
