## 1. 结论先行

1. **行情、估值、状态、指数、交易日历以 parquet 为权威只读源**，不把全量历史重复搬进 PG；
   PG 只建「服务层」近期窗口（默认 2016-01-19 起）与检索维度，历史深查回退 parquet。
2. **财务三表、分红、回购、股本、公告、新闻** parquet 没有，走公开源采集入 PG；
   每行必须带 `source`、`as_of`、`notice_date`（财务）、`raw_hash`，禁止无来源覆盖。
3. **一致预期历史、集合竞价五档**免费源无解，首版不承诺；用替代口径并在页面显式标注。
4. **手机端当前 SQLite 与主站 PG 隔离**；建议保留 `invest-api` 作为 BFF，存储切到 PG，
   账号复用主站 `users`，不再维护第二套账号。
5. **机构端当前只有 `inst_orgs` / `inst_members`**；研究、证据、辩论、议案、审批、授权、
   模拟执行、投后全部新建，首版按「一条闭环」建表，不按 112 条 FR 全量铺开。

## 5. PG 分层

```text
ref_*      主数据：证券、日历、行业、指数、成分
md_*       行情服务层：A 股/指数日线、估值、状态、风险指标
fin_*      财务与公司行动：三表、指标、分红、回购、股本
doc_*      文档与证据：来源、条目、证据引用
inst_*     机构业务：公司池、研究、辩论、议案、审批、授权、执行、投后
invest_*   手机业务：自选、事件、组合、风测、审计
ingest_*   采集元数据：运行、水位、质量检查
复用        users、app_audit_logs、kh_*（全文/附件）
```

**边界**：
- parquet 权威、PG 服务层可重建；任何 `md_*` 表都能由 parquet + 采集任务重放。
- 业务表只存业务事实，不存 parquet 的宽表副本。
- 全文检索/附件继续用 KnowledgeHub，`doc_item` 只存结构化元数据与摘要。

| `sync_ref_index` | 每周/调样日 | parquet + BaoStock/AKShare | `ref_index`、`ref_index_member` | (`index_code`,`symbol`,`effective_from`) |
| `fetch_fin_statements` | 每季度 + 每日补漏 | AKShare 东财 | `fin_*` | (`symbol`,`report_date`,`statement_type`,`source`) |
| `fetch_corporate_actions` | 每日 | AKShare | `fin_dividend`、`fin_buyback`、`fin_share_capital` | (`symbol`,`announce_date`,…) |
| `fetch_docs` | 每日 | 东财/巨潮 | `doc_item` | (`source`,`content_hash`) |
| `compute_risk` | 每日 | `md_daily_bar` + 指数 | `md_risk_daily` | (`symbol`,`trade_date`,`calc_version`) |

**质量门禁**（不过则任务失败并告警，不静默写入）：
- 主键唯一、日期连续（对照 `ref_trading_calendar`）、行数环比波动 < 20%；
- 关键字段空值率阈值（收盘价 < 1%、财务科目 < 30%）；
- 跨源重叠期抽样一致率 ≥ 99%（iFinD vs BaoStock）；
- 数据新鲜度：A 股 EOD 在交易日 18:30 前就绪，否则 `is_stale=true`；
- 财务 `notice_date` 为空的行标记 `point_in_time_ok=false`，不进入点时回测。

## 8. 关键口径

1. **点时原则**：财务用 `notice_date`；行业归属用 `effective_from`；指数成分用 `effective_from`；
   公告/研报用 `publish_at`。禁止用 `report_date` 代替公告日。
2. **复权**：收益/回测用后复权 `hfq`；展示价、涨跌停、成交价用未复权；同一计算不得混用。
3. **市值**：现有 `date_sequence.ths_current_mv_stock` 是**流通市值**；总市值需由总股本 × 未复权价派生。
4. **来源优先级**：iFinD parquet > BaoStock > AKShare；字段级冲突记录到 `ingest_field_provenance`，
   不静默覆盖，服务层按优先级取。
5. **演示/真实**：所有响应带 `data_date`、`source`、`is_demo`；演示数据不得进入机构审批/授权链。
6. **合规**：公开源仅内部研究与演示；不对外再分发；页面保留来源与延迟口径。

### 11.3 手机端形态

保留 `invest-api`（独立 FastAPI + SQLite）作为移动端 BFF：

- **PG 是汇总层**：行情/估值/财务/公告先入 PG；`sync_invest_sqlite.py` 再把服务层写入 SQLite。
- **SQLite 是可重建读取缓存**：用户数据（自选/组合/风测/事件/审计）不被同步覆盖；缓存可由 PG 随时重建。
- **账号复用主站**：`/api/auth/login` 仍可代理 SVQuant；`users` 是唯一账号源。
- **AI**：`invest-api/ai_endpoints.py` 复用 `backend/ai/router` 的 TaskSpec；无 Key 时返回 503，不用 mock 伪装。

选择该形态而不是把 `invest-api` 直接改成 PG 的原因：移动端现有 `rules.py` 是 35KB 的 SQLite 读模型，直接改 PG 需要重写全部查询且回归面大；缓存同步能在不破坏现有页面的前提下先拿到全市场真实数据。后续可在读模型稳定后把 `rules.py` 迁到 PG repository。
