# 主观机构端六维分析 · 第二批数据需求

> 提出方：主观机构端（/inst）
> 日期：2026-11-06
> 用途：把六维 Agent 从“用财务结果反推”升级为“有行业、经营、治理与预期数据可核验”。
> 第一批（已完成）：10 年财务、同业财务中位数、同业估值、净债务近似、股息/股本；部分数据闸门已生效。

## 0.1 数据业务评估结论（2026-11-06）

数据业务按可行性分三层，已确认按以下顺序执行：

| 层级 | 内容 | 周期 | 说明 |
|---|---|---|---|
| A 组 | `segment_revenue`、`holder_top10`、`holder_float_top10`、`audit_opinion`、`interest_debt`、合同负债/预收款、分红回购、PS/股息率序列 | 2–3 天 + 三只样例 | 免费结构化源，先发 schema/DDL，再发 600519/000858/300750 样例，最后全市场 |
| B 组 | 前五大客户、应收账龄、存货构成、在建工程、受限资金、非经常性损益、KAM、问询函；关联交易/担保/处罚/承诺/高管/董事会 | 2–3 周起 | 需公告索引 + PDF 解析 + 抽样校验；先三只试点，准确率达标再扩 |
| C 组 | 行业 TAM/CR3/CR5/份额、行业价格/产量/库存/产能、政策量化、海外对标、留存/CAC/LTV | 待采购/研究决策 | 无统一免费源；不阻塞 A/B |

交付约定：
- 消费端默认 PostgreSQL；数据业务提供冻结 DDL（schema `svquant`，表名 snake_case）+ loader，负载凭据由运维注入 `SVQUANT_PG_DSN`，不写入仓库或日志。
- `holder_top10.ratio` 只是报告期前十大合计，不含一致行动人认定；消费端不得当作控制权集中度，也不单独作为治理 gate 通过依据。
- `available_time`：有 NOTICE_DATE 用 NOTICE_DATE；无则用法定披露截止日（年报次年 4/30、Q1 4/30、H1 8/31、Q3 10/31）。
- 一致预期当前只有快照，标 partial，不当作历史序列。

## 0. 为什么需要这批数据

当前六维 Agent 实际只有：公司基本信息、行情/PE/PB、申万行业代码、10 年合并三表、同业财务中位数、近似净债务。缺少：
- 行业规模/份额/价格/产能/政策 → 产业分析只能从公司财务反推，系统性偏乐观；
- 分部/客户/量价/成本 → 商业模式回答不了“增长来自量、价还是结构”；
- 份额/留存/专利 → 护城河只能拿毛利率做循环论证；
- 附注/审计/问询/母公司报表 → 财务质量无法判断造假；
- 股东/质押/关联交易/高管 → 治理维度没有事实，只能写“待补充”；
- 一致预期/PS/EV-EBITDA/完整净债务 → 估值只能回答“相对自己贵不贵”，回答不了“值多少钱”。

目标：让每个维度至少能给出“有数据、有来源、有证伪条件”的结论；数据不足时明确降级，而不是让模型编。

## 1. 通用交付要求（所有表）


| 要求 | 说明 |
|---|---|
| 主键/粒度 | 每张表必须能按 `symbol`（或 `industry_code`）+ `period/report_date` 唯一定位；同一报告期多来源需保留 `source` 维度。 |
| PIT（时点） | 必须提供 `announce_date` 与 `available_time`；查询只允许使用 `available_time <= as_of` 的记录，禁止未来数据。 |
| 证据链 | 每条记录带 `source`、`document_id`、`page_ref`、`source_uri`（可空但要说明），能回链原文。 |
| 单位/口径 | 每个数值带 `unit`、`caliber`（合并/母公司、含税/不含税、总额/净额、复权/未复权、全球/中国）。 |
| 空值语义 | 缺失用 NULL，不得用 0 代替；0 是真实值时必须能区分。 |
| 覆盖与回填 | P0 字段先覆盖 A 股演示池与主要宽基成分；财务/治理至少回填 10 年，行业/估值至少 5 年。 |
| 更新频率 | 行情/估值日频；财务/股东/治理按公告；行业月度/季度；一致预期周频。 |
| 对账 | 分部收入合计 = 合并营收（±1%）；TAM ≥ SAM ≥ SOM；CR3 ≤ CR5；前五大客户占比 0–100%；股东持股合计 ≤ 100%。 |
| 交付形式 | 优先 PostgreSQL 表（附 DDL）；或 parquet + 明确 loader；接口需支持按 symbol/行业/日期增量拉取。 |

## 2. 产业分析（P0）

### 2.1 行业规模与增速
表建议：`ref_industry_size`

| 字段 | 类型 | 说明 |
|---|---|---|
| industry_code | text | 申万 L1/L2 代码 |
| period | date | 年度/季度 |
| tam / sam / som | numeric | 三档规模 |
| unit | text | 亿元/万台/吨等 |
| caliber | text | 全球/中国、出货量/销售额、含税/不含税 |
| cagr_3y_bear/base/bull | numeric | 未来 3 年增速三情景 |
| source / document_id / page_ref | text | 来源与页码 |
| available_time | timestamptz | PIT |

验收：至少覆盖申万 L1 全行业；每个行业最近 5 年、未来 3 年；TAM/SAM/SOM 关系成立；同一行业多来源冲突并列保留，不平均。

### 2.2 竞争格局与份额
表建议：`ref_industry_competition`

| 字段 | 说明 |
|---|---|
| industry_code, period | 行业与期间 |
| cr3, cr5 | 集中度（0–1 或 %，注明） |
| player_name, player_symbol, share | 主要玩家份额；player_symbol 可空 |
| share_source | 第三方/协会/公司公告 |
| trend | rising/stable/falling（可选，由数据计算） |

验收：CR3/CR5 与玩家份额可复算；玩家份额合计不超过 100%；跨年序列可追溯。

### 2.3 行业经营指标
表建议：`ref_industry_operating`

| 字段 | 说明 |
|---|---|
| industry_code, period | 行业与期间 |
| price_index / price_value | 行业价格指数或代表品价格 |
| output / sales_volume | 产量/销量 |
| inventory_days / inventory | 库存天数或库存量 |
| capacity / utilization | 产能与开工率 |
| source, unit, caliber | 来源/单位/口径 |

验收：至少提供价格或产量其中一条连续序列；月度/季度频率；能回答“周期位置”。

### 2.4 政策与标准
表建议：`ref_industry_policy`

| 字段 | 说明 |
|---|---|
| industry_code, policy_name | 行业与政策名 |
| effective_date | 执行日 |
| quantified_impact | 量化影响（补贴元/单位、关税百分点、目标渗透率等） |
| beneficiary / affected_segment | 受益/受影响环节 |
| document_id, source_uri | 原文 |

验收：至少一条政策量化到元/单位、百分点或明确日期；不能量化的写“仅方向”，不得编数字。

### 2.5 海外对标（P1）
字段：市场（美/日/欧）、同类行业、集中度演变、龙头终局毛利率/ROIC、时间跨度、来源。

## 3. 商业模式（P0）

### 3.1 分部收入与毛利
表建议：`fin_segment_revenue`

| 字段 | 说明 |
|---|---|
| symbol, report_date, announce_date | 公司与报告期 |
| segment_type | product / region / channel |
| segment_name | 分部名称 |
| revenue, gross_profit, gross_margin | 收入/毛利/毛利率 |
| share_of_revenue | 收入占比（可由数据计算） |
| source, document_id, page_ref | 年报“主营业务构成”页码 |

验收：分部收入合计与合并营收差异 ≤1%；至少覆盖最近 5 年年报；产品/地区两类至少各有一类。

### 3.2 客户集中度
表建议：`fin_customer_concentration`

| 字段 | 说明 |
|---|---|
| symbol, report_date | 公司与报告期 |
| top1_share … top5_share | 前五大客户占比 |
| top5_total | 合计 |
| customer_names | 可空；匿名客户用“客户A”等 |
| source, document_id, page_ref | 年报/问询函 |

验收：0–100%；合计与分项一致；最近 5 年。

### 3.3 量价拆分
表建议：`fin_volume_price`

| 字段 | 说明 |
|---|---|
| symbol, period, product | 公司/期间/产品 |
| volume, unit_price, revenue | 销量/单价/收入 |
| unit, source | 单位与来源 |

验收：收入 ≈ 销量 × 单价（±1%）；至少一条产品线连续 3 年；无数据时明确 NULL。

### 3.4 成本结构
表建议：`fin_cost_structure`

字段：symbol, report_date, raw_material, labor, manufacturing, depreciation, energy, other；单位与来源。验收：合计与营业成本差异 ≤1%。

### 3.5 合同负债/预收款、经常性收入（P1）
- 合同负债/预收款：从资产负债表补列 `contract_liabilities`、`advance_receipts`。
- 经常性收入占比：按业务披露或订阅/耗材收入拆分。
- 消费类：CAC、LTV、回收期（P2）。

## 4. 护城河（P0/P1）

### 4.1 份额序列
表建议：`fin_market_share`：symbol, industry_code, period, share, basis（收入/销量）, source。验收：与行业规模、公司收入可复算；至少 5 年。

### 4.2 价格与价格战
表建议：`ref_industry_price_history`：industry_code/product, period, price, source；`ref_price_war_event`：industry_code, start/end, description, source。

### 4.3 客户留存/续约（P1）
字段：symbol, period, retention_rate, renewal_rate, churn_rate, basis, source。

### 4.4 专利/牌照（P1）
字段：symbol, type（专利/牌照/资质）, name, number, granted_date, expiry_date, status, source。

## 8. 优先级与交付顺序

| 优先级 | 内容 | 原因 |
|---|---|---|
| P0 | 治理全部字段、财务附注/审计/问询、分部收入/客户集中度、行业 TAM/CR/份额、行业价格或产量 | 直接决定“能否买入”和结论是否可信 |
