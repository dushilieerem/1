## 2. 架构目标

| 目标 | 说明 |
|---|---|
| 边界清晰 | SVQuant 只做产品层（体验、用户业务、权限、知识库、AI 编排、展示缓存），ResearchEngine 只做研究计算（行情、因子、策略、回测、结果管理） |
| 独立演进 | 两系统不共享 Python 包、数据库连接、本地文件；各自独立发布，锁步兼容 |
| 可信结果 | 研究结果永远来自 ResearchEngine，RE 不可用时明确失败，禁止本地伪造 |
| AI 差异化 | AI 编排、额度、护栏（metrics_trust）沉淀在 SVQuant 产品层，模型供应商可替换 |
| 数据可信 | 行情数据由 IFind 采集发布、RE 校验消费，SVQuant 不持有研究数据本体 |
| 可审计 | 写操作与错误落入审计日志；任务状态有终态；缓存可再生 |

非目标（当前版本）：生产级高可用、容器编排、自动回滚、消息队列、分布式任务调度。

## 3. 系统范围

### 3.1 系统内部

| 组成 | 说明 |
|---|---|
| `frontend/` | 主 Web 前端（Vite + React + TypeScript），默认 :9530 |
| `backend/` | FastAPI 产品后端，默认 :8766；路由、鉴权、业务服务、BFF、RE 网关、AI 编排 |
| `KnowledgeHub/` | 知识库产品模块；API 以 `/api/kh` 挂载在 backend，前端可独立运行 |
| `scripts/` | 本地一键启动脚本（`svquant.sh`） |
| `docs/` | 产品、架构、设计、测试、部署、使用文档与 ADR |

### 3.2 外部系统

| 系统 | 交互方式 |
|---|---|
| ResearchEngine（独立部署、独立仓库） | HTTP API（`YG_RE_BASE`，默认 :9527） |
| PostgreSQL | `DATABASE_URL`（psycopg 直连） |
| IFind 数据采集项目 → marketdata 目录 | SVQuant 间接依赖：IFind 发布 → RE 校验读取，SVQuant 不接触 |
| LLM 供应商（OpenAI 兼容 / 火山方舟 / 硅基流动） | HTTP（`LLM_*`、`AI_FACTOR_*`、`SILICONFLOW_*` 配置） |
| 语音转写供应商 | HTTP（硅基流动） |
| 资讯源（财联社/东方财富/巨潮/华尔街见闻/同花顺） | HTTP 抓取（后台线程 + 手动触发） |

### 3.3 系统边界

- SVQuant 负责：页面、用户与权限、产品数据、BFF、展示缓存、社区、资讯、知识库、AI 编排、审计。
- ResearchEngine 负责：行情读取与版本校验、因子目录与计算、策略执行、回测编排、回测结果 SQLite、AI 因子/策略生成与解读的计算侧。
- SVQuant 不导入 ResearchEngine Python 包，不直接读取行情目录或回测结果 SQLite，不从本地文件推断任务状态。
- ResearchEngine 不连接 SVQuant PostgreSQL，只接收经过鉴权与解析的请求快照。

## 4. 总体架构

```text
┌─────────────────────────────────────────────────────────────────┐
│ 用户浏览器                                                        │
│  （只访问 SVQuant frontend :9530 / backend :8766 的 /api）         │
└──────────────┬──────────────────────────────────────────────────┘
               ▼
┌─────────────────────────────── SVQuant ─────────────────────────┐
│ frontend（React/Vite）                                           │
│   页面 · 图表 · 编辑器 · 状态                                      │
│ backend/app（FastAPI :8766）                                      │
│   路由层（routers/*）· 鉴权依赖（deps）· 统一错误 · 中间件           │
│   ├─ 审计中间件（写操作与错误 → app_audit_logs）                    │
│   ├─ 防缓存中间件（no-store）                                      │
│   └─ lifespan：bootstrap_schemas（建表/种子/迁移/定时任务）          │
│ backend/services（业务层）                                        │
│   auth · community · news · core · data · factor · strategy      │
│   └─ core：db / env_config / re_config / re_http_gateway / lan_http│
│ backend/ai（AI 编排）                                             │
│   gateway（模型网关）· runtime（额度/编排/skills）· crews（流水线）  │
│ KnowledgeHub/backend（/api/kh 挂载）                              │
│   http_handlers · store · chunking · embedding · llm · attachments│
└───────┬──────────────────┬──────────────────┬───────────────────┘
        ▼                  ▼                  ▼
  PostgreSQL          ResearchEngine      外部供应商
 （产品事实/缓存）    （独立部署 :9527）    （LLM/转写/资讯源）
                          ▲
                          │ 读取已发布 release
                     IFind → marketdata
                   （SVQuant 不接触）
```

说明：

- 前端只访问 SVQuant `/api`；RE 地址唯一来源是 `backend/.env` 的 `YG_RE_BASE`（Vite 开发代理读取同一份配置）。
- PostgreSQL 是产品事实与可再生缓存的主存储；`backend/output/` 只存本机临时状态。
- `backend/data/strategy_run_blobs/` 保存策略回测完整结果 gzip blob（大 JSONB 不入库）。

## 5. 请求拓扑

```text
浏览器 ──HTTPS/HTTP──▶ SVQuant backend
   ├─ 鉴权（JWT Bearer → require_user / require_admin / optional_user）
   ├─ 参数校验与业务规则
   ├─ 产品数据：PostgreSQL（services/*_store）
   ├─ 研究计算：re_gateway / re_http_gateway ──YG_RE_BASE──▶ ResearchEngine
   │    └─ 错误映射：RE 超时/连接失败/契约不兼容 → 502 + 产品错误
   ├─ AI 能力：backend/ai ──HTTPS──▶ LLM/转写供应商
   │    └─ 需要 RE 计算的 AI 操作 → 网关代理（/api/ai/factor-generations 等）
   └─ 资讯：services/news（后台线程定时 + 手动触发）──HTTPS──▶ 资讯源
```

约束：浏览器不携带任何 RE 地址或内部凭据；网关限制允许转发的路径与方法。

## 6. SVQuant 与 ResearchEngine 职责划分

| 领域 | SVQuant | ResearchEngine |
|---|---|---|
| 用户、登录、JWT、权限 | 负责 | 不负责 |
| 用户资产、因子/策略配置 | 保存、鉴权、展示 | 接收请求快照，不拥有 CRUD |
| 社区、资讯、知识库 | 负责 | 不负责 |
| 行情目录（marketdata）与数据版本校验 | 不保存、不读取 | 读取 IFind 发布的已校验数据 |
| 因子目录、因子计算 | 用户因子同步状态；API 展示/调用 | 官方目录、校验、计算 |
| 策略执行和回测 | 配置、展示、网关调用 | 执行、撮合语义、结果生成 |
| 回测结果 SQLite | 不直接访问 | 存储与查询 |
| AI 因子/策略生成、回测解读 | 入口、额度、护栏；代理转发 | 生成与解释计算 |
| 任务状态 | 产品侧 job/run 记录、轮询 | 任务调度与终态事实 |
| Web 页面 | 负责 | 不负责 |

内置策略元数据经 RE `GET /api/strategies` 同步到 `builtin_strategies` 表；页面只读镜像，回测只提交 `strategy_id`。

## 8. 模块依赖关系

```text
frontend
   ↓ 只访问 /api
backend/app（路由 + 鉴权依赖 deps）
   ├─▶ services/auth（登录态解析被所有模块依赖）
   ├─▶ services/factor ──▶ services/core 网关 ──▶ ResearchEngine
   ├─▶ services/strategy ──▶ services/core 网关 ──▶ ResearchEngine
   ├─▶ services/data ──▶ services/core 网关 ──▶ ResearchEngine
   ├─▶ services/community ──▶ PostgreSQL
   ├─▶ services/news ──▶ PostgreSQL + 资讯源
   ├─▶ backend/ai ──▶ LLM/转写供应商；（需要计算时）──▶ RE 网关
   └─▶ KnowledgeHub handlers ──▶ PostgreSQL + 附件目录
```

依赖方向约束：

1. 路由层不实现行情读取、因子计算或策略回测。
2. services 可访问 PostgreSQL 与外部网关；core 是唯一 HTTP 出口封装（`lan_http` 直连白名单绕过本机代理）。
3. `services/strategy/strategy_library_store.py` 是兼容门面，实际数据来自 `builtin_strategies_store` 的数据库镜像。
4. KnowledgeHub 不依赖 ResearchEngine；ResearchEngine 不连接 SVQuant PostgreSQL。
5. `backend/ai` 通过 `ai/gateway/llm_client` 与 `ark_chat` 出外网，不直接访问 PostgreSQL 之外的存储（额度记录除外，经 `ai/runtime/store`）。

## 9. 数据流

### 9.1 产品数据流

```text
用户操作 → 路由鉴权 → *_store → PostgreSQL（产品事实）
                └→ 审计中间件 → app_audit_logs（写操作与错误）
```

### 9.2 研究计算数据流

```text
用户配置 → SVQuant 鉴权 + 请求快照（日期/资产/因子或策略引用/参数）
        → RE 网关（forward_re）
        → ResearchEngine（校验 manifest → 计算 → 结果 SQLite）
        → 状态/结果 → SVQuant 展示缓存（PostgreSQL）→ 前端
```

### 9.3 AI 数据流

```text
用户输入 → 额度校验（ai_usage / users.ai_quota_daily）
        → skills/crews（LLM 网关 → 供应商）
        → 护栏（metrics_trust：数字标记/承诺话术检测/platform_ref）
        → 运行记录（ai_usage）→ 前端
需要 RE 计算时：AI 产物经 /api/ai/*-generations 网关 → ResearchEngine
```

### 9.4 资讯数据流

```text
后台定时线程（NEWS_INGEST_INTERVAL_SEC，默认 900s）/ 手动 ingest
   → 多源抓取（CLS 签名/东财/巨潮/见闻/同花顺）
   → 正文补抓与清洗 → 标签字典匹配 → 证券代码识别
   → upsert news_items（去重键 hash(source,url,title,published_at)）
   → 保留策略 enforce_news_retention
```

## 11. 外部依赖矩阵

| 依赖 | 访问方式 | 配置项 | 用途 | 失败影响 | 降级策略 |
|---|---|---|---|---|---|
| PostgreSQL | psycopg 直连（`get_conn`） | `DATABASE_URL` | 产品事实、缓存、审计、AI 用量 | 登录与所有产品写操作失败 | 无（运维恢复；启动 bootstrap 有明确报错） |
| ResearchEngine | HTTP（`forward_re`，urllib 直连） | `YG_RE_BASE`（必填，缺失启动报错） | 行情、因子目录、回测、AI 生成代理 | 全部研究功能 502 | 明确"研究服务暂不可用"；不本地伪造 |
| IFind/marketdata | 间接（仅 RE 读取） | RE 部署侧 | 研究数据供给 | RE 拒绝计算（manifest 校验） | SVQuant 显示计算服务不可用 |
| LLM 供应商 | HTTP（`llm_client` / `ark_chat`） | `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL/LLM_TIMEOUT_SEC`、`AI_FACTOR_*`、`SILICONFLOW_*` | 对话/生成/解读/Agent/润色 | 对应 AI 功能 502/503 | 社区润色降级本地 mock；gather 回退规则摘要 |
| 语音转写供应商 | HTTP（`speech_transcribe`） | 硅基流动密钥 | 语音输入 | 转写不可用（状态接口可查） | 明确"未配置"，不影响文字输入 |
| 资讯源 | HTTP 抓取 | `NEWS_INGEST_INTERVAL_SEC/NEWS_INGEST_LIMIT` | 资讯列表 | 单源失败跳过，其余继续 | 结果中标注失败源 |
| KnowledgeHub 附件目录 | 本地文件系统 | `KnowledgeHub/data/kh_attachments` | 知识库附件 | 附件下载/摄取失败 | 明确报错；元数据与文件成对备份 |

补充约定：

- `lan_http.ensure_lan_no_proxy` 在进程导入时把 RE 主机、`192.168.0.0/16`、`127.0.0.1`、`localhost` 合并写入 `NO_PROXY`，避免本机代理（如 Clash）劫持局域网请求；所有外部 HTTP 使用无代理 opener 直连。
- `AUDIT_LOG_RETENTION_DAYS`（默认 30）控制审计日志启动清理。

## 12. 架构约束

1. **前端不得直连 ResearchEngine**：业务 TS 文件不保存 RE 地址；浏览器只携带 SVQuant 会话凭据。
2. **SVQuant 不导入 ResearchEngine Python 包**：只依赖公开 HTTP 契约，不依赖其内部模块路径或文件布局。
3. **SVQuant 不读取 marketdata 和结果 SQLite**：不通过本地文件判断任务状态；不复制数据清单/质量报告回本仓库。
4. **敏感配置只在 `.env` 或密钥系统**：密码、Token、Secret Key、私钥不进 Git、文档、日志或响应；`.env` 不提交。
5. RE 地址唯一来源 `YG_RE_BASE`；未配置或非法 URL 时 `re_config` 直接抛错（快速失败）。
6. 网关限制允许转发的路径和方法，不提供任意 URL 代理能力。
7. 路由层不做计算；计算事实属于 ResearchEngine；产品缓存可再生，不作审计唯一事实。
8. `backend/output/` 与 `backend/data/` 为本机运行时目录（临时状态/结果 blob），不作为跨服务事实来源。
9. 生产环境 `DEV_SKIP_AUTH=0`、`JWT_SECRET`/`ADMIN_PASSWORD` 必须替换。
10. 两仓库锁步发布：接口变化先更新 RE 契约测试，再同步 SVQuant BFF、前端类型与集成验证。

## 13. 失败与容错矩阵

| 故障 | 检测点 | SVQuant 行为 | 用户感知 | 处理责任 |
|---|---|---|---|---|
| PostgreSQL 不可用 | `get_conn` 连接异常；bootstrap 报错 | 登录/写操作 500；审计中间件静默吞错不放大 | 登录失败、保存失败 | SVQuant 运维恢复数据库 |
| ResearchEngine 连接失败/超时 | 网关 `request_json`（URLError → 502） | 502 + `{"error": ...}`；poll_url 保持可重试 | "研究服务暂不可用"，输入保留 | RE 运维与网络配置 |
| RE API 契约不兼容 | 网关校验/契约冒烟脚本 | 集成验证阻断发布 | 发布前拦截 | 两仓库锁步修复 |
| marketdata 版本/哈希不匹配 | RE 侧拒绝计算 | 透传 RE 错误 | 计算服务不可用 | 数据发布方与 RE |
| LLM 未配置 | `llm_configured()`/`ark_configured()` | 503"未配置"；润色 mock 降级；gather 回退规则摘要 | 明确降级提示 | SVQuant 运维配置密钥 |
| LLM 供应商超时/失败 | `LlmError`/`ArkChatError` | 502 或 SSE error 帧；额度不扣（失败不记录用量） | AI 暂不可用 | 供应商/配置 |
| 转写供应商未配置 | `speech_ready()` | 状态接口返回未配置；transcribe 503 | 语音不可用，文字可用 | SVQuant 运维 |
| 资讯源失败/接口变更 | fetcher 异常 | 该源跳过；ingest 结果标注失败源 | 部分来源缺失 | SVQuant 维护 fetcher |
| KnowledgeHub 附件缺失 | 下载/摄取时文件不存在 | 明确报错"附件缺失" | 提示重新上传或联系管理员 | SVQuant 运维（成对恢复） |
| RE 回测任务丢失/超时终态 | 轮询超时（因子 1800s 默认） | 任务标记失败，可重提 | 明确失败可重试 | SVQuant+RE 排查 |
| 进程重启丢失后台任务 | dashboard job.json 状态为 running | 启动时仅提示，不自愈 | 面板刷新需手动重提 | 待确认（引入任务 API 后解决） |

## 14. 安全设计

| 层面 | 设计 |
|---|---|
| 认证 | 用户名密码（bcrypt 哈希）→ JWT Bearer（`JWT_SECRET`，`JWT_EXPIRE_DAYS` 默认 7 天） |
| 授权 | 后端依赖注入分级：`optional_user` / `require_user` / `require_db_user_id` / `require_admin`；资产按 `user_id` 隔离 |
| 开发后门 | `DEV_SKIP_AUTH=1` 返回假用户，仅限本地；生产必须 0 |
| 网关安全 | 转发路径/方法白名单；RE 地址与凭据不暴露给浏览器 |
| 审计 | HTTP 中间件记录写操作与错误（登录/注册由路由显式记录避免重复）；`app_audit_logs` 管理员可查可清理 |
| 输入 | 统一错误形状 `{"error": ...}`；请求体验证失败 400；不做盲目重试放大 |
| 凭据 | 模型/资讯凭据只在 `.env`；KH 模型供应商凭据存数据库配置但不出现在日志与文档 |
| CORS | 当前 `allow_origins=["*"]`（生产需收紧：**待确认**） |

## 17. 架构风险

| 风险 | 影响 | 应对 |
|---|---|---|
| RE 契约变化 | 研究功能不可用 | 契约测试先行、锁步发布、配套版本集成验证 |
| job.json 本机临时任务状态 | 重启不自愈、非审计事实 | 推动 RE 任务 API 接管（跨仓库契约） |
| 后台线程任务（资讯/面板/目录预热）无统一调度框架 | 重启丢任务、无重试标准 | 引入任务队列/调度前，文档化人工重提方式；待确认 |
| AI 供应商波动与成本 | AI 功能延迟、费用失控 | 多供应商配置、每日额度、用量监控；兜底策略待确认 |
| 资讯源无正式授权/接口变更 | 合规与功能中断 | 授权确认（待确认）、fetcher 白名单与失败隔离 |
| CORS `*` 与登录无限流 | 生产安全风险 | 生产前收紧（待确认清单见 PRD §10.2） |
| 生产部署/监控缺位 | SLA 无法承诺 | 部署文档监控清单落地；生产方案立项 |
| 单文件大 store（community_store ~2000 行） | 可维护性 | 后续按域拆分（待确认，避免一次性大重构） |
