# AI 与 Agent 模块 流程设计

## 1. 流程说明

覆盖四条流程：SSE 对话、Agent run（技能编排 + 计费）、研究流水线五段、用量与配额管理；并说明语音转写与降级路径。

## 2. 参与模块

| 参与者 | 职责 |
|---|---|
| frontend | 聊天页、社区创作页、研究助手页、管理后台 |
| `routers/ai.py` / `routers/agent.py` | HTTP 入口 |
| `ai/gateway/*` | LLM/方舟/硅基流动/语音调用 |
| `ai/runtime/*` | 技能路由、board 编排、配额记账 |
| `ai/crews/gather_idea` | 五段流水线 |
| 外部 API | 火山方舟 / 硅基流动 / OpenAI 兼容 LLM |

## 3. 正常流程

### 流程 A：SSE 对话（/api/ai/chat）

```text
前端 POST /api/ai/chat {messages, model, temperature}
  → ark_chat.resolve_provider(model_id) → (provider, base_url, api_key)
  → iter_chat_stream(...) 流式拉取
  → _sse_chat_frames 组装 SSE 帧 → StreamingResponse
  → strip_thinking 剥离思考链后输出
```

### 流程 B：Agent run（社区创作/读帖）

```text
前端 POST /api/agent/runs {skills?, goal?, context}
  → require_user → assert_quota_available(user_id)（配额不足 → 403"配额…"）
  → start_run:
      resolve_skills(skills, goal)   # 显式 skills 或关键词路由
      → start_run_single / 多技能串联
      board = new_board / new_read_board(goal, context)
      for skill: _run_and_bill（执行 + record_usage 计费）
        创作链：polish_title → polish_body → suggest_section → audit_claims → strip_unverifiable
        读帖链：truncate → summarize_post → lookup_panel_metrics → flag_read_risks
      → 返回 board（步骤、草稿、审计与信任标记）
```

### 流程 C：研究流水线（五段）

```text
POST /api/agent/gather          → run_gather_pipeline：normalize_request → 来源平衡取样 → rule/llm digest → 证据缺口
POST /api/agent/idea            → run_idea_pipeline：证据 → 因子规格（_normalize_factor_spec/_normalize_validity）
POST /api/agent/factor          → run_factor_pipeline：规格 → 因子代码（_validate_factor_code，失败 _fallback_code）
POST /api/agent/factor-backtest → run_backtest_pipeline：回测报告（执行经 RE 回测链路）
POST /api/agent/factor-eval     → run_eval_pipeline：评估结论
（各段可独立调用，上游产物以 body 传入）
```

### 流程 D：用量与配额

```text
GET  /api/agent/usage/me?days=7   → usage_summary_for_user
GET  /api/agent/usage?days=7      → usage_admin_summary（非 admin → 403）
POST /api/agent/usage/quota       → set_user_ai_quota（管理员调整 ai_quota_daily）
POST /api/agent/runs 每次执行前   → assert_quota_available → record_usage（按次记账）
```

### 流程 E：语音转写

```text
GET /api/ai/speech/status → speech_ready()（凭据/模型状态）
POST /api/ai/speech/transcribe（multipart 音频）
  → _build_multipart → 硅基流动 ASR → _clean_text → 文本
```

## 4. 时序流程（run 计费与护栏）

```text
前端 -> agent 路由：POST /api/agent/runs
agent 路由 -> runtime/store：assert_quota_available(user_id)
alt 配额不足
  store -->> agent 路由：PermissionError（文案含"配额"）→ 403
else 放行
  agent 路由 -> runtime.start_run：resolve_skills → start_run_single
  start_run -> orchestrator：new_board(goal, context)
  loop 每个技能
    orchestrator -> skills.run_skill：执行（可含 LLM 调用）
    skills -> metrics_trust：audit_claims 数字/承诺/platform_ref 对账（容差 2%）
    skills -> orchestrator：结果
    orchestrator -> runtime/store：record_usage（计费）
  end
  orchestrator --> 前端：board（草稿 + 审计 + 信任标记 + mock 标记）
end
```

## 5. 异常流程

| 异常 | 触发 | 处理 |
|---|---|---|
| LLM 未配置 | env 缺失（文案含"未配置"） | 503；skills 走 `_mock_polish_*` / `_mock_summary_md` 降级 |
| 方舟/硅基流动调用失败 | 网络/凭据 | `ArkChatError` → 502 |
| 配额不足 | 当日次数 ≥ 配额 | PermissionError → 403 |
| 非 admin 查全局用量 | 路由 role 判断 | 403 仅管理员可查看 |
| 语音未配置/参数错误 | speech_ready=false / 文件非法 | 503 / 400 |
| 因子代码校验失败 | `_validate_factor_code` | `_fallback_code` 兜底并标注 |
| 生成内容含未验证数字 | audit_claims | strip_unverifiable 剥离 + trust 标记（不阻断） |

## 6. 状态流转

```text
run：created → step 依次推进（board.steps 追加）→ completed / failed
配额：每日重置（ai_usage 按日聚合）；管理员可随时调整 ai_quota_daily
对话：无状态（SSE 即用即弃）；社区草稿由前端提交社区模块落库后进入 帖子状态机
```

## 7. 并发处理

- run / 流水线均为请求内同步执行，无共享可变状态；并发受后端线程池约束。
- 用量记账（usage_today_count → record_usage）非原子事务，极端并发下计数可能少记（可接受偏差，待确认是否需加锁）。
- SSE 长连接占用工作线程直至流结束。

## 8. 幂等设计

- GET 类幂等；POST run/流水线非幂等（每次新 run_id，`new_run_id`）。
- 配额设置重复提交以最后值为准（覆盖语义）。
- mock 降级输出确定性（同输入同输出），重试安全。

## 9. 超时和重试

| 调用 | 超时 | 重试 |
|---|---|---|
| SSE 对话 | 流式持续至完成（请求级） | 前端重试 |
| LLM 单次调用 | 请求级默认 | 无自动重试 |
| 流水线各段 | 请求级默认（多段串行） | 用户手动重跑 |
| 语音转写 | 请求级默认 | 用户重试 |

## 10. 待确认

- run/流水线的异步化方案（当前同步，长任务线程占用）。
- 用量记账粒度（次数 vs token）与并发原子性。
- mock 降级在前端的显式提示策略。
- RE 侧 AI 生成（factor/strategy-generations）与本地流水线的分工边界与合并计划。
- 语音转写文件大小/时长上限。
