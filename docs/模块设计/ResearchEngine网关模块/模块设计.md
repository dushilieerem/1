# ResearchEngine 网关模块 模块设计

## 1. 模块信息

- 模块名称：ResearchEngine 网关模块（含行情/自选股适配）
- 位置：`backend/services/core/re_config.py`、`backend/services/core/re_http_gateway.py`、`backend/services/core/lan_http.py`、`backend/app/routers/re_gateway.py`、`backend/services/data/`、`backend/app/routers/watchlists.py`
- 负责人：SVQuant 技术组
- 文档版本：v1.0（2026-09-23）
- 需求依据：[PRD §6.10 ResearchEngine 集成边界](../../产品与需求/PRD.md)、[PRD §6.4 数据/行情/自选股](../../产品与需求/PRD.md)
- 专述文档：[架构与技术/engine-design.md](../../架构与技术/engine-design.md)

---

## 2. 模块职责

1. RE 地址唯一来源管理与快速失败（`re_config.RE_BASE`，`YG_RE_BASE` 缺失/非法即启动报错）。
2. RE HTTP 薄转发：`forward_re`（无自建队列）、超时控制、错误/状态透传、`Retry-After` 头透传。
3. poll_url 改写：把 RE 返回的轮询地址改写为本站路径（`rewrite_run_poll_url`）。
4. 局域网直连白名单：`ensure_lan_no_proxy` 把 RE 主机写入 `NO_PROXY`，所有外呼使用无代理 opener。
5. RE 侧稳定端点的 HTTP 入口：策略回测（submit/poll/cancel）、RE 健康代理、行情 symbols/indices/constituents、AI 生成代理（factor/strategy-generations、backtest-interpretations）。
6. 行情展示适配：`market_data_bff.fetch_market_daily`（日线 + 产品侧缓存 + bypass）。
7. 自选股：分组与成员 CRUD、批量添加（按用户隔离）。

## 3. 不负责的范围

- 不实现计算、排队语义（因子回测排队在 [因子研究模块](../因子研究模块/模块设计.md) 的 `re_backtest_jobs`）；策略回测为"薄转发，无自建队列"。
- 不读取/缓存 RE 结果 SQLite 与 marketdata 文件。
- 不持有 RE 凭据（当前 RE API 未经 SVQuant 注入认证头，见待确认）。
- 不做任意 URL 代理（转发目标为网关路由白名单内的 RE 端点）。

## 4. 输入

| 输入 | 来源 | 说明 |
|---|---|---|
| 回测请求 | `POST /api/backtest/strategy` | strategy_id 或 code + start_date/end_date + params |
| 轮询/取消 | `GET/DELETE /api/backtest/strategy/{run_id}` | run_id |
| 行情查询 | `GET /api/market-data/symbols|indices|indices/{key}/constituents`、`GET /api/market-data/daily/{code}` | 关键词/代码/起止/fresh |
| AI 生成代理 | `POST /api/ai/factor-generations|strategy-generations|backtest-interpretations` | 生成/解读请求 |
| 自选股 | `/api/watchlists*` | 分组名、证券代码（单个/批量） |

## 5. 输出

| 输出 | 接收方 |
|---|---|
| RE 响应原样透传（状态码 + 头 + JSON） | 前端/调用模块 |
| 改写后的 poll_url + Location 头 | 前端 |
| RE 健康（`/api/re/health`） | 运维/前端 |
| 日线序列（缓存适配后） | 前端图表 |
| 自选股分组/成员 | 前端 |

## 6. 子模块

| 单元 | 位置 | 职责 |
|---|---|---|
| re_config | `services/core/re_config.py` | `RE_BASE` 解析与校验（模块导入即校验，快速失败）；`re_host()` |
| lan_http | `services/core/lan_http.py` | `ensure_lan_no_proxy`（导入时执行）、`urlopen_direct`、`request_json`（4xx/5xx 返回 status+body 而非抛错）、`get_json`、`post_json[_with_status]` |
| re_http_gateway | `services/core/re_http_gateway.py` | `forward_re(method, path, payload, query, timeout)`、`rewrite_run_poll_url(data, base_path)` |
| re_gateway 路由 | `app/routers/re_gateway.py` | 策略回测三端点、`/api/re/health`、market-data 三端点、AI 三端点代理 |
| market_data_bff | `services/data/market_data_bff.py` | `fetch_market_daily`（`_cache_key` 产品侧缓存，`fresh` bypass） |
| watchlist_store | `services/data/watchlist_store.py` | 自选股表 CRUD、批量添加、代码归一化 |

## 7. 内部结构

```text
routers/re_gateway.py ──▶ re_http_gateway.forward_re ──▶ lan_http.request_json ──▶ RE
routers/news.py（/api/market-data/daily/{code} 挂载在 news 路由）──▶ market_data_bff ──▶ RE
routers/watchlists.py ──▶ watchlist_store ──▶ PostgreSQL
backend/ai（需要 RE 计算时）──▶ 网关（/api/ai/*-generations 由 re_gateway 代理转发）
```

> 挂载说明：`GET /api/market-data/daily/{code}` 当前注册在 `routers/news.py`（复用 `services/data/market_data_bff`），归属数据适配；文档如实记录，收敛路由归属为待确认重构项。

## 8. 核心逻辑

### 转发（forward_re）

1. path 以 `/` 开头拼接 `RE_BASE`；query 过滤 None 后 urlencode。
2. `request_json` 无代理直连；4xx/5xx 不抛异常，返回 `(status, headers_lower, body)` 交由调用方决定。
3. 提取 `Retry-After` 头透传给浏览器。

### 策略回测三端点

1. `POST`：timeout 1800s；若响应含 `run_id`，改写 poll_url 为 `/api/backtest/strategy/{run_id}` 并加 `Location` 头（兼容 RE 同步/202 异步两种形态）。
2. `GET`：timeout 60s 透传状态/结果。
3. `DELETE`：timeout 60s 取消。

### 行情适配

- `fetch_market_daily(code, start, end, bypass_cache)`：先查产品侧缓存（`_cache_key(symbol,start,end)`），`fresh=1` 绕过；RE 拉取后做展示字段适配。

### 自选股

- `watchlist_store`：分组 CRUD 均先 `_require_watchlist(conn, user_id, wl_id)` 校验归属；`_normalize_symbol` 统一代码格式；`add_watchlist_symbols_batch` 批量插入。

## 9. 外部依赖

| 依赖 | 用途 | 失败行为 |
|---|---|---|
| ResearchEngine | 全部研究计算与行情 | `URLError` → `(502, {}, {"error": ...})`；不伪造 |
| PostgreSQL | 自选股表 | 写失败并记录日志 |

## 10. 数据依赖

| 存储 | 说明 |
|---|---|
| `user_watchlists` / `user_watchlist_symbols` | 自选股（用户隔离） |
| 产品侧日线缓存（market_data_bff，具体存储位置以实现为准） | 可再生 |

## 11. 异常处理

| 异常 | 行为 |
|---|---|
| `YG_RE_BASE` 缺失/非法 | `re_config` 导入时抛 RuntimeError（进程启动即失败，快速暴露配置问题） |
| RE 连接失败/超时 | 502 + `{"error": "..."}`（URLError 转换） |
| RE 4xx/5xx | 状态码与 body 透传（由业务路由决定是否包装） |
| 自选股越权 | `_require_watchlist` 校验 user_id，403/404 |
| 行情代码不存在 | RE 侧 404/空结果透传 |

## 12. 性能要求

- 网关为零队列薄转发：不缓冲大响应、不改写 body（除 poll_url 字段）。
- 策略回测提交超时 1800s：同步兼容 RE 长计算；轮询 60s 短连接。
- 日线展示带缓存，`fresh=1` 强制刷新。

## 13. 风险

- 同步长等（1800s）占用后端工作线程，并发回测多时可能耗尽线程池（因子侧已有限流；策略侧依赖 RE 202 化，待确认）。
- RE API 当前未要求 SVQuant 注入服务间认证（内网信任模型）；暴露公网前需补充（待确认）。
- 转发白名单依赖路由层约定而非网关强制（网关函数本身接受任意 path）；新增转发端点需评审。
