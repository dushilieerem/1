# 因子研究模块 模块设计

## 1. 模块信息

- 模块名称：因子研究模块
- 位置：`backend/services/factor/`、`backend/app/routers/factor.py`、`backend/app/routers/detect.py`、`backend/factor/`
- 负责人：SVQuant 技术组
- 文档版本：v1.0（2026-09-23）
- 需求依据：[PRD §6.2 因子研究](../../产品与需求/PRD.md)
- 历史基线：[产品与需求/功能需求/因子研究.md](../../产品与需求/功能需求/因子研究.md)；RE 集成契约见 [FEAT-030](../../功能包/FEAT-030-因子回测流程重构/README.md)

---

## 2. 模块职责

1. 用户因子库与库内因子的 CRUD（PostgreSQL + `backend/factor/` 同步产物）。
2. 用户自定义因子（Python 方法代码）管理与同步产物重建（index.yaml / custom_lib）。
3. 自定义因子试算：转发 RE 短周期回测，快速验证代码可运行。
4. ResearchEngine 官方因子目录的拉取、快照缓存（PostgreSQL）与后台预热。
5. 因子检测项目与运行记录（CRUD、备注、标记）。
6. RE 因子回测任务：本地排队（限流）、异步转发、job 状态查询与取消。
7. 因子面板：指标批量刷新（后台线程）、指标缓存、人工校验记录、旧 SQLite 迁移。
8. 兼容旧同步回测入口 `/api/backtest/factor`（经异步代理转发 RE）。

## 3. 不负责的范围

- 不做因子数值计算、IC/IR 计算、撮合——全部由 ResearchEngine 完成。
- 不保存行情数据；不读取 RE 的 marketdata 与结果 SQLite。
- 不管理策略回测（属 [策略研究模块](../策略研究模块/模块设计.md)）。
- job.json 只是本机临时状态，不作为跨服务审计事实。

## 4. 输入

| 输入 | 来源 | 说明 |
|---|---|---|
| 因子库/因子 CRUD | `/api/factor/libraries*` | 库名、因子名、Python 函数代码（`def NAME(self)`，函数名须与因子名一致）、描述 |
| 试算 | `POST /api/factor/custom/trial` | 因子代码、名称、universe（默认 CSI300）、period（默认 3m） |
| 目录同步 | `POST /api/factor/re-catalog/sync` | include_all 等 |
| 回测任务 | `POST /api/factor/re-backtest` | factor、universe、benchmark、start_date、end_date；SV 侧附加键会被剥离 |
| 检测项目/运行 | `/api/detect/projects*`、`/api/detect/runs*` | 项目配置（因子、日期/预设周期、universe、基准）、运行结果与备注 |
| 面板刷新 | `POST /api/factor/dashboard/refresh` | universe、period、过滤选项、limit、skip_ok、analysis_level |
| 校验 | `POST /api/factor/dashboard/verify` | 因子、状态（pending/passed/failed）、备注 |

## 5. 输出

| 输出 | 接收方 |
|---|---|
| 因子库/因子列表与详情、同步产物（YAML 索引、custom_lib 源码） | 前端 |
| 试算结论（无 error 且有 metrics 即成功） | 前端 |
| 官方目录快照（库/因子/分类标签/content hash） | 前端 |
| job_id + 状态（queued/running/completed/failed）+ 结果 | 前端 |
| 检测项目/运行记录与报告 | 前端 |
| 面板指标（factor_dashboard_metrics）与校验状态 | 前端 |

## 7. 内部结构

```text
routers/factor.py ─┬─ user_factor_store / user_library_store（CRUD）
                   ├─ factor_trial ──▶ re_backtest_bff.forward_factor_backtest ──▶ RE
                   ├─ re_factor_catalog（fetch/sync，快照表）
                   ├─ re_backtest_jobs（排队）──▶ re_backtest_bff ──▶ RE
                   ├─ dashboard_store.start_refresh（后台线程）──▶ RE 批量回测
                   │      └─▶ factor_dashboard_metrics_store / factor_verification_store
                   └─ re_factor_async_proxy（/api/backtest/factor 兼容）──▶ RE
routers/detect.py ──▶ detect_store
backend/factor/（index.yaml、custom_lib.py 等同步产物，由 user_factor_store 重建）
```

## 8. 核心逻辑

### 因子回测（异步任务）

1. `POST /api/factor/re-backtest` → `submit_factor_backtest(payload, user_id)`：生成 job_id，入 queued 队列，立即返回。
2. 后台线程池按 `SVQUANT_RE_BACKTEST_INFLIGHT`（默认 8）限流转发 RE；任务写 job.json（状态/done/total/结果引用）。
3. `GET /api/factor/re-backtest/{job_id}` 查询状态（校验 user_id 归属）；`DELETE` 取消/清理。
4. 转发前剥离 SV 专有键（`_SV_ONLY_KEYS`），RE 校验因子与数据 release；失败/超时显式终态。

### 官方目录同步

1. `sync_from_re` 拉取 RE 目录 API → 归一化库/因子/分类 → `content_hash` 比较 → 有变化才写 `re_factor_catalog_snapshot` + 同步日志。
2. 读取路径：优先快照表；`fresh=1` 强制拉取。启动时 `warm_re_catalog_async` 后台预热。

### 因子面板刷新

1. `start_refresh` 加锁防并发（已有 running 直接拒绝）；daemon 线程批量回测面板因子（skip_ok 跳过已成功）。
2. 每个因子结果经 `map_yg_response` 映射为指标行，upsert `factor_dashboard_metrics`；job.json 记录进度。
3. 人工校验写 `factor_dashboard_verifications`（长期记录，可审计）；旧 metrics.sqlite/verifications 仅迁移时只读导入。

### 检测项目

- 新用户自动建样例项目（`SAMPLE_ID`）；历史无主项目由 `reassign_misowned_named_projects` 修正归属。

## 9. 外部依赖

| 依赖 | 用途 | 失败行为 |
|---|---|---|
| ResearchEngine | 目录、试算、回测、面板计算 | 502/显式失败；不本地伪造 |
| PostgreSQL | 全部产品表 | 写失败并记录日志 |

## 10. 数据依赖

| 存储 | 说明 |
|---|---|
| `user_custom_factors` / `user_factor_libraries` / `user_library_factors` | 用户因子与库 |
| `re_factor_catalog_snapshot` / `re_factor_catalog_sync_log` | 官方目录快照与同步日志 |
| `detect_projects` / `detect_runs` | 检测项目与运行记录 |
| `factor_dashboard_metrics` / `factor_dashboard_verifications` / `factor_dashboard_legacy_imports` | 面板缓存 / 校验记录 / 迁移标记 |
| `backend/output/factor_dashboard/job.json` | 任务临时状态（待 RE 任务 API 接管后退役） |
| `backend/factor/`（index.yaml、custom_lib.py） | 用户因子同步产物（代码仓库受控样例 + 运行时重建） |

## 11. 异常处理

| 异常 | 行为 |
|---|---|
| 因子代码非 `def` 开头/函数名不一致 | 400 + 可修复提示（试算与保存均校验） |
| RE 超时/连接失败 | 502；job 标记 failed；面板单因子失败记入指标 error |
| job.json 丢失/损坏 | 状态视为丢失，用户重提；不作为审计事实 |
| 目录同步失败 | 保留上次快照，记录日志；同步接口返回错误 |
| 重复刷新面板 | "已有任务在跑"，返回当前 job |
| 检测项目/运行无权限 | 403/404（按 user_id 过滤） |

## 12. 性能要求

- 回测在途限流默认 8（RE 同步线程池约 40，预留面板/试算）。
- 面板批量刷新后台执行，接口立即返回 job。
- 指标缓存可重建；全市场因子计算 ≤5s 为 RE 侧目标。
- 目录读取优先快照表，避免每次外呼。

## 13. 风险

- job.json 本机状态重启不自愈、非审计事实（待 RE 任务 API 接管）。
- 因子代码为任意 Python 方法文本，仅格式校验；执行安全由 RE 侧约束（SV 侧沙箱：待确认）。
- 面板线程与回测排队共享 RE 容量，高峰可能互相挤占（限流值可调）。
