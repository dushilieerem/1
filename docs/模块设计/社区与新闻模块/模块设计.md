# 社区与新闻模块 模块设计

## 1. 模块信息

- 模块名称：社区与新闻模块（社区帖子/评论/投票/收藏/通知/举报 + 资讯采集与展示）
- 位置：`backend/app/routers/community.py`、`backend/app/routers/news.py`、`backend/services/community/community_store.py`、`backend/services/news/{news_store,news_ingest,news_tag_dict}.py`
- 负责人：SVQuant 技术组
- 文档版本：v1.0（2026-09-23）
- 需求依据：[PRD §6.5 社区](../../产品与需求/PRD.md)、[PRD §6.4 数据/行情/自选股](../../产品与需求/PRD.md)（资讯部分）

---

## 2. 模块职责

1. 社区帖子：发布/编辑/删除（strategy / factor / qa / hotspot / official 五个板块，板块常量来自 `backend/ai/crews/skills.py` 的 `SECTION_IDS`）。
2. 互动：评论、帖子/评论投票、收藏、热门榜（`list_hot_posts`）。
3. 通知：@提及解析（`_find_mentioned_user_ids`）、站内通知列表、未读数、批量已读。
4. 内容管理：管理员置顶/上下架（`moderate_post`）、彻底清除（`purge_post`）、运营摘要（`ops_summary`）、举报与处理（`create_report` / `list_reports` / `resolve_report`）、待审核队列（`list_moderation_posts`）。
5. 资讯展示：`list_news`（分类/来源/关键词/模式/主题/个股/行业过滤）、`get_news` 详情。
6. 资讯采集：后台定时任务（CLS / 东方财富（市场+研报+政策）/ 巨潮 / 华尔街见闻 / 同花顺），去重入库，标签回填与正文增强。
7. 资讯标签词典：`news_tag_dict`（代码内置词典）匹配生成标签。
8. 展示用日线（挂载在 news 路由，见 [ResearchEngine网关模块](../ResearchEngine网关模块/模块设计.md)）。

## 3. 不负责的范围

- 不负责用户注册/登录与 token 校验（见 [用户与权限模块](../用户与权限模块/模块设计.md)）。
- 不负责内容的 AI 生成/摘要/审核判定（社区帖子由 [AI与Agent模块](../AI与Agent模块/模块设计.md) 的 community crews 生成草稿，本模块只存储展示）。
- 不负责行情/回测计算（日线展示通过 RE 网关获取）。
- 不做全文搜索引擎；关键词过滤为 SQL `ILIKE` 级别。

| 输入 | 来源 | 说明 |
|---|---|---|
| 帖子/评论/投票/收藏/举报请求 | `routers/community.py` | JSON body + 登录用户 |

## 6. 子模块

| 单元 | 位置 | 职责 |
|---|---|---|
| community 路由 | `app/routers/community.py` | 25 个端点；浏览类 `optional_user`（viewer），写操作 `require_user`；权限在 store 层按 role 判定 |
| community_store | `services/community/community_store.py` | 帖子/评论/投票/收藏/通知/举报/运营全套存储逻辑 |
| news 路由 | `app/routers/news.py` | 资讯列表/详情/词典/手动采集/正文增强 + 展示日线 |
| news_store | `services/news/news_store.py` | `news_items` 表：查询过滤、保留策略、容量上限、样例种子 |
| news_ingest | `services/news/news_ingest.py` | 各源 fetcher、签名、去重 upsert、标签回填、正文增强、后台调度 |
| news_tag_dict | `services/news/news_tag_dict.py` | 内置词典匹配（`match_labels` / `enrich_news_tags` / `dict_snapshot`） |

## 7. 内部结构

```text
routers/community.py ──▶ community_store ──▶ PostgreSQL（posts/post_comments/…）
routers/news.py ──▶ news_store（读） / news_ingest（手动触发）
后台线程 start_news_ingest_scheduler ──▶ news_ingest.ingest_news ──▶ 各源 fetcher
news_ingest ──▶ news_tag_dict.enrich_news_tags（标签）
```

## 8. 核心逻辑

### 社区权限模型

- 路由层仅区分"匿名浏览（optional_user）/ 登录写（require_user）"。
- 管理能力（moderate/purge/审核队列/举报处理/ops_summary）在 store 函数内以 `author_role`/`viewer_role` 参数判定，非 admin 抛 `PermissionError`（如 `moderate_post` 中 `if author_role != "admin": raise PermissionError("仅管理员可操作")`）。
- 路由统一把 `PermissionError → 403`、`KeyError → 404`、`ValueError → 400`。

### 通知与提及

- `create_post`/`create_comment` 时 `_find_mentioned_user_ids` 解析 @用户名 → `_insert_notification` 落库。
- `unread_notification_count` 供消息红点；`mark_notifications_read` 批量已读。

### 资讯采集

1. `ingest_news` 遍历 `FETCHERS`（cls/eastmoney/eastmoney_research/eastmoney_policy/cninfo/wallstreetcn/10jqka；不支持的源记入 `UNSUPPORTED_SOURCES`）。
2. 每源限量 `NEWS_INGEST_LIMIT`（默认 12）。
3. 去重键 `_hash_key(source, url, title, published_at)`。
4. `upsert_news_items` 入库；`backfill_news_tags` + `news_tag_dict` 打标签；`enrich_news_body` 补正文。
5. `start_news_ingest_scheduler` 后台线程周期执行，`NEWS_INGEST_INTERVAL_SEC`（默认 900s；≤0 关闭）。
6. 保留策略：`enforce_news_retention` 清理过期；`ensure_news_within_caps` 控制总量。

## 9. 外部依赖

| 依赖 | 用途 | 失败行为 |
|---|---|---|
| PostgreSQL | 社区 7 张表 + news_items | 写失败抛错由路由转 5xx |
| 外部资讯源 | 采集 | 单源失败不阻塞其他源，下周期重试 |
| ResearchEngine | 展示日线（经 market_data_bff） | 502 透传 |

## 10. 数据依赖

| 存储 | 说明 |
|---|---|
| posts / post_comments / comment_votes / post_votes / post_favorites / notifications / community_reports | 社区全量 |
| news_items | 资讯（含标签/正文/关联代码），去重 hash，保留策略清理 |

## 11. 异常处理

| 异常 | 行为 |
|---|---|
| 非管理员执行管理操作 | store 抛 `PermissionError` → 路由 403 |
| 帖子/评论不存在 | `KeyError` → 404 |
| 参数非法（板块/状态/长度） | `ValueError` → 400 |
| 资讯源失败/超时（约 20s） | 跳过该源，日志记录，下一周期重试 |
| 重复资讯 | hash 去重 upsert，不产生重复行 |

## 12. 性能要求

- 帖子列表/热门榜：分页 + 索引查询；热门按互动指标聚合。
- 资讯采集单次 ≤ 每源 12 条；单源超时约 20s；整轮采集与用户请求解耦（后台线程）。
- `list_news` 过滤走 SQL 条件，无外部搜索依赖。

## 13. 风险

- 社区管理端点在路由层只做 `require_user`，管理判定依赖 store 内 role 参数传递；新增管理端点若漏传 role 会退化为普通用户（需评审约定/测试覆盖）。
- 资讯页端点当前无鉴权（匿名可读，含手动 `POST /api/news/ingest`），是否收紧为管理员待确认。
- 外部资讯源无正式契约（页面结构变更即失效），UNSUPPORTED_SOURCES 机制用于显式降级。
- 正文增强/标签回填与采集串行，源多时单轮耗时上升（可调度参数调节）。
