# 策略研究模块 流程设计

## 1. 流程说明

覆盖策略回测端到端（含 RE 网关交互）、内置策略目录同步、策略库管理、策略广场发布与浏览。

## 2. 参与模块

| 参与者 | 职责 |
|---|---|
| frontend | 策略编辑器、回测页、历史、报告、广场页 |
| `routers/strategy.py` | 资产 HTTP 入口 |
| `routers/re_gateway.py` | `/api/backtest/strategy` 薄转发（见 ResearchEngine网关模块） |
| `strategy_store` | 项目/运行/摘要/blob |
| `builtin_strategies_store` | 内置目录镜像 |
| `user_strategy_library_store` | 用户策略库 |
| `strategy_plaza_store` | 广场快照 |
| ResearchEngine | 策略目录、回测执行、结果生成 |

## 3. 正常流程

### 流程 A：策略回测（端到端）

```text
1. 用户在策略项目页配置（代码/内置 strategy_id + 日期/费用参数）
2. 前端 POST /api/backtest/strategy（require_user）
3. 网关 forward_re：POST RE /api/backtest/strategy（timeout 1800s）
   - RE 已异步：202 + run_id → 前端轮询 GET /api/backtest/strategy/{run_id}（60s 超时）
   - RE 同步：长等后直接返回结果
4. 结果返回前端（净值/指标/持仓/成交）
5. 前端 POST /api/strategy/runs 保存运行记录：
   strategy_store.save_run
     ├─ write_run_blob：完整结果 gzip → backend/data/strategy_run_blobs/
     └─ PostgreSQL 存摘要（slim_strategy_result_for_db）
6. 报告页 GET /api/strategy/runs/{run_id}：摘要 + blob 还原展示
```

### 流程 B：内置策略目录同步

```text
POST /api/strategy/library/sync
  → builtin_strategies_store.sync_builtin_strategies_from_re
      → RE GET /api/strategies
      → upsert builtin_strategies（展示/请求元数据）
  → 页面 GET /api/strategy/library 读镜像
```

### 流程 C：用户策略库

```text
创建库 → add_library_strategy（代码/引用入条目）
       → POST mark-detected（标记已检测）
       → GET archive（查看代码归档）
```

### 流程 D：策略广场

```text
发布：用户选一次满意运行 → POST /api/strategy/plaza
      build_snapshot：_slim_metrics + _downsample_curve(≤360 点)
      → INSERT strategy_plaza_items（published）
浏览：GET /api/strategy/plaza（列表）/ {item_id}（详情 + view_count+1）
管理：作者或管理员 hide → status=hidden（管理员可见）
删除：作者 DELETE
```

## 4. 时序流程（策略回测轮询）

```text
前端 -> re_gateway：POST /api/backtest/strategy {strategy_id|code, start_date, end_date, params}
re_gateway -> RE：POST（timeout=1800）
RE --> re_gateway：202 {run_id} （或同步结果）
re_gateway --> 前端：202 + Location: /api/backtest/strategy/{run_id}（poll_url 已改写为本站路径）
loop 直到终态
  前端 -> re_gateway：GET /api/backtest/strategy/{run_id}（timeout=60）
  re_gateway -> RE：GET 同路径
  RE --> 前端：running / completed(结果) / failed(原因)
end
前端 -> strategy 路由：POST /api/strategy/runs 保存
```

## 5. 异常流程

| 异常 | 触发 | 处理 |
|---|---|---|
| RE 不可达/超时 | 提交或轮询 | 502 + 明确文案；前端保留配置可重试 |
| RE 校验拒绝 | 策略/参数不合法 | 透传 RE 错误 |
| run 不存在/无权限 | 详情/删除 | 404/403 |
| 同步失败 | RE 目录接口不可用 | 保留旧镜像；接口报错 |
| 广场条目隐藏 | 审核或作者自隐藏 | 列表对普通用户不可见 |
| blob 缺失 | 详情读取 | 降级摘要 + 提示（待确认实现细节） |

## 6. 状态流转

```text
回测 run（RE 侧事实）：submitted/running → completed / failed / canceled
运行记录（SV 侧产品记录）：saved →（备注/标记更新）→ deleted（库行 + blob 同删）
广场条目：published ⇄ hidden（管理员可见 hidden）；deleted
内置镜像：synced（每次同步覆盖 upsert）
```

## 7. 并发处理

- 运行记录以 run_id 唯一；同 run 重复保存以 upsert/唯一约束兜底（待确认）。
- 广场 view_count 为简单自增，高并发下计数可容忍偏差。
- 同步镜像为覆盖式 upsert，无版本合并。

## 8. 幂等设计

- 目录同步幂等（覆盖 upsert）。
- DELETE run/plaza 重复调用安全。
- 回测提交非幂等（每次新 run_id）；重复提交去重待 RE 契约确认。

## 9. 超时和重试

| 调用 | 超时 | 重试 |
|---|---|---|
| 回测提交 | 1800s（兼容同步长等） | 无自动重试 |
| 轮询/取消 | 60s | 前端轮询即事实上的重试 |
| 目录同步 | RE 请求默认超时 | 手动重试 |
