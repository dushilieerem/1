## 这次要解决的问题

保留公司产品的模块导航、六个业务环节和可人工操作的专业工具。让同一个研究任务在各环节产生可追溯的版本和证据，同时允许研究 Agent 根据工具结果决定修代码、改假设、请求数据或停止。页面展示、编辑研究状态；页面访问顺序不控制研究系统的执行顺序。

这里没有另做一个自主研究产品，也不要求人逐字段审批。Agent 和人工操作使用同一套工具契约、权限、任务与资产记录；人工可以从任意已有资产开始研究。不会因某位因子研究员尚未完成本轮工作，就锁住策略研究。

## 建议体验顺序

1. 保持“检验失败 → 自主返工”，点击“委托 Agent 完成研究”，确认本次授权。
2. 观察 F1–F4 自动推进。E1 未达标后，Agent 返回 F2，创建 H2；H1 和 E1 保留。
3. 打开“版本与记录”或“任务与产物”，查看版本来源和失败依据；打开报告可以悬停查看示例净值。
4. 运行时点一个其他环节，页面不会被强行跳走；点“跟随 Agent”才重新跟随。
5. 点击“暂停并接管”，再“另开人工分支”。手动修改保存在新分支；继续原研究时不覆盖该分支。
6. 最后停在“待人工复核”；可以预览独立复核角色的审批交互。所有审批仅为原型状态。
7. 切换“数据不足”或“范围外变更”，体验不同暂停原因。“人工研究”可以自行编辑、采纳助手建议和使用工具。

“推进一步”是原型讲解控制，不是正式产品要求人逐步点击。自动场景约半分钟；暂停时单步不会恢复连续播放。切换场景/新建任务有确认，当前场景可以导出。

## 工作台结构

| 区域 | 用户需要知道 / 可以做什么 |
| --- | --- |
| 左侧业务导航 | 保持管理驾驶舱、业务模块、协作与管理；其他模块链接回原 V3，不清空其他成果 |
| 因子工厂三级视图 | 研究工作台、因子资产、任务与产物，避免全部工具挤在一页 |
| 研究状态条 | 当前执行环节、具体动作、暂停原因、接管/继续/处理请求 |
| 六步环节导航 | 表示工作的业务位置与已有产物；可以点击查看，不代表必须串行审批 |
| 中央专业工作区 | 人可编辑的假设、表达式、实现、参数、报告与因子卡片；Agent 的修改直接落在同类产物中 |
| 右侧研究助手 | 当前行动、工具结果、下一步、对话补充、工具和权限；不单列无法对应产物的“思考动画” |
| 版本与实验 | H1/H2 等研究版本、E1/E2 等输入快照和报告；失败也保存，不以新代码覆盖旧报告 |

## 六个环节及 Agent 职责

下列是职责拆分，不是强制六个独立进程/模型。可以先由一个研究协调 Agent 调用专业能力，依据评测再拆多 Agent；独立验证、规则判定和审批权限不能由同一个研究 Agent自行放宽。

| 环节 | 人工工作与输入 | Agent 能力 / 工具 | 产物与可回退方向 |
| --- | --- | --- | --- |
| F1 研究起点 | 研究方向、已有因子与可用数据 | 研究策划：目录检索、参考证据整理、拟题、输入可用性检查 | 任务、输入与比较清单；数据不足发出数据请求 |
| F2 假设与计划 | 机制、表达式、窗口、目标、预设门槛 | 假设研究：可证伪机制、候选方案、实验设计、授权内修订 | 有版本的假设与计划；允许从 F4 返回，产生 H2，不覆盖 H1 |
| F3 因子实现 | 定义、算子、字段口径、现有实现 | 实现能力：代码编辑/生成、静态校验、受限执行、错误诊断 | 代码与依赖快照；工具错误返回修复实现，机制问题返回 F2 |
| F4 研发检验 | 已固定的候选、数据、成本、基准、比较清单 | 评测与诊断：平台因子计算、IC、分层、成本/稳定性分析、相关性去重 | 实验与报告；决定修复、修订、停止或进入验证 |
| F5 独立验证 | 达标候选与冻结输入 | 验证执行器：完整性检查、冻结、一次独立评测、证据归档 | 独立报告；失败终止该候选，不用验证反馈反复调参 |
| F6 资产管理 | 候选定义、全部证据、用途和局限 | 研究报告能力：整理因子卡片、申请复核、跟踪后续表现 | 待复核包；人工决定研究用途，其他准入和交易权限另行管理 |

跨环节研究协调职责：维护任务目标和授权，选择下一个工具/步骤，处理停止条件，避免重复调用和并发覆盖。步骤角色不是固定人类岗位，也不要求机构为每个内部能力配置一个人。

## 人机共同编辑约定

- 运行分支与当前查看的分支分开。查看旧版本或另一环节，不中止后台任务，也不强制跳页。
- Agent 正在使用的版本只读；可暂停，或另开人工分支。在正式系统中，暂停需要先禁止后续调度，再处理已发出的工具调用，不能假装撤销已经开始的计算。
- 含实验/复核证据的版本不可原地编辑。变更形成新版本，旧报告仍绑定原代码、假设、数据和参数。
- 助手建议先展示差异，再由人采纳到草稿；后台研究已获授权时，其授权内修改可直接生成版本并记录理由。
- 人工意见是可追溯输入，不自动等于扩大授权。研究范围、门槛、费用设定、数据权限或预算变化需单独确认并形成新计划。
- 研究员、独立复核人、共享准入及实盘审批者仍需真实权限隔离；原型中的“复核视角”只是体验角色切换。

## 停止和证据规则

- 未达到预设研发门槛：记录失败，在许可范围及预算内继续研究，不将所有失败送给人审批。
- 数据/工具异常：记录 incomplete/error，不伪造 0、正常报告或失败收益；重试绑定新输入或明确复用原输入。
- 高相似或比较不完整：不能称为合格新因子；已有因子复现与新发现分别标记。
- 达标且独立证据完整：提交人工研究复核，停止自动审批。
- 独立验证失败、达到候选/资源上限、人要求终止：停止并归档。后续研究需新计划；不可删除不利试验或用封存区间无限筛选。
- 范围外请求：可拒绝并要求继续原研究；同意分钟数据等新范围时应另建计划和数据授权，而非悄悄沿用原候选的通过状态。

原型中的 IC、相似度等阈值仅用于讨论交互，不是通用因子准入标准。

## 开发接续边界

本聊天目前承担产品经理职责。真正业务接入由开发人员完成，优先复用既有因子库、ResearchEngine 因子计算/回测、数据视图、报告和认证权限接口。不要复用个人版前端来替代机构端工作台。

所需后端契约至少包括：任务/授权版本、假设/实现版本、带幂等键的工具任务、不可变实验输入、事件与产物引用、暂停/恢复、人工分支、权限变更请求、独立验证/复核记录。运行状态必须来自后端，不能靠页面定时器生成。正式实现应在已有量化任务与迭代表基础上评估扩展，不在未协调时重复建设数据库表。

本版只提出上述契约，不声称这些能力已完成；现有系统实现状态以开发交接和 PRD V3.8 为准。需要先解决的开放问题：多用户并发编辑、人工分支如何正式交回 Agent、不可比因子清单策略、验证区间防泄漏、预算幂等计数、服务重启后的恢复及审批角色授权。
