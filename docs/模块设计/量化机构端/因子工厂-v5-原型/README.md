# 因子工厂 V5：研究系统 + 人工工作台（交互原型）

状态：2026-11-05，Claude（主产品经理）定稿，交开发实现；正式需求见《因子工厂V5-需求规格.md》。前端交互原型，场景数据；不调用模型、计算服务或真实审批，不修改服务器 V4、PRD V3.8 或任何业务代码。

打开：`index.html`（本地静态服务 `.claude/launch.json` 的 `workspace-static`，端口 8790）。右下角“演示控制”可切换身份（研究员 / 复核人 / 负责人）、暂停或单步推进模拟、显示设计说明；顶栏切换中 / EN。

## 核心主张

因子研究的主体是一个**持续运行的研究系统**：研究决策 Agent（F0） 根据结果自主选择下一步，可以修实现、修订假设、开分支、换方向或放弃。页面不驱动研究，而是给人观察、介入和亲自研究的地方。人仍然掌握课题、授权、预算和入库决定。

## 五个页签

| 页签 | 给谁 | 能做什么 |
| --- | --- | --- |
| 研究运行 | 负责人、研究员 | 系统状态与预算；课题看板（运行 / 待复核 / 等待数据 / 等待授权 / 完成 / 放弃）；研究树；分支详情；暂停、给意见、从任意分支接手；研究系统组成与实时动态 |
| 人工研究 | 研究员 | 接手的分支按工具使用（起点、假设、实现、检验、封存验证、提交），不要求顺序；右侧研究助手调用同一套工具，改动先确认；可交回 Agent 或归档 |
| 审查 | 复核人 | 只审通过门槛的候选，但列出课题全部试验（含失败、重复、放弃）；门槛按当前试验总数校正；独立复核 Agent 意见；入库 / 退回补证 / 归档 |
| 因子库 | 所有人 | 统一口径指标、近 60 日 IC 走势、来源与状态 |
| 能力与评测 | 负责人 | 研究系统组成；业务鱼骨图 F1–F6 对应的能力单元与评测集；编排方案对照实验（计划，未运行）与拆分规则 |

## 建议体验顺序（约 5 分钟）

1. 打开即可看到 T2 自主运行约 30 秒：H1 失败 → 修订为 H2 → 显著但与库内因子重复 → 正交化开 H2a → 达标 → 封存验证 → 提交候选 C2。点击检验标签可看报告。
2. 点 T1 看完整研究树：修订、三路分支、因重复放弃、换方向放弃、人工分支 H2c。
3. 点 H2c → 打开工作台 → 检验：E6 未达标（t 2.40 < 按 6 次试验校正的 2.64）→ 助手诊断 → 采纳建议 → 校验 → 再检验 E7（门槛升到 2.69）→ 封存验证 → 提交，生成 C3。
4. 审查：研究员身份下按钮禁用；切到复核人，勾选确认后入库，因子库出现新因子。注意 C1 的门槛随 T1 新增试验而提高。
5. 能力与评测：每个 AI 功能点如何成为可评测的专职单元、F0 的位置，以及三种编排方案的对照实验设计。

## 相对 V4 的变化

1. **统计规范进入交互**：每个课题一本只追加的试验台账；显著性门槛按试验数做多重检验校正（演示用 Bonferroni，可选 Holm / BHY）；人工检验同样计数；封存样本每个候选只用一次；新颖性同时对比库内因子和待审候选。
2. **研究树**：一个课题多条分支，显示修订、分支、换方向、放弃及其原因，替代单线 H1→H2。
3. **课题看板**：多个课题并行，各有预算、状态、等待原因，人一眼看到哪些需要自己。
4. **人工分支交回 Agent**：人工分支的代码、试验和说明成为研究决策的输入，计入同一台账和预算。
5. **检验维度**：IC 衰减（1/5/10/20 日）、五分组、扣费多空、换手、ICIR；报告绑定当时版本。
6. **能力与评测页**：每个 AI 功能点落成专职单元 + 评测集；补出 F0 研究决策；形态与编排方式交给评测和对照实验决定。

保留 V4 的：公司导航与六个业务环节（作为工具而非流水线）、一次授权、暂停接管、人工分支不被覆盖、超范围请求需授权、独立验证与研究隔离、AI 不批准。

## Agent 子系统结构

| 层 | 形态 | 职责 |
| --- | --- | --- |
| 课题调度 | 规则程序 | 课题排队、并发上限、跨课题预算；以后可按评测改为 Agent |
| F0 研究决策 | Agent，每个课题一个实例 | 根据结果决定下一步：改实现、修订假设、开分支、换方向、放弃、申请封存验证、提交 |
| F2 假设研究、F3 因子实现 | 子 Agent，有自己的小循环 | F2 可并行提出多个假设；F3 自行“编译—报错—修改”，交回校验通过的实现 |
| F1 起点检索、F4 检验诊断、F6 因子卡 | 能力单元，单次调用 | 调用工具并解读结果后返回 |
| F5 独立复核 | 独立 Agent | 不共享研究上下文，执行封存验证与复核意见，只给建议 |
| 数据视图、因子计算、试验台账、封存样本、查重 | 确定性服务 | 不由模型决定 |

每个 AI 功能点都是一个专职单元，有提示词与工具版本、评测集和得分，可以单独优化。F0 是在业务流程上补出的“决定下一步与回退”的功能点。单元的形态由评测决定；编排方式（固定顺序流水线 / 研究决策 + 专职单元 / 人工基线）用同预算对照实验比较，让效果说话。

## 演示边界与待定问题

- 所有数值、评测得分、研究结果为演示；对照实验仅为计划。
- 待定：显著性校正口径（按课题还是按全模块）；新颖性线与相关性定义（Rank 相关的平均绝对值）；封存区间滚动规则；多课题并发的预算分配；人工分支交回后的合并策略；复核人与研究员的权限隔离实现。
- 后端可复用：本地自主研究版的运行器（动作白名单、预算预留结算、检查点、分层筛选与 AI 复核），以及服务器 V4 已列的任务 / 版本 / 幂等工具 / 暂停恢复契约。
