# 因子工厂 V5 · Agent 研究子系统改进

CR-100 · 2026-11-09 · 产品/算法设计：Codex
状态：基于现行源码、真实 A/B 试验与一手文献的实施规格；尚未完成新版方法开发或性能评估。

## 1. 决策

“因子研发”是可替换内部方法的 Agent 子系统，而不是把全部任务塞进一个提示词，也不要求一个页面等于一个 Agent。

保持 CR-083 的四个业务环节。内部先采用“研究规划、因子实现、证据诊断”三个职责与受约束控制器；真实计算、预算、权限、封存和准入仍由确定性服务负责。三个职责可分别优化提示词、工具与记忆，后续某职责可再替换为多 Agent 或搜索算法。首轮不引入新的大框架，不开启并行算力搜索。

## 3. 实测与代码问题

- A 自动任务生成两版源码并完成两次真实检验。E1 有效日数59不足60且显著性未过；E2 观测60、RankIC 0.040558，但 NW t=1.63461 仍低于 K=2 时门槛2.24140。系统正确停止，未查全库、未封存、未入库。
- A 的首版使用 turnover，而研究说明限定 OHLCV：应将字段约束放入可校验的结构化契约，不能只靠自然语言。
- B 人工版本 RankIC=-0.009901、NW t=-0.339124、有效日数61，复核驳回。不据此反向取负伪装新发现。
- f0_agent._context 主要提供 gate、状态和少量历史编号；缺少与所选分支绑定的完整实现、可用研发诊断和失败经验。
- 首次自主执行直接调用 F3，未利用 F1 已有的资产目录/研究背景能力；_revise 又通过通用助手重写决策假设，可能产生语义漂移。
- 初始提示固定举20日窗口、截断内容，未按已冻结短研究窗提示有效样本约束。
- f0.stop_when 将连续 development_failed 都当作“无实质修订”，停止原因与实际行为不一定相符。

A/B 是有限样本的功能证据，不能用两次失败归因于某个模型，也不能宣称以下设计一定产出合格因子。

## 5. 统一契约与版本

### 5.1 ResearchContract

由后端从当前授权、数据视图、任务计划和 RE 能力生成：

- 任务、研究家族/父试验、机构、数据版本、固定证券范围；
- 已冻结研发/封存区间、预测持有期、方向、IC口径和全部门槛；
- 可用字段、算子、缺失值规则、可用数据日数和已实现预热能力；
- 历史报告当时K/门槛、当前累计K、下一次新增市场试验的next_trial_K与精确门槛、剩余试验/封存预算、模型余额、受控计算限制；复用同一份既有真实证据不假增K；
- 人工建议及其目标版本、当前控制版本。

available_fields 是“数据能力 ∩ RE能力 ∩ 本次任务字段限制”；F1、F0、F3共用。用户明确只用OHLCV时，不能自动加turnover。没有预热参数时禁止伪造 warmup_sessions 或减少60日要求。

样本可行性预检只读日期、字段覆盖及静态算子要求；保守估计不等于实际有效观测，最终以 RE 的因子与标签对齐结果为准。若当前约束不足，明确报缺口/提出范围申请，不能自动换日期。

### 5.2 Proposal / Diagnosis

Proposal 至少保存：hypothesis、mechanism、required_fields、expected_direction、parent_branch/candidate、change_scope、expected_effect、falsification、evidence_refs。没有试验时允许引用数据能力/资产元信息，不编造 E1。

Diagnosis 先从已保存报告生成确定性摘要，再由模型解释：
- 实际门槛值与失败项；
- 若已有对应系列：覆盖不足日期、有效样本、研发内分段 IC、分组结果与换手；
- 与父试验的实现差异和指标差异；
- 已完成/未完成检查边界。

报告缺失的维度标记未知，不调用额外未记账回测补数，不从封存结果制作调参上下文。模型意见必须能对应 evidence_refs，不能将文字“合理”写成 passed。

每份诊断必须保存 metric_type、evaluation_stage、candidate_id 和 report_id。若门槛是 RankIC，显著性和分段统计须来自对应的 rank_ic_series；Pearson IC 可以另列，但不得替换为同一门槛证据。研发报告不能因通用提示中的“样本外”字样被标成封存验证。前端简写精度不改变后台全精度判定。仅有40只事后固定证券与零费用收益时，应保留其研究样本与成本局限，不能描述成可交易的全市场超额收益。


#### 机器产物边界

控制器提供不可由模型改写的上下文：contract_id、method_version、task/project、父E/H与冻结源码身份、metric_type、当前K和下一次真实试验门槛。模型输出只允许描述与选择，不能重新填写这些权威值覆盖原契约。

- Proposal：action沿用现有控制器白名单（run_test/revise/pivot/request_seal/stop）、hypothesis、mechanism、required_fields、change_scope、expected_effect、falsification、evidence_refs。parent引用只能来自本次允许选择的证据集合，具体执行身份由控制器绑定。
- Implementation：source、entry、used_fields、lookback说明、与Proposal逐项对应说明。字段/源码/因果性工具检查结果独立保存，不能采用模型自报的“已通过”。
- Diagnosis：确定性 facts 与模型 interpretation 分开保存。facts 由报告适配器生成，包含报告/E/H身份、评分口径、完整精度门槛结果、有效样本、缺失诊断与已检查范围；interpretation 只含带证据引用的发现、可证伪解释、下一步建议与不确定性。
- 真正的 gate_passed、resource_allowed、approval、trial_count 和 next_threshold 一律由现行服务计算；结构解析失败最多在原额度中作明确修正，失败后保留记录并停止，不能改用自由文本假装执行成功。

可将已完成A任务作为无新增市场计算的回归材料：E1的n=59与NWt=1.1764是两项不同失败；规划E2时必须看到K将升为2、门槛约2.2414。E2的n=60已过线但NWt=1.63461未过，不得继续以1.96为目标或称已完成正式查重。该例只验证证据理解和契约遵守，不能作为方法提高收益的证据。

### 5.3 方法版本

首批命名 bounded-factor-rd-v2。新运行固定 method_version、prompt版本与配置身份；运行中不因服务更新悄悄换方法。历史记录无此字段时标为 legacy，不推定旧调用使用新版。现有 CR-080 方法接口优先复用，不另建第二套管理控制台。

每个职责先用一个模型任务，独立 TaskSpec 和结构化输出；正常一轮至多规划、实现、诊断三个主要模型步骤。已有功能可复用并合并冗余调用，取消“规划完再用通用助手重写同一假设”。模型预算遵守用户最新明确授权，不因更换内部方法自行扩额，也不偷偷换计费模型。

### 5.4 真实调用额度（加载前补项）

CR099只读核对发现：当前服务器有账号每日调用次数和全站可配置额度，但全站token上限为0（旧设置关闭），F3生成任务也未显式设输出上限。不能据此宣称旧版本“空间累计1,000,000 Tokens、各模块200,000 Tokens”已经迁移或正在强制执行。混合实测已在创建/调用之前暂缓，先补本产品预算，不改共享全站配置。

2026-11-09 用户在获知历史至少180,331 Tokens及46次生成缺少用量后，明确答复“可以，而且这点token算个啥。。1个亿token都行”。据此，本项目后续Agent研究新授权额度最高100,000,000 Tokens；旧可确认用量和未知历史继续单列，不以新授权伪装旧记录已经核清，不再把旧200,000模块余额作为本批启动阻塞。此授权只用于本项目，不修改公司共享全站/账号限额、模型选择或计算资源限制。开发仍须先补真实计量及明确调用上限。

- 审计现有用量能否按机构、任务与调用来源可靠归属；全站数字不能直接冒充本机构因子累计用量，缺失历史不能默认为0。迁移基线与不可归属项单独记载；不能声称未知余额已经核准。
- 调用前在本产品事务中预留输入保守上界与明确max_output，检查本产品已生效授权与剩余额度；旧空间/模块限制的替代关系按本次授权显式记录。相同调用身份幂等，但每次真实重试单独记账。
- 有provider用量则按实际结算；超时、响应丢失或usage缺失保留预留/待核，不因失败立即释放额度。能确认未发出的请求可释放；不自动重复计费调用来补回执。
- F0规划、F1资料、F3实现与人工助手路径共用守卫；不能靠入口切换绕过。隔离替身测试不写真实用量。
- 模型方法版本与已冻结研究预算保持；超限明确等待，不能静默换模型、改上限或丢弃历史。仅用户新授权改变额度，本规格和模型不能自行加额。

## 6. 研究循环与停止规则

1. 检查固定契约和剩余额度；复用已有资料工具，给出有依据的首个方案。
2. 在执行之前记录提案与父证据。优先做一个可解释的实质改动，避免同轮任意加权、换窗口、翻方向后无法归因。
3. 实现与检查：明确字段、因果性、方向、假设对齐。对相同源码/AST进行去重，防止空格或变量名变化被当成新研究；不把AST差异当“新因子认证”。
4. 通过现有冻结执行服务提交一次检验，所有实际返回指标按现有台账计数。纯静态检查/合成前缀检查不是市场试验；有真实指标就不能隐藏为“预检查”。
5. 生成研发诊断、更新同任务记忆，再自主决定继续、换分支或停止。分支可并存，计算仍串行。
6. 已达当前数值要求但完整对照未完成时，保留证据并等待依赖，不能自动大规模补算或宣称可准入。
7. 完整研发门槛满足后才申请冻结验证；人独立决定研究用途入库。失败可以提交研究复盘。

停止应区分：试验/模型预算耗尽；相同实现反复出现；数据或工具不支持；连续计算异常；明确证据不支持当前假设；人工暂停；资源限制；等待正式对照。若保留“连续三次统计失败”策略，应如实如此命名并记录，不能写成无实质修订。首批优先按已冻结预算和明确无改动来停止，不通过新建同一搜索任务重置K。

## 7. 研究记忆与数据隔离

首批仅使用当前任务及用户已获授权的资产元信息/既有复盘；成功、失败、未完成均保留，取有界最近记录和相关例证。记录使用了哪些条目，不只拼接一个成功样例。跨机构私有研究不得检索；未获授权的个人聊天不进入共享训练集。

不把原始长报告全塞入提示词。保留完整证据在存储，生成有界诊断视图；截断时保留字段/门槛/方向/版本这些硬约束，显式记录被省略的非关键材料。

未来可引入语义检索、树搜索、bandit、自动模型训练等方法，但须作为可比较的新版本，不在本批直接替换现有计算环境。

## 8. 与前端、人机协作的关系

前端继续呈现四环节、假设/试验/候选、当前动作和研究历程。内部多 Agent 展示在可展开运行详情中，使用真实工具事件与简洁决策摘要，不暴露模型隐藏思维链或伪造辩论。

研究员可随时查看证据、提交建议，或明确暂停后接手。CR-099 的控制版本、冻结 E/H 来源、迟到结果保护、交回绑定与预算连续必须成立。新增 method_version/诊断产物不要求增加新的一级页面。

- P2：在事前固定预算和窗口下跑新方法的真实自主及混合试验；记录未达标结果，不以最好一个样本宣布方法优越。
