# 因子工厂 V5：业务流程与用户体验改版

版本 1.2 · CR-083 · 2026-11-09 · 产品经理 Codex · 开发 张新迪 · 分支 dev-zxd。

状态：依据用户会后反馈重做因子模块的业务表达与交互。本文与配套原型是本轮开发依据，交互场景不代表真实功能已实现。真实启动故障单独按082/084立即修复，不等改版。

## 1. 本次必须改变什么

1. 默认呈现清晰业务环节、当前工作和可操作成果。研究树移入详情，仍保存全部分支和试验。
2. 主界面统一使用“挖掘任务”，按钮“启动挖掘”；不使用“课题”。历史用户自填标题和后端topic_id保留，不能批量篡改历史记录。
3. 一次“创建并启动”真正开始有限预算自主研发，用户不用接连点F2/F3或“交回”才能开始。
4. 默认新因子挖掘，不预选老因子后悄悄当复现运行。复现/改进已有因子是明确的另外两类任务。
5. 因子库统一呈现。删除“SVQuant已有/平台内置”来源导航，按业务分类、多级标签、可用状态检索；用户不需要理解迁移和存储实现。
6. 首页不展示F0/F1、AC编号、内部UUID、能力实验方案和大片“待接入”。业务上确实不可用的操作明确原因，不能把不可用隐藏成可用。
7. 先完成真实任务纵向链路。CR-080方法边界仍有效，但适配器扩展、算法对照面板、微调平台延后，不作为本轮必做依赖。

## 2. 四个业务环节与责任角色

这四项是稳定业务职责，不是必须部署四个进程，也不强迫每个内部模型只做一件小事。

| 环节 | 输入 | Agent职责/工具 | 输出与完成条件 | 人工介入 |
| --- | --- | --- | --- | --- |
| 1 研究准备 | 挖掘方向、授权范围、数据视图、预算；可选资料或参考因子 | 研究准备Agent：理解目标，检索已有因子和历史试验，核对可用字段、股票池、频率；复用目录/数据接口 | 研究任务说明、数据清单、可执行范围与检验计划；缺数据明确等待 | 创建时确认范围和预算；超范围由负责人处理；无需每条假设逐次批准 |
| 2 因子研发 | 固定任务说明和研发数据；既有研发证据 | 因子研发Agent：提出假设、生成受限实现、调用RE研发检验、分析结果、修订/分支/停止；复用F0/F2/F3/F4能力 | 一个或多个有实现与研发证据的候选；或有原因的未达标归档 | 给意见、暂停、人工改版本并检验、交回；同一工具、台账和预算 |
| 3 独立验证 | 冻结的候选、全量试验记录、固定政策 | 独立复核Agent整理/解释证据；计算服务执行封存、相关性/重复性及完整性检查；不能由模型填指标 | 固定版本的验证证据包，通过后进入待审批；缺服务等待，未通过按政策结束 | 查证据和局限；不能临时降低门槛或替换封存结果 |
| 4 审批入库 | 合格证据包、因子说明、分类/标签建议 | 成果管理Agent整理报告与标签建议；平台在人工决定后登记资产，AI不能批准 | 审批决定、因子版本、报告、权限和分类标签；入库仅授予研究用途 | 独立复核人批准/退回补证/驳回；研究员不能自审 |

日常研发的“读资料—改假设—改代码—检验—再修改”集中在第2环节内部。环节之间通过固定产物与状态交接，不要求逐条互相聊天。阶段不是单行道：数据问题可以回准备；超范围走授权；研发检验失败在第2环节继续。独立封存失败不能把具体结果反馈给研发后继续调参重测同一封存区间，沿用既有政策归档/复盘。

## 3. 用户首页与任务详情

配套原型：[因子工厂改版](../../../frontend/public/quant-delivery/v5/factor-factory.html)。它替代旧因子首页、审查入口与因子库的对应交互基线；其他业务模块继续V5。旧factor.html与factor-methods.html保留为历史设计参考，不作为本轮因子首页底稿。

### 3.1 导航和首屏

原型顶部场景/身份切换和明确标注“设计样例”的注释用于评审，不能复制进正式业务界面。正式界面展示真实环境、实际身份与证据。静态原型不实现真实后台执行、数据库持久化或资源调度。


- 保留公司统一左侧业务导航和视觉主题。因子模块只设三个主入口：“挖掘任务 / 待审批 / 因子库”。
- 首页主操作“启动挖掘”，次操作“人工研究”。任务列表只列名称、真实状态、当前环节、更新时间和必要的待办；支持搜索与按状态过滤，默认运行/待处理优先，历史任务不铺满首屏。
- 选中任务后，上方四环节导航显示完成/当前/未开始；每环节标责任角色。点环节只看该环节内容，不能触发执行或假装流程前进。
- 主区是当前成果与工作：准备说明、假设/实现、检验摘要、验证报告、入库结果。右侧显示“正在做什么、最近真实操作、是否需要你处理”。内部调用详情可展开。
- “研究历程”展开后保留H1/Ha/Hb研究树、虚线、各轮试验与版本；“全部试验”保留K/统计细节。主卡只显示“已检验2次 / 上限8次、当前第3版”，不把额度消耗当完成百分比。
- “人工研究”进入当前任务的工具页，不新建另一条不计账路径；旧工作台路由保留可深链。能力与评测从Agent管理或更多菜单进入，不占首屏。

### 3.2 创建与自动启动

新建框默认“新因子挖掘”，另可显式选择“改进已有因子”“复现已有因子”。新挖掘只需方向（可选系统建议方向）、简短目标；范围与预算使用机构允许的默认值并可查看。选择“系统建议方向”只在已有授权数据和预算内，不是无限发任务。

- 新挖掘不要求先选择已有因子。参考因子选填且标“参考/对照”，不能将它直接当新发现成果。
- 原型默认显示日频可用范围；无分钟数据时不提供可执行的分钟选择。数据范围来自实际接口，不写死原型样例。
- **一次启动已确认**：点击“创建并启动”本身就是用户对当前所示范围与预算的执行指令，创建成功后自动启动F0，不追加二次确认、不要求再点“启动研究”。研究角色仍需真实权限。任务试验预算预填机构已生效政策默认值，在已有授权内可调整；若未配置默认值，创建前要求明确填写。原型8次是场景值，开发诊断1次不是产品默认；不因此提高机构累计模型费用上限。
- 主按钮“创建并启动”，次按钮“保存草稿”。主按钮提交后显示“正在提交”；收到运行标识后显示“排队/研究准备”，不能仅创建topic就声称启动。
- 服务资源约束：同一任务不得重复启动并行编排；计算按受控队列执行。上线前由开发测定单任务数据规模与内存峰值，设置工作区并发/数据范围上限和明确的排队、超限错误。超限进入等待或失败并保留记录，不能无限重试。小样本资源诊断不能算完整研究验收；全库相关性需要单独资源评估，不能偷偷缩成单参考后声称全库通过。
- 后端复用项目/任务/分支/F0服务，建立一次可恢复编排；使用同一请求幂等身份，失败重试不重复创建项目或重复扣费。部分创建成功但启动失败时保留同一任务，明确失败并提供“重试启动”。
- 初始分支状态为待启动/准备中；“人工接手”只能由实际接手事件产生。旧source=manual不能推断用户接手。
- 一次启动后在授权内连续生成、研发检验、迭代、申请验证并送审；无需用户逐页确认模型草稿。复核/授权/明确人工接手时才等待人。
- 新发现第一次候选必须有模型生成或人工编写的实际定义/实现及出处；已有公式可以作为对照，但必须标“基线复现”，不得计作新因子产出。最终是否足够不同由真实查重决定，不承诺每次都发现新因子。
- 关闭页面不停止后端工作；刷新后恢复同一运行。浏览器轮询只读状态，不负责推进研究。

### 3.3 状态和异常

后端提供明确的业务阶段、执行状态、最近事件、绑定产物和阻断原因；前端不按打开页签或最大试验号猜运行状态。

| 情形 | 用户看到 | 可做动作 |
| --- | --- | --- |
| 任务尚未提交执行 | 待启动 | 启动挖掘 |
| 已接受请求、尚未执行 | 排队中、提交时间 | 查看排队原因；可暂停 |
| Agent/工具在工作 | 所在环节、真实动作和更新时间 | 查看结果、暂停、给意见/人工接手 |
| 数据/计算服务缺失 | 等待数据/计算服务，具体缺项和处理方 | 查看详情、刷新状态；必要时请求处理 |
| 超范围/预算不足 | 等待负责人授权；已用量和所需变更 | 负责人处理；研究员不自行加总额 |
| 模型/系统故障 | 运行异常，所在环节和用户可理解的原因 | 重试/反馈问题；技术原文在详情 |
| 研发预算用尽且未达标 | 未达标，已结束；结果与尝试保留 | 复盘或经授权再开运行，不能清零旧记录 |
| 进入人工独立审查 | 待审批，责任人/权限明确 | 查看冻结证据；独立复核人操作 |
| 已批准且登记成功 | 已入库，因子版本与入口 | 查因子、报告、用于后续研究 |

异常不能写成“研究失败”或“待人工复盘”掩盖服务故障。不能显示停止但按钮仍只有“暂停”。无事件显示尚无记录；有事件流断连显示更新中断，不编造工作日志。研发失败与系统异常分开处理，既有报告不覆盖。

## 4. 人工操作和授权入口

- 研究员仅在机构已授予的研究权限、数据范围和预算内创建/启动任务；扩大权限、范围或额度仍由负责人处理。独立复核人只读研究内容，不创建任务、改实现或发计算；不能因原型提供身份切换而在真实产品开放角色自选。沿用真实权限校验，必要变更先报业务方。
- 每个环节使用成果表单与真实工具，自动模式下Agent填入版本化结果，人可查看。人工修改先暂停到安全边界，派生人工版本；已执行产物只读。人工检验计入同一台账。
- 给意见只成为下一决策输入；不得暗中改门槛、预算、封存或数据范围。意见关联任务和版本并有提交回执。
- 授权入口：任务头部“范围与预算”查看当前授权；需要变更时右侧“需要你处理”出现授权卡。负责人打开卡，在同一抽屉看旧值、新值、理由、消耗和影响并批准/拒绝；不另建全局审批平台。
- 采用CR-080第4.1规则：can_manage审批；新计划版本；旧证据/K/消耗/曝光保留；拒绝按原范围继续。普通研究意见不替代授权。异步执行仍受全局暂停约束。
- 本轮中文完整路径和键盘操作为验收要求，现有英文入口不能假切换；完整双语从本轮阻断项后移为明确待办，不因此拦住真实因子交付。该优先级调整覆盖AC-18的交付次序，不表示双语已完成。

## 5. 因子库：按用户找因子的方式组织

### 5.1 分类与标签

默认是一套统一因子目录。删除“SVQuant已有”“平台内置”“迁移资产”等产品入口。相同因子以稳定身份去重展示；不因导入一次多出一份资产。

- 一级业务分类例如量价、基本面与规模、风险与波动；二级沿用现有category_id/category_label（动量、反转、流动性、估值等）；标签可多选（数据、频率、风格等）。这是业务分类层级，不把库存放位置当一级类目。
- 一级到二级映射用版本化字典，二级ID继续用平台已有值；未知类别进入“待分类”，不由名称猜测。目录没提供标签时显示“未标注”，不捏造。实际分类与数量按可访问目录生成，样例名称不能写死生产。
- 来源/作者/方法、导入时间、计算服务等在详情中按需要展示；来源不代表质量、审核或使用权限。
- 首期复用现有标签字段/类别和目录接口；机构自研因子标签与类别随成果登记保存。Agent可建议，复核人确认；研究员不能改公共官方分类或其他机构因子。

### 5.2 查找与使用

- 搜索支持名称、代码、说明和标签；输入与分类/标签/状态组合过滤。同组多标签使用明确的“包含任一”，不同维度取交集。选父类别包含子类；变更筛选回第一页，支持清空。
- 显示已选条件、结果数量、排序、分页。搜索结果为空给“清空筛选”，不要把0结果当目录接口失败。
- 权限过滤先于搜索、数量和分页，不能泄露其他机构私有因子。331规模可以基于完整授权目录前端过滤；若服务分页，不能只搜已加载页并声称搜全库。
- 默认列：因子名称/代码、业务分类、标签、可用状态、报告、操作。指标展开或按相同口径可比较时显示，附数据/区间来源；历史参考指标不冒充当前统一验证。
- 可研究、已审核、暂停等状态由实际权限和审核记录生成，不由“导入/内置/AI”来源推断。导入参考不自动升级为V5审核通过；原平台已授权的研究使用不因本次UI迁移被无故锁住。
- 详情包含定义、参数、数据依赖、适用范围、固定报告、版本、审核记录、来源与局限。提供“查看报告”“用此因子研究/改进”，复用现有接口；不跳回个人版前端。

### 5.3 已查明可复用的能力

- `frontend/src/lib/factorCatalog.ts`：FactorMeta/categoryId/libraryLabel/tags、loadFactors、类别顺序；`/api/factor/re-catalog?all=1`全目录。
- `frontend/src/pages/FactorLibraryPage.tsx`与`FactorPickerModal.tsx`：名称/代码/说明检索、类别筛选、分页、目录缓存和用户库操作逻辑可参考/抽取；机构页面继续统一V5样式，不整页复用个人端。
- 机构现有imports/reference、library和候选证据API保留；新增标签写入或层级字段时按公司业务DB规范迁移并汇报业务方。
- 当前源码提供类别与平面tags，不等于已实现完整多级标签管理；缺的只补业务映射/元数据层，避免重做计算引擎或全量重算因子。

## 6. 页面文案和信息层级审查
