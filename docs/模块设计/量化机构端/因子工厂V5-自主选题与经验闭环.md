# 因子工厂 V5 · 自主选题与经验闭环

版本 1.0 · CR-102 · 2026-11-10 · 用户已批准开始实施。
产品与验收：Codex 主会话；业务开发：原 factor_developer。
实施顺序：先完成 CR-101 执行与排队可靠性，再实现本文。本文批准开发，不代表功能已上线或已启动新研究。

## 1. 目标与范围

用户一次开启已授权范围内的自主研究，系统读取真实数据能力、因子目录和历史研发证据，自行提出并启动值得验证的研究；在任务内自主迭代、停止或送审，并将可复用经验用于下一次选题。人可以指定方向、提出意见、接手和独立审批。

保留“挖掘任务 / 待审批 / 因子库”和任务内“研究准备 / 因子研发 / 独立验证 / 审批入库”。不另建岗位平台、聊天首页、向量数据库或训练平台；三项职责不要求三个新 Agent 进程。

| 职责 | 输入及工具 | 输出 |
| --- | --- | --- |
| 研究规划 | 已授权范围、实际数据与引擎能力交集、因子目录、本人及明确共享的研发记录 | 一项有依据、可证伪且符合范围的提案，或有理由的等待 |
| 研究执行 | 固定任务、研究方法、研发证据与人工意见；复用 F0、实现、RE 与台账 | 真实版本/试验/停止结论；需要时返回修订假设 |
| 评估与积累 | 确定性检验事实、失败原因和冻结证据 | 合格候选送审；结构化研发经验；独立人作准入决定 |

首版使用现有模型，不新增模型供应商、不微调，不扩展策略模块。当前任务、真实历史、手动工具和审批契约保留。

## 2. 授权与用户行为

1. 在机构已生效的研究范围内，普通研究不逐项人工批准；“开启自主研究”即允许系统在该范围内选题并排队启动。
2. 系统保存授权人、机构、范围版本、方向偏好、开启/暂停时间。后台每次发调用前核对成员仍有效、原权限仍在、授权版本未被撤销。
3. 范围来自实际生效政策，包括数据字段/视图、股票范围、研发和验证区间、预测口径、计算限制、试验政策。模型不能选择更宽的范围、增加权限或修改门槛。若尚无有效范围，明确“请先确认研究范围”，不使用原型样例兜底。
4. 首版同时运行1项后台研究，排队、父子动作及未知物理调用沿 CR-101；自动规划也通过现有后台队列执行，不绕过并发保护。轻量人工咨询依原规则可用。
5. 累计 Token 采用 CR-101 unlimited，并继续实际计量；单次服务容量、超时、公司日调用规则和计算资源边界仍如实处理。
6. “暂停选题”停止新增自动规划及尚未转成任务的提案应用；已经创建的研究保留其状态，用户可在任务上点“暂停”。不得把暂停选题显示成已停止所有物理计算。
7. 最终因子入研究库仍需独立人工审查。旧复盘、研发通过或模型推荐均不直接变成批准。
8. 当前真实验收继续40只、每次评分不超过93日、原任务最多2次研发/1次封存；本文不自动扩大这些范围，不改旧任务或把它们转为自动生成任务。

## 3. 事件驱动的最小规划器

复用 F1 的数据/目录读取和模型调用链，增加真实研发证据输入与可校验提案。不要保留旧 F1 人为偏小的3000输出/60秒作为新规划器无说明的限制；按已核的单次模型契约保存方法快照与实耗。

### 3.1 什么时候运行

首次开启、用户更新方向、授权范围出现新的可用资料、或上一项研究明确结束时，产生一个持久触发。
- 同一授权只保留一个尚未处理的触发；重复事件按输入指纹合并。
- 当已有待执行任务或研究仍在运行时，触发保留，优先执行现有任务，不预生成一长串自动任务。
- 同一个输入快照只规划一次。结论为“暂无值得执行的方向”时，不因轮询、刷新、登录、时间流逝或重复结束事件反复调用模型。
- 人工明确“重新考虑”可以生成新触发，记录原决定与新的请求，不能无限自我重试。
- 旧任务处于技术等待或请求结果未知时，优先恢复原身份，不用新建任务掩盖故障。
- 资源暂不可用可在实际恢复事件后继续；技术错误不解释为研究假设失败。
- 现有任务的数据视图固定不变。首版自主授权使用明确固定视图；current变化只提示有新版本，未授权换版不自动换数据重新研究。

### 3.2 输入与产物

规划快照固定：授权版本/实际字段与可计算口径/数据身份/因子目录摘要及指纹/去重后的研发经验和证据编号/相关任务谱系与消耗/用户方向。先按授权与相关性检索，再提供有界证据摘要；不能只取30个任务名字。

一次规划只输出一项 proposal 或 wait。proposal 至少包括：
- title、hypothesis、mechanism、expected_effect、falsification；
- required_fields、forecast_horizon_sessions；
- why_now、difference_from_existing；
- evidence_refs（只能引用输入中真实可见的编号）；
- related_research_refs（续作、相关尝试；未找到也要明确）。
wait 输出具体原因及能改变决定的条件。

数据/工具范围、角色权限、股票/日期、政策、K、运行身份、审批结果都由程序确定，不能作为模型输出的权威值。证据资料中的自然语言也不构成执行指令。

### 3.3 从提案到真实任务

程序核对结构、字段/口径、证据引用权限、重复性、谱系、原授权和可执行资源；随后复用现有“创建并启动”事务服务，获得实际project/topic/初始H/F0/queue身份。
- 保留 planning_id + proposal_id → project/topic/F0 的唯一映射；网络重试、重复事件、重启只能恢复同一映射，不能新建另一项目或重复付费。
- 规划作业在映射持久化后结束并释放自己的队列占位，F0作为后续研究作业排队接续；规划器不持有槽位等待整个研究结束，也不通过额外嵌套线程绕过并发数。
- 选题调用不能长时间占数据库事务。返回时用原授权版本做CAS；暂停或撤权后的迟到输出保存但不创建/启动。
- 如项目已创建而启动失败，状态为原任务“启动未完成”，从原身份恢复，不能回到规划器重新选题。
- 提案为新挖掘不保证最终新颖。名称不同、反号、缩放、常见窗口变体不当作查重通过；正式数值相关性仍走已有门槛。
- 没有满足范围的提案时可以等待。不能用硬编码公式/名称伪装真实规划结果。

## 4. 经验记录与检索

先从现有台账、已完成研发报告、明确结束原因派生“经验视图”，不另造一份可被模型覆盖的数值真相。可以缓存摘要，但缓存必须绑定源记录ID/版本/指纹，源变化后重新生成。

每条记录包含：来源任务/假设/实现及报告、可见范围、固定数据/样本与窗口、事实结论、限制、结束类别、后续建议、源版本。事实由程序提取，解释标明由AI或人工提供，二者不能互相覆盖。

| 结束类别 | 选题时的使用方式 |
| --- | --- |
| technical_incomplete 技术未完成 | 不构成假设负面证据；用于修复依赖和避免重复无效提交 |
| insufficient_evidence 证据不足 | 记录样本/覆盖限制，不宣称普遍无效；条件未变不重复同一检验 |
| unsupported_in_scope 本范围内未获支持 | 降低相似尝试优先级；再次研究必须说明实质变化及其依据 |
| duplicate_or_no_increment 重复或无增量 | 引用已知定义/试验，避免改名重复；不是自动判定所有相近机制无用 |
| promising_development 研发有支持 | 可以进入独立验证；不能称已入库或已证明未来有效 |
| stopped_by_user 人工停止 | 记录停止意图；不伪装数值不达标，不自动换名重开 |

缺少证据不得硬归类为unsupported；历史不足显示“暂无可引用结论”。首版检索同成员私有记录和明确授权共享的研究资产，不能凭同机构就读取同事私人项目。

独立封存指标、逐日序列、方向性诊断及复核人的封存细节不得输入选题/实现模型。可以提供“该封存范围已经使用，不可据此再调参”的权限事实，不反馈封存表现高低。最终审查端仍可按权限查看完整证据。

## 5. 防止换任务清零：最小谱系约束

现有台账是事实来源。模型不能决定试验计数、重算豁免或“全新家族”。

- 服务端按授权及固定数据/证券范围/研发窗口/目标口径建立保守evaluation family；同授权产生的新任务默认属于同family。名称、机制表述、参数或项目编号变化不会重置累计K。
- family从已关联原台账派生累计计数；同一事实不重复计算。保留每任务本地序号，同时对后续新检验展示实际采用的family计数与阈值。
- family累计K是统计修正口径，与每任务max_trials分别存储和使用，不能混为一个变量。原任务的续作/改名继续使用原剩余次数；有实质新假设的新任务仍受授权中明确的每任务及整体上限。不能把当前单任务2次诊断限制误改成全机构永久仅能2次，也不能忽略授权本来存在的整体限制。当前真实验收仍只继续旧0cf任务，首个CR102真实自动任务另由PM绑定明确范围后开启，不在开发时自行增开。
- 引用旧研究续作时，继承可证明的来源谱系和已曝光研发试验；不能删除旧绑定后另建空family。手动/自动切换不影响计数。
- 相关范围/数据变更需要新授权，但历史谱系与封存曝光记录仍保存。授权版本号变化本身不是归零依据。
- 统计/计算次数边界继续执行原授权，耗尽就明确等待；不因Token无限而产生无限次市场检验。
- 首版不重写既有历史判定；只有新family关联的后续检验使用新身份与真实累计。当前0cf任务原K/上限不回写。
- 原有随K变化的研发门槛不宣称保证无限自适应搜索的整体错误率。本文不引入新的统计方法；需要扩展长期搜索能力时另做评测，不能通过文字包装已有检验。

若现有append/evaluate接口无法保证该绑定，先反馈产品与算法负责人，不以注释或只展示一个family_id替代实际门槛接线。

## 6. 最小前端增量

以 factor-factory.html + factor-factory.js/css 为当前底稿。只增以下内容，不重排四环节和现有工具。

1. 挖掘任务页上方一个紧凑的“自主研究”区块：开启状态、当前研究数/待启动数、下一步说明；“开启自主研究 / 暂停选题”、研究范围/方向入口。待审批/因子库页不重复铺此区块。
2. 开启弹窗显示真实授权范围、同时运行数和可选方向；不要求填写任务名称、假设或代码。没有有效范围时不允许假启动。
3. 任务列表/标题显示“系统发起 / 人工发起”；不要显示F1、原始UUID、SQL、技术租约或CR编号。
4. 研究准备中展示“为什么研究这个方向”：当前依据、与已有尝试的区别、采用的历史经验与证据入口。不是完整内部推理文本。
5. 等待状态显示原因与可改变条件；在运行时显示实际动作与更新时间，不能靠动画或定时切换制造工作。
6. 所有控制具有提交中/已接受/错误状态，刷新恢复后端真实状态。切页、打开详情、轮询都是只读。
7. 独立复核人不能开启/改变自主研究；机构研究员不能扩大授权。自动创建任务沿用实际责任账号，日志保存授权人和system发起来源。

原型场景可显式切换“已关闭/正在研究/等待机会/选题异常”；它们只验证交互，不接业务服务或模型，不能复制到正式运行状态。

## 7. 交付与验收

拆成两个可核验交付，首个不是全功能完成：
A. CR-101执行可靠性、固定数据、单并发与人机接力完成并真实复验；
B. CR-102规划/经验/创建映射/最小UI接入，再验真实自动立项。

| 编号 | 必须观察的行为 |
| --- | --- |
| AP-01 | 用户只开启范围内自主研究，不输入名称/假设/代码，系统真实规划并创建、排队、执行一个任务 |
| AP-02 | 规划中实际引用相关研发证据，能打开原来源；未知编号、他人私有证据、封存细节被拒绝/排除 |
| AP-03 | 技术失败不变成假设不成立；数据不足与研发未达标区别可见 |
| AP-04 | 返回wait后刷新/轮询/重复触发不增加模型调用；真正的新输入或明确重新考虑才能再规划 |
| AP-05 | 双请求/迟到回复/服务重启不重复创建或启动；已创建失败保留原身份恢复 |
| AP-06 | 暂停选题或撤权后的旧输出不启动任务；已运行任务仍可单独暂停/人工接手/交回 |
| AP-07 | 同一时间只有1个后台研究根任务，人工任务不被自动任务海量挤占；无浏览器也能推进 |
| AP-08 | 新建同family任务/改名/手动改动不能清零K、试验授权和封存曝光；新判定真实采用累计 |
| AP-09 | 真实已结束任务的经验影响下一次提案或等待判断，保留来源和为什么改变方向 |
| AP-10 | 符合硬门槛才送人工审查；未达标/技术等待均可如实结束，无自动批准或伪造好因子 |

先用隔离PG、受控模型返回与合成市场文件验证竞态/权限/状态，再在现有小范围上作一次真实模型验收；二者分开记录。真实研究可以最终不达标。当前没有完整全库相关性能力时，不宣称完成好因子正式准入。
