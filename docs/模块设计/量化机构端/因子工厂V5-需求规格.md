# 因子工厂 V5 · 需求规格

版本 V5.0 · 2026-11-05 · 产品经理：Claude（主），GPT/Codex 提建议 · 决策人：张新迪

原型：`docs/模块设计/量化机构端/因子工厂-v5-原型/`（预览 `/quant-delivery/factor-v5/index.html`），设计说明见同目录 `README.md`。本文是因子工厂的需求基线，与 PRD V3.8 冲突时以本文为准；其他模块仍按 PRD V3.8。

## 0. 决策摘要

1. **研究系统是主体，页面是观察、介入和人工研究的地方。** 因子研究由持续运行的 Agent 子系统完成，它能根据结果回头修改前面的决策（改实现、修订假设、开分支、换方向、放弃）。现有 F1—F6 页面保留，作为人工研究工具；页面访问顺序不决定执行顺序。
2. **每个 AI 功能点是一个可单独评测的专职单元**；在此之上新增功能点 **F0 研究决策**，负责决定下一步与回退，每个课题一个实例。
3. **研究规范是硬约束**：课题级试验台账、按试验次数校正的显著性门槛、一次性封存验证、对库内和待审候选查重。Agent 越自主，这些约束越必须由程序执行，而不是靠模型自觉。
4. **人掌握课题、授权、预算与入库决定。** AI 只建议，不批准；入库只授予研究用途。
5. **编排方式让效果说话**：固定顺序流水线、研究决策 + 专职单元、人工基线三种方式用同数据、同预算对照，结果决定后续结构。

不做：正式共享准入、实盘或资金授权、全平台无限自主运行、任意代码执行、为演示降低门槛或删除失败记录。

## 1. 用户与权限

| 角色 | 对应现有角色 | 可以做 | 不可以做 |
| --- | --- | --- | --- |
| 研究负责人 | `manager`（机构管理员）；如需新角色先报备 SVQuant业务 | 新建课题；授权与预算；批准扩展数据范围；修改研究政策（新版本）；暂停/恢复研究系统；提交对照实验 | 替代复核人做入库决定 |
| 因子研究员 | `quant_researcher` | 观察研究系统；给研究意见；从任意分支接手、人工研究、交回 Agent；提交本人分支的候选 | 修改授权、门槛、预算；复核自己提交的候选 |
| 因子复核人 | `quant_reviewer` | 读取本机构已提交候选的完整证据；入库（研究用途）/退回补证/归档 | 写研究、运行 Agent 或计算；复核自己提交的候选 |

研究系统（Agent）以“机构研究系统”身份运行，权限等于当前生效的授权版本，不继承任何个人的额外权限。

## 3. 核心对象

| 对象 | 关键字段 | 规则 |
| --- | --- | --- |
| 研究课题 Topic | id、方向、类型（新发现/复现）、数据范围（view_id 锁定）、研发区间、封存区间、预算（试验次数、Token、封存使用次数）、政策版本、状态 | 建立时锁定数据版本和区间；改范围须新建计划版本；与现有 `detect_projects` 对应或扩展 |
| 分支 Branch | id、parentId、来源（Agent/人工）、所有者、假设版本、实现版本、状态 | 一个分支是一版假设；有证据的版本不可原地修改，修改产生新分支或新版本 |
| 试验 Trial | 课题内序号 K、分支、实现快照哈希、数据版本、参数、结果、执行者（Agent/人工）、时间 | **只追加，不可删改**；人工检验、Agent 检验、失败和出错都计入 |
| 试验台账 Ledger | 课题的全部 Trial 与封存使用记录 | 门槛计算的唯一依据；课题页、审查页、导出都从这里读 |
| 封存验证 SealedValidation | 候选快照、执行者（F5）、结果、时间 | 每个候选最多一次；失败即终止该候选 |
| 候选 Candidate | 冻结快照、门槛结果、证据引用、提交来源 | 复用 `quant_factor_candidates` |
| 复核决定 Review | 候选版本、复核人、决定、理由 | 复用现有复核，决定绑定提交时版本 |
| 授权 Authorization | 版本、可自主/需确认/禁止的动作、预算上限、有效期、批准人 | 只影响之后的动作 |
| 研究事件 Event | 课题、分支、执行者、动作、工具调用、产物引用、用量 | 可核验的动作与依据，不保存模型私有思维链 |

数据落地：优先扩展现有 `quant_factor_candidates`、`quant_factor_agent_jobs`、`quant_factor_iterations`。试验台账和分支大概率需要新表；**新增表/迁移先向 SVQuant业务 和 数据业务 报备**，确认后再实施。

状态：

- 课题：排队中 → 运行中 ⇄ 已暂停；运行中 → 等待数据 / 等待授权 / 待复核 → 已入库 / 已完成（复现）/ 已放弃。
- 分支：进行中 → 未达标 / 已分支 / 已放弃 / 待复核 / 已入库；人工分支：人工进行中 → 已提交审查 / 已交回 Agent / 已归档。

## 4. Agent 子系统

### 4.1 结构

| 层 | 形态 | 职责 | 允许的工具 |
| --- | --- | --- | --- |
| 课题调度 | 规则程序 | 课题排队、并发上限、跨课题预算分配 | 读课题状态与预算 |
| F0 研究决策 | Agent，每课题一个实例 | 读台账与最新结果，选择下一步动作 | 只能发出 4.2 白名单动作 |
| F1 起点检索 | 能力单元 | 检索因子库、历史试验、数据目录，给出研究起点与重复风险 | 因子库检索、历史试验查询、数据目录 |
| F2 假设研究 | 子 Agent | 提出可证伪的机制假设，可一次提出多个候选假设 | 文献/知识检索、机制模板、可证伪检查 |
| F3 因子实现 | 子 Agent | 把假设写成平台表达式或受限代码，自行编译—报错—修改，交回校验通过的实现 | 代码生成、静态校验、未来函数检查、受限试算 |
| F4 检验诊断 | 能力单元 | 调用检验并解读：未达标原因、暴露、衰减、重复 | 因子计算（RE）、报告读取、查重 |
| F5 独立复核 | 独立 Agent | 不共享研究上下文；执行封存验证、完整性检查，给出复核意见 | 封存样本（仅此角色可读）、完整性检查 |
| F6 因子卡 | 能力单元 | 整理证据包与因子卡 | 报告、台账读取 |

每个单元有独立的方法版本（提示词、工具清单、模型配置）和评测集。形态可以调整（例如能力单元改为子 Agent），条件见第 8 章。

### 4.2 F0 动作白名单

| 动作 | 前置条件 | 程序检查 |
| --- | --- | --- |
| `plan_hypothesis` | 无进行中分支或决定开新分支 | 调用 F2；新分支记入课题 |
| `implement` | 分支有假设无实现，或需修实现 | 调用 F3；只接受校验通过的实现 |
| `run_test` | 分支有校验通过的实现 | 计入台账；预算不足拒绝；同一实现快照重复检验拒绝 |
| `revise` / `branch` / `pivot` | 已有检验结果 | 产生新分支，旧分支和证据保留只读 |
| `abandon` | 任意 | 写明原因，分支只读 |
| `request_sealed_validation` | 最近检验在当前 K 下达标且查重通过 | 交 F5；每候选一次；课题封存次数未超限 |
| `submit` | 封存验证通过 | 生成候选，进入审查；停止该分支的自动改进 |
| `request_data` / `request_scope` | 缺数据或需超范围 | 课题进入等待，通知负责人；不自行扩权 |
| `wait` / `stop` | 预算不足、无合理方向 | 记录原因 |

每次动作前检查授权、暂停状态和预算；每次动作后持久化检查点。服务重启后从检查点恢复，不重发已可能计费的调用。

### 4.3 预算与停止

- 课题：试验次数上限、Token 上限、封存使用上限（默认 3）。模块：本月试验上限、Token 上限、并发课题数。
- 模型调用按保守上界预留、按实际结算；余额不足进入可解释的等待，不自动加额度。
- 课题停止条件：候选已提交且无其他进行中分支；预算用尽；连续若干次（默认 3）无改进；人工终止。

参考实现：本地自主研究版的运行器（动作白名单、预算预留与结算、检查点、分层筛选与 AI 复核）已在真实数据上跑过 71 个任务，可作为设计参考；服务器上暂无该代码，是否迁移由张新迪决定。

## 5. 研究规范与门槛

默认值属于研究政策 v1，可由研究负责人改为新版本；**不是公司正式准入标准**。门槛的阈值、校正方法和政策版本随候选冻结并展示。

| 检查 | 默认规则 |
| --- | --- |
| 计算完整 | 无未来函数、无数据版本漂移、计算无错误；缺失指标视为失败 |
| 覆盖率 | 研发区间平均覆盖 ≥ 90% |
| Rank IC | 主持有期日度截面 Spearman 均值 ≥ 0.02（方向按预登记） |
| 显著性 | Newey-West 调整 t 值 ≥ t*(K)，K 为该课题台账中的试验总数；默认 Bonferroni：t*(K) = Φ⁻¹(1 − 0.025/K)。K=1 时 1.96，K=5 时 2.58，K=10 时 2.81，K=20 时 3.02 |
| 新颖性 | 与冻结因子库**及本机构待审候选**的日度截面 Spearman 相关绝对值均值 < 0.70（复用现有新颖性服务口径） |
| 封存验证 | 封存区间 Rank IC 同向且 t ≥ 1.96；每候选一次；结果不得用于再调参 |

补充规则：

- **门槛按当前 K 计算。** 候选提交后，课题若新增试验导致 t*(K) 上升，审查页显示“门槛已变化”，复核时以当前 K 判定（保守口径；见第 10 章待定 1）。
- 人工检验与 Agent 检验共用台账；任何人都无法删除或修改试验记录。
- 复现型课题：与目标因子相关 ≥ 0.70 视为复现成功，记为复现，不作为新因子。
- 检验报告至少包括：Rank IC、NW t 值与当前门槛、ICIR（年化）、IC 为正占比、IC 衰减（1/5/10/20 日）、五分组超额、扣费多空、换手、覆盖率、最大相关因子；报告绑定当时的实现、数据和参数。

**计算能力依赖（不得伪造）**：当前 RE 的 IC 只支持未来 1 个交易日收益。多持有期 IC、中性化/行业内排序算子、日度 Rank IC 序列输出属于 RE 扩展（第 9 章）。能力上线前，界面对应项显示“计算能力待接入”，门槛只用已支持的口径，不用文案冒充。

## 6. 页面需求

### 6.1 研究运行

- 系统状态条：运行/暂停、授权有效期与批准人；课题数（运行/待复核/等待）、本月试验台账、封存使用次数、待人决定事项、Token 用量。负责人可“暂停全部”：不再调度新动作，进行中的计算完成后记录并停止。
- 课题看板：每个课题显示编号、类型、状态、当前动作或等待原因、试验 K/预算、分支数、最佳 t 与当前门槛。
- 课题详情：数据范围、台账、下一次检验所需 t；研究树（分支层级，每个分支显示实现、检验、封存、决定、放弃原因；检验可打开报告）；分支详情（假设、全部试验与决定、“从此分支接手”）。
- 运行中的课题页面实时更新，但用户手动选中其他分支时不被强制跳转，提供“跟随最新进展”。
- 动作：暂停/继续课题、给研究意见、等待授权时负责人批准（另建计划）或拒绝、查看数据请求。
- 右栏：研究系统组成（调度、各运行实例、正在工作的单元）、实时动态。

### 6.2 人工研究

- 页头：课题/分支、来源（接手自哪个分支）、课题台账 K、下一次检验门槛、剩余预算；交回 Agent、归档分支。
- 工具页签（不要求顺序）：起点（交接说明、相似因子含待审候选、数据可用性）；假设（保存为新版本）；实现（编辑、校验、请助手改进）；检验（每次运行计入台账，事前提示“第 K+1 次，需 t ≥ …”）；封存验证（仅达标时可申请，确认后冻结）；提交（清单齐全才可提交）。
- 研究助手：调用与 Agent 相同的工具；修改先展示差异，采纳后进入草稿；任何会花费试验次数的操作需人确认。
- 交回 Agent：人工分支的代码、试验、说明成为 F0 的输入；同一台账与预算。Agent 不修改人工分支。

### 6.3 审查

- 队列：候选编号、来源（研究系统/人工）、课题与分支、状态。
- 证据包：假设、表达式、数据与口径；门槛检查（按当前 K）；证据图表（研发与封存区间分色）；**课题全部试验**（含失败、重复、放弃，标出被提交的那次）；F5 独立复核意见与局限；可跳转研究树。
- 决定：勾选“已查看全部试验、封存结果和局限”后才能入库；入库（研究用途）/ 退回补证 / 归档。研究员身份不可操作；提交者不能复核自己的候选。

### 6.4 因子库

统一口径（股票池、区间、主持有期）的 Rank IC、t、换手、近 60 日 IC 走势与状态（研究用途/观察/停用）；来源区分平台内置、人工、研究系统。近期表现需要定期重算任务（P2）。

### 6.5 能力与评测

- 研究系统组成：人、Agent 与专职单元（标注形态）、确定性服务。
- 专职单元表：功能点、单元、形态、工具、评测集、当前得分、基线、版本。
- 编排对照实验：A 固定顺序流水线、B 研究决策 + 专职单元、C 人工基线；同数据视图、同课题、同预算、同门槛与封存样本；指标见第 8 章。只有负责人能提交实验计划。

## 7. 人机协作规则

- 人可以在任意分支接手（产生人工子分支），也可以新建人工课题；人工与 Agent 共用工具、台账、门槛。
- 研究意见作为 F0 下一次决策的输入并留痕；意见不扩大授权、门槛或预算。
- 暂停：阻止新的调度；已发出的计算完成后记录，不伪装撤销。
- 冲突：同一分支同一时间只有一个写入者；Agent 正在使用的版本只读。
- 超范围请求（如分钟数据）：课题进入等待授权；负责人批准则另建计划版本，原范围下的结论不沿用；拒绝则按原范围继续。

## 8. 评测与对照实验（P2）

- 每个单元维护评测集与评测记录：F0 历史课题回放（下一步与专家一致率、无效试验占比）；F1 相似因子召回；F2 专家评“可证伪且不重复”比例；F3 一次编译通过率与未来函数检出率；F4 失败原因判断一致率；F5 植入问题识别率；F6 证据包完整率。
- 方法版本：草案 → 评测 → 发布；编辑后旧评测失效；失败保留旧版本。
- 对照实验指标：通过校正门槛的候选数、封存验证通过率、每个合格候选的试验与 Token 成本、失败后正确回退比例（专家标注）、人工投入时间、入库后 3 个月 IC 保持率。
- 形态调整规则：某单元改变形态后，其单元评测显著更好且整体指标不下降，才发布新编排版本；否则回退。

1. **门槛按当前 K**：
   - 课题页、审查页一律按当前 K 判定，并同时显示“提交时 K / 当前 K”。
   - 待审候选若因 K 增加不再达标，审查页标“按当前 K 未达标”，复核人只能退回补证或归档，不能入库。
   - 已入库因子不回溯撤销；因子库显示入库时的 K。
2. **K 的计数口径**：K 是课题内对研发区间做过的检验次数，以“研发区间结果是否已被研究者或 Agent 看到”为准。
   - 计入：
     - 每次完成的研发区间检验，人工或 Agent 都算；
     - 自动迭代的每一轮；
     - 参数、窗口等变体，每个各算一次；
     - 结果失败的检验；
     - 出错但已经返回任何研发区间指标的检验。
   - 不计入（台账照记）：
     - 出错或取消、且没有返回任何指标的（outcome 记为 error / cancelled）；
     - 同一实现哈希、同一数据版本、同一参数的确定性重算（记为 rerun，引用原试验）；
     - 静态校验、编译，以及不看收益的冒烟运行；
     - 封存验证：单独记录，受“每候选一次、课题上限 3 次”约束。
   - 门槛只看课题建立时预登记的主持有期；同一报告里的其他持有期只作诊断，不另计 K。
