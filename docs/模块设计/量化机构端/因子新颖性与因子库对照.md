# 因子新颖性与因子库对照

2026-11-05 · V3.8 增量规格与真实验收。保留原 V3 的 F1—F6 导航和其他模块。

## 要解决的问题

回测达标不能证明因子是新发现。此前使用已有的一日反转演示计算、留档和复核，只能算已有因子复现，不能当成“挖出新因子”。新研究必须预先声明目的，并验证与已有资产的关系。

新发现仅指本次指定可访问库范围内的候选；不代表全球原创，也不代表已经证明组合增量收益。

## 页面与业务规则

| 环节 | 输入和工具 | Agent / 人工动作 | 产出与限制 |
| --- | --- | --- | --- |
| F1 研究起点 | 发布数据目录、本人研究、完整可访问因子目录 | 研究策划 Agent 读取既有目录摘要后提出可检验假设，可由研究员修改 | 保存实际读取数量、目录指纹、相似定义提示；文字比较不是数值去重 |
| F2 研究计划 | 新因子挖掘 / 已有因子复现；相关阈值、有效日数、配对股票数、覆盖率 | 人工预登记，与研究日期、方向、预算一起冻结 | 历史计划不自动升级为新因子研究；必须明确确认用途 |
| F3 因子实现 | 受限代码及校验、已有平台代码生成接口 | Agent 按假设和允许改进范围生成实现 | 改名和改注释不等于新因子；代码生成接口仍有提示长度限制，过长应明确停止 |
| F4 检验改进 | 既有 RE 回测 + RE 因子值对照 | 先保存研发报告；数值门槛通过后对完整冻结清单逐项计算 | 源码重复直接失败；尚未计算或不完整不得显示通过；失败报告保留 |
| F5 冻结复验 | 固定代码、同一数据版本、日期分离的样本外检验 | 研发数值和去重条件通过后执行一次复验 | 不使用样本外反馈继续自动调参；仍未实现跨接口封存 |
| F6 研究复核 | 冻结证据、逐项比较、报告与研究因子卡 | 合格候选自动送独立研究复核，人员给意见 | 新因子缺少完整通过的去重证据时，后端拒绝“研究支持”意见；无正式准入或交易授权 |

自动循环冻结可访问目录及本人代码，后续轮次复用相同清单。内置源码由 RE 读取，实际源码指纹随计算返回；跨轮来源变化停止搜索。未通过数值门槛时延后昂贵全库计算，明确标记 deferred，不视为新颖性通过。

## 门槛与计算口径

默认值只是可配置初值，不是公司已批准的研究政策：最大日绝对 Spearman 均值 0.8，至少 60 个有效交易日，每日至少 30 只共同有效股票，共同样本覆盖率至少 0.8。

1. 范围为平台内置目录和当前账号有权访问且具有可计算定义的自建因子，不包含无代码草稿或其他成员私有库。F1 覆盖全部目录条目，但单条为有限长度摘要并标记截断，不等于逐行读取全部源码。实际数量随库变化；本次冻结 334 个定义（331 内置 + 3 自建）。
2. 先做源码/来源去重：函数名、局部变量名、注释变化不能规避；这不是完整的代数等价判定。
3. 数值检验按同一日期、股票及研发口径对齐因子值，按共同有限值计算当日 Spearman，先取每日相关系数绝对值，再对有效日求均值。反号、缩放仍会显示高相关；不使用收益曲线相关替代。
4. 覆盖率分母为有效相关日的候选有效股票日总数，分子为共同有效股票日总数；有效天数另设门槛。常数、缺失或有效配对不足不是相关为零。
5. 所有比较对象须可计算且满足覆盖条件才可通过。任一有效对象已高度相关即可拒绝，即使其他对象尚不完整；不完整状态也绝不会通过。
6. 候选值复用原研发规格和窗口。参考因子默认至少 252 个前置交易日；更长依赖通过 max_window 声明。不足历史明确失败，不偷偷缩短。递归滤波更长历史的影响仍需专门评测。
7. 请求清单、候选源码、实际参考源码、数据发布和计算规格逐一核验；不同数据版本的结果不得拼接。
8. 残差 Rank IC、正交化后的增量、组合收益增量尚未实现；低相关不能替代这些检验。

## 系统实现及复用

机构 BFF 负责身份、可见库清单、冻结、门槛和送审；已有 ResearchEngine 的 DataEngine、FactorEngine、ExperimentManager 负责数据读取、因子计算和任务调度。没有在前端另写回测或因子计算引擎。

本次新增独立 RE 特性分支 `feat/quant-factor-novelty`，隔离工作副本和 127.0.0.1:18803 服务供联调。常规回测仍使用公司 9527；业务 BFF 18801、前端 19538 不变。共享 RE 服务未被覆盖；新接口合入和正式发布仍需维护方评审。

| 接口 | 行为 |
| --- | --- |
| RE `POST /api/factor/novelty` | 服务凭据认证；显式候选规格、参考清单、期望数据/源码版本；异步任务 |
| RE `GET /api/factor/novelty/{run_id}` | 实际处理进度、逐项统计和错误、来源指纹；其他类型任务不可读取 |
| RE `DELETE /api/factor/novelty/{run_id}` | 请求取消；在参考计算间检查，不能声称瞬间终止正在执行的单个计算 |
| BFF `POST /api/factor-workflow/candidates/{id}/novelty/retry` | 只对本人、同机构、数值已通过但对照服务未完成的固定候选重试；复用原报告，不重跑回测或新增候选；禁止并发循环 |

BFF 保存冻结目录、逐项证据和来源指纹；新增信息使用既有候选/迭代表 JSONB，本次没有新业务表。服务令牌只在忽略的本机配置中。

## 真实去重验收

- 原演示因子 `price_reversal_1d` 与本人库中已有定义匹配。将它以新发现方式检查时，源码门槛实际返回 failed；原有历史报告没有篡改。
- 使用真实行情和标准 RE 回测重新建立独立负例诊断：相同定义、反号、放大 100 倍，日绝对秩相关均值均为 1.0，有效 116 日、覆盖率 1；常数定义无有效相关性，返回 failed/空值而不是零。
- 首次诊断被数据版本变化拦截。独立诊断重新计算同一新发布版本，不替换原研发报告。原研究数据指纹以 `fe5e0771` 开头，诊断数据指纹以 `f1c21e4a` 开头。
- 对第三轮实现另做完整 334 定义的真实诊断（用于验证接口，不用于改写研究门槛）：处理 334，331 可计算，327 满足预登记覆盖条件；3 项截面无有效变化、4 项覆盖不足。有效比较最大值 0.365209，对照 `主因子库:SV01_0005`；最终 incomplete，不能称去重通过。
- 全库任务 `67cea4e9940f436da09ed3affa04595b`，约 172 秒。诊断原始证据保存在服务器 `.runtime/novelty-full-diagnostic.json`；不提交完整行情或私人因子代码到公共交付包。

覆盖不足的对象不得为了演示通过而临时删掉。后续须由数据/研究负责人修复数据，或在新的预登记政策中明确可比库范围；不能把本次不完整结果改称全库通过。
