## 二、数据模型（拟新增迁移 `0011_quant_factor_v5_ledger.sql`）

1. `quant_factor_topics`：把课题与 `detect_projects` 一一绑定，锁定 `view_id`、研发/封存区间、政策版本、试验/封存预算、状态。目的：课题建立后数据版本和区间不可悄悄变化。
2. `quant_factor_branches`：`id/parent_id/source(agent|manual)/owner_id/hypothesis_version/implementation_version/status`；一个分支一版假设，证据版本只读。
3. `quant_factor_trials`：**只追加**。`project_id/branch_id/trial_no(K)/implementation_hash/data_release_id/parameters/result_summary/report_id/executor(human|agent)/outcome(created_at)`；`UNIQUE(user_id,org_id,project_id,trial_no)`；`BEFORE UPDATE OR DELETE` 触发器拒绝修改。
4. `quant_factor_sealed_validations`：`candidate_id UNIQUE`、`snapshot_hash`、`result`、`report_id`、`executor_id`、`status`；每候选至多一行。

约束：`user_id/org_id` 只从 quant 会话取；`project_id` 外键到 `detect_projects(user_id,id)`；仅 `svquant_dev` 应用；不 seed、不清库。按产品答复 10.1-7：`trials/branches/sealed_validations` 对 project/topic 一律 `ON DELETE RESTRICT`，不用 CASCADE；有试验记录的课题只能归档，不能硬删。

**迁移编号与合入顺序（SVQuant业务 + 产品 10.1-10 确认）**：0010 已被 H5 `0010_invest_ai_agent` 占用并进生产，V5 改用 `0011`。`0011.sealed_validations.candidate_id` 依赖 `0006_quant_factor_candidates`，而 0006/0008/0009 尚未进 master；必须先把 0006/0008/0009 分批开 PR、用户合并，再让 0011 合入，不能从旧分支基点直接合。仍从 `dev-zxd` 开 PR 到 master，用户审批。P0 拆成 P0a / P0b 两个 PR（10.1-9）。

## 三、服务与接口

- `services/quant_factor/ledger.py`：`next_k`、`append_trial`、`threshold(K)`、`newey_west_t(series)`。
- `policy.evaluate`：按当前 K 计算 NW t 与门槛；保留覆盖、方向、回撤、观测数检查；门槛/政策版本随候选冻结。
- `service.run`：每次研发/复验成功或失败都追加一条 trial（含错误/取消）；候选状态仍保留现有语义。
- `service.validate`：改为一次封存验证；每候选一次，第二次 409；只允许研发达标且新颖性通过的候选。
- `novelty.py`：参考清单增加同机构 `review_requested` 待审候选；不把待审候选的封存结果带入。
- `review.py`：详情返回课题全部 trials、当前 K 与门槛；继续校验 reviewer≠submitter。
- 路由（均挂 `/api/inst/quant/factor-workflow`）：
  - `GET /projects/{id}/ledger`、`GET /projects/{id}/threshold?k=`
  - `GET /projects/{id}/branches`、`POST /projects/{id}/branches`
  - `POST /candidates/{cid}/sealed-validation`（researcher）、`GET /candidates/{cid}/sealed-validation`（reviewer）
  - `GET /reviews/{cid}` 扩展 trials；`GET /capabilities` 返回 `rank_ic_series / multi_horizon / industry_neutral` 等能力状态。

## 四、页面

- 研究运行：课题看板、系统状态条、研究树、台账（K、当前门槛、下一次检验所需 t）、实时动态；复用现有 `/quant/factor` 壳。
- 人工研究：F1–F6 工具页签；检验前显示“第 K+1 次，需 t≥…”；封存验证按钮仅在达标+去重通过时可用且只能一次。
- 审查：候选证据包含全部 trials（失败/重复/放弃标出）、当前 K 门槛、封存结论；保留研究员禁用与自审拦截。
- 能力未接入：Rank IC 序列/多持有期/中性化等在接口能力清单为 false 时显示“待接入”，不显示场景数值。
