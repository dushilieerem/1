## 二、数据模型（拟新增迁移 `0011_quant_factor_v5_ledger.sql`）

1. `quant_factor_topics`：把课题与 `detect_projects` 一一绑定，锁定 `view_id`、研发/封存区间、政策版本、试验/封存预算、状态。目的：课题建立后数据版本和区间不可悄悄变化。
2. `quant_factor_branches`：`id/parent_id/source(agent|manual)/owner_id/hypothesis_version/implementation_version/status`；一个分支一版假设，证据版本只读。
3. `quant_factor_trials`：**只追加**。`project_id/branch_id/trial_no(K)/implementation_hash/parameters/result_summary/report_id/executor(human|agent)/outcome/view_id/release_id/contract_revision/as_of/created_at`；`UNIQUE(user_id,org_id,project_id,trial_no)`；`BEFORE UPDATE OR DELETE` 触发器拒绝修改。
4. `quant_factor_sealed_validations`：`candidate_id UNIQUE`、`snapshot_hash`、`result`、`report_id`、`executor_id`、`status`、`view_id/release_id/contract_revision/as_of`；每候选至多一行。复现字段按产品 10.1-14 记录。
5. `quant_factor_imported_factors`：`org_id + source_library + source_factor_id` 唯一；保留 RE 原始 `factor_id`，不改编号。字段：原名、`display_name`、`definition`（内置目录只有说明，无源码，标“源码不可见（RE 内置）”）、来源 `svquant_existing`、状态 `imported_unreviewed`、`import_hash`、`source_repo/source_path/source_commit/imported_at`；指标快照 `metrics`（JSONB 可空）/`metrics_status`/`metrics_reason`/`view_id`/`release_id`（ifind/derived/free）/`contract_revision`/`as_of`。约束：`source IN ('svquant_existing')`、`status IN ('imported_unreviewed','reviewed','retired')`、`metrics_status IN ('pending','ok','not_computable')`，`org_id REFERENCES inst_orgs`，`source_factor_id NOT NULL`。幂等：身份字段冲突时只更新元数据并保留变更记录；指标重算只更新 metrics/status/reason/updated_at；不计 K；供机构共享因子库与新颖性对照读取，报告标 `imported_unreviewed`。数据侧与 SVQuant 均已确认无契约冲突。

约束：`user_id/org_id` 只从 quant 会话取；`project_id` 外键到 `detect_projects(user_id,id)`；仅 `svquant_dev` 应用；不 seed、不清库。按产品答复 10.1-7：`trials/branches/sealed_validations` 对 project/topic 一律 `ON DELETE RESTRICT`，不用 CASCADE；有试验记录的课题只能归档，不能硬删。

**迁移编号与合入顺序（SVQuant业务 + 产品 10.1-10 确认）**：0010 已被 H5 `0010_invest_ai_agent` 占用并进生产。V5 台账用 `0011_quant_factor_v5_ledger.sql`；AC-08a 导入表**单独用 `0012_quant_factor_imports.sql`**（不依赖 candidate FK，便于独立评审；仍随 P0a 交付）。`0011.sealed_validations.candidate_id` 依赖 `0006_quant_factor_candidates`，而 0006/0008/0009 尚未进 master；必须先把 0006/0008/0009 分批开 PR、由 mentor 审批合并，再合 0011/0012，不能从旧分支基点直接合。仍从 `dev-zxd` 开 PR 到 master，mentor 审批合并。P0 拆成 P0a / P0b 两个 PR（10.1-9）。

## 三、服务与接口

- `services/quant_factor/ledger.py`：`next_k`、`append_trial`、`threshold(K)`、`newey_west_t(series)`。
- `policy.evaluate`：按当前 K 计算 NW t 与门槛；保留覆盖、方向、回撤、观测数检查；门槛/政策版本随候选冻结。
- `service.run`：每次研发/复验成功或失败都追加一条 trial（含错误/取消）；候选状态仍保留现有语义。
- `service.validate`：改为一次封存验证；每候选一次，第二次 409；只允许研发达标且新颖性通过的候选。
- `novelty.py`：参考清单增加同机构 `review_requested` 待审候选；不把待审候选的封存结果带入。
- `review.py`：详情返回课题全部 trials、当前 K 与门槛；继续校验 reviewer≠submitter。
- `imports.py`：从 RE 目录 `GET /api/factors/{library}` 同步读取 331 条元数据，按 `org_id + library + factor_id` 幂等 upsert；**仅 manager 可触发**，导入到机构共享库；状态 `imported_unreviewed`。指标走后台批次（不逐条阻塞导入请求），RE 并发 ≤2，状态 `pending/ok/not_computable`（原因枚举），可断点续算、失败项单独重试；页面显示“计算中”或具体原因。不计 K，不写 candidates/trials；把导入项加入 `catalogue()` 的新颖性参考清单。定义用“说明 + `library_name/factor_name` 可执行引用”，标“源码不可见（RE 内置）”；后续补源码要留历史。
- 路由（均挂 `/api/inst/quant/factor-workflow`）：
  - `GET /projects/{id}/ledger`、`GET /projects/{id}/threshold?k=`
  - `GET /projects/{id}/branches`、`POST /projects/{id}/branches`
  - `POST /candidates/{cid}/sealed-validation`（researcher）、`GET /candidates/{cid}/sealed-validation`（reviewer）
  - `GET /reviews/{cid}` 扩展 trials；`GET /capabilities` 返回 `rank_ic_series / multi_horizon / industry_neutral` 等能力状态。
  - `POST /imports/svquant-existing`（幂等导入，manager/researcher）、`GET /imports/svquant-existing`（批次/数量/指标状态）。
