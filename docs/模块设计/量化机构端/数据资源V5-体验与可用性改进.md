# 数据资源 V5 · 体验与可用性改进

版本 1.0 · CR-094 · 2026-11-09 · 产品经理 Codex
状态：用户已批准优化方向；本文件与 data.html/data.js/data.css 为本批设计基线，正式业务实现待开发和验收。
关联：主PRD §5、总体路线 §7。保留数据资源MVP的只读目录、版本追踪、需求交接职责，不在研究端重建采集、清洗、发布系统。

## 1. 问题与本批目标

2026-11-09 实页有60项数据集，原型只有少量样例：长表无检索，详情出现在全表之后；数据适用性标签与字段限制不一致；版本使用卡会残留在其他页签；接口失败被空列表吞掉。本批改善“找得到、看得懂、能判断需要进一步确认什么”，保留已验证的权限与版本接口。
页面参考 [数据资源原型](../../../frontend/public/quant-delivery/v5/data.html)。数据与状态均为场景示例，不代表实际供应、质量检查或研究结果。正式页面不得导入该fixture。

## 2. 保留与不做

- 保留四个页签：数据目录 / 版本与使用 / 数据需求 / 质量。保留公司机构端外壳、紫色主题和导航。
- 复用已发布视图、目录和字段元数据、质量结果、需求单、研究版本锁定与机构/成员权限。
- 不更改共享数据平台current、采集源、存储、发布及修订流程；不自动修改已有研究绑定的版本。
- 本批不新增采集Agent、模型问答或“AI判定可回测”。AI助手可在后续基于版本化元数据引用出处，但不得替代适用性验证、授权或数据交付。
- 日频真实研究仍优先。分钟数据缺口不阻塞不依赖分钟数据的研究；目录显示分钟数据不等于公司已有全市场连续分钟历史。

## 3. 数据目录

### 3.1 首屏
上方显示当前发布版本、实际目录数量和有使用限制的数据集数量，提供版本入口。统计按同一版本/同一可见目录计算，不用原型数字。
搜索支持中文名、技术名称、字段名和字段中文名。筛选含分类、频率、使用说明；可清空，保留输入焦点，零结果显示清除筛选和提交需求。
正式接口如果只有字段计数而没有字段索引，应增加有界元数据索引/搜索能力或明确仅搜索名称；不能为了字段搜索逐个读取60张行情表。原型可直接查场景字段，不能据此说正式接口已具备字段搜索。
结果每页20条，显示总数与分页；原型为便于评审每页6条。筛选后回到第一页，返回详情保留筛选和列表位置。

### 3.2 列表字段
五列：数据集（名称+标识+类别）、频率与覆盖、使用前需要了解、发布与检查、详情操作。
发布和质量分别显示：
- 发布：已发布 / 未发布 / 状态待确认，来自实际发布成员与可用文件验证。
- 质量：本期通过 / 本期告警 / 本期未检查 / 检查结果读取失败。未检查不能自动解释为无数据，读取失败不能冒充未检查。
- 使用说明：有时点说明 / 有使用限制 / 适用性待确认。它是说明入口，不是执行授权和“可用于任何历史回测”的承诺。
列表优先展示关键限制，不能藏在窄屏右边。长说明两行摘要，完整内容在详情。

### 3.3 详情侧栏
打开选中数据集的右侧侧栏；正文独立滚动，标题、关闭和底部操作保持可用，Escape可关闭，键盘焦点进入且关闭后返回触发控件。1366/1024可用；手机可铺满宽度。
依次显示：名称与技术标识；三个独立状态；使用限制与可得时点；覆盖/频率/版本/更新时间；本期质量项目；字段名/中文名/可得口径/限制；折叠的来源与版本详情。
反馈数据问题会预填数据集标识与当前版本，用户确认后才生成需求。不能因为打开详情就新建工单或发起计算。
切换数据集时先明确加载对象，取消/忽略旧请求的晚到结果；版本变化不能把旧字段拼到新版本上。失败保留明确重试入口，不展示上一数据集作为当前结果。

## 4. 适用性与证据契约（必须先修）

### 4.1 独立维度
存在日期行、发布成功、质量检查通过、按历史可得时点使用，是不同维度。
尤其 industry_daily：逐日铺开的当前行业分类，不得显示成历史分类已获保证；sw_l1_code/name的latest_only、sw_l2未提供和ths_code口径各自说明。
日期范围只表示记录覆盖；date <= as_of只表示过滤条件，不能单独证明历史PIT。用户在研究参数中选定股票池/区间/字段后，还需后端校验实际范围和依赖。

### 4.2 数据依据
后端可在既有响应增补 evidence/version 字段（兼容旧消费者），建议：
- published: true/false/null，发布成员、物化和版本校验结果；
- publication_version / catalog_version / quality_version：可核验的实际来源；
- applicability: {status, summary, assessed_fields, evidence_refs}；
- field_availability: [{name, status, rule, note, source_ref}]；
- 元数据来源缺失/冲突时返回明确unknown/conflict，不默认通过。
只使用数据维护方提供的结构化版本契约和已核实、版本化的限制映射。禁止LLM猜测、仅按名称判断或用自由文本正则拼出“历史可用”。现有硬编码限制不得在改版中丢失；迁移时保留保守限制和出处。
monitor-data与current视图不是天然同一个快照。目录、字段、质量、发布成员必须按同一view/version校验；不一致时只标受影响项目，给出具体解释，不能把监测目录所有项目硬标已发布。
若上游没有字段级契约：先显示“字段适用性待确认”及现有原文，记录对接缺口；不伪造数据，也不把这项缺口扩展成所有日频研究不可用。未经证实的回测用途仍不得被自动批准。

## 5. 其余三个页签

### 5.1 版本与使用
列版本、真实发布时间、变更说明、可见研究数/入口。点击弹窗/侧栏展示该版本的使用对象，带业务名称与有权限的入口。
保留历史锁定，不因查询或当前发布更新自动迁移。
只对有权限对象计数和列出；研究员与负责人范围保持现有后端规则。没有权限可见记录与接口读取失败分别说明。
技术契约、manifest、存储目录放折叠详情，不直接占据用户首屏。
版本详情只属于此页签，切到数据需求/质量时必须关闭或移除。

### 5.2 数据需求
显示请求编号、内容、用途、范围、关联研究、处理状态、处理意见和交付版本；可打开完整详情。
“已提交”=服务端已保存，不等于数据负责人已接收或已调用任何数据采集。
MVP允许人工交接，产品称“数据负责人”，不要把Claude会话名当产品角色。明确交接责任人和可取得的交接信息，接收/处理/交付留痕；未实现自动转发时不写“已转发”。
状态复用 submitted/in_progress/delivered/unsupported；页面用已提交/处理中/已交付/暂不支持。负责人登记交付必须引用真实可用已发布版本；不存在、仅定义未物化的版本仍拒绝。既有研究员不能代替负责人登记交付。
提交超时保留表单和可恢复身份，重试防止重复需求；输入校验与只读权限均在前后端落实。需求详情/修改失败不应清空旧记录。

### 5.3 质量
显示当前版本及检查时间、总数、通过/告警/未检查数，支持状态筛选；点击到具体数据集检查项与影响字段。
项目无结果说明“本期未检查”，不能统一写“待接入”；接口/文件错误单独说明读取失败，不能把真实异常藏成未检查。
已发布不代表本期已检查；质量通过也不掩盖字段适用性限制。

## 6. 加载与异常

四个页签独立加载和重试：目录不可用仍可进入版本/需求页；版本、需求接口非200不得转成空数组并显示“没有记录”。
旧成功数据可保留但必须显示更新失败/数据时点，不能让用户误认为最新。
请求按当前数据集/版本/用户/机构身份隔离，失效响应丢弃；卸载后不更新界面。不改变现有鉴权，不因前端隐藏按钮当权限检查。
接口错误首屏给用户可行动的解释，内部错误码和技术诊断折叠。不能写SQL、内部端口、回执路径或未关联的开发事项。
原型演示控制支持目录失败、版本失败、需求失败、无发布数据；只供设计验收，不出现在正式产品流程里。

## 8. 真实发布格式与缺失口径补充
2026-11-09 实施澄清；沿用本批界面与权限范围，不改变数据平台。

- 现有物化版多数成员使用指向固定 release 的符号链接，不能要求所有发布数据物理复制在 view 目录。词法路径必须在当前 view 内；解析后的链接须与 manifest.source、同版 view 定义和受支持的 DATA_HOME 发布根/固定 release 一致。任意外部链接、错版本或路径越界仍拒绝，不因为存在就当有效发布。
- contract.path 可能指向 manifest 数据集目录内的具体文件。以已声明格式、包含关系、同一数据集 SHA 与发布身份核对，不仅凭两个路径字符串是否相同。日行情 wide_multiindex 的记录数可能为日期行数，不自动解释为证券×日期条数。
- 元数据可解析但类型错误、必要字段缺失也属于读取失败或依据待确认；不能落为“本期未检查”或0。各维度分别标注受影响范围。
- 目录原文、字段单位与版本契约存在差异时保留双方出处和原文，显示待确认。数据集时点限制照样保守生效。实际行业契约的申万二级当前快照有部分覆盖，不照抄原型样例的“未提供”；原型仍是标注的设计场景。
- 发布清单日期为空而其他目录有日期时，若契约指定以发布清单为准，正式覆盖显示待确认，其他来源只能作补充依据，不能声称连续完整历史。
- 数据需求响应丢失后的重试必须保持同一请求身份；同身份不同正文不得覆盖旧单；跨账号/机构不返回旧单。允许在现有主键与事务上做兼容扩展，不因此要求新增采集/工单系统。此前真实已保存记录、后续处理状态均不得被重试覆盖。
