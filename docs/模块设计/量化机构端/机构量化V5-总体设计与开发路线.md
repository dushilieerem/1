# SVQuant 机构量化 V5 · 总体设计与开发路线

版本 1.0 · 2026-11-06 · 产品经理：Claude · 开发：服务器 Claude Code 会话“张新迪” · PR 审批：mentor · 产品决定：张新迪本人

## 0. 原则：先完成，再完美

用户 2026-11-06 要求：产品先完成，能跑通，再去优化。本文据此规定全产品的开发顺序和每个模块的**最小可用版本（MVP）**。

1. **一条真实纵向链路优先**：数据视图 → 因子 → 策略 → 组合（模拟）→ 运行监控 → 复盘。每个模块先做到“真实数据能走通一遍、结果可查”，再回头打磨。
2. **每个里程碑都要能演示**：做完一个里程碑，研究员在 19536 上能实际操作，不是只有接口或单测。
3. **不做的事写明**：MVP 范围以外的功能放进“完善期”（第 9 章），不在 MVP 期间开工。开发中想到的改进写进进度文档的“完善建议”，不要顺手做。
4. **诚实标注**：未接入的能力显示“待接入”和原因，不用场景数据冒充；模拟和实盘严格区分，本期**没有实盘、没有真实下单**。
5. **复用优先**：已有后端接口、RE 回测、因子工厂 V5 的台账/分支/封存/复核/F0 框架，策略模块直接复用。新建前先查有没有现成能力。

## 3. M1 因子工厂“完成”的定义

不再追加新需求，满足以下即算完成，转入 M2：

1. QA-01～06 全部修复，产品经理浏览器复核通过。
2. F0 是模型驱动的研究决策：AC-10a～10d 通过（真实模型 + 真实 RE）。
3. 至少一个真实课题完整记录：多次试验 → 达标或明确失败 → （达标时）封存验证 → 人工复核。允许最终失败，记录可查即可（AC-08）。
4. F5 独立复核：MVP 可以是“独立上下文的模型复核意见 + 程序完整性检查”，不共享研究对话，复核人看到意见后人工决定（AC-17）。
5. 依赖外部合入的能力（R4 正式新颖性、逐日 PIT 股票池）标“待接入”即可，**不阻塞 M1 完成**，列入完善期。

## 4. M2 策略研究 MVP

### 4.1 基线

采用《策略研究V5-需求规格.md》（同目录，GPT 2026-11-05 评审稿，产品经理 2026-11-06 修订采纳），MVP 只做其中 S-P0a、S-P0b，并加入 S0 的最小自主推进。修订见该文件顶部“产品经理修订”。

### 4.2 MVP 范围

- **课题与计划**：从因子库选因子（V5 入库或导入的 331 个，导入因子标“未经 V5 复核”），固定股票池、基准、区间（研发 / 封存）、成本、调仓频率、门槛政策版本、预算。
- **受控策略模板（只做一种）**：A 股日频、纯多头、因子打分选前 N 只、等权、定期调仓。参数只有：因子与方向、多因子等权合成、N、调仓周期、股票池。不开放任意代码。
- **回测**：复用 `/api/inst/quant/backtest/strategy` → RE `/api/backtest/strategy`。报告显示净值、相对基准超额、最大回撤、换手、费用拖累、分年表现。引擎不支持的约束写明“未建模”。
- **台账与门槛**：复用因子工厂的台账/K 计数/分支/封存/复核框架（独立的策略表或带类型字段，由开发设计并报备），策略有自己的 K，不计入因子课题。
- **S0 研究决策**：复用 F0 的决策引擎（同一套“模型决策 + 白名单 + 程序校验 + 检查点”），动作白名单换成策略版：改参数（在授权范围内）、换因子组合、开分支、放弃、申请封存、提交。**F0 改造时就把决策引擎写成可复用的**，不要为策略再写一套。
- **页面**：研究运行（课题看板 + 研究树）、人工研究（工具页签 + 助手）、审查（进入统一审查中心的策略筛选）、策略库。能力与评测页 MVP 只读列表。

### 4.3 MVP 不做

多种策略模板、自定义代码策略、优化器、事件驱动回测、模拟跟踪账本（M4 用组合的模拟运行代替）、方法评测与编排对照。

### 4.4 验收

| 编号 | 用例 |
| --- | --- |
| ST-M1 | 研究员从因子库选 1～3 个因子建课题，配置模板参数，回测返回真实 RE 结果，报告字段齐全；引擎不支持的项显示“未建模” |
| ST-M2 | 每次看过研发结果的回测计入策略台账 K；同一配置确定性重算不计 K |
| ST-M3 | S0 读到失败结果后自主调整（参数或因子组合）并再次回测，理由引用上次指标；超出授权范围的动作被程序拒绝 |
| ST-M4 | 达标候选可申请封存验证（每候选一次），复核人在审查中心看到全部试验与封存结果并决定入库；研究员不能自审 |
| ST-M5 | 入库策略出现在策略库，显示来源因子及其状态、参数、证据、局限，可被组合模块选用 |

## 5. M3 投资组合与模拟执行 MVP

### 5.1 范围

- **组合方案**：投资负责人（MVP 由 `manager` 担任）选择研究入库的策略，设置模拟资金、各策略权重（手工或等权）、单票上限、行业上限。
- **风险检查（确定性规则）**：权重和为 100%、单票/行业集中度、策略间持仓重叠率、流动性（成交额占比上限）。硬失败不能提交。
- **审批**：组合方案固定版本后提交审批；审批人不能是方案提交人（MVP 若只有一个 manager，复核人 `quant_reviewer` 审批，写明是 MVP 安排）。审批写明环境=模拟、资金上限、有效期。
- **模拟部署**：审批通过后，服务端每个交易日收盘后根据各策略最新信号生成目标持仓和调仓清单（订单意图），按次日开盘价、预设成本模拟成交，记录模拟持仓、现金、净值。幂等：同一交易日重复运行结果不变。
- **调整与退出**：修改权重或策略产生新版本，重新审批；退出则停止生成订单意图，保留历史。

### 5.2 MVP 不做

真实账户连接、真实下单、优化器、容量模型、多账户。

### 5.3 数据来源

信号由策略的固定版本在当日数据视图上计算；若 RE 无法按日增量计算，可以每日重跑一次短区间回测并取最后一日持仓，开发在实施计划中说明方案。

### 5.4 验收

| 编号 | 用例 |
| --- | --- |
| PF-M1 | 选 1～2 个入库策略建组合，错误权重（和≠100%）、超集中度被拦截并提示原因 |
| PF-M2 | 提交人不能审批自己的方案；审批记录绑定方案版本 |
| PF-M3 | 审批后服务端（不依赖页面打开）每日生成订单意图与模拟成交，净值曲线可查；同日重复运行不重复成交 |
| PF-M4 | 修改权重产生新版本并要求重新审批，旧版本历史保留 |
| PF-M5 | 页面全程标“模拟”，任何位置不出现真实下单入口 |

## 6. M4 运行监控与风险 MVP

### 6.1 范围

- **服务端巡检（定时任务，不依赖页面）**：数据视图是否按时更新；因子/策略/组合任务是否失败或超时；模拟组合当日收益、回撤、单票集中度是否越过风险规则阈值。
- **事件**：巡检产生事件，有等级（提示/警告/严重）、影响对象、证据。同类事件去重合并。
- **保护措施（确定性）**：严重事件可按规则自动暂停相关模拟组合的新调仓（只影响模拟）。
- **处置与恢复**：风控负责人（MVP 由 `manager` 或复核人担任，开发确认角色映射）确认、处置、复测；恢复需要填写复测证据，确认收到告警和解除风险是两个操作。
- **归因与复盘（MVP 简版）**：模拟组合按策略拆分收益贡献；可从事件或归因结果“创建改进任务”，指定到因子或策略课题，写明负责人和验收标准。

### 6.2 MVP 不做

实盘监控、复杂归因模型（Brinson、风险模型归因）、告警外发（短信/企业微信）。

### 6.3 风险规则

规则表由管理员配置，带版本；MVP 预置：单日亏损、最大回撤、单票权重、数据延迟、任务失败。阈值是演示默认值，界面标注“需按机构政策校准”。

### 6.4 验收

| 编号 | 用例 |
| --- | --- |
| RK-M1 | 关闭页面后巡检仍按时运行，事件记录有时间和证据 |
| RK-M2 | 构造一次越线（如把阈值调低），触发严重事件并自动暂停该模拟组合调仓 |
| RK-M3 | 没有复测证据不能恢复；恢复后组合继续调仓，全程留痕 |
| RK-M4 | 归因显示各策略贡献且合计与组合收益一致（差异显示为残差） |
| RK-M5 | 从事件创建改进任务，任务出现在对应因子/策略模块 |

## 7. 数据资源 MVP

### 7.1 范围

数据采集、清洗、发布由数据平台（`svquant-data`，“数据业务”会话负责）完成，研究端**不自建采集**。数据资源模块 MVP：

- **数据目录（只读）**：当前发布视图 `views/current`，各数据集的字段、覆盖区间、更新时间、release、质量与时点口径说明（含已知限制，如行业为当前 vintage、部分指数成分仅快照）。
- **版本与血缘**：列出历史视图，哪些课题/策略/组合锁定了哪个视图。
- **数据需求单**：研究员提交数据需求（用途、字段、区间、频率），状态流转（已提交 → 数据业务处理中 → 已发布/不予支持）。MVP 可由开发把需求单同步给“数据业务”会话，或在页面显示“请联系数据业务”并记录。
- **质量状态**：显示数据平台已有的质量检查结果；没有的显示“待接入”。

### 7.2 MVP 不做

在本产品里配置采集任务、清洗规则编辑器、发布操作。

### 7.3 验收

DA-M1 目录与数据平台实际视图一致（抽 3 个数据集核对）；DA-M2 能看到某课题锁定的视图；DA-M3 数据需求单可提交并查看状态。

## 8. 公共入口 MVP

### 8.1 管理驾驶舱 `/quant`

真实计数：各模块进行中课题、待我处理（待复核、待审批、待处置事件、待授权）、本月试验数与 Token 用量、模拟组合净值概览、最近事件。每个数字可点击进入对应列表。不显示虚构统计。

### 8.2 审查中心 `/quant/reviews`

统一待办：因子候选复核、策略候选复核、组合方案审批、风险恢复复核、Agent 越权/扩范围授权申请。按类型筛选；各类型复用各自详情页。身份和自审限制由后端执行。

### 8.3 Agent 管理 `/quant/agents`

MVP 只读 + 简单开关：列出各能力单元（F0～F6、S0～S6、组合/风控中用到的 Agent），显示方法版本（提示词版本、模型、工具清单）、调用次数、Token 用量、失败率、最近运行；管理员可暂停某个 Agent（暂停后对应自动推进停止，人工工具仍可用）。评测与发布放到完善期。

### 8.4 验收

HB-M1 驾驶舱数字与各列表实际数量一致；HB-M2 审查中心五类待办可筛选、可进入处理；HB-M3 暂停 F0 后课题不再自动推进，恢复后继续。

## 9. 完善期（M6 之后，按优先级）

1. R4 正式新颖性、逐日 PIT 股票池、IC 衰减多持有期（依赖 RE 合入）。
2. 各能力单元评测集、方法版本发布与回退（因子规格第 8 章、策略 S-P2）。
3. 编排对照实验：固定流水线 vs 研究决策 + 专职单元 vs 人工基线，同预算比较（因子规格第 8 章）。
4. 课题调度（多课题并发、跨课题预算）。
5. 更多策略模板、优化器、模拟跟踪账本。
6. 告警外发、复杂归因。
7. 页面视觉逐屏对齐原型、1366/1024 宽度与键盘操作。

## 10. M6 全链路验收脚本

研究员和负责人（可同一人分饰，复核/审批用不同账号）在 19536 依次完成，产品经理逐步核对并截图记录：

1. 数据资源：查看当前视图与某数据集口径。
2. 因子工厂：建课题，交给 F0 自主推进至少 3 步（失败、修订、再检验），台账 K 正确；有达标候选时走封存与复核入库，没有则记录失败结论。
3. 策略研究：用入库或导入因子建策略课题，S0 自主调整至少一次，达标候选封存复核入库。
4. 组合：用入库策略建模拟组合，风险检查、审批、模拟部署，看到第一日订单意图与模拟净值。
5. 运行监控：调低阈值触发事件，自动暂停，填写复测证据后恢复；查看归因，创建改进任务回到因子或策略模块。
6. 驾驶舱和审查中心的数字与上述操作一致；Agent 管理看到本次所有 Agent 的调用与用量。

全部为模拟环境；任何收益数字都不代表投资建议。

## 11. 防偏差协作规则（产品经理 ↔ 开发）

1. **规格为准**：本文、《因子工厂V5-需求规格.md》、《策略研究V5-需求规格.md》是唯一需求来源。与原型冲突时以规格为准；规格没写的，写进“需产品确认”，先做不受影响的部分。
2. **里程碑开工先报计划**：实施计划写进进度文档后即可开工，不必等产品回复；产品经理在下一次跟进时审阅，有偏差会发 PM-QA 消息纠正。
3. **验收证据**：每个验收用例写明证据类型——“真实模型/真实 RE/真实数据”、“替身单测”、“浏览器操作”。只有替身单测的不能写“已完成”。
4. **产品经理复核**：开发声称完成的里程碑，产品经理在 19536 用研究员/复核员账号实际操作核对；发现的问题以 QA-编号下发，开发修复后再复核。
5. **不擅自扩大或缩小范围**：MVP 外的功能不做；MVP 内的功能不因“难”而降级为页面说明，做不了的写明阻塞（具体接口、数据或权限）并报告。
6. **连续推进**：一个里程碑完成并提交后，直接开始下一个，不必等待产品消息；遇到只能由人决定的事项（新角色、生产数据、合并 PR）才停下来报告。
