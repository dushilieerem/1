# AI 与 Agent 模块 模块设计

## 1. 模块信息

- 模块名称：AI 与 Agent 模块（LLM 网关 + 运行时/技能编排 + 用量配额 + 研究流水线 crews）
- 位置：`backend/ai/{gateway,runtime,crews}` + `backend/app/routers/ai.py`、`backend/app/routers/agent.py`
- 负责人：SVQuant 技术组
- 文档版本：v1.0（2026-09-23）
- 需求依据：[PRD §6.8 AI 与 Agent](../../需求文档/PRD.md)

---

## 2. 模块职责

1. **LLM 网关（ai/gateway）**：
   - `llm_client`：OpenAI 兼容 chat/completions（`LLM_*` 环境变量配置）。
   - `ark_chat`：火山方舟 + 硅基流动双供应商（`resolve_provider` 按 model_id 路由）、模型列表、流式输出（`iter_chat_stream`）、思考链剥离（`strip_thinking`）。
   - `speech_transcribe`：语音转写（硅基流动 ASR，multipart 上传）。
2. **AI 对话端点（routers/ai.py）**：`/api/ai/chat` SSE 流式对话、模型列表、语音状态/转写。
3. **Agent 运行时（ai/runtime）**：
   - `runtime.py`：`resolve_skills`（goal 关键词路由到技能）、`start_run` / `start_run_single`。
   - `orchestrator.py`：board（看板）状态机、`_run_and_bill`（执行+计费）、社区创作 crew（`run_community_crew`）与读帖 crew（`run_community_read_crew`）。
   - `skills.py`：技能注册与实现（润色标题/正文、板块建议、声明审计、不可验证内容剥离、面板指标查询、帖子摘要、阅读风险提示）；LLM 不可用时 mock 降级。
   - `store.py`：`ai_usage` 用量表、每日配额（默认 200，`ai_quota_daily`）、用量汇总（个人/管理员）、配额设置。
4. **Agent 端点（routers/agent.py)**：用量查询/配额管理 + run 启动 + 研究流水线五端点。
5. **研究流水线（ai/crews/gather_idea）**：gather（证据收集）→ idea（因子构思）→ factor（因子代码生成）→ backtest（回测报告）→ eval（评估）五段流水线，可分段调用（pipeline.py）。
6. **内容安全护栏（ai/crews/_shared/metrics_trust.py）**：承诺话术检测（PROMISE_RE）、量化数字声明检测（QUANT_CLAIM_RE）、平台引用对账（platform_ref + 容差 2%）、`trust_prompt_block` 注入提示词。

## 3. 不负责的范围

- 不负责 RE 侧 AI 生成（AI 因子/策略生成、回测解读走 [ResearchEngine网关模块](../ResearchEngine网关模块/模块设计.md) 代理，计算在 RE）。
- 不负责 KnowledgeHub 的 LLM/embedding 配置（KH 有独立供应商体系，见 [KnowledgeHub模块](../KnowledgeHub模块/模块设计.md)）。
- 不存储对话历史（`/api/ai/chat` 无状态流式；社区帖子落库在 [社区与新闻模块](../社区与新闻模块/模块设计.md)）。
- 不训练/不部署模型。

## 4. 输入

| 输入 | 来源 | 说明 |
|---|---|---|
| 对话请求 | `POST /api/ai/chat` | messages + model + temperature，SSE 响应 |
| 语音文件 | `POST /api/ai/speech/transcribe` | multipart 音频 |
| Agent run | `POST /api/agent/runs` | skills 或 goal（关键词路由） |
| 流水线请求 | `POST /api/agent/gather|idea|factor|factor-backtest|factor-eval` | 各段 schema（crews/gather_idea/schemas.py） |
| 凭据 | `backend/.env`：`LLM_*`、`ARK_API_KEY`、`AI_FACTOR_BASE_URL/API_KEY/MODEL_ALIAS`、`SILICONFLOW_*` | 含 Windows 用户级环境变量兜底（`_pull_windows_user_env`） |
| 面板数据 | `skill_lookup_panel_metrics` 查询因子面板 | 供摘要/审计引用真实数字 |

## 5. 输出

| 输出 | 接收方 |
|---|---|
| SSE 对话帧（`_sse_chat_frames`） | 前端聊天页 |
| run 结果 board（步骤/草稿/审计/信任标记） | 前端社区创作页 |
| 流水线产物（EvidencePack / IdeaBundle / 因子代码 / 回测报告 / 评估） | 前端研究助手页 |
| 用量汇总/配额 | 用户中心 / 管理后台 |
| 转写文本 | 前端语音输入 |

## 6. 子模块

| 单元 | 位置 | 职责 |
|---|---|---|
| ai 路由 | `app/routers/ai.py` | chat SSE / models / speech 端点；错误码 503（未配置）/502（调用失败）/400 |
| agent 路由 | `app/routers/agent.py` | 用量/配额/run/流水线端点；`_perm_http`：含"配额"→403 否则 401 |
| gateway/llm_client | `ai/gateway/llm_client.py` | `LlmError`、`llm_configured`、`llm_settings`、`chat_completions`（`LLM_*` env） |
| gateway/ark_chat | `ai/gateway/ark_chat.py` | 方舟/硅基流动凭据解析、`resolve_provider`、`list_ark_models`、`chat`、`iter_chat_stream`、`strip_thinking` |
| gateway/speech_transcribe | `ai/gateway/speech_transcribe.py` | `SpeechError`、`speech_ready`、`transcribe_bytes`、`_build_multipart` |
| runtime/store | `ai/runtime/store.py` | `ai_usage` schema、配额断言与记账、用量汇总 |
| runtime/runtime | `ai/runtime/runtime.py` | `resolve_skills`、`start_run_single`、`start_run` |
| runtime/orchestrator | `ai/runtime/orchestrator.py` | `new_board`/`new_read_board`、`_step`、`_run_and_bill`、`run_community_crew`/`run_community_read_crew` |
| runtime/skills | `ai/runtime/skills.py` | 技能实现与注册（见类设计） |
| crews/gather_idea | `ai/crews/gather_idea/` | 五段流水线 + `pipeline.py` 组合 + `web_sources.py` 资料源 |
| crews/_shared | `ai/crews/_shared/metrics_trust.py` | 内容信任护栏（数字/承诺/platform_ref） |

> crews/community 目录仅有 `__init__.py`；社区 crew 实现在 `orchestrator.py`。

## 7. 内部结构

```text
routers/ai.py ──▶ gateway/ark_chat（chat SSE） / speech_transcribe
routers/agent.py ──▶ runtime/runtime.start_run ──▶ runtime/orchestrator（board 状态机）
                 ──▶ crews/gather_idea/pipeline（五段流水线）
orchestrator ──▶ skills（技能执行）──▶ gateway/llm_client（LLM 调用）
orchestrator ──▶ runtime/store（assert_quota_available / record_usage 计费）
crews/_shared/metrics_trust ──▶ 被 skills 与 orchestrator 引用（护栏）
```

## 8. 核心逻辑

### 技能路由（runtime.resolve_skills）

1. 显式 skills 参数：过滤 `SINGLE_SKILLS`（polish_title / polish_body / summarize_post）去重。
2. 无参数时按 goal 关键词：`读帖/tldr/tl;dr/摘要（非润色）` → `["summarize_post"]`；仅标题 → `["polish_title"]`；仅正文 → `["polish_body"]`；默认两者。

### Board 状态机（orchestrator）

- `new_board` / `new_read_board` 初始化步骤看板；`_step` 执行单步；`_run_and_bill` 包裹技能调用并 `record_usage` 计费（配额不足先 `assert_quota_available` 拒绝）。
- 社区创作 crew：标题润色 → 正文润色 → 板块建议 → 声明审计（audit_claims）→ 不可验证剥离（strip_unverifiable）；读帖 crew：truncate → summarize → lookup_panel_metrics → flag_read_risks。
- `_latest_critic_decision` 取最近审计决策供下一步使用。

### 用量与配额（runtime/store）

- `ai_usage` 表按 user_id + 日期记账；`usage_today_count` 查当日次数。
- `get_user_quota`：`ai_quota_daily`（默认 200）+ 用户覆盖值；`assert_quota_available(need=1)` 超额抛 PermissionError（文案含"配额"→ 403）。
- `usage_summary_for_user(days=7)` / `usage_admin_summary(days=7, limit=200)`；`set_user_ai_quota` 管理员设置。

### 内容信任护栏（metrics_trust）

- `PROMISE_RE`（稳赚/必涨/保证收益…）命中 → 风险标记。
- `QUANT_CLAIM_RE` 数字声明 → 与 `platform_ref`（帖子引用的平台分享/面板）数字对账，容差 2%（`_number_near_allowed(tol=0.02)`）；无引用来源的数字标记为不可验证。
- `evaluate_metrics_trust` 汇总评估 → `trust_prompt_block` 注入后续 LLM 提示；`skill_strip_unverifiable` 移除未证实数字。

### 流水线（crews/gather_idea）

- gather：`normalize_request`（配额/参数归一）→ `_take_balanced`（来源平衡取样）→ `_rule_digest`/`_llm_digest` → `_build_gaps`（证据缺口）。
- idea：`_normalize_factor_spec` / `_normalize_validity` 产出因子规格；factor：`_validate_factor_code` 校验生成代码，失败 `_fallback_code` 兜底。
- backtest：`run_backtest_report`（回测报告组装，实际执行经 RE 回测）；eval：`run_eval` 评估结论。
- `pipeline.py` 串联五段，各段可单独经 `/api/agent/*` 调用。

### 降级

- LLM 未配置：skills 的 `_mock_polish_*` / `_mock_summary_md` 提供确定性 mock 输出（标记为 mock），主链路不断。

## 9. 外部依赖

| 依赖 | 用途 | 失败行为 |
|---|---|---|
| 火山方舟 API | 对话/生成（ARK_API_KEY） | `ArkChatError` → 502；未配置 → 503 |
| 硅基流动 API | 对话（备用供应商）/ 语音转写（SILICONFLOW_*） | 同上；语音未就绪 `speech_ready` 状态展示 |
| OpenAI 兼容 LLM（LLM_* env） | skills 内部调用 | `LlmError` → mock 降级或报错 |
| PostgreSQL | ai_usage 表 | 记账失败抛错（run 终止） |
| Windows 用户级环境变量 | 凭据兜底（`_pull_windows_user_env`） | 缺失即"未配置"路径 |

## 10. 数据依赖

| 存储 | 说明 |
|---|---|
| ai_usage | user_id, run_id, skill, tokens, created_at（按日聚合） |
| 用户表 ai_quota_daily 列 | 每日配额（默认 200，管理员可改） |
| 无对话历史持久化 | `/api/ai/chat` 无状态；社区草稿经 board 返回由社区模块落库 |

## 11. 异常处理

| 异常 | 行为 |
|---|---|
| LLM 未配置（文案含"未配置"） | 503 |
| LLM/方舟调用失败 | 502（ArkChatError / LlmError） |
| 语音参数错误 | 400；未就绪 503 |
| 配额不足 | PermissionError（文案含"配额"）→ 403 |
| 管理员端点非 admin | 403 仅管理员可查看 |
| 流水线代码校验失败 | factor `_fallback_code` 兜底并标注 |
| 审计发现不可验证声明 | strip_unverifiable 剥离 + trust 标记（不阻断） |

## 12. 性能要求

- 对话首响：SSE 流式输出，PRD 目标 AI 首响 ≤3s。
- 流水线为同步请求内执行（多段串行），gather 段受外部资料源耗时支配；无独立任务队列（长任务异步化规划中）。
- 用量记账为轻量 INSERT/UPDATE。

## 13. 风险

- 流水线/crew 同步执行占用请求线程，长任务（多源 gather + 回测）可能超前端等待窗（异步化待确认）。
- 护栏基于正则与数字对账，无法覆盖语义级误导；`strip_unverifiable` 依赖 platform_ref 数据质量。
- mock 降级输出可能被误当真实 LLM 结果（有 mock 标记，前端展示策略待确认）。
- 凭据分散于 .env + Windows 用户级变量（ark/speech），配置漂移风险；KH 供应商体系与之并存易混淆。
- 配额按"次数"记账（非 token 粒度），重度用户成本模型待确认。
