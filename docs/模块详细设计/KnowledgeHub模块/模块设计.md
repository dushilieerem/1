# KnowledgeHub 模块 模块设计

## 1. 模块信息

- 模块名称：KnowledgeHub 知识库模块（知识收集/切块/检索/问答 + 对话与模型供应商管理）
- 位置：`KnowledgeHub/backend/knowledge_hub/`（store.py、http_handlers.py、chunking/、embedding.py、extractors.py、attachments.py、llm.py、payload_utils.py、openapi_docs.py、schemas/）+ SVQuant 侧挂载 `backend/app/routers/kh.py`
- 负责人：SVQuant 技术组
- 文档版本：v1.0（2026-09-23）
- 需求依据：[PRD §6.7 KnowledgeHub 知识库](../../需求文档/PRD.md)

---

## 2. 模块职责

1. 知识库管理：知识库（collection）/ 文档（document，含结构化文档）CRUD、文档附件上传与读取。
2. 摄取（ingest）：文档文本抽取 → 切块（chunking 策略注册表）→ 向量化（embedding）→ 落 `kh_chunks`；进度可查（`get_ingest_progress`）。
3. 检索：`search_chunks`（关键词分词 + 向量余弦相似度混合召回，结构化字段覆盖补充）、附件命中增强。
4. 问答：`ask`（检索上下文 → LLM 生成回答，`_format_knowledge` 组装知识块）。
5. 对话：chat / conversation / message 三层管理（含默认会话 `ensure_default_conversation`、消息清空）。
6. 模型供应商：provider CRUD（`kh_model_providers`）、默认模型配置（`kh_default_models`，role=llm/embedding）、连通性测试（`/api/kh/model-providers/test`）。
7. 文件资料：`kh_files` 资料文件列表/上传/删除。
8. OpenAPI 文档：`/api/kh/docs`（Swagger 页）+ `/api/kh/openapi.json`。

## 3. 不负责的范围

- 不负责 SVQuant 用户体系（复用 `app.deps.optional_user` 解析用户；`created_by` 写入 users.id，匿名写 NULL）。
- 不负责社区帖子/研究数据的生成（ KH 是独立知识平台，挂载进 SVQuant 进程）。
- 不训练模型、不缓存 RE 数据；LLM/embedding 均为外部 OpenAI 兼容 API 调用。

## 4. 输入

| 输入 | 来源 | 说明 |
|---|---|---|
| 全部 `/api/kh/*` 请求 | SVQuant `routers/kh.py` catch-all（GET/POST/PUT/DELETE） | JSON body / 附件文件 |
| 文档源 | 上传附件（docx/pdf/文本）或直接粘贴文本/结构化字段 | `extractors.extract_text` 抽取 |
| LLM / Embedding 凭据 | `kh_model_providers` + `kh_default_models`（数据库配置，非 .env） | OpenAI 兼容 chat/completions 与 embeddings |
| 用户身份 | `optional_user` | 见权限模型 |

## 5. 输出

| 输出 | 接收方 |
|---|---|
| 知识库/文档/切块/检索/问答 JSON | KH 前端页面 |
| 问答答案（含引用文档） | KH 问答页 |
| 摄取进度（百分比/状态） | 文档列表页 |
| 供应商测试结果 | 设置页 |

## 6. 子模块

| 单元 | 位置 | 职责 |
|---|---|---|
| kh 路由（挂载） | `backend/app/routers/kh.py` | `@router.api_route("/api/kh/{path:path}", methods=[GET,POST,PUT,DELETE])` catch-all；`_collect_json` 包装 handler 的 `send_json` 回调；`PermissionError → 401` |
| http_handlers | `knowledge_hub/http_handlers.py` | `handle_kh_get/post/put/delete` 按 path 分发到 store；`_require_admin` 权限门；`_actor_id` 匿名写 NULL |
| store | `knowledge_hub/store.py`（约 2500 行） | 10 张 `kh_*` 表 schema、全部业务函数 |
| chunking | `knowledge_hub/chunking/{registry,strategies}.py` | 策略注册表（`register`/`list_strategies`/`get_strategy`/`chunk_text`）；内置策略 markdown_heading / plain_window / qa_pair / table_row / paragraph_merge / numbered_heading / structured_fields |
| embedding | `knowledge_hub/embedding.py` | `get_role_credentials` / `get_provider_credentials`、`embed_texts`、`cosine` |
| extractors | `knowledge_hub/extractors.py` | `is_binary_doc` / `extract_text`（docx `_from_docx`、pdf `_from_pdf`、纯文本） |
| attachments | `knowledge_hub/attachments.py` | `attachment_root()`（`KH_ATTACHMENT_DIR`）、`save_attachment_bytes` / `read_attachment` / `delete_attachment`、`_safe_name` |
| llm | `knowledge_hub/llm.py` | `KhLlmError`、`llm_configured`、`chat_completions`（返回 content/model/tokensIn/tokensOut/providerKey） |
| openapi_docs | `knowledge_hub/openapi_docs.py` | `openapi_spec` / `swagger_html` |

## 7. 内部结构

```text
SVQuant app/routers/kh.py（catch-all, optional_user）
  └─▶ knowledge_hub.http_handlers.handle_kh_{get,post,put,delete}
        ├─ _require_admin（role 门，见权限模型）
        └─▶ knowledge_hub.store（PostgreSQL kh_* 表）
              ├─▶ extractors（文本抽取）
              ├─▶ chunking.registry.chunk_text（切块）
              ├─▶ embedding.embed_texts（向量化 → 外部 API）
              ├─▶ attachments（附件目录 KH_ATTACHMENT_DIR）
              └─▶ llm.chat_completions（问答生成 → 外部 API）
```

### 权限模型（关键实现事实）

```text
_require_admin(user):
  user 存在：role == "admin" → 放行；否则 403「仅管理员可进入知识库平台」
  user 为空：KH_REQUIRE_AUTH 未开启（默认）→ 以 _ANON_ADMIN（kh-anon/admin）放行（内网调试/Swagger 便利）
            KH_REQUIRE_AUTH=1 → 401 未登录
```

- `_actor_id`：匿名（user.id 为空）时 `created_by` 写 NULL，避免 FK 撞 `users.id=0`。

## 8. 核心逻辑

### 摄取（store.ingest_document）

1. `_set_ingest_progress` 记录进度（内存态 + `get_ingest_progress` 查询；完成 `_clear_ingest_progress` 延迟清理）。
2. `extractors.extract_text` 抽取正文（docx/pdf/文本）。
3. `chunking.registry.chunk_text(strategy_id)` 按文档选择策略切块。
4. `embedding.embed_texts` 向量化（凭据来自默认模型 role=embedding）。
5. 块写入 `kh_chunks`（向量 + 元数据）；结构化文档走 `create_structured_document` 的字段块。

### 检索（store.search_chunks）

1. `_tokenize_query` 分词（中英文混合）。
2. 查询向量与 `kh_chunks` 向量做 `cosine` 相似度；关键词命中叠加。
3. `_hinted_structured_fields` + `_ensure_structured_field_coverage` 保证结构化字段覆盖。
4. `_enrich_hits_with_attachment` 命中块附带附件信息；`referenced_documents_from_hits` 汇总引用文档。

### 问答（store.ask）

1. `search_chunks` 召回 → `_format_knowledge` 组装知识上下文。
2. `llm.chat_completions`（凭据 role=llm；`model_override` 支持指定模型）。
3. 会话消息落 `kh_conversations`/`kh_chat_messages`；未配置 LLM 时 `KhLlmError`（"未配置默认 LLM…"）。

### 供应商测试（POST /api/kh/model-providers/test）

- 用请求体中的 baseUrl/key/model 发起真实调用验证连通性（在 kh.py 路由层特殊处理，不经 store）。

## 9. 外部依赖

| 依赖 | 用途 | 失败行为 |
|---|---|---|
| OpenAI 兼容 LLM API | 问答生成 | `KhLlmError` → 错误提示；未配置时引导设置页 |
| OpenAI 兼容 Embedding API | 摄取向量化/查询向量化 | 摄取失败（进度置失败）；检索退化为关键词 |
| 附件目录（`KH_ATTACHMENT_DIR`） | 附件/文件存储 | 目录缺失/文件删除 → `FileNotFoundError` → 404 |
| PostgreSQL（共享主库） | 10 张 `kh_*` 表 | `ensure_kh_schema` 幂等建表；连接失败 → 5xx |

## 10. 数据依赖

| 存储 | 说明 |
|---|---|
| kh_collections / kh_documents / kh_attachments / kh_chunks | 知识库、文档、附件元数据、切块（含向量） |
| kh_files | 资料文件 |
| kh_chats / kh_conversations / kh_chat_messages | 对话三层 |
| kh_model_providers / kh_default_models | 供应商凭据与默认模型（role: llm / embedding） |
| attachments 目录 | 二进制附件正文（数据库只存元数据） |

## 11. 异常处理

| 异常 | 行为 |
|---|---|
| 未登录且 KH_REQUIRE_AUTH=1 | 401 未登录 |
| 登录用户非 admin | 403 仅管理员可进入知识库平台 |
| handler 未匹配 path | `_collect_json` → 404 not found |
| 非法 JSON body | 400 invalid JSON |
| 文档/会话不存在 | 404（KeyError 类） |
| LLM 未配置 | `KhLlmError` 文案「未配置默认 LLM（设置页…）」 |
| 附件缺失 | `FileNotFoundError` → 404 |
| 摄取异常 | 进度状态置失败，保留已入库块（幂等重摄取） |

## 12. 性能要求

- 摄取为同步请求内执行（含向量化），大文档耗时主要在 embedding API；进度接口供前端轮询。
- 检索为全量 chunk 内存余弦 + SQL 关键词，数据量大时需关注 `kh_chunks` 规模（向量无专门索引，规模上限待确认）。
- `ask` 首响受 LLM API 支配（PRD 非功能目标 AI 首响 ≤3s，适用其上）。

## 13. 风险

- **默认免登录即 admin**（`KH_REQUIRE_AUTH` 未设置时匿名获得 admin 身份）：生产部署必须显式开启，否则内网任何访客可增删知识库与查看供应商 Key 配置（待确认部署基线）。
- 供应商 Key 明文存 `kh_model_providers` 表，导出/日志脱敏策略待确认。
- 摄取同步执行，大附件可能长时间占用请求线程。
- 向量检索无索引，chunk 量级增长后性能退化（规划：量化/索引方案待确认）。
