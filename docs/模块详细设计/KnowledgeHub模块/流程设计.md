# KnowledgeHub 模块 流程设计

## 1. 流程说明

覆盖四条流程：文档摄取（ingest）、知识检索与问答、对话管理、模型供应商配置与测试；并说明 catch-all 分发与权限门。

## 2. 参与模块

| 参与者 | 职责 |
|---|---|
| KH 前端 | 知识库页面、问答页、设置页 |
| SVQuant `routers/kh.py` | catch-all 挂载 + optional_user |
| `knowledge_hub.http_handlers` | path/method 分发 + 权限门 |
| `knowledge_hub.store` | 全部业务与持久化 |
| chunking / embedding / extractors / attachments / llm | 摄取与问答的支撑单元 |
| 外部 LLM / Embedding API | 生成与向量化 |

## 3. 正常流程

### 流程 A：文档摄取

```text
1. 创建文档：POST /api/kh/documents（文本）或 /api/kh/documents/structured（结构化字段）
   附件：POST /api/kh/files → attachments.save_attachment_bytes（KH_ATTACHMENT_DIR）
2. POST /api/kh/documents/{id}/ingest
   store.ingest_document:
     a. _set_ingest_progress（running, 0%）
     b. extractors.extract_text（docx/pdf/纯文本）
     c. chunking.registry.chunk_text(strategy_id)   # markdown_heading/plain_window/qa_pair/table_row/paragraph_merge/numbered_heading/structured_fields
     d. embedding.embed_texts（role=embedding 凭据）
     e. 块写入 kh_chunks → _clear_ingest_progress（延迟 2s 清理）
3. GET /api/kh/documents/{id}/progress → get_ingest_progress 轮询
4. GET /api/kh/documents/{id}/chunks → 块预览
```

### 流程 B：检索与问答

```text
检索：POST /api/kh/search {query}
  → _tokenize_query 分词
  → 查询向量（embed_texts）× kh_chunks 余弦 + 关键词命中
  → _ensure_structured_field_coverage 结构化覆盖
  → _enrich_hits_with_attachment → 命中列表 + referenced_documents_from_hits

问答：POST /api/kh/ask {chat_id?, query}
  → search_chunks 召回 → _format_knowledge 组装上下文
  → llm.chat_completions（role=llm 凭据，可 model_override）
  → 答案 + 引用文档落会话消息（kh_conversations / kh_chat_messages）
```

### 流程 C：对话管理

```text
POST /api/kh/chats 建对话空间
  → ensure_default_conversation 自动建默认会话
POST /api/kh/chats/{id}/conversations 建会话
POST /api/kh/chats/{id}/messages 或 /api/kh/conversations/{id}/messages 追加消息
GET .../messages 列表；POST /api/kh/conversations/{id}/messages/clear 清空
DELETE /api/kh/conversations/{id}、/api/kh/chats/{id} 删除
```

### 流程 D：供应商与默认模型

```text
GET  /api/kh/model-providers → 列表（Key 展示策略待确认）
POST/PUT /api/kh/model-providers → upsert_model_provider（baseUrl/key/model）
POST /api/kh/model-providers/test → 用提交的凭据真实调用验证（路由层直连，不入库）
GET/POST /api/kh/default-models → set_default_models（role: llm / embedding 指向 provider+model）
```

## 4. 时序流程（ask 问答）

```text
前端 -> routers/kh.py：POST /api/kh/ask（catch-all, optional_user）
routers/kh.py -> http_handlers.handle_kh_post：path=/api/kh/ask
handle_kh_post -> _require_admin：role 门（匿名且 KH_REQUIRE_AUTH 关 → _ANON_ADMIN 放行）
handle_kh_post -> store.ask
store.ask -> embedding.embed_texts：查询向量（外部 API）
store.ask -> store.search_chunks：余弦 + 关键词混合召回
store.ask -> llm.chat_completions：知识上下文 + 问题（外部 LLM API）
store.ask -> PostgreSQL：append 会话消息
store.ask --> 前端：{answer, 引用文档, 用量 tokens}
```

## 5. 异常流程

| 异常 | 触发 | 处理 |
|---|---|---|
| 匿名 + KH_REQUIRE_AUTH=1 | 权限门 | 401 未登录 |
| 登录用户 role≠admin | 权限门 | 403 仅管理员可进入知识库平台 |
| path 未匹配 | handler 返回 False | `_collect_json` → 404 |
| body 非法 JSON / 非 dict | 路由解析 | 400 invalid JSON |
| Embedding API 失败 | 摄取/检索 | 摄取进度置失败；检索退化为关键词匹配 |
| LLM 未配置/调用失败 | ask | `KhLlmError`（提示到设置页配置） |
| 附件文件缺失 | 下载/命中增强 | `FileNotFoundError` → 404 |
| `PermissionError`（handler 内抛出） | 各处 | 路由统一 `except PermissionError → 401` |

## 6. 状态流转

```text
文档：draft/ready（以实现为准）→ ingesting（进度内存态）→ 完成（块入库）/ failed
会话消息：追加 → clear（清空）/ 删除随会话
供应商：upsert 覆盖；default-models 按 role 单选指向
```

## 7. 并发处理

- 摄取进度为进程内内存态（`_set_ingest_progress`），多进程部署时进度查询仅在本进程有效（待确认部署形态）。
- 同一文档并发摄取未加锁（重复摄取产生重复块的风险，以 upsert/清理逻辑为准，待确认）。
- 会话消息追加为顺序写，无并发冲突点。

## 8. 幂等设计

- `ensure_kh_schema` / `_migrate_chat_conversations` 幂等（请求入口处执行）。
- 重新摄取覆盖旧块（幂等语义以实现为准，待确认）。
- DELETE 重复调用安全（返回是否删除）。

## 9. 超时和重试

| 调用 | 超时 | 重试 |
|---|---|---|
| Embedding API | 请求级（_post_json） | 无自动重试，摄取可手动重跑 |
| LLM chat/completions | 请求级 | 无自动重试 |
| 供应商测试 | 请求级 | 用户手动重试 |
| 摄取整体 | 同步请求内 | 手动重新 ingest |

## 10. 待确认

- 生产部署是否强制 `KH_REQUIRE_AUTH=1`（默认匿名 admin 仅限内网调试）。
- 摄取并发锁与重复摄取的块清理语义。
- 进度内存态在多进程/重启下的表现（重启即丢失进度）。
- 供应商 Key 在列表接口的脱敏策略。
- `kh_chunks` 向量规模上限与检索性能方案。
