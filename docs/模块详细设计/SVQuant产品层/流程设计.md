# SVQuant 产品层 流程设计（总览）

> 本文描述产品层跨模块的通用运行时流程。各模块的具体时序见各模块目录的 `流程设计.md`。

## 1. 流程说明

覆盖四类通用流程：HTTP 请求主流程、启动初始化流程、研究计算集成流程、后台任务流程。

## 2. 参与模块

| 模块 | 职责 |
|---|---|
| frontend | 发起请求并展示结果 |
| backend/app | 路由、鉴权依赖、中间件（审计/防缓存）、统一错误 |
| backend/services | 业务逻辑、数据访问、外部编排 |
| backend/ai | AI 编排与供应商适配 |
| KnowledgeHub handlers | 知识库 API 处理 |
| PostgreSQL / ResearchEngine / 供应商 | 存储与外部能力 |

## 3. HTTP 请求主流程

```text
浏览器 → FastAPI 中间件链 → Router Handler
  1. audit_access_log 中间件计时（finally 中落审计）
  2. cache_control_headers 中间件补防缓存头
  3. deps 鉴权（optional_user / require_user / require_admin）
  4. 参数校验（422/400 → {"error":"invalid JSON"}）
  5. 服务层执行（PostgreSQL / RE 网关 / 供应商）
  6. 统一错误形状 {"error": ...}
  7. 中间件 finally：写操作与错误 → app_audit_logs
```

审计过滤规则（`main._should_audit`）：跳过 OPTIONS、非 `/api/`、文档与健康检查、登录/注册（路由显式记录）、管理日志 GET 轮询、成功只读请求。

## 4. 启动初始化流程（lifespan → bootstrap_schemas）

```text
进程启动
  → sys.path 注入 backend 与 KnowledgeHub/backend
  → bootstrap_schemas()
      ├─ load_env / ensure_lan_no_proxy
      ├─ auth schema + seed_admin + profile schema + audit schema
      ├─ 启动清理审计日志（AUDIT_LOG_RETENTION_DAYS，默认 30 天）
      ├─ ai_usage / community（含种子帖）/ news（含种子与保留策略）schema
      ├─ 旧 SQLite 只读迁移（面板指标 / 校验状态 / 自定义因子）
      ├─ 用户因子库 / 策略库 / builtin_strategies 镜像 / 自选股 schema
      ├─ kh schema / detect / strategy / plaza schema / re_factor_catalog schema
      └─ 错归属检测项目修正（reassign_misowned_named_projects）
  → start_news_ingest_scheduler（后台资讯定时拉取）
  → dashboard job running 状态提示（不自愈）
  → warm_re_catalog_async（官方因子目录后台预热）
```

任何一步失败打印日志但不阻断启动（登录不可用除外场景在日志中明确）。

## 5. 研究计算集成流程

```text
用户操作 → SVQuant 鉴权 + 请求快照组装
  → 网关 forward_re（urllib 直连，NO_PROXY 白名单）
  → ResearchEngine
  → 同步：直接返回结果；异步：202/提交 → 轮询状态接口 → 终态
  → 产品侧缓存/记录（PostgreSQL）→ 前端
```

关键约束：

- 提交成功 ≠ 完成；必须经状态接口确认终态。
- 失败、取消、超时、不可达显式返回；不本地伪造。
- 策略回测网关把 RE 的 poll_url 改写为本站路径（`rewrite_run_poll_url`）。

## 6. 后台任务流程

| 任务 | 触发 | 实现 | 重启行为 |
|---|---|---|---|
| 资讯定时拉取 | 进程启动 | `start_news_ingest_scheduler` 线程，间隔 `NEWS_INGEST_INTERVAL_SEC` | 随进程重启，重新计时 |
| 因子面板批量刷新 | 手动 POST | `dashboard_store.start_refresh` daemon 线程 + `_job_lock`；job.json 持久化状态 | running 状态仅提示，不自愈 |
| 官方因子目录预热 | 进程启动 | `warm_re_catalog_async` 线程 | 每次启动重新预热 |
| RE 因子回测排队 | POST 提交 | `re_backtest_jobs` 线程池，inflight 限流默认 8，job TTL 3600s | job.json 保留状态，处理进程内任务不恢复（待确认） |

## 7. 异常流程

| 异常 | 处理 |
|---|---|
| 未登录/权限不足 | 401/403，前端引导登录或提示无权限 |
| RE 不可用 | 网关 502 + 明确文案，保留用户输入，不伪造结果 |
| PostgreSQL 不可用 | 写操作 500，审计中间件静默吞错避免级联；运维恢复 |
| LLM 未配置 | 503 明确提示；润色 mock、gather 规则摘要降级 |
| 供应商超时 | 502 或 SSE error 帧；失败不记 AI 用量 |
| 未知异常 | 全局 handler 500 + `{"error": str(exc)}` + traceback 打日志 |

## 8. 状态流转（任务/记录通用）

```text
Created → Running → Completed / Failed / Canceled
内容类：Draft → Published → (Hidden/Archived/Purged)
```

具体状态集合按模块不同（检测运行、策略运行、因子回测 job、广场条目），详见各模块流程设计。

## 9. 并发处理

- 用户资产写入依赖数据库事务、唯一约束与归属校验。
- RE 回测并发：SVQuant 侧 inflight 限流（默认 8）+ RE 侧线程池（约 40）。
- 面板刷新单任务锁（`_job_lock`），重复触发返回"已有任务在跑"。
- 审计写入失败不影响主响应（finally 中吞异常）。

## 10. 幂等设计

- 查询接口无副作用。
- 删除/取消类接口重复调用返回幂等结果或 404。
- 任务提交类接口当前无幂等键；重复提交产生新任务（重试责任在前端/用户）。幂等键待 RE 契约确认。

## 11. 超时和重试

| 调用 | 超时 | 重试 |
|---|---|---|
| RE 策略回测提交 | 1800s（同步长等兼容异步 202） | 无自动重试 |
| RE 策略轮询/取消 | 60s | 无 |
| RE 因子回测（BFF 内部） | 1800s 默认 | 无（任务失败显式返回） |
| RE 目录拉取 | 45s | 启动预热后台重试至成功 |
| 资讯源抓取 | 20s | 单源失败跳过，下个周期重试 |
| LLM 调用 | `LLM_TIMEOUT_SEC`（默认 60s） | 无自动重试 |
| KH 摄取 | 异步进度查询 | 无自动重试，失败显式状态 |

> 项目级统一重试策略待确认；写操作不盲目自动重试。
