# 因子研究模块 流程设计

## 1. 流程说明

覆盖四条主流程：自定义因子保存与试算、异步因子回测任务、官方目录同步、因子面板刷新与校验；另附检测项目记录流程。

## 2. 参与模块

| 参与者 | 职责 |
|---|---|
| frontend | 因子库/检测/面板页面 |
| `routers/factor.py`、`routers/detect.py` | HTTP 入口与鉴权 |
| `user_factor_store` / `user_library_store` | 因子资产与同步产物 |
| `factor_trial` / `re_backtest_bff` / `re_backtest_jobs` | 试算与回测适配 |
| `re_factor_catalog` | 目录快照 |
| `dashboard_store` + 两个指标/校验 store | 面板 |
| `detect_store` | 检测项目/运行 |
| ResearchEngine | 目录、试算回测、正式回测、面板计算 |

## 3. 正常流程

### 流程 A：保存并试算自定义因子

```text
用户提交 {name, body, description}
  → 校验 body 以 def 开头、函数名 == name
  → user_factor_store.add_user_factor（写 user_custom_factors + 重建 backend/factor 同步产物）
  → （试算）factor_trial.trial_via_re：
      组装短周期回测 payload（universe=CSI300, period=3m 默认）
      → re_backtest_bff.forward_factor_backtest → RE
      → 成功判定：无 error 且有 metrics
```

### 流程 B：异步因子回测

见 §4 时序。

### 流程 C：官方目录同步

```text
POST /api/factor/re-catalog/sync（或启动预热 / fresh=1 读取）
  → _pull_from_re（RE 目录 API，45s 超时）
  → 归一化库/因子/分类标签 → content_hash
  → hash 变化：写快照表 + sync_log；未变化：仅记录心跳
  → 页面读取快照
```

### 流程 D：因子面板刷新与校验

```text
POST /api/factor/dashboard/refresh
  → start_refresh：_job_lock 抢锁（running 拒绝）；再探跨进程 flock，被占用则同步拒绝
  → daemon 线程持有 flock 逐因子：组 payload → RE 回测（skip_ok 跳过已成功）
      → map_yg_response → upsert factor_dashboard_metrics
      → job.json 更新进度
POST /api/factor/dashboard/verify
  → set_factor_verification_status（pending/passed/failed + 备注）
  → 写 factor_dashboard_verifications（长期记录）
```

## 4. 时序流程（异步因子回测）

```text
前端 -> factor 路由：POST /api/factor/re-backtest（factor/universe/benchmark/起止日期）
路由 -> require_user：鉴权
路由 -> re_backtest_jobs.submit_factor_backtest：
    生成 job_id → 队列 queued → 立即返回 {job_id, status:"queued"}
后台线程（inflight < 8 时）：
    jobs -> re_backtest_bff.forward_factor_backtest
    bff  -> RE：POST /api/backtest/factor（剥离 SV 专有键）
    bff  -> RE：轮询 /api/backtest/factor/{run_id}（默认超时 1800s）
    bff --> jobs：终态结果或错误
    jobs -> job.json：status=completed/failed + 结果引用
前端 -> 路由：GET /api/factor/re-backtest/{job_id}（轮询）
路由 --> 前端：状态直到终态
前端 -> 路由：DELETE（可选，取消/清理）
```

## 5. 异常流程

| 异常 | 触发 | 处理 |
|---|---|---|
| 代码校验失败 | 保存/试算 | 400 + 提示（非 def、函数名不一致、空代码） |
| RE 不可达/超时 | 转发或轮询 | job → failed；接口 502；用户可重提 |
| RE 校验拒绝 | 因子不合法/数据 release 不匹配 | 透传 RE 错误为产品错误 |
| 任务 TTL 过期 | job 超 3600s | `_purge_locked` 清理旧 job |
| 面板任务被占 | refresh 时已有 running | 返回 `{ok:false, error:"已有任务在跑", job}` |
| 指标迁移失败 | 启动时旧 SQLite 读取失败 | 打日志跳过；旧文件保留，可重试迁移 |
| 目录拉取失败 | RE 不可用 | 读路径回退上次快照；同步路径显式报错 |

## 6. 状态流转

```text
回测 job：queued → running → completed / failed / canceled
检测项目：created → updated →（visible 标记）
检测运行：saved → 备注更新 / flagged 标记 / 删除
校验状态：pending → passed / failed（可反复改写，保留历史语义为最新态）
面板任务：idle → running → completed（job.json）
```

## 7. 并发处理

- 回测排队：`SVQUANT_RE_BACKTEST_INFLIGHT`（默认 8）限制同时在途；其余 queued 等槽。
- 面板刷新：进程内 `_job_lock` + daemon 线程；跨进程用 `flock`（`output/factor_dashboard/panel_refresh.lock`）互斥，覆盖 API「刷新指标」与命令行日更/补算；抢不到锁则本轮跳过并告警，不并发写同表。
- 因子保存：`user_custom_factors` 唯一约束（user_id + name）；同步产物重建为整文件重写。
- 目录快照：content_hash 相同不重复写。

## 8. 幂等设计

- 试算/回测提交非幂等（每次新 job/run）；重复提交由用户控制。
- DELETE job/run 重复调用安全（不存在返回幂等结果或 404，以实现为准）。
- 目录同步幂等（hash 判重）。
- 指标 upsert 幂等（同因子同参数覆盖）。

## 9. 超时和重试

| 调用 | 超时 | 重试 |
|---|---|---|
| RE 因子回测（BFF 内部同步等待/轮询） | 1800s 默认 | 无自动重试；job failed 后用户重提 |
| 目录拉取 | 45s | 启动预热后台线程重试至成功 |
| 面板单因子 | RE 回测超时（600s 量级，以实现为准） | `skip_ok` 下次刷新重算失败项 |
| job 队列滞留 | TTL 3600s 清理 | — |

## 10. 待确认

- job 状态迁至 RE 任务 API 的时间点与字段契约。
- 因子代码在 RE 侧执行的资源限制/沙箱边界（SVQuant 侧只做格式校验）。
- 面板刷新单因子超时具体值与失败重试策略。
