# 用户与权限模块 模块设计

## 1. 模块信息

- 模块名称：用户与权限模块（含管理与审计）
- 位置：`backend/services/auth/`、`backend/services/core/audit_log_store.py`、`backend/app/routers/auth.py`、`backend/app/routers/admin_logs.py`、`backend/app/deps.py`
- 负责人：SVQuant 技术组
- 文档版本：v1.0（2026-09-23）
- 需求依据：[PRD §6.1 用户与权限](../../需求文档/PRD.md)、[PRD §6.9 管理与审计](../../需求文档/PRD.md)

---

## 2. 模块职责

1. 账号注册、登录、JWT 签发与解析、当前用户查询。
2. 用户资料（头像/背景/一句话简介/简介，data URL 归一化）与用户主页。
3. 关注/取关、关注与粉丝列表。
4. 鉴权依赖注入（全站共用）：`optional_user` / `require_user` / `require_db_user_id` / `soft_db_user_id` / `require_admin`。
5. 管理员审计日志：HTTP 中间件写入、查询、清理；`infer_module` / `infer_action` 动作推断。
6. 本地示例管理员种子（`ADMIN_USERNAME`/`ADMIN_PASSWORD`）。

## 3. 不负责的范围

- 不负责套餐/订阅/计费（规划中）；当前角色仅 `user` / `admin`。
- 不负责组织、团队、机构模型（规划中）。
- 不负责用户管理界面（列表/禁用 UI，规划中；`status` 字段已存在）。
- 不负责 Agent 用量管理（属 [AI与Agent模块](../AI与Agent模块/模块设计.md)，但同样受 `require_admin` 约束）。
- 不负责邮箱验证、找回密码、第三方登录（未实现，待确认优先级）。

---

## 4. 输入

| 输入 | 来源 | 说明 |
|---|---|---|
| 注册 | `POST /api/auth/register` | username（必填）、password（必填）、email/display_name（可选） |
| 登录 | `POST /api/auth/login` | username、password |
| Authorization 头 | 所有请求 | `Bearer <JWT>` |
| 资料更新 | `POST /api/profile/me` | display_name、avatar_url、cover_url、headline、bio（图片为 data URL，超长拒绝） |
| 关注 | `POST/DELETE /api/users/{username}/follow` | 目标用户名 |
| 日志查询 | `GET /api/admin/logs` | module/username/action/statusCode/statusMin/statusMax/method/writeOnly/path/since/until/limit/offset |
| 日志清理 | `POST /api/admin/logs/purge` | days 等条件 |

## 5. 输出

| 输出 | 接收方 | 说明 |
|---|---|---|
| JWT + 用户字典 | 前端 | `{access_token, token_type:"bearer", user}` |
| 当前用户/主页/关注列表 | 前端 | 公开字段（不含 password_hash） |
| 审计日志列表/清理结果 | 管理端 | 分页 + 筛选 |
| 鉴权结果 | 全站路由 | 401/403 或用户字典 / db_user_id |

## 6. 子模块

| 单元 | 位置 | 职责 |
|---|---|---|
| auth_store | `services/auth/auth_store.py` | users 表、密码哈希、JWT、注册/登录、`user_from_authorization`、`DEV_SKIP_AUTH` |
| profile_store | `services/auth/profile_store.py` | user_follows 表、公开资料、资料更新、关注关系、用户帖子列表聚合 |
| audit_log_store | `services/core/audit_log_store.py` | app_audit_logs 表、审计写入、模块/动作推断、查询、清理、重复 5xx 抑制 |
| 鉴权依赖 | `app/deps.py` | FastAPI 依赖：optional/require/db_user_id/admin |
| 路由 | `routers/auth.py`、`routers/admin_logs.py` | HTTP 入口；注册/登录显式写业务审计 |
| 审计中间件 | `app/main.py`（`audit_access_log`） | 写操作与错误自动落审计，附 X-Request-Id |

## 7. 内部结构

```text
routers/auth.py ──┬─▶ auth_store（register_user / login_user / me_response）
                  └─▶ audit_log_store.write_audit（注册成功/失败显式记录）
routers/admin_logs.py ──▶ audit_log_store（list_audit_logs / purge_audit_logs）
app/deps.py ──▶ auth_store.user_from_authorization ──▶ factor.user_factor_store.resolve_db_user_id
app/main.py（中间件）──▶ auth_store（请求级用户解析）+ audit_log_store（写入）
```

> 注意：`deps.py` 复用 `services/factor/user_factor_store.resolve_db_user_id` 把 JWT 用户映射到数据库用户 ID——这是模块间已存在的依赖，原因见 [类设计 §4](类设计.md)。

## 8. 核心逻辑

### 注册

1. 校验用户名/密码非空；username 唯一约束兜底重复。
2. `hash_password`（bcrypt 风格哈希）落库；role 默认 `user`，status 默认 `active`，`ai_quota_daily` 默认 200。
3. 写审计 `auth.register`（成功/失败各一条，失败截断 detail 200 字）。

### 登录与身份

1. `verify_password` 校验；成功 `issue_token` 签发 JWT（sub/uid/role，`JWT_EXPIRE_DAYS` 有效期）。
2. 每次请求由 `user_from_authorization` 解码 JWT → 查库取最新用户状态；`disabled` 用户拒绝。
3. `DEV_SKIP_AUTH=1` 时返回假用户（本地联调专用）。

### 审计

1. 中间件 finally 块：`_should_audit` 过滤（跳过 OPTIONS/非 /api/文档健康/登录注册/管理日志 GET/成功只读）。
2. `infer_action(method, path)` 推断动作名；5xx 重复抑制（`_should_skip_dup_5xx`）。
3. 无有效登录用户落"游客"；`X-Request-Id` 透传。

## 9. 外部依赖

| 依赖 | 用途 |
|---|---|
| PostgreSQL | users / user_follows / app_audit_logs |
| 无外部 HTTP | 本模块不外呼 |

## 10. 数据依赖

| 表 | 读写 |
|---|---|
| `users` | 读写（id, username, email, password_hash, role, status, display_name, ai_quota_daily, avatar_url, cover_url, headline, bio…） |
| `user_follows` | 读写（follower_id, following_id 联合主键，禁止自关注） |
| `app_audit_logs` | 写（中间件/路由）+ 读/删（管理端） |

## 11. 异常处理

| 异常 | 行为 |
|---|---|
| 用户名已存在/参数不合法 | 400 + 明确 detail（注册失败也写审计） |
| 用户名或密码错误 | 401 |
| JWT 过期/非法/用户被禁用 | `user_from_authorization` 返回 None → 受保护接口 401 |
| 非管理员访问管理接口 | 403"需要管理员权限" |
| 数据库不可用 | 500；审计中间件 finally 吞异常不放大主流程错误 |

## 12. 性能要求

- JWT 解码 + 单次 users 查询即完成鉴权（每请求 1 次 DB 读）。
- 审计写入为同步 INSERT（每请求至多 1 条）；量大时清理依赖 `AUDIT_LOG_RETENTION_DAYS`（默认 30 天，启动时执行）。
- 无缓存；用户量级与查询 P95 待确认。

## 13. 风险

- 登录无限流/失败锁定（生产前必须补充，待确认）。
- `DEV_SKIP_AUTH` 误配到生产将绕过鉴权（部署文档已强调，需启动校验，待确认）。
- `resolve_db_user_id` 跨模块依赖（factor 包）造成隐式耦合，重构时需收敛（待确认归属）。
- CORS 当前 `allow_origins=["*"]`（生产收紧待确认）。
