# Definition of Done

Feature 只有在批准范围完成实现并形成可追溯的测试、发布和业务验收证据后，才能标记为已完成。

## 范围与一致性

- [ ] 已批准的需求、业务规则、架构约束和功能范围全部实现，未擅自扩展。
- [ ] 代码、配置、数据迁移、接口契约、用户文档和技术设计保持一致。
- [ ] 每条业务验收标准都有明确的通过、失败或限制结论。

## 测试与质量

- [ ] 已完成开发自测、功能测试、边界测试和必要的前后端联调。
- [ ] 相关自动化测试和回归测试全部通过。
- [ ] 性能、安全、兼容性、数据质量和异常恢复要求已验证。
- [ ] 已知限制、未完成项和技术债已登记，并标明负责人。

## 发布与运行

- [ ] 发布环境、权限、数据、配置和依赖已校验。
- [ ] 发布记录包含版本、范围、监控、告警、回滚方式和负责人。
- [ ] 线上问题兜底、运维说明和支持入口明确。
- [ ] 业务验收已完成，结果与需求层目标指标完成对照。

## 文档回写

- [ ] 验收证据已写入功能包 README「验收与证据」或包内 `verification.md` / 交付记录文件。
- [ ] Feature README 和项目组合需求池状态已更新。
- [ ] 项目状态、发布记录、风险和技术债已同步。
- [ ] 如实现结果改变了需求、业务或架构结论，已回退修订对应上游文档。
