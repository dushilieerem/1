# 文档更新规则

## 1. 按变化回写对应文档

| 发生的变化 | 首先更新 | 需要同步的文档 |
|------------|----------|----------------|
| 产品定位、目标用户、商业模式或价值指标改变 | `产品与需求/产品定位.md`、`产品与需求/PRD.md` | 路线图、项目组合需求池、受影响的功能包 |
| 新增、合并、拆分产品能力或改变业务模块边界 | `产品与需求/产品能力地图.md` | 领域战略、架构文档和相关功能包 |
| 角色、流程、规则、状态或异常处理改变 | `产品与需求/` 对应 Initiative `domain-design.md` 或 PRD 业务章节 | 功能包 README、验收用例、接口和测试 |
| Initiative 优先级、阶段、资源或范围改变 | `产品与需求/产品路线图.md`、`产品与需求/组合/` | `项目管理/` 计划、风险、会议结论 |
| Feature 新增或状态改变 | `功能包/FEAT-*/README.md`、项目组合需求池 | 上游需求/架构文档、验收证据 |
| 公共接口或跨服务字段改变 | `接口设计/` | 架构文档、网关实现和契约/集成测试 |
| 数据所有权、表结构或持久化策略改变 | `数据设计/` | 架构文档、数据访问实现和迁移说明 |
| 模块边界、数据流或部署拓扑改变 | `架构与技术/` | 受影响功能包、数据库/API/部署文档和 ADR |
| 测试范围、验证步骤或测试环境改变 | `测试设计/` 与对应 FEAT 验收记录 | 部署文档、CI 或项目状态 |
| 环境配置、启动、健康检查或回滚步骤改变 | `部署与运维/` | README 快速入口、架构文档和发布记录 |
| 重大且长期有效的技术选择 | `技术决策/ADR-XXX-*.md` | 架构文档、功能包技术设计 |
| 任务、Sprint、发布、风险或技术债改变 | `项目管理/` | 项目状态、功能包 README |
| Feature 完成或版本发布 | 功能包 README「验收与证据」/ 交付记录 | 项目组合需求池、项目状态、用户文档 |

## 2. 主流程约束

- 新能力按 `需求 → 业务 → 架构 → 功能 → 实现` 顺序形成结论，不得跳层进入开发；分级投入规则见 [需求到交付工作流](需求到交付工作流.md)。
- 需求结论不明确时不得进入业务梳理；业务规则不闭环时不得进入架构设计；架构边界不清楚时不得拆解功能；验收标准不可测试时不得进入实现。
- 实现阶段若发现上游结论失效，必须回退并更新对应文档，不能只在代码或会议纪要中留痕。
- 文档深度跟随决策权重：平台级走完整五层，普通 FEAT 走轻量包，小改动不要求文档；禁止为凑层写空壳文件。

## 3. 单一事实来源

- **价值与范围（需求）**：`产品与需求/`。
- **业务能力与规则（业务）**：`产品与需求/` 内 Initiative `domain-design.md`、PRD 业务章节与功能包「业务规则与场景」。
- **系统骨架与技术约束（架构/概要设计）**：`架构与技术/`。
- **具体功能与详细设计**：`模块设计/` 各 FEAT 功能包。
- **数据结构和所有权**：`数据设计/`；**接口契约**：`接口设计/`。
- **测试方法**：`测试设计/`；功能验收证据仍归对应 FEAT 包。
- **部署和使用说明**：`部署与运维/`、`用户指南/`。
- **开发、发布与项目状态**：功能包验收记录及 `项目管理/`。
- **长期技术选择（技术选型）**：`技术决策/` ADR。
- **当前状态**：`项目管理/项目状态/`；ResearchEngine 的模块状态在[独立仓库](https://gitee.com/yanggu-yuanqi-intelligence/research-engine)维护。
- **模块级 ResearchEngine 文档**：独立 ResearchEngine 仓库；产品级价值和跨模块业务仍以根目录为准。
- **SVQuant 产品帮助文档**：`用户指南/`；不再维护旧的 WebApp 文档交接目录。

## 4. 状态约束

统一状态为：`待分析 → 待决策 → 已批准 → 待开发 → 开发中 → 待验收 → 已完成`。

补充终止状态：`已暂缓`、`已拒绝`、`已取消`。

状态改变必须同时更新项目组合需求池、对应 Feature README，并在功能包内留下可追溯的测试/发布/验收证据。
