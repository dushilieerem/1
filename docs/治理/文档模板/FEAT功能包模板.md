# FEAT-XXX：功能名称

- 状态：待分析 / 已批准 / 开发中 / 已完成 / 已暂缓
- 所属 Initiative：INIT-XXX
- 所属能力：数据 / 因子研究 / 策略回测 / …
- 优先级：P0 / P1 / P2
- 上下游：需求池条目、相关 ADR、相关架构文档（写链接）

> 本模板覆盖普通 FEAT；平台级 / P0 / 跨模块能力先立 Initiative 并走完整五层关卡（见 [需求到交付工作流](../需求到交付工作流.md)）。
> 默认本文件即功能包全部内容；只有内容量大时才拆分子文件，禁止为凑层写空壳章节。

## 1. 价值与范围

- 背景：真实场景、当前短板。
- 价值：用户价值、商业价值。
- 范围冻结：必须做 / 可以以后做 / 明确不做。
- 优先级评估：（商业价值 × 用户价值 × 战略价值）÷ 开发成本。

## 2. 业务规则与场景

- 用户故事或业务场景（含正常、分支、异常路径）。
- 核心流程与业务规则、校验、状态变化。
- 边界与异常处理表。

## 3. 方案设计

- 模块影响、接口与数据影响、兼容与回滚。
- 内容量大时拆分 `technical-design.md`，在此链接并写摘要结论。

## 4. 验收与证据

- 验收标准（可测试）。
- 测试执行结果、回归结论、已知限制。
- 内容量大时拆分 `verification.md` 或 `交付记录.md`，在此链接。

## 5. 计划与状态

- 任务拆解与里程碑（简单功能可省略）。
- 状态变更记录与遗留问题。

## 附：拆分文件的命名约定

| 文件 | 放什么 | 何时需要 |
|------|--------|----------|
| `requirements.md` | 用户故事、业务规则、边界异常、验收标准 | 业务规则超过 README 可承载的篇幅 |
| `technical-design.md` | 模块边界、数据与接口设计、测试与回滚策略 | 方案设计超过 README 可承载的篇幅 |
| `verification.md` / `交付记录.md` | 自动化验证、验收映射、交付与回滚证据 | 需要独立留档的验证或交付证据 |
| 其他专项参考文档 | 字段字典、目录清单、API 文档、写作指南等 | 按内容需要 |
