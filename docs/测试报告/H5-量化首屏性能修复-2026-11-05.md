# H5 量化首屏性能诊断与修复（2026-11-05）

## 现象
首次点击底部「量化」时页面等待明显，主要卡在 `/api/invest/quant/overview`；进入后再刷新很快。

## 定位
`overview` 首先调用 `factor_board`，冷启动链路是：

1. `_load_panel` 加载全市场总市值前 500 的约 430 天面板；
2. 无 numpy 的 Python 回退路径逐日计算 6 个因子、IC、拥挤度和多空收益；
3. `_overview_counts` / `_focus` 再查策略、草稿、回测、模拟盘。

在 `svquant_dev` 全量历史、只读测试中：

- `factor_board('1m')` 冷启动约 **5.4–5.5s**；
- 热内存约 **0.0s**；
- 进程内 30 分钟缓存过期/后端重启后会再次冷算；
- 当前运行环境没有 numpy，实际走 Python 回退路径，因此不能靠“有 numpy 就快”兜底。

## 修复
1. **因子面板响应磁盘缓存**
   - `backend/data/invest_quant_cache/board_<dataDate>_<range>.json`；
   - 缓存内容为市场级 `factor_board` 响应，不含用户数据；
   - 按 `dataDate + range` 失效，数据更新不会命中旧缓存；
   - 缓存读失败/写失败不影响主流程，直接回退计算；
   - 读取磁盘缓存时不再加载面板，冷重启可直接返回。

2. **启动预热**
   - `app/main.py` lifespan 中启动 daemon 线程，预热 `factor_board('1m')` 与 `('1y')`；
   - 不阻塞启动，失败只记 warning；
   - pytest 下跳过，避免测试额外负载。

3. **保留原有内存缓存**，避免同一进程重复读盘。

## 结果
- 冷启动计算：约 `5.4s`；写入磁盘后再次冷启动：约 `0.0s`（直接读缓存）。
- `warm_board` 预热耗时约 `5.6s`（后台完成）。
- 预热后 `overview`：
  - `svquant_dev` 用户：**0.09s**；
  - `svquant_test` 首次请求：0.42s，热请求 0.03s（测试库面板小）。
- 页面不再在用户点击时才承担全市场因子计算；首次点击通常命中预热缓存。

## 验证
- 量化/首页相关后端：**51 passed**（含新增磁盘缓存 roundtrip 测试）。
- 数据同步单测：**14 passed**。
- H5 E2E：**35 passed**。
- `npm run build` 成功。

## 注意
- 如果用户在后端启动后、预热线程完成前立刻点击，仍可能等待一次冷计算；有磁盘缓存时不会。
- 缓存按数据日期保存，历史缓存文件很小，可后续按保留天数清理。
- 本次修改了共享入口 `backend/app/main.py`（仅启动预热线程），未改路由契约；已同步 PR 说明。
