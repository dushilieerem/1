## 3. BUG-R3-001修复过程

问题原因：

`backend/services/auth/auth_store.py` 中 JWT 签名密钥存在硬编码默认 fallback。测试环境使用默认值时，攻击者可使用已知默认密钥构造管理员 JWT，并访问管理员接口。

修复方案：

1. JWT 签名密钥改为只读取 `JWT_SECRET_KEY`。
2. 删除默认值和 fallback。
3. 启动阶段执行 `validate_auth_config()`，缺失、弱值、默认占位值均直接失败。
4. `.env.example` 只保留空键 `JWT_SECRET_KEY=`，不提供可用默认密钥。
5. 部署文档和 API 文档同步改为 `JWT_SECRET_KEY`。

修改文件：

| 文件 | 变更 |
| --- | --- |
| `backend/services/auth/auth_store.py` | 删除默认 secret；新增弱值检查与配置校验 |
| `backend/app/bootstrap.py` | 后端启动时执行 JWT 配置 fail-fast 校验 |
| `backend/.env.example` | `JWT_SECRET` 改为 `JWT_SECRET_KEY=` |
| `backend/tests/r3_security_suite.py` | 更新 R3 JWT 与配置检查逻辑 |
| `backend/tests/r3_jwt_regression.py` | 新增 JWT 安全修复回归套件 |
| `docs/部署与运维/部署文档.md` | 更新配置项 |
| `docs/部署与运维/部署文档.md` | 更新配置项 |
| `docs/接口设计/API设计.md` | 更新 JWT 认证说明 |
| `docs/测试设计/06-安全测试.md` | 更新 TC-SEC-009 口径 |

安全设计变化：

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| 密钥来源 | `JWT_SECRET`，存在默认 fallback | `JWT_SECRET_KEY`，必须由环境提供 |
| 缺失密钥 | 使用默认值继续运行 | 启动失败 |
| 弱值/占位值 | 可能继续运行 | 启动失败 |
| 旧默认密钥伪造 Token | 管理接口返回 200 | 返回 401/403 |

## 5. BUG-R3-002修复过程

漏洞来源：

R3 原始依赖扫描显示前端存在 high/critical 漏洞项 5 个，主要来自 Tiptap、js-yaml、react-router-dom 及其传递依赖。

依赖安全分析表：

| Package | 修复前版本 | 修复后版本 | Severity | CVE / Advisory | 是否生产依赖 | 依赖类型 | 处理方案 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `@tiptap/core` | 3.28.0 | 3.31.3 | High | GHSA-j95f-988m-3j2f | 是 | transitive | 升级 Tiptap 直接依赖族到 3.31.3 |
| `@tiptap/*` direct packages | 3.28.0 | 3.31.3 | Moderate/High 传递影响 | GHSA-cp6q-959q-f8rh / GHSA-j95f-988m-3j2f | 是 | direct | 小版本同族升级，保持 peer 版本一致 |
| `js-yaml` | 5.2.1 | 5.4.2 | High | GHSA-pm4m-ph32-ghv5 | 是 | direct | 小版本安全升级 |
| `react-router-dom` | 7.18.1 | 7.18.4 | High | GHSA-qwww-vcr4-c8h2 | 是 | direct | 小版本安全升级 |
| `react-router` | 7.18.1 | 7.18.4 | High | GHSA-qwww-vcr4-c8h2 | 是 | transitive | 随 `react-router-dom` 升级 |
| `dompurify` | 3.4.12 | 3.4.16 | Moderate | GHSA-55q2-fjhq-7xh7 | 是 | direct | 小版本安全升级 |
