# SVQuant 测试策略

> 版本：v1.0（2026-09-23）。状态：设计完成，未执行。
> 需求基线：[PRD v2.0](../产品与需求/PRD.md)；代码事实基线：140 个 API 端点（[API设计](../接口设计/API设计.md)）、40 张表（[数据库设计](../数据设计/数据库设计.md)）。

## 1. 目标与原则

1. **目标**：用合理测试成本降低上线风险——保住 P0（认证、隔离、契约、数据完整性），覆盖 P1，抽查 P2，不追求覆盖率数字。
2. **风险驱动**：测试深度跟随 §4 风险矩阵，不搞平均用力。
3. **需求驱动**：每条用例可追溯到 REQ-\*（见 §6 与 [RTM](08-需求测试追踪矩阵.md)）；PRD 每模块「验收标准」必须有用例承接。
4. **证据驱动**：执行必须留痕（命令、响应、截图、日志），结果只有 PASS/FAIL/BLOCKED/NOT_RUN；未执行不写 PASS。
5. **可维护**：优先复用既有栈（Python/FastAPI/urllib），唯一新增框架为 pytest；不为凑数写无价值用例。

```text
浏览器 ─► frontend:9530 (Vite) ──/api──► backend:8766 (FastAPI) ─► PostgreSQL（40 表）
                                         ├─► re_gateway / BFF ─► ResearchEngine(:9527) ─► marketdata / 回测 SQLite

```

**责任边界（决定测试责任）**：

| 责任方 | 内容 | SVQuant 测试怎么对待 |
|---|---|---|
| SVQuant 自身 | 用户/JWT/RBAC、数据隔离、业务 CRUD、审计、缓存、契约适配、错误映射、额度 | 全量分层测试（本体系主体） |
| ResearchEngine | 行情数据正确性、因子/策略计算、回测撮合语义、结果 SQLite | **不验证其算法正确性**；只验证 SVQuant 侧契约、转发、超时、错误映射、不伪造结果 |
| LLM 供应商 | 模型质量、供应商可用性 | Mock/Stub 为主 + 少量真实供应商冒烟（两层） |
| 资讯源 | 内容质量、接口稳定性 | 只测白名单校验、失败隔离、去重、保留策略 |
| IFind 采集 | 行情数据生产 | 不在范围（独立项目 FEAT-031） |

## 5. 测试分层（Test Pyramid）

| Level | 名称 | 解决什么风险 | 载体 | 当前状态 |
|---|---|---|---|---|
| L1 | 静态检查 | 编译/构建/类型/依赖配置低级错误 | `python -m compileall`、`npm run build`（含 tsc）、依赖清单核对 | 已有（手工），CI PLANNED |
| L2 | 单元测试 | 权限判定、错误映射、参数校验、状态转换、降级逻辑（`resolve_skills`、`_perm_http`、store 层 role 判定、错误码映射） | **pytest（需新增）**，针对纯函数与可注入依赖的 store | PLANNED |
| L3 | 契约测试 | SVQuant↔RE、SVQuant↔LLM、前端↔后端的 schema/状态码/字段兼容 | RE 桩（pytest fixture 起本地 stub server）+ 既有 `scripts/contract/` | 部分（脚本）/ 扩展 PLANNED |
| L4 | 集成测试 | Controller→Service→PostgreSQL 真实链路；bootstrap 幂等；RE/LLM 真实依赖 | pytest + 测试库（TEST 环境 Docker PG） | PLANNED |
| L5 | API 测试 | 140 端点 happy path + 异常 + 权限 + 分页 + 幂等 | 既有契约脚本（冒烟）+ pytest API 套件 | 冒烟已有；全量 NOT RUN |
| L6 | E2E | 6 条核心用户链路（见 [10-测试执行计划](10-测试执行计划.md) §5） | 手工浏览器（本轮）；Playwright PLANNED | PLANNED |
| L7 | 安全验证 | 认证/授权/IDOR/JWT/CORS/密钥/注入/上传（[06-安全测试](06-安全测试.md)） | 手工 + 脚本化检查清单 | NOT RUN |
| L8 | 性能验证 | PRD §8.1 指标与责任边界（[07-性能测试](07-性能测试.md)） | 轻量计时脚本；压测工具 PLANNED | NOT RUN |
| L9 | UAT | PRD 各模块「验收标准」逐条签收 | 产品验收清单（[02-测试计划](02-测试计划.md) §6） | NOT RUN |

分层原则：**不全部依赖 E2E**——E2E 仅 6 条核心链路；权限与隔离在 L5 API 层用"后端真实拒绝"验证，不依赖前端隐藏按钮。

| M5 RE 契约 | AUTO | 高 | pytest + RE 桩 server | test_modules.py 部分 |
