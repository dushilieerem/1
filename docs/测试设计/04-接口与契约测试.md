# 04 接口与契约测试（L3 层设计）

> 层级：L3 Contract。本文是**设计文档**，不新增用例编号；契约类用例分布在各模块文件（TC-RE-*、TC-KH-001/002、TC-AI-001/004/005/007、TC-COMMON-002/003 等）。
> 状态：设计完成，未执行。Req 基线：PRD §6.10、§7.3。

## 1. 目标与范围

L3 验证"两端的接口约定"而非业务正确性，共三个契约面：

| 契约面 | 端点族 | 验证载体 | 对应用例 |
|---|---|---|---|
| SVQuant ↔ ResearchEngine | /api/backtest/*、/api/ai/factor-generations 等代理、/api/re/health、market-data、re-catalog、custom/trial | 本地 RE 桩（可编程 4xx/5xx/慢响应/坏 JSON）+ 真实 RE | TC-RE-001..022 |
| SVQuant ↔ LLM/语音供应商 | /api/ai/chat（含 SSE）、/api/ai/speech/transcribe | OpenAI 兼容 fake server（桩）+ 批准后的真实供应商冒烟 | TC-AI-001/004/005/006/007/008 |
| 前端 ↔ 后端 | 全部 140 端点 | openapi.json schema 抽查 + SSE 帧序断言 | TC-COMMON-002/003、TC-KH-002 |

RE 侧算法正确性、LLM 生成质量**不在契约测试范围**（责任边界见 01-测试策略 §2）。

## 2. 状态码矩阵（以代码实现为基线）

| 状态码 | 实际语义 | 典型来源 | 测试处理 |
|---|---|---|---|
| 200 | 成功（含异步提交改写 poll_url 后的 200） | 全部成功路径 | 断言结构 |
| 400 | 业务校验失败（ValueError 显式映射） | community/news/factor/strategy/KH/… | 断言 {"error"|"detail"} 文案 |
| 401 | 未登录（require_user/require_admin）；KH `PermissionError` 特例映射 401 | deps.py、kh router | 安全用例逐一验证 |
| 403 | 权限不足：admin 门、store 层 author_role 校验、AI 配额、KH 非 admin | 各 router/store | 权限矩阵执行 |
| 404 | 资源不存在（KeyError 映射）；未登记路由 | 各 router | IDOR 用例依赖其区分 404/403 |
| 422 | FastAPI 参数校验（Query ge/le、body 模型） | admin_logs limit/days、分页参数 | 边界用例 |
| 500 | 未预期异常（不应出现） | 全局 | 专门扫描（TC-COMMON-010），出现即缺陷 |
| 502 | RE 不可达/上游失败透传/连接失败 | re_gateway、market daily、library sync | TC-RE-008/009 |
| 503 | LLM 未配置等依赖缺失 | ai gateway | TC-AI-006 |
| 201 | **未使用**（DCM-07：创建类全部返回 200） | — | 标记 NOT APPLICABLE，文档/API设计 不再声称 201 |
| 409 | **未使用**（DCM-07：冲突走 400，如同名分组） | — | 标记 NOT APPLICABLE |
| 504 | 未使用（超时统一 502） | — | NOT APPLICABLE |

错误体双口径现状：部分端点返回自定义 `{"error": ...}`，FastAPI 校验/HTTPException 返回 `{"detail": ...}`——**不强行统一**，契约断言按端点实际口径编写，并在 04 矩阵中逐族登记（执行时填充）。

## 3. 契约测试设计

### 3.1 RE 桩（核心 fixture，PLANNED）
- 独立进程/线程启动 HTTP stub，监听随机端口，测试内把 `YG_RE_BASE` 指向它。
- 能力：按脚本返回指定状态码/body/延迟/截断 JSON/连接拒绝；记录收到的请求（method/path/body 逐字段比对——TC-RE-002"请求体原样到达"依赖此能力）。
- 红线：桩只用于 TEST 环境；不得把测试桩地址写入任何配置文件提交。

### 3.2 LLM fake server
- OpenAI 兼容最小实现：`/chat/completions`（流式分片、错误注入）、语音转写端点。
- 用例 TC-AI-001..007 在其上验证请求 schema（model/temperature 默认 0.7/消息结构）与响应映射（ArkChatError→503 未配置/其他→502）。

### 3.3 前后端契约
- 以 `/openapi.json` 为基准做 schema 抽查（方法/必填/类型），配合 KH 手工 spec 漂移检查（TC-KH-002）。
- SSE 契约独立断言器（PLANNED）：解析 `data:` 帧 → 断言帧序 start→delta×N→[DONE]、错误帧形态（TC-AI-004/005）。

## 4. 现有脚本资产与改进计划

现有：`backend/scripts/contract/`（http_client.py、run_all.py、test_auth.py、test_detect.py、test_modules.py，共 5 文件）。

**现状事实**：urllib 轻客户端 `req()` 返回 (status, json)；`login()` 硬编码 max/123456；`assert_error` 断言响应含 `error` 键；`CONTRACT_BASE` 环境变量指定目标；run_all 顺序执行 auth→detect→modules、**fail-fast**；test_modules 允许 re-catalog 200|502（脚本通过≠RE 可用）；覆盖约 20 端点；无 CI 挂接、无报告产物。
