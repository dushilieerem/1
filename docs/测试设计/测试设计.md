## 1. 测试目标

1. 验证 SVQuant 当前 V0 范围内的核心能力可启动、可访问、可回归：主前端、后端 API、PostgreSQL、KnowledgeHub、ResearchEngine 网关、AI Provider。
2. 验证关键业务链路符合需求文档与 API 设计：登录鉴权、行情、因子、策略、回测代理、AI、知识库、社区、新闻、管理能力。
3. 验证系统在依赖异常、参数错误、权限不足、外部服务不可用、AI 限流或超时时有可理解错误，不白屏、不无限加载、不泄露密钥。
4. 建立可复用的企业级测试资产：用例矩阵、执行记录、缺陷模板、证据目录、回归清单、并行测试提示词。
5. 为后续 CI、自动化、性能压测、安全专项、UAT 验收提供门禁标准和建设路线。

### 2.2 不包含

| 不包含项 | 原因与边界 |
|---|---|
| ResearchEngine 内部算法正确性 | 属于 RE 仓库测试范围；SVQuant 只测 HTTP 契约和产品层展示 |
| 真实交易、券商接口、资金账户 | 当前需求未进入 V0 验收范围 |
| 生产级容量压测、高可用演练、灾备演练 | 当前环境为本地联调，作为后续专项 |
| 第三方 AI 模型内容质量评测 | 本轮只测接入、结构、超时、错误处理和安全边界 |
| 计划中功能 | 如模拟交易、基本面数据、组织计费、完整可观测平台，未实现前不作为失败项 |

## 3. 测试类型

| 类型 | 当前执行方式 | 企业级目标 | 状态 |
|---|---|---|---|
| 静态/编译检查 | `python -m compileall`、`npm run build` | 每次提交自动执行 | 已有基础 |
| 单元测试 | 当前未发现统一 pytest/Vitest 套件 | 核心服务、工具函数、权限判断覆盖率持续提升 | 待建设 |
| 集成测试 | 后端契约脚本、前后端联调 | 数据库、RE、AI、KH 依赖可切换真实/桩服务 | 部分具备 |
| API 测试 | `backend/scripts/contract` | OpenAPI 契约校验、状态码与错误体断言 | 部分具备 |
| 系统测试 | 手工场景 + 浏览器验证 | 主链路 E2E 自动化，失败留截图/日志 | 待建设 |
| 回归测试 | 按模块清单执行 | P0/P1 自动化回归进入门禁 | 待建设 |
| 性能测试 | 当前仅可做轻量接口计时 | 明确 QPS、P95、错误率、资源阈值 | 待建设 |
| 安全测试 | 权限、XSS、密钥泄露冒烟 | OWASP 风险矩阵、IDOR 与越权自动化 | 待建设 |
| UAT 验收 | 产品验收清单 | 按角色、业务流、证据签收 | 待建设 |

参考成熟实践：自动化分层采用“更多单元/组件测试，适量集成测试，少量端到端测试”的测试金字塔思想；发布门禁采用小批量验证、可回滚、可观测的发布工程方法；权限测试采用 actor-resource-action 矩阵。参考资料见文末。

## 5. 准入、准出与测试门禁

### 5.1 准入条件

| 编号 | 条件 | 未满足处理 |
|---|---|---|
| ENTRY-01 | `.env` 已配置数据库、JWT、AI、RE 基础地址，且不含占位值 | 阻塞后端和集成测试 |
| ENTRY-02 | PostgreSQL 可连接，schema 初始化无错误 | 阻塞登录、社区、KH、策略记录等数据库链路 |
| ENTRY-03 | 后端可启动并监听 `8766` | 阻塞 API、系统、E2E |
| ENTRY-04 | 主前端与 KH 前端依赖已安装 | 阻塞前端构建与 UI 测试 |
| ENTRY-05 | 测试账号明确：管理员、普通用户 A、普通用户 B、禁用用户 | 阻塞权限和数据隔离测试 |
| ENTRY-06 | 测试数据可清理，所有测试对象带 `RUN_ID` | 防止污染正式样例数据 |

### 5.2 准出标准

| 级别 | 准出要求 |
|---|---|
| 本地冒烟 | 编译/构建通过，后端健康通过，登录成功，至少一条行情/因子/策略/AI/KH/社区链路可用 |
| 功能验收 | P0/P1 缺陷为 0；P2 有规避方案和排期；所有阻塞项有责任人与恢复条件 |
| 回归验收 | 本轮影响模块全部通过；历史 P0/P1 修复项有回归证据 |
| 发布候选 | 构建产物可复现，配置变更可追溯，数据库迁移可重复执行，回滚方案明确 |

### 5.3 缺陷分级

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 阻断 | 系统不可启动、核心数据丢失、登录全量不可用、密钥泄露 | 后端无法监听、数据库迁移破坏用户表 |
| P1 严重 | 主链路不可用、越权、结果明显错误、外部依赖失败无提示 | 普通用户访问他人策略、RE 502 被当成功 |
| P2 一般 | 局部功能异常、有规避路径、错误提示不完整 | 筛选条件失效、空态文案缺失 |
| P3 轻微 | 样式、文案、低频体验问题 | 对齐偏差、非核心图标不一致 |

## 8. 异常测试

| 异常 | 预期行为 | 优先级 |
|---|---|---|
| PostgreSQL 不可用 | 后端启动或业务接口给出明确错误；登录不得无限等待；日志不泄露密码 | P0 |
| Docker 未启动 | 测试准入失败，报告标记环境阻塞 | P0 |
| ResearchEngine 不可用 | 相关 API 返回 502/明确错误；不返回伪造成功结果 | P0 |
| ResearchEngine 超时 | 前端不无限加载，后端错误体可理解 | P0 |
| AI Key 错误 | AI 接口提示鉴权/配置错误，不影响非 AI 模块 | P1 |
| AI Provider 限流 | 返回限流提示，记录失败，不吞掉错误 | P1 |
| Token 缺失/过期 | 401，前端跳转登录或提示重新登录 | P0 |
| 普通用户越权 | 403/404，审计记录完整 | P0 |
| 参数格式错误 | 400/422，字段级错误清晰 | P1 |
| 上传损坏文件 | 解析失败原因明确，文件不进入可检索成功态 | P1 |
| XSS 输入 | 页面不执行脚本，富文本内容被净化 | P0 |
| 后端 500 | 前端显示错误态，不白屏；日志可定位 | P1 |
| 网络中断 | 请求失败可重试，用户操作不丢失或有提示 | P2 |

## 9. 性能测试

当前性能指标分为两类：PRD 已给出的目标和本项目待确认目标。未实测前不得在报告中写“达标”。

| 指标 | 目标/建议 | 口径 |
|---|---|---|
| 后端健康接口 P95 | ≤ 300ms | 本地、无数据库写入 |
| 登录接口 P95 | 待确认，建议 ≤ 500ms | 依赖 PostgreSQL |
| 普通 CRUD API P95 | 待确认，建议 ≤ 1s | 单用户、本地 |
| RE 网关额外开销 | 待确认，建议 ≤ 200ms | 不含 RE 计算时间 |
| 3 年日频单策略回测 | PRD/RE 目标 ≤ 10s | RE 负责，SVQuant 记录总耗时 |
| 10 因子组合检测 | PRD/RE 目标 ≤ 30s | RE 负责 |
| AI 首字响应 | PRD 目标 ≤ 3s | 受 Provider 和网络影响 |
| KnowledgeHub 检索 | 建议 P95 ≤ 2s | 指定数据量下测量 |
| 前端首屏 | 建议本地 ≤ 2s | Chrome DevTools/Playwright 采集 |
| 错误率 | 冒烟 0；压测另定 | HTTP 5xx、超时、断言失败 |

性能测试最低输出：场景、并发数、数据量、持续时间、P50/P95/P99、错误率、CPU、内存、瓶颈分析、是否可发布建议。

回归结果必须写明：执行版本、环境、用例总数、通过数、失败数、阻塞数、未执行数、缺陷链接或缺陷编号。

## 13. 证据与报告规范

每轮测试建议目录：

```text
docs/测试设计/evidence/<run_id>/
  commands.txt
  env-summary.md
  screenshots/
  api-responses/
  logs/
  test-result.csv
```

| 类型 | 要求 |
|---|---|
| 命令行检查 | 记录命令、退出码、关键输出，不记录密钥 |
| API 测试 | 记录 URL、方法、状态码、关键响应字段、耗时 |

## 14. 多窗口测试分工

| 窗口 | 职责 | 输出 |
|---|---|---|
| 协调窗口 | 维护方案、分配任务、汇总报告、判断准入准出 | 总方案、测试报告、缺陷清单 |
| 启动环境窗口 | 启动 DB、后端、前端、RE；确认端口与配置 | 环境记录、启动日志 |
| API 窗口 | 执行契约、鉴权、业务 API、异常 API | API 结果表 |
| 前端窗口 | 浏览器手工/E2E 检查、截图、Console | UI 证据 |
| AI/KH 窗口 | AI、知识库、上传检索问答 | 模块报告 |
| 性能窗口 | 轻量接口计时和资源观察 | 性能报告 |

并行规则：

1. 未经协调窗口确认，不重启共享后端和数据库。
2. 每个窗口使用独立 `RUN_ID` 或资源名前缀。
3. 失败不得自行改代码掩盖问题，先记录缺陷。
4. 所有报告区分 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`。
