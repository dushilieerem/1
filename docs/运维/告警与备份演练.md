# 告警巡检与备份恢复演练

> 2026-11-01 · 对应 P0-16 / B4。脚本已入库，演练执行需要带 PostgreSQL 客户端的主机。

## 1. 告警巡检

脚本：`scripts/ops/check_alerts.py`（纯 Python，走 HTTP 读 health / data-quality / metrics，并检查磁盘）。

| 信号 | 来源 | 阈值（环境变量） |
|---|---|---|
| 服务/数据库不可用 | `/api/health` | 固定 critical |
| 未应用迁移 | `health.schema.pending` | 有即 critical |
| 行情陈旧 | `/api/invest/data-quality` 的 `ageDays` | `SVQ_MAX_DATA_AGE_DAYS`，默认 2 天 |
| 待处理举报积压 | `/api/metrics` | 固定 200 条 warning |
| 磁盘剩余 | `SVQ_DISK_PATH`（默认仓库根） | `SVQ_MIN_DISK_FREE`，默认 10% |

其它变量：`SVQ_API_BASE`（默认 `http://127.0.0.1:8766`）、`SVQ_ALERT_TIMEOUT_SEC`（默认 5）、
`ALERT_WEBHOOK_URL`（可选，POST `{"text": "..."}`，兼容企业微信/钉钉/Slack 文本机器人）。

退出码：`0` 无告警，`2` 有告警；可直接接 cron/systemd 的 `OnFailure`。

```bash
# cron：每 5 分钟
*/5 * * * * cd /home/dev01/project/SVQuant && SVQ_API_BASE=http://127.0.0.1:8766 \
  ALERT_WEBHOOK_URL="$SVQ_ALERT_WEBHOOK" python3 scripts/ops/check_alerts.py >> deploy/logs/alerts.log 2>&1
```

```ini
# systemd timer 示例
# /etc/systemd/system/svquant-alerts.service
[Service]
Type=oneshot
WorkingDirectory=/home/dev01/project/SVQuant
Environment=SVQ_API_BASE=http://127.0.0.1:8766
EnvironmentFile=/etc/svquant-alert.env
ExecStart=/usr/bin/python3 scripts/ops/check_alerts.py
# /etc/systemd/system/svquant-alerts.timer
[Timer]
OnCalendar=*:0/5
Persistent=true
```

## 2. 备份

`scripts/backup_pg.sh`：`pg_dump` custom format + gzip，保留 `RETENTION_DAYS`（默认 14）天，
日志写 `deploy/backups/backup.log`。要求 `pg_dump` 在 PATH。

```bash
BACKUP_DIR=/data/backups RETENTION_DAYS=14 ./scripts/backup_pg.sh
```

每日备份由 `scripts/ci/daily-backup.sh` 挂在既有 poll timer 上：03:10–03:59 的首次轮询触发一次，
成功后写 `/var/lib/svquant/db-backup.date`；失败不写标记，下一轮重试。日志在
`/var/lib/svquant/db-backup.log`，保留最近 7 份（不改变 CD 发布备份的 `BACKUP_KEEP=2`）。
它仍写本机 `deploy/backups`，异地副本需配置 `BACKUP_REMOTE` 或挂载独立磁盘。

CD 发布前的备份走 `scripts/ci/backup-db.sh`：全量 `pg_dump | gzip`，发布前执行
`gzip -t` 校验；失败会删除半截文件并终止发布，避免用损坏备份继续上线。
默认保留最近 `BACKUP_KEEP=2` 份。配置 `BACKUP_REMOTE=user@host:/path` 后，会先校验
再 `rsync` 到异地；异地复制失败同样终止发布。生产建议同时配置 WAL 归档/PITR，
本脚本只解决“发布前可回滚”的最小备份。

## 3. 恢复演练

`scripts/ops/backup_restore_drill.sh`：

1. 取最新备份（或 `BACKUP_FILE=...`），支持 CD 的 `svquant-*.sql.gz` 和历史
   `svquant-*.dump.gz`；
2. `createdb` 建临时库 `svquant_restore_drill_<ts>`；
3. SQL 备份用 `gunzip | psql -v ON_ERROR_STOP=1` 恢复，custom 备份用 `pg_restore`；
4. 校验 `users` / `posts` / `md_daily_bar` 行数非 0；
5. 无论成功失败都 `DROP` 临时库，不动生产库。

```bash
bash scripts/ops/backup_restore_drill.sh
```

**前置**：`pg_dump`、`pg_restore`、`createdb`、`dropdb`、`psql`、`gunzip` 在 PATH，
且 `backend/.env` 的 `DATABASE_URL` 可连接。
