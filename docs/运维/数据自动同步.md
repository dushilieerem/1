# 数据自动同步（view → PG）

> 目标：数据平台发布新 view 后，SVQuant 服务层自动跟上，不需要人工判断。
> 状态：Batch 1（loader / state / dry-run / 单测）已落地；Batch 2 定时器与生产切换见下文。

## 1. 边界

- 数据平台负责采集、构建 view、`contract-check`、原子切换 `views/current`。
- SVQuant 只读 `views/current`（或显式 view），把 `md_*` / `ref_*` / `invest_*` 写入自己的服务库。
- 不写 `free/`、`vendor/`、`views/`；不新增采集脚本。
- 研究/回测记录使用同步后的实际 `view_id`，不记录 `current` 这个别名。

## 2. 当前问题

1. 生产 `deploy/.env` pin 死 `SVQUANT_DATA_VIEW=research-rv-20261031`，数据平台切 `views/current` 不会影响线上。
2. 发布流水线只部署代码，没有数据同步任务。
3. 旧 loader 只覆盖财务/估值；`md_daily_bar` 没有自动 loader，导致 H5 的 `dataDate` 不前进。

## 3. Batch 1：同步核心

新增：

- `backend/services/data/view_sync.py`：view 解析、校验、增量 loader、状态表。
- `scripts/sync_data_view.py`：CLI。
- `backend/tests/test_view_sync.py`：纯逻辑单测。
- `data_sync_state` / `data_sync_run`：记录已应用 view、数据日、行数、错误、耗时。

### 3.1 命令

```bash
cd /home/dev01/project/SVQuant

# 只看计划，不写库（可在生产库上跑）
python3 scripts/sync_data_view.py --dry-run

# 写开发库（库名必须含 _dev/_test/_e2e；默认拒绝 svquant）
python3 scripts/sync_data_view.py --from 2026-10-31 --json

# 首次全量
python3 scripts/sync_data_view.py --full --with-financials --json

# 显式 view
python3 scripts/sync_data_view.py --view research-rv-20261103-23 --dry-run
```

生产库必须显式加 `--allow-production`，防止误写：

```bash
DATABASE_URL=postgresql://.../svquant \
  python3 scripts/sync_data_view.py --allow-production --json
```

### 3.2 同步内容

- `ref_security` / `ref_trading_calendar` / `ref_security_industry` / `ref_industry`
- `md_daily_bar`（hfq + none，含 `pre_close`）
- `md_valuation_daily`
- `md_status_daily`（含涨跌停价）
- `md_index_bar`
- `invest_stocks` / `invest_meta`（`dataDate`、`dataView`、`dataSyncedAt`）
- 财务四表仅在 `--with-financials` 时重载（季度数据，不必每天跑）

### 3.3 状态与幂等

`data_sync_state` 只有一行：

| 字段 | 含义 |
|---|---|
| `view_id` | 已应用的 view |
| `data_date` | 该 view 的数据日 |
| `status` | `ok` / `failed` / `idle` |
| `rows` | 各表写入行数 |
| `last_error` | 最近错误 |
| `started_at` / `finished_at` | 时间 |

- 同一 `view_id` 默认直接退出。
- 新 view 从 `min(上次 data_date, DB max(trade_date)) + 1` 开始增量；`--full` 从头。
- 所有写入在一个事务里；失败回滚，旧数据继续服务。
- `pg_try_advisory_lock` 防并发；定时器重叠时后一个直接退出。

### 3.4 安全校验

- `contract_version` 必须等于 `SVQUANT_DATA_CONTRACT`（默认 `2026-11-01`）。
- 必需 dataset 缺失、`date_max < data_date` 直接拒绝。
- 默认只允许 `*_dev` / `*_test` / `*_e2e` 库；生产库必须 `--allow-production`。
- 失败写 `data_sync_run.failed`，不覆盖 `data_sync_state` 的旧成功 view。

## 4. Batch 2：定时器与 current 支持（代码已落地，待生产安装）

1. `SVQUANT_DATA_VIEW=current`：`platform_view.py` 已支持 `views/current` 直接指向 materialized 目录；`/api/invest/meta` 返回 `dataView`。
2. systemd timer：`deploy/systemd/svquant-data-sync.{service,timer}`，每 10 分钟执行一次，失败下一轮重试。
3. 健康接口：`/api/health` 增加 `data_sync`（`view_id/data_date/status/finished_at/last_error`）。
4. 告警：`scripts/ops/check_alerts.py` 已识别 `data_sync.status=failed`，走现有 webhook。
5. 回滚：`--view <old_view> --full --allow-production` 重新加载旧 view。

安装（root）：

```bash
sudo REPO_DIR=/home/dev01/svquant-deploy \
     PYTHON=/home/dev01/program/anaconda3/bin/python \
     RUN_USER=dev01 \
     ./deploy/systemd/install-data-sync.sh
```

建议时间窗口：18:30–23:00 每 10 分钟 + 次日 08:00–09:00；或全天每 10 分钟（同步本身是 no-op，成本很低）。

## 5. Batch 3：生产切换

1. 建 `svquant_test`（独立测试库），e2e 只连它。
2. 先在生产库跑 `--dry-run`，核对 `view_id`、`data_date`、`start/end`。
3. 手动跑一次 `--allow-production --from <last+1>`，观察 `data_sync_state` 与 `/api/invest/meta`。
   - 先把 PG 服务表更新到新 view，线上 H5 立即读到新 `dataDate`；
   - 再把 `deploy/.env` 的 `SVQUANT_DATA_VIEW` 从旧 pin 改为 `current`，重启 backend，让 parquet 直读接口也跟随 `views/current`。
4. 启用 timer，观察 3 个交易日。
5. 回滚演练：用旧 view 全量重载，确认 H5 数据日回退且不影响代码版本；`deploy/.env` 可临时 pin 回旧 view。

注意：生产库写入必须显式 `--allow-production`；脚本默认只允许 `*_dev` / `*_test` / `*_e2e`。

## 6. 验收

- `pytest backend/tests/test_view_sync.py` 通过。
- `--dry-run` 能正确识别当前 view、data_date、增量起点。
- 同步后 `SELECT MAX(trade_date) FROM md_daily_bar` = view 的 `daily_bars.date_max`。
- `/api/invest/meta.dataDate` = view 的 `data_date`。
- 同一 view 重复执行返回 `unchanged`，不写库。
- 生产库未加 `--allow-production` 时拒绝写入。
