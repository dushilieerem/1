# SVQuant 部署文档

## 1. 部署架构

```text
用户
 ↓
SVQuant frontend
 ↓
SVQuant backend
 ↓
PostgreSQL

SVQuant backend
 ↓
ResearchEngine

SVQuant backend
 ↓
LLM / 资讯供应商
```

本仓库当前提供本地开发启动方式；生产环境的 Nginx、进程守护、容器编排、高可用和自动回滚方案待确认。

## 2. 环境

| 环境 | 地址 | 用途 |
| ---- | ---- | ---- |
| dev | `http://127.0.0.1:9530` | 本地开发前端 |
| dev api | `http://127.0.0.1:8766` | 本地开发后端 |
| dev invest h5 | `http://127.0.0.1:9540` | 本地开发手机 H5（演示账号 `demo/demo1234`） |
| dev invest api | `http://127.0.0.1:8767` | 本地开发 Invest API |
| test | 待确认 | 测试 |
| prod | `http://127.0.0.1:9630` | 生产前端（容器编排，见 `deploy/compose.yml`） |
| prod api | `http://127.0.0.1:9766` | 生产后端（容器内仍是 8766，仅宿主机映射不同） |

## 3. 服务器要求

- OS：Linux Bash 环境，需具备 `setsid`、`curl` 和可用 Conda。
- CPU：待确认。
- 内存：待确认。
- 磁盘：需容纳项目代码、前后端依赖、日志和 KnowledgeHub 附件。
- GPU：SVQuant 本身不强制需要；AI/ResearchEngine 是否需要由外部服务决定。

## 4. 软件依赖

- Python：Conda 环境 `svquant`。
- Java：当前未发现项目依赖。
- Node：用于 Vite 前端。
- Docker：当前未定义强依赖。
- 数据库：PostgreSQL。
- 后端依赖：`backend/requirements.txt`。
- 前端依赖：`frontend/package.json`。

## 5. 配置项

| 配置 | 说明 |
| --------- | ---- |
| `DATABASE_URL` | SVQuant PostgreSQL 连接 |
| `JWT_SECRET_KEY` | 登录令牌签名密钥，必须由环境变量提供；不得为空、不得使用默认值或弱值 |
| `JWT_EXPIRE_DAYS` | 登录有效期 |
| `YG_RE_BASE` | ResearchEngine 服务地址 |
| `DEV_SKIP_AUTH` | 开发跳过鉴权开关，协作演示和生产应为 0 |
| `ADMIN_USERNAME` | 本地示例管理员用户名 |
| `ADMIN_PASSWORD` | 本地示例管理员密码，生产必须替换 |
| `LLM_BASE_URL` | OpenAI 兼容模型服务地址 |
| `LLM_API_KEY` | 模型服务密钥 |
| `LLM_MODEL` | 默认模型 |
| `NEWS_INGEST_INTERVAL_SEC` | 资讯定时拉取间隔 |
| `NEWS_INGEST_LIMIT` | 单次拉取条数 |

禁止在文档中记录：

- 密码
- Token
- Secret Key
- 私钥

## 6. 部署步骤

```bash
git clone <repo-url>

cd SVQuant

cp backend/.env.example backend/.env
# 编辑 backend/.env，至少配置 DATABASE_URL、JWT_SECRET_KEY、YG_RE_BASE

conda activate svquant
pip install -r backend/requirements.txt

npm --prefix frontend install

./scripts/svquant.sh
```

## 7. 启动顺序

```text
PostgreSQL
 ↓
ResearchEngine
 ↓
SVQuant backend
 ↓
SVQuant frontend
 ↓
invest-api（FastAPI，首次启动自动生成演示库 invest-api/data/invest.db）
 ↓
手机 H5（frontend/invest，/api 反代到 invest-api）
 ↓
cloudflared 临时通道（主前端 :9530、H5 :9540 各一条）
```

KnowledgeHub API 随 SVQuant backend 挂载；如需单独运行 KnowledgeHub 前端，按其子目录前端命令启动。

cloudflared 快速通道（`*.trycloudflare.com`）每次启动地址都会变，无需账号但没有 SLA，
且对公网完全开放、无额外鉴权，只适合临时演示；不需要时执行 `./scripts/svquant.sh untunnel`
或启动时加 `--no-tunnel`。首次使用先运行 `./scripts/svquant.sh install-cloudflared`。
Vite 已通过 `server.allowedHosts` 放行 `*.trycloudflare.com`，否则隧道会被 403 拦截。

## 12. 回滚

回滚条件：

- 后端或前端启动失败。
- 登录、核心 API、因子/策略研究主链路不可用。
- ResearchEngine 契约不兼容且无法快速修复。
- 数据迁移导致关键数据不可用。

回滚步骤：

1. 停止当前 SVQuant 前后端服务。
2. 恢复上一组已验证的 SVQuant 代码、依赖和配置。
3. 确认 ResearchEngine 版本与上一版 SVQuant 兼容。
4. 恢复数据库备份或回滚迁移。
5. 执行健康检查和核心冒烟测试。

## 13. 常见故障

| 问题 | 排查方式 |
| -------------- | -------- |
| 服务无法启动 | 查看 `backend/output/dev-services/` 日志，确认 Conda、依赖和端口 |
| 数据库连接失败 | 检查 `DATABASE_URL`、PostgreSQL 状态、账号和网络 |
| API 500 | 查看后端日志和最近部署变更 |
| ResearchEngine 502 | 检查 `YG_RE_BASE`、RE 服务状态和 API 契约版本 |
| 前端无法访问 API | 检查后端端口、开发代理和浏览器网络请求 |
