## 3. 项目背景

### 3.1 业务背景与问题

SVQuant 是以 AI 为核心驱动的一站式 A 股量化投研平台。平台希望让量化研究者在一个产品中完成数据查看、因子研究、策略研发、回测、结果解读、行业政策分析和研究资产管理。

当前量化投研市场的主要问题（继承自旧 PRD v1.0，仍是本产品立意）：

1. **AI 渗透浅**：现有平台 AI 多停留在代码补全或辅助层，缺少从想法到因子、策略、回测、归因和报告的端到端研究助手。
2. **链路割裂**：数据、因子、策略、回测、社区协作和知识沉淀链路割裂，研究过程需要在多个工具之间切换。
3. **行业/政策分析缺失**：行业、政策、新闻和基本面分析与传统量化回测结合不足，难以形成定量与定性融合的研究闭环。

项目希望解决：

1. 用 AI 降低量化研究门槛，提升因子和策略研发效率。
2. 将用户、权限、资产、社区、知识库和研究结果展示沉淀在统一产品层。
3. 通过独立 ResearchEngine 承载行情、因子、策略和回测计算，使 SVQuant 专注产品体验与业务数据。

### 3.2 产品定位与公司宗旨

一句话定位：**SVQuant 是一个以 AI 为核心驱动的一站式 A 股量化投研平台**（详见 [01-需求文档/产品定位.md](../01-需求文档/产品定位.md)）。

公司三大宗旨在本产品中的体现（继承旧 PRD，作为需求取舍准绳）：

1. **最大化发挥 AI 能力**：AI 生成因子/策略代码、解读回测、发帖润色、信息搜集与评估，贯穿研究全链路。
2. **全面分析各行业和政策走向**：行业分类、指数成分、新闻政策来源、AI 行业问答为规划中的行业/政策分析提供数据与入口。
3. **数据和回测等基础量化设施不低于竞品**：因子目录、检测指标、双执行模式回测由 ResearchEngine 承载，对标聚宽/米筐/BigQuant 同级能力。

### 3.3 系统拓扑

~~~text

    │ 只访问 SVQuant frontend(:9530) / backend(:8766)
    ▼
SVQuant backend（FastAPI）
    ├─ 鉴权、权限、参数校验
    ├─ 用户资产解析与请求快照

    ├─ AI/资讯供应商调用

    └─ 回测结果 SQLite（服务部署侧）
~~~

## 4. 项目目标与范围

### 4.1 业务目标

- 跑通数据 → 因子 → 策略 → 回测 → 分析 → 报告的完整投研闭环（当前版本已在本地/单机形态跑通）。
- 建立 AI 驱动的差异化投研体验：AI 渗透率目标 ≥ 70%（旧 PRD 指标，度量口径待确认）。
- 保持基础量化设施能力不低于主流竞品。
- 规划中：形成可商业化的多租户 AI 投研平台（Wave 3）。

### 4.2 用户目标

- 量化开发者：高效创建、检测、回测和管理因子/策略；AI 辅助生成代码与解读结果。
- 投研团队（规划中）：管理研究资产、复用结果并进行协作。
- 普通研究用户：通过 AI 对话、社区、新闻和知识库理解研究结果。
- 学习者：跟随 AI 引导学习因子/策略概念（对应旧画像"投研教学/学习"）。

### 4.3 系统目标

- SVQuant 负责产品层：Web 体验、用户业务、权限、知识库、社区、AI 编排和展示缓存。
- ResearchEngine 负责研究计算：行情访问、因子/策略执行、回测编排和回测结果管理。
- 两个系统通过 HTTP API 集成，不共享 Python 包、数据库连接或本地结果文件；锁步发布。

### 4.4 SVQuant 与 ResearchEngine 的边界

| 领域 | SVQuant | ResearchEngine |
|---|---|---|
| 用户、登录、JWT、权限 | 负责 | 不负责 |
| 用户资产、因子/策略配置 | 保存、鉴权、展示 | 接收已解析的请求快照，不拥有 CRUD |
| 社区、资讯、知识库 | 负责 | 不负责 |
| 行情目录（marketdata）与数据版本校验 | 不保存、不读取 | 读取部署环境中 IFind 发布的已校验数据 |
| 因子目录、因子计算 | 保存用户因子同步状态，通过 API 展示/调用 | 官方因子目录、校验、计算 |
| 策略执行和回测 | 保存配置、展示结果、调用网关 | 执行、撮合语义、结果生成 |
| 回测结果 SQLite | 不直接访问 | 存储和查询 |
| AI 因子/策略生成、回测解读 | 提供入口并代理转发 | 生成与解释计算（`/api/ai/*` RE 侧代理） |
| Web 页面 | 负责 | 不负责 |

内置策略元数据通过 ResearchEngine 的 `GET /api/strategies` 同步到 SVQuant PostgreSQL 的 `builtin_strategies` 表；SVQuant 页面只读该镜像并提交 `strategy_id`，内置策略源码和执行由 ResearchEngine 管理。

### 4.5 明确不做（当前版本）

- 不在 SVQuant 内部执行行情读取、因子计算、策略撮合和完整回测；不保留本地备用回测引擎。
- 不直接读取 ResearchEngine 的 marketdata、结果 SQLite 或内部文件，不从结果文件推断任务状态。
- 不提供实盘交易、券商接入和投顾/荐股服务（AI 输出不构成投资建议）。
- 不做高频/Tick 级策略研究。
- 不自研行情数据源；数据采集由独立 IFind 项目负责（FEAT-031，已完成拆分）。
- 当前不提供生产级高可用、容器编排、自动回滚和完整监控方案。
- 不做港美股/期货数据与交易（远期扩展点，见旧 PRD §8）。

## 6. 功能需求

> 每个模块按统一模板：功能说明 / 使用场景 / 输入 / 处理规则 / 输出 / 异常情况 / 验收标准 / 范围外与规划。
> 接口路径以 [API设计/API设计.md](../API设计/API设计.md) 与运行时 OpenAPI（`GET /openapi.json`）为准。

### 6.1 用户与权限 【部分实现】

#### 功能说明

提供账号注册、登录、会话身份、用户资料、用户主页与关注关系、管理员权限基础、AI 额度字段。为全部业务模块提供鉴权上下文。

#### 使用场景

- 新用户注册并登录，访问需要身份的功能（因子/策略/自选股/社区发帖/AI）。
- 用户维护个人主页资料（头像、背景、一句话简介、简介）。
- 用户关注其他用户，查看关注/粉丝列表与作者主页。
- 管理员按角色访问管理接口。

#### 输入

- 注册：用户名、密码（注册接口当前不支持邮箱必填；`email` 字段可选唯一）。
- 登录：用户名、密码。
- 资料：display_name、avatar_url、cover_url、headline、bio。
- 关注：目标用户名。

#### 处理规则

1. 密码以哈希存储（`password_hash`），明文不落库、不进日志。
2. 登录成功签发 JWT（`JWT_SECRET` 签名，`JWT_EXPIRE_DAYS` 有效期，默认 7 天），前端以 Bearer Token 携带。
3. 后端依赖 `require_user` / `require_admin` 执行权限校验，前端不作为权限事实来源。
4. `DEV_SKIP_AUTH=1` 时返回假用户，仅限本地开发；协作演示和生产必须为 0。
5. 管理接口统一校验 `role == 'admin'`。
6. 密码、Token、Secret Key 不写入文档或仓库。

#### 输出

- 注册/登录结果、JWT、当前用户信息、资料更新结果、关注关系与用户主页数据、权限错误提示。

#### 异常情况

| 异常 | 行为 |
|---|---|
| 用户名已存在 / 参数不合法 | 400 |
| 用户名或密码错误 | 401 |
| 未登录访问受保护接口 | 401 |
| 无权限访问管理接口 | 403 |
| 会话过期 | 401，前端引导重新登录 |
| PostgreSQL 不可用 | 登录和产品写操作失败并记录日志 |

#### 验收标准

- [ ] 未登录用户不能访问受保护接口（除健康检查、登录注册、公开社区/新闻浏览）。
- [ ] 用户只能访问自己权限范围内的资产；非资源所有者访问私有资产返回 403。
- [ ] 管理接口具备管理员权限校验（`require_admin`）。
- [ ] 密码哈希存储；日志与文档无明文凭据。

#### 范围外与规划

- 套餐/订阅/计费、邮箱验证、找回密码、第三方登录：**规划中，待确认优先级**。
- 组织/团队/机构模型：**规划中**（Wave 3）。
- 用户管理界面（列表/禁用）：**规划中**；当前可通过数据库运维方式处理 `status` 字段。

### 6.2 因子研究 【部分实现】

#### 功能说明

支持因子库管理（用户因子库 + 库内因子）、用户自定义因子（Python 函数代码）、因子试算、ResearchEngine 官方因子目录同步、因子检测项目与运行记录、异步因子回测任务、因子面板（指标缓存与人工校验）和因子索引接口。计算全部由 ResearchEngine 完成。

#### 使用场景

- 用户创建因子库，将自定义因子（如 `def RET_5D(self): ...`）保存到库中。
- 用户编辑因子代码后先"试算"，用 RE 短周期回测快速验证代码可运行。
- 用户建立检测项目，配置因子、日期、证券池、基准，提交检测/回测并查看 IC/IR 等指标报告。
- 用户在因子面板查看已计算的指标，刷新（重新经 RE 计算）并对指标做人工校验存证。
- 用户浏览 RE 官方因子目录（同步快照）。

#### 输入

- 因子库：名称、描述。
- 用户因子：名称、Python 函数代码（函数名须与因子名一致）、说明。
- 检测项目：名称、因子引用、日期范围或预设周期（预设周期以"今天"为 end 往前推，可用 `RE_MARKET_END` 固定截止日）、证券池、基准、参数。
- 回测任务：因子（名称/表达式/引用）、universe、benchmark、start_date、end_date。

#### 处理规则

1. SVQuant 保存用户因子、因子库、检测项目和运行记录到 PostgreSQL（`user_factor_libraries`、`user_library_factors`、`user_custom_factors`、`detect_projects`、`detect_runs`）。
2. 官方因子目录经 `GET /api/factor/re-catalog` 从 ResearchEngine 拉取并同步到快照表 `re_factor_catalog_snapshot`（含同步日志 `re_factor_catalog_sync_log`）；页面读快照。
3. 用户自定义因子同步产物保存在 `backend/factor/`（index.yaml 等），`GET /api/factor/index` 输出按登录用户过滤的 YAML 因子索引。
4. 试算（`POST /api/factor/custom/trial`）转发到 RE 短周期回测；成功标准为"无 error 且有 metrics"。
5. 因子回测采用异步任务：`POST /api/factor/re-backtest` 立即返回 `job_id`，SVQuant 侧排队并限制同时在途请求数（环境变量 `SVQUANT_RE_BACKTEST_INFLIGHT`，默认 8），后台转发 RE；`GET /api/factor/re-backtest/{job_id}` 查询状态；`DELETE` 取消/清理。任务状态暂存 `backend/output/factor_dashboard/job.json`（本机临时文件，待 RE 任务 API 接管后退役）。
6. 因子面板指标与校验状态写入 PostgreSQL（`factor_dashboard_metrics` 可再生缓存、`factor_dashboard_verifications` 长期校验记录）；旧面板 SQLite 仅升级时只读导入，记录于 `factor_dashboard_legacy_imports`。
7. ResearchEngine 不可用时返回明确失败（502/服务不可用），不回退到本地隐式计算。
8. 私有因子访问需校验归属；`optional_user` 场景（如因子索引）未登录时仅暴露公开内容。

#### 输出

- 因子库/因子列表与详情、试算结果、检测项目与运行记录、检测报告（IC/IR、分层等指标）、回测任务状态（queued/running/completed/failed）与结果、因子面板指标与校验记录、官方因子目录快照。

#### 异常情况

| 异常 | 行为 |
|---|---|
| 因子代码错误（非 def 开头、函数名不一致） | 400，返回可修复提示 |
| 参数不合法（日期、universe） | 400 |
| RE 超时/连接失败/契约不兼容 | 502，明确"研究服务暂不可用"，保留用户输入 |
| 数据版本（manifest）不匹配 | RE 拒绝计算，SVQuant 展示计算服务不可用 |
| 任务失败/取消 | 状态接口返回终态与错误信息 |
| job.json 丢失或损坏 | 视为临时状态丢失，用户重提任务；不作为审计事实 |

#### 验收标准

- [ ] 可创建、编辑、删除用户因子库与库内因子；因子代码命名校验生效。
- [ ] 可触发试算并得到可运行/不可运行的明确结论。
- [ ] 可提交因子回测任务并通过 job_id 轮询到终态；失败有可读错误。
- [ ] 官方目录同步成功后页面可浏览；RE 不可用时同步失败有明确提示。
- [ ] 检测项目/运行记录 CRUD 与归属权限校验通过。
- [ ] 因子面板指标可刷新、可校验；校验记录随 PostgreSQL 备份。
- [ ] RE 不可用时无任何本地伪造结果。

#### 范围外与规划

### 6.3 策略研究与回测 【部分实现】

#### 功能说明

支持策略项目、策略运行记录、内置策略目录同步快照、用户策略库、策略回测网关与策略广场（公开发布回测快照）。回测执行全部由 ResearchEngine 完成。

#### 使用场景

- 用户创建策略项目，配置回测范围与参数，提交策略回测，查看收益曲线、回撤、持仓和报告。
- 用户浏览内置策略目录（RE 同步快照），直接以 `strategy_id` 发起回测。
- 用户将策略整理进个人策略库，标记"已检测"，查看策略源码归档。
- 用户把一次满意的回测运行发布到策略广场，附标题、说明、指标与净值曲线快照，供他人浏览。
- AI 生成策略（经 RE 代理）后保存并回测。

#### 输入

- 策略项目：名称、描述、配置。
- 策略回测：`strategy_id`（内置策略）或策略代码（用户策略）、start_date、end_date、params。
- 策略库：库名称、库内策略条目（代码/引用）。
- 策略广场：标题（≤120 字）、正文（≤8000 字）、来源 run_id、指标与净值曲线快照（曲线自动降采样至 ≤360 点）、代码快照（≤200,000 字符）。

#### 处理规则

1. 策略项目、运行记录、用户策略库与广场条目由 SVQuant PostgreSQL 持久化（`strategy_projects`、`strategy_runs`、`user_strategy_libraries`、`user_library_strategies`、`strategy_plaza_items`）。
2. 内置策略目录经 ResearchEngine `GET /api/strategies` 同步到 `builtin_strategies` 表（`POST /api/strategy/library/sync` 触发）；SVQuant 不保存或执行内置策略源码，回测只提交 `strategy_id`。
3. 策略回测请求必须经 SVQuant 后端鉴权与网关转发（`POST /api/backtest/strategy` → `run_id` → `GET /api/backtest/strategy/{run_id}` 轮询 → `DELETE` 清理）。
4. 运行记录支持重命名（PATCH）、删除；删除运行记录不删除 RE 侧事实。
5. 策略广场条目有 `published` / `hidden` 状态；浏览计数 `view_count` 累加；作者可删除自己的条目。
6. 浏览器只能访问 SVQuant；前端不保存 ResearchEngine 地址或凭据。

#### 输出

- 策略项目/运行记录列表与详情、内置策略目录、用户策略库、回测任务状态与结果（净值、指标、持仓、成交）、策略广场列表/详情/分享对话框、报告页数据。

#### 异常情况

| 异常 | 行为 |
|---|---|
| 策略不存在 / 无权限 | 404 / 403 |
| 回测参数不合法 | 400 |
| RE 不可达/超时/契约不兼容 | 502，明确提示，保留用户输入 |
| 回测执行失败 | 状态接口返回失败原因 |
| 广场条目被隐藏 | 普通用户不可见，管理员可见并可处理 |

#### 验收标准

- [ ] 策略资产（项目/运行/库）具备创建、查询、修改、删除能力且校验归属。
- [ ] 策略回测只经 SVQuant 后端调用 ResearchEngine；前端无直连。
- [ ] 内置策略以元数据同步快照方式展示；同步接口可触发并可查询。
- [ ] 策略广场可发布、浏览、隐藏、删除；净值曲线快照降采样生效。
- [ ] 报告页能展示收益、回撤、持仓与指标；RE 不可用时明确降级提示。

#### 范围外与规划

- 参数优化（网格/贝叶斯）、多品种混合回测：**规划中**（[01-需求文档/功能需求/策略回测.md](../01-需求文档/功能需求/策略回测.md) V2）。
- 日终模拟盘：**已实现（首期）**（FEAT-032；SVQuant 负责账户/持仓/订单/净值持久化与日终调度，RE 提供单日同步结算接口）。不支持滑点、部分成交、多空、公司行为和券商实盘。
- 实时/盘中模拟、部分成交、滑点与公司行为、券商实盘：**明确不做（当前版本）**。

### 6.7 KnowledgeHub 知识库 【已实现】

#### 功能说明

知识库模块（仓库 `KnowledgeHub/`，API 以 `/api/kh` 挂载在 SVQuant backend）提供数据集（集合）、文档（上传/结构化创建/摄取分块/进度/附件下载）、文件、向量/关键词检索、问答（ask）、多轮对话（chats/conversations/messages）、模型供应商配置与默认模型管理，及独立 OpenAPI 文档页（`/api/kh/docs`）。

#### 使用场景

- 用户创建数据集（collection），上传/新建文档，系统分块（chunking）并向量化（embedding）。
- 用户在数据集范围检索资料，或就文档提问（ask），获得带引用的回答。
- 用户维护多轮对话会话，选择模型供应商（model-providers）与默认模型（default-models）。
- 用户下载文档附件，跟踪文档摄取进度。

#### 输入

- 集合：名称、描述。
- 文档：上传文件（附件）、结构化创建（结构化内容）、摄取参数（分块策略）。
- 检索/问答：检索词、集合/文档范围、问题。
- 对话：会话与消息；模型供应商参数（base_url、密钥、模型名）。

#### 处理规则

1. 知识库元数据（`kh_collections`、`kh_documents`、`kh_attachments`、`kh_chunks`、`kh_files`、`kh_chats`、`kh_conversations`、`kh_chat_messages`、`kh_model_providers`、`kh_default_models`）归 SVQuant PostgreSQL；附件文件按 `KnowledgeHub/data/` 规则管理（默认不提交 Git）。
2. API 经 `app/routers/kh.py` 的 catch-all 转发到 `knowledge_hub.http_handlers`，用户身份用 `optional_user`；权限校验由知识库处理器执行。**当前部分只读接口可匿名访问：哪些接口必须登录待确认**。
3. 模型供应商凭据保存在数据库的供应商配置中，测试连通性用 `/api/kh/model-providers/test`；凭据不得出现在日志与文档。
4. 分块策略支持扩展（见 `KnowledgeHub/docs/分块策略扩展.md`）；摄取为异步过程，进度可通过接口查询。
5. ResearchEngine 不依赖 KnowledgeHub；知识库与因子/策略研究的数据联动（如引用知识库内容到研究）为**规划中，待确认**。

#### 输出

### 6.8 AI 与 Agent 【部分实现】

#### 功能说明

提供 AI 对话（含 SSE 流式）、模型列表、语音转写、Agent 运行时（single/multi 模式与技能注册表）、五条研究流水线（信息搜集 gather、想法生成 idea、因子生成 factor、因子回测 factor-backtest、因子评估 factor-eval）、每日额度管理、指标可信度护栏，以及 ResearchEngine 侧 AI 能力代理（AI 因子生成、AI 策略生成、回测解读）。

#### 使用场景

- 用户在 AI Hub 使用对话助手提问量化问题、生成代码草稿。
- 语音输入转写为文字（依赖供应商转写能力，状态接口可查）。
- 用户运行 gather：从外网资讯/研报/论文/帖子搜集证据（EvidencePack，含 LLM 摘要），多站检索均摊、单站失败继续、正文补抓。
- 用户依次运行 idea → factor → factor-backtest → factor-eval，完成"想法 → 因子 → 回测 → 评估"的 AI 辅助研究闭环。
- 用户在因子/策略页面用 AI 生成代码（经 RE 代理），提交回测后用 AI 解读结果。
- 管理员查看全员用量并调整个人每日额度。

#### 输入

- 对话：messages、model（可选）、temperature、stream。
- 语音：audio_base64、mime。
- Agent 运行：goal、skills（可选）、context、mode（single/multi）、crew。
- 流水线：各页面表单（研究目标、主题、因子代码、回测参数等）。
- 额度管理：user_id、quota_daily。

#### 处理规则

1. 模型供应商凭据只放 `backend/.env` 或部署密钥系统（`LLM_BASE_URL/LLM_API_KEY/LLM_MODEL`、`AI_FACTOR_BASE_URL/AI_FACTOR_API_KEY/ARK_API_KEY`、`SILICONFLOW_*`）；响应、日志和文档不得包含凭据。
2. 所有 AI 入口需登录；每次运行校验并扣减每日额度（`users.ai_quota_daily`，默认 200）；额度不足返回 403。
3. 未配置密钥时：对话/转写返回"未配置"明确错误（503 语义）；社区润色降级为本地 mock。
4. AI 输出作为研究辅助，全程遵守研究工具边界，不提供投资建议或荐股承诺；对话与生成内容展示免责声明。
5. 指标可信度护栏（`ai/crews/_shared/metrics_trust.py`）：对 AI 产出中的量化断言做数字标记、收益承诺话术检测，并要求引用平台真实数据（platform_ref）时经可信度评估；检测到不可信内容时在结果中标注。
6. 需要 ResearchEngine 能力的 AI 操作（AI 因子/策略生成、回测解读）经后端网关代理（`/api/ai/factor-generations` 等），不绕过权限与研究边界。
7. Agent 运行记录与用量统计持久化，支持按用户/天汇总。

#### 输出

- 对话响应（含流式 delta）、模型列表、语音转写结果、Agent 运行结果（EvidencePack、想法、因子代码、回测任务引用、评估结论）、用量汇总（个人/管理员）、额度设置结果。

#### 异常情况

| 异常 | 行为 |
|---|---|
| 模型未配置 | 503，明确"未配置"提示 |
| 供应商超时/失败 | 502 或流内 error 帧；保留用户输入 |
| 额度不足 | 403，提示额度与重置周期 |
| 输出不可执行（如因子代码不合法） | 下游校验失败并返回可修复提示；AI 不直接写库 |
| 外网检索失败 | gather 回退规则摘要并标注数据可信度状态 |

#### 验收标准

- [ ] 未配置密钥时有明确降级或错误提示，不出现静默失败。
- [ ] AI 能力不绕过用户权限和研究服务边界（经 SVQuant 后端）。
- [ ] 每日额度扣减、查询和管理员设置生效。
- [ ] 敏感凭据不出现在响应、日志和文档中。
- [ ] 护栏对收益承诺类话术和不可信数字给出标注。

#### 范围外与规划

- 多步研究 Agent 深化（自主规划→生成→回测→解读→报告全链路）：**规划中**（旧 PRD F7、Wave 3）。
- 对话式行业轮动/行业问答：**规划中**（依赖行业政策分析能力，Wave 2）。
- AI 成本与多模型兜底策略：**待确认**。

### 6.9 管理与审计 【部分实现】

#### 功能说明

提供系统级审计日志（请求级）记录、管理员查询与清理、Agent 用量管理、社区审核与运营汇总。目标是为用户操作、内容治理和研究调用提供可追溯事实。

- 清理：purge 条件。
- 额度：user_id、quota_daily。

#### 处理规则

1. 审计事实存 PostgreSQL `app_audit_logs`；写入动作覆盖敏感操作与内容操作（覆盖范围以实现为准，清单待确认）。
2. 查询与清理接口仅管理员可用（`require_admin`）。
3. `backend/output/` 下的 JSON 任务状态和日志是本机临时文件，不是跨服务审计事实。
4. 审计日志随 PostgreSQL 备份策略保留；保留时长待确认。

#### 输出

- 审计日志列表（分页/筛选）、清理结果、用量汇总、额度设置结果、举报处理结果、运营汇总。

#### 异常情况

| 异常 | 行为 |
|---|---|
| 非管理员访问 | 403 |
| PostgreSQL 不可用 | 查询/清理失败并记录服务日志 |
| 清理条件过宽 | 需明确条件，防止误删（交互确认方式待确认） |

#### 验收标准

- [ ] 管理接口全部具备管理员权限校验。
- [ ] 审计记录包含时间、用户、动作、路径与状态信息，可按条件检索。

- [ ] 临时文件不作为审计事实（文档与实现一致）。

### 6.10 ResearchEngine 集成边界 【已实现】

#### 功能说明

定义 SVQuant 使用 ResearchEngine 的统一方式：网关转发、鉴权与请求快照、异步任务语义、错误映射、健康检查代理与锁步发布约束。本模块是跨仓库契约的产品层落点。

#### 使用场景

- 任何研究计算（因子/策略回测、行情、官方目录、AI 生成）经 SVQuant 网关访问 RE。
- 运维排障时通过 `/api/re/health` 确认 RE 可用性。
- RE 与 SVQuant 联合发布时验证契约兼容性。

#### 输入

- 已鉴权、已解析的用户请求快照（日期、资产、因子/策略引用、参数）。
- 配置：`YG_RE_BASE`（唯一地址来源，位于 `backend/.env`）。

#### 处理规则

1. 浏览器只访问 SVQuant 前后端；前端业务代码不保存 RE 地址；Vite 开发代理读取同一份 `backend/.env`。
2. SVQuant 不导入 ResearchEngine Python 包，不读取 marketdata、结果 SQLite 或内部文件，不根据本地文件推断任务状态。
3. 网关（`app/routers/re_gateway.py` + `services/core/re_http_gateway.py`）统一转发、超时控制与错误映射（RE 错误 → 502/产品错误码）；限制允许转发的路径和方法，不提供任意 URL 代理能力。
4. 异步接口语义：提交返回任务标识，必须经状态接口确认终态；"已提交"不等于"已完成"；失败、取消、超时、不可达显式返回。
5. RE 不可用时明确显示"研究服务暂不可用"，禁止伪造结果或本地隐式回退计算。
6. 锁步发布：接口字段变化先更新 RE 契约测试，再同步 SVQuant BFF、前端类型/文案和集成验证；SVQuant 侧契约脚本见 `backend/scripts/contract/`。

#### 输出

- 统一的产品语义结果或映射后的错误；健康状态；任务状态与结果。

#### 异常情况

| 异常 | SVQuant 行为 | 处理责任 |
|---|---|---|
| RE 连接失败/超时 | 502 + 明确文案，前端保留用户输入 | RE 运维与网络配置 |
| API 响应不兼容 | 集成测试/网关校验阻断发布 | 两仓库共同修复并锁步发布 |
| marketdata 版本/哈希不匹配 | RE 拒绝计算，SVQuant 展示计算服务不可用 | 数据发布方与 RE |
| 版本发布异常 | 人工回滚上一组兼容版本 | 发布负责人 |

#### 验收标准

- [ ] 断开 RE 后所有研究入口返回一致的"服务不可用"，无伪造数据。
- [ ] 网关仅转发白名单路径与方法。
- [ ] 契约冒烟脚本与指定 RE 版本配套通过。
- [ ] 前后端无第二份 RE 地址来源。

## 7. 业务规则与全局约束

1. 浏览器只能访问 SVQuant 前端和后端，不能直连 ResearchEngine；RE 地址唯一来源为 `backend/.env` 的 `YG_RE_BASE`。
2. SVQuant 不导入 ResearchEngine Python 包，不读取其行情目录或结果库。
3. 用户只能访问自己权限范围内的策略、因子、知识库和社区管理数据；后端是权限事实来源。
4. ResearchEngine 不可用时，明确失败，不允许用本地隐藏逻辑伪造研究结果。
5. AI 输出只作为投研辅助，不构成投资建议；界面展示免责声明。
6. 密码、Token、Secret Key、私钥不写入 Git、文档、日志或群聊。
7. 行情数据、回测结果等大体积生成物不进入 SVQuant 仓库与 PostgreSQL。
8. 产品缓存（指标缓存、目录快照、展示缓存）均可再生，不作审计唯一事实。
9. 生产环境 `DEV_SKIP_AUTH` 必须为 0；`JWT_SECRET`、`ADMIN_PASSWORD` 必须替换默认值。

### 8.6 可用性
