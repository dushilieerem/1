## 1. 系统组成与运行形态

### 1.1 组成

```text
用户浏览器
  │
  ├─ SVQuant 主前端（Vite/React，默认 :9530）
  │     └─ 同源 /api → SVQuant 后端（FastAPI，默认 :8766）
  │
  ├─ KnowledgeHub 前端（独立 SPA，默认 :9531）
  │     └─ /api → SVQuant 后端 /api/kh
  │
  └─ 浏览器不直连 ResearchEngine

SVQuant 后端
  ├─ PostgreSQL（用户、社区、资讯、因子/策略资产、面板缓存、审计、知识库元数据）
  ├─ ResearchEngine HTTP API（YG_RE_BASE，默认 :9527）
  ├─ LLM / 语音供应商
  └─ 本地文件（因子同步产物、策略回测大结果、面板任务状态、知识库附件）

ResearchEngine
  ├─ 外部只读 MarketData Parquet 发布目录
  ├─ 因子/策略计算、回测调度
  ├─ 回测结果 SQLite（批量因子）
  └─ AI Provider（因子/策略草稿、回测解读、帖子摘要）
```

| 组件 | 端口 | 代码入口 | 说明 |
|---|---|---|---|
| SVQuant 主前端 | 9530 | `frontend/src/main.tsx` | React Router 单页应用，所有请求同源 `/api` |
| SVQuant 后端 | 8766 | `backend/api_server.py`、`backend/app/main.py` | FastAPI，当前单 worker |
| KnowledgeHub 前端 | 9531 | `KnowledgeHub/frontend/src/App.tsx` | 独立 SPA，主前端导航不内嵌 |
| ResearchEngine | 9527 | `app/main.py` | FastAPI，当前固定 `workers=1` |

### 1.2 边界

- SVQuant 不导入 ResearchEngine 的 Python 包，不读取 `marketdata` 目录，不直接读取 ResearchEngine 的回测结果 SQLite。
- 因子/策略计算、行情读取、批量因子回测全部由 ResearchEngine 完成。
- SVQuant 负责用户与权限、业务资产 CRUD、展示、缓存、后台调度、审计和供应商调用。
- ResearchEngine 当前没有身份认证、租户隔离和 Python 代码沙箱，只应按可信网络内部服务部署。

### 1.3 持久化与启动

- SVQuant 使用 PostgreSQL，连接由 `DATABASE_URL` 指定；没有 Alembic 等迁移框架，所有表在启动或首次调用时通过 `CREATE TABLE IF NOT EXISTS` / `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 创建。
- 启动时执行：JWT 配置校验、建表、管理员种子、示例社区帖/资讯种子、旧 SQLite 面板数据迁移、内置策略目录表、资讯定时器、因子面板日更定时器、RE 因子目录预热。
- 当前账户体系只有 `user` / `admin` 两级；管理员由 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 初始化。

## 3. SVQuant 产品层功能

### 3.1 用户、认证、资料与关注

**状态：部分实现。**

已实现：

- 注册：用户名 `3–32` 位字母/数字/下划线；密码至少 6 位；可选邮箱（`@` 且 ≤120 字符）；用户名、邮箱唯一；注册成功直接返回 JWT。
- 登录：bcrypt 校验；停用账号返回 401；JWT 使用 HS256，`JWT_SECRET_KEY` 必填且至少 32 位、禁止弱默认值，默认有效期 7 天。
- 会话：前端用 `sessionStorage` 保存 Token；每次请求后端重新读取用户表并要求 `status='active'`。
- 角色：`user` / `admin`；`require_admin` 统一返回 403。
- 登录/注册限流：按 IP 的进程内滑动窗口，默认登录 30 次/分钟、注册 10 次/分钟，可由 `AUTH_LOGIN_RATE_LIMIT` / `AUTH_REGISTER_RATE_LIMIT` 调整。
- 资料：显示名（≤32）、一句话简介（≤80）、简介（≤2000）、头像/背景（`data:image/...`，分别 ≤700,000 / 1,200,000 字符）。
- 用户主页：关注数、粉丝数、帖子数、按版块筛选的帖子列表、关注/取关（禁止关注自己，幂等）。
- 管理员种子：启动时若不存在则创建 `ADMIN_USERNAME` 对应管理员。

主要接口：

```text
POST /api/auth/register
POST /api/auth/login
GET  /api/auth/me
POST /api/profile/me
GET  /api/users/{username}
GET  /api/users/{username}/posts
GET  /api/users/{username}/following|followers
POST/DELETE /api/users/{username}/follow
```

未实现/限制：

- 无邮箱验证、找回密码、登出/Token 吊销、刷新 Token、第三方登录。
- 无管理员用户列表、禁用/启用、重置密码界面；只能通过数据库运维处理。
- 无套餐、组织、团队、机构、计费。
- `DEV_SKIP_AUTH=1` 会把所有请求视为 id=0 的 admin，仅限本地开发。

### 3.2 社区

**状态：已实现。**

版块：策略分享（`strategy`）、因子笔记（`factor`）、问答（`qa`）、热点分析（`hotspot`）、官方（`official`，仅管理员可发）。

已实现能力：

- 帖子：标题 ≤120 字；正文按去除 HTML 后的文本计数 ≤20,000；支持 Markdown/富文本、代码片段、图片、草稿。草稿仅作者/管理员可见；已发布不能退回草稿；作者或管理员可删除，已发布删除为软隐藏。
- 列表：按版块、关键词（标题/正文/代码）、排序（浏览/收藏/点赞/最新）、分页；置顶帖优先；热帖列表最多 30 条。
- 详情：默认浏览计数 +1（前端 2.5 秒去重）；草稿/隐藏内容按角色过滤。
- 评论：两级楼中楼（根评论 + 精确回复目标）；正文 ≤2000；最多 3 张图片；按点赞数/时间排序；评论列表不分页。
- 投票：帖子/评论的 `-1/0/1`；不能给自己帖子点赞；首次点赞产生通知；评论允许自投。
- 收藏：不能收藏自己的帖子；分页列表。
- 通知：`reply` / `mention` / `like` 三类；`@username` / `@display_name` 解析（最多 10 个）；未读数、按 ids/type/all 标记已读。
- 举报：帖子/评论；原因 `spam|abuse|illegal|misinfo|other`；说明 ≤500；不能举报自己的内容；同一对象不允许重复未处理举报。
- 审核：管理员置顶/取消、隐藏/恢复、彻底删除；举报处理（resolve/dismiss）；运营汇总（发帖、评论、收藏、点赞、未处理举报、按日发帖、AI 用量）。
- AI 辅助发帖：快速润色、深度审校（Writer/Critic/Router）、版块建议、夸大承诺/不可验证内容审计、读帖 TL;DR；无 `LLM_API_KEY` 时部分技能降级为本地规则并标注 `mock_local`。
- 社区 → 研究资产：帖子代码可克隆到因子检测项目或策略研究项目；分享因子/策略时携带指标快照。
- 管理员“管理仓”：举报/隐藏/置顶、系统审计日志、按用户调整 AI 日额度。

主要接口（24 个）：

```text
GET  /api/community/posts|hot|posts/{id}|posts/{id}/comments
GET  /api/community/favorites|my-posts|notifications|notifications/unread-count
GET  /api/community/moderation|reports|ops/summary
POST /api/community/posts
PUT/DELETE /api/community/posts/{id}
POST /api/community/posts/{id}/comments|favorite|vote|moderate|purge
POST /api/community/comments/{id}/vote
POST /api/community/reports
POST /api/community/reports/{id}/resolve
POST /api/community/notifications/read
```

未实现/限制：

- 社区写操作没有限流或发帖配额。
- 正文按原样存储，服务端不做 HTML 清洗；展示侧由前端 Markdown/DOMPurify 处理。
- 评论、举报、审核等列表不分页；通知和 `ai_usage` 无保留清理。
- `platform_ref` 由客户端提交，服务端只做形状归一化，不验证指标来源。
- 无团队空间、无自动策略点评。

### 3.3 资讯

**状态：已实现（抓取源稳定性是主要外部风险）。**

真实抓取源（`services/news/news_ingest.py`）：

| 源 | 覆盖内容 |
|---|---|
| 财联社 `cls` | 电报快讯（带签名 API） |
| 东方财富 `eastmoney` | 个股/市场新闻，支持正文补抓 |
| 东方财富研报 `em_research` | 研报列表（category=`research`） |
| 东方财富政策 `em_policy` | 政策栏目（category=`policy`） |
| 巨潮资讯 `cninfo` | 法定公告（POST 查询） |
| 华尔街见闻 `wallstreetcn` | 宏观/全球 |
| 同花顺 `10jqka` | 题材/热点 |
| 彭博 `bloomberg` | 明确不支持（本机超时/403），仅保留外链 |

已实现能力：

- 后台 daemon 线程定时拉取，默认每 900 秒、每源 12 条；`NEWS_INGEST_INTERVAL_SEC=0` 关闭。启动后首轮延迟 5–45 秒。
- 管理员可手动触发 `POST /api/news/ingest`，支持指定源与条数；不支持的源返回支持/不支持清单。
- 去重：`raw_hash` 唯一；重复时更新正文但保留原发布时间。
- 查询：分类（快讯/市场/公告/研报/政策/海外）、来源、关键词、主题、证券、行业；主题/证券/行业为数组内 AND 语义；置顶优先、发布时间倒序；分页 ≤100。
- 标签：硬编码主题/行业关键词字典；合并来源标签，最多 8 个主题、6 个行业；`GET /api/news/dict` 返回字典快照。
- 正文补抓：单条 `POST /api/news/{id}/enrich` 仅处理东方财富文章。
- 保留策略：快讯 10,000、公告 2,000、总信息流 15,000；启动、入库后和列表前执行清理。当前实例列表总数 15,000。

前端：

- `/news`：要闻流/电报快讯/公告表三种模式；分类/来源/主题/行业/证券筛选；搜索；公告表格；快讯时间线；分页 20。
- `/news/:id`：正文、主题、关联证券、原文链接、相关推荐。
- 指数条、热门主题云、投资日历是静态样例；研报/政策为空时显示“本期尚未接入真源”的旧文案，但后端实际已有 `em_research` / `em_policy` 抓取器（运行实例分别有 80 / 1,724 条）。

限制：

- 无全文索引，关键词为 `ILIKE`；无按源限流、重试、退避。
- 抓取依赖上游 HTML/API，接口变更会导致单源失败；失败源不影响其他源。
- 资讯列表/详情匿名可读；手动入库仅管理员；AI 补全需登录。

### 3.4 行情数据与自选股

**状态：行情展示为部分实现；自选股为已实现。**

行情数据（不落 SVQuant）：

| 接口 | 行为 |
|---|---|
| `GET /api/market-data/daily/{code}` | 转发 RE 日线；进程内缓存默认 600 秒、最多 64 条；`fresh=1` 绕过缓存；RE 404 返回空 `bars`，其他错误 502 |
| `GET /api/market-data/symbols` | 转发 RE 证券主数据；300 秒缓存；RE 故障时可用 1 小时旧缓存；仍失败时使用 12 个硬编码证券 + 自选股/资讯中的代码 |
| `GET /api/market-data/indices` | 转发 RE 指数列表；故障时使用 5 个硬编码指数（沪深300/中证500/中证1000/上证50/深证100） |
| `GET /api/market-data/indices/{key}/constituents` | 透传 RE 成分股，无缓存 |

运行实例事实：

- 行情版本 `ifind-sync-20261019-093703`，证券主数据 5,951 只。
- RE 当前指数列表实际返回 2 个：`000300.SH`（沪深300）、`000905.SH`（中证500）；沪深300 成分股 300 只。
- RE 日线返回 `date/open/high/low/close/is_show`；SVQuant 前端未展示成交量柱。

前端页面：

- `/data/kline`：证券搜索、今日聚焦、日/周/月/季/年切换、K 线、区间涨跌幅、关键统计。
- `/data/kline/search`：基于完整证券主数据的客户端过滤，6 张/页，迷你走势 + 最新价格。
- `/data/symbol/:code`：个股概览；`/chart`：完整 K 线，MA5/10/20/60/120/250、BOLL、MACD、RSI、十字光标、全屏/横屏。
- `/data/fields`：静态字段字典，无真实样例数据。
- `/data/watchlist`：自选股组合。

自选股：

- 表：`user_watchlists`、`user_watchlist_symbols`，均按 `user_id` 隔离并级联删除。
- 组合名 1–64 字符（中英文/数字/下划线/连字符/空格），保留名 `浏览选股`、`全部`；同一用户内唯一。

#### 3.5.4 因子回测执行

**状态：已实现（全部委托 ResearchEngine）。**

SVQuant 有两条调用路径：

| 路径 | 语义 |
|---|---|
| `POST /api/backtest/factor` | 薄转发到 RE 异步接口，返回 `run_id`；`GET/DELETE /api/backtest/factor/{run_id}` 轮询/取消；提交前校验 `execution_timing`，对原始因子代码做 AST 校验并注入空值/全 NaN 检查 |
| `POST /api/factor/re-backtest` | SVQuant 进程内排队；立即返回 `job_id`；`GET/DELETE /api/factor/re-backtest/{job_id}` 查询/取消 |

进程内排队行为：

- 同时在途 RE 调用默认 8（`SVQUANT_RE_BACKTEST_INFLIGHT`，1–32）。
- 任务只存内存，按 `user_id` 隔离；完成态 TTL 1 小时。
- 排队中的取消立即生效；运行中的取消只置标记，不能中止已经发往 RE 的请求。
- 内部转发默认超时 1,800 秒；提交本身 120 秒。
- 前端按 202 + 轮询处理；若 RE 直接返回同步结果，前端也兼容。

- 附件：按 SHA-256 内容寻址存 `KnowledgeHub/data/kh_attachments`；结构化文档可上传/下载（base64 JSON）。

限制：

- 仅管理员可用，没有多租户/个人知识库隔离；所有管理员共享全量数据。
- 检索没有 pgvector/倒排索引，逐条扫描全部 ready chunk 并在 Python 计算余弦，数据量大时线性变慢。
- 摄取同步发生在 HTTP 请求内；进度只存进程内存，重启丢失。
- 没有版本历史/对比/回滚；`version` 只是递增计数。
- 上传只支持 `.docx` / `.pdf`，不支持 `.doc/.xlsx/.html`、图片 OCR；结构化附件不抽文本。
- 删除 collection 只级联数据库行，不删除附件文件。
- `GET /documents/{id}/chunks` 会返回 chunk meta 中的完整 embedding。
- 无分页（文档/chunk/消息）；无附件大小上限；供应商密钥明文；无 rerank。

### 4.2 因子回测

**状态：已实现。**

请求 `FactorBacktestRequest` 主要字段：

| 字段 | 说明 |
|---|---|
| `factor_code` / `library_name` / `factor_name` | 自定义因子源码、SQLite 因子库（可为单个库名或库名列表）、因子标识；源码与库至少一个 |
| `universe` / `universe_snapshot` | 股票池名或静态证券池快照（不可同时提供） |
| `start` / `end` | 回测区间 |
| `portfolio_type` | `long_only` / `long_short` |
| `groups` | 分层数 2–10 |
| `rebalance_days` | 调仓间隔（交易日） |
| `winsorize` / `standardize` | 去极值/标准化方式 0–3 |
| `benchmark` / `benchmark_snapshot` | `CSI300` / `CSI500` 或固定权重快照 |
| `filter_suspended/filter_st/filter_limit_up/filter_limit_down` | 过滤开关 |
| `commission_rate` / `stamp_tax` / `slippage_rate` | 交易成本 |
| `execution_timing` | `same_close` / `next_close` / `next_open` |
| `analysis_level` | `core` / `full` |

执行：

- `POST /api/backtest/factor` 返回 202 + `run_id` + `poll_url` + `Retry-After`。
- `ExperimentManager` 有界 FIFO，默认 2 worker、队列 8；队列满返回 429，管理器关闭返回 503。
- `GET /api/backtest/factor/{run_id}` 返回状态 `queued/running/succeeded/failed/cancelled` 和结果；`DELETE` 取消（运行中仅标记）。
- 任务状态在进程内存，完成态 60 秒后回收；重启丢失。
- 数据错误、参数错误、因子代码错误会写入任务 `error`，不以 500 崩溃。

输出：

- `metrics`：年化收益、夏普、Sortino、Calmar、最大回撤、波动率、IC、Rank IC、胜率、换手、IC 标准差。
- `equity_curve`（含回撤）、`drawdowns`、`annual_returns`、`final_equity`、`benchmark_curve`、`excess_return`。
- `factor_analysis`：IC 均值/标准差、Rank IC、分层收益、累计分层净值、分位指标（年化/波动/夏普/换手/最大回撤/超额/信息比率/胜率）、IC 序列、累计 IC、滚动 IR；`analysis_level=full` 时额外计算行业净值与行业内分组净值。
- `meta`：因子、股票池、组合类型、调仓、分组、基准、过滤状态、成本回显、成交口径、执行/指标版本、数据 release、spec/source hash、时间拆分、资产元信息。
- 分层编号口径：Q1 为因子值最高组，QN 为最低组。

### 4.3 策略回测

输出：

- 指标、净值曲线、回撤区间、分年收益、基准曲线、超额收益。
- 事件模式额外：订单（含拒绝原因码）、成交、日终持仓快照、事件日志、统一执行时间线。
- 向量化模式可选择返回持仓权重、调仓日志、执行时间线。

- `POST /api/backtest/strategy` 同步等待结果，没有异步任务查询。
- 事件模式不支持 `universe_snapshot` / `benchmark_snapshot`。
- 服务固定单 worker；任务和缓存不跨实例共享。

| `POST /api/ai/factor-generations` | 自然语言 → 单因子草稿；字段/方法白名单；AST 静态校验；失败一次受控修正；幂等键；不执行代码 |
| `POST /api/ai/strategy-generations` | 自然语言 → 向量化策略草稿；字段限定 `close`；AST 校验；不支持部分提示词（如事件策略）；幂等键 |
| `POST /api/ai/backtest-interpretations` | 基于净值曲线/回测快照生成证据、诊断、候选实验；模型只排序候选；无模型时确定性降级；10,000 点上限、至少 60 点 |

供应商配置：`config.yaml` 的 `ai.base_url/api_key/model`，可被 `AI_FACTOR_*`、`AI_STRATEGY_*`、`AI_BACKTEST_INTERPRETATION_*` 环境变量覆盖；不配置 AI 时普通行情和回测仍可用。

### 4.7 ResearchEngine 非功能边界

- 无身份认证、授权、租户隔离、审计；应只部署在可信内网。
- 无用户代码沙箱；自定义因子/策略在服务进程内执行。
- 固定 `uvicorn workers=1`；任务、队列、缓存均在进程内；重启后不保留任务状态。
- 批量结果 SQLite 只支持单实例；没有共享任务队列。
- CORS 为 `*`（无 credentials）。
- 健康检查只反映进程存活，不检查数据完整性（启动时已校验）。

## 5. 已跑通的端到端流程

### 5.1 数据 → 因子 → 检测 → 报告 → 分享

1. 登录 SVQuant，进入 `/factor/library` 浏览 RE 官方因子（331 个）或创建用户因子。
2. 进入 `/factor/detect/:projectId` 选择因子/组合方式、股票池、区间、参数、过滤。
3. 前端 `POST /api/backtest/factor` → SVQuant 鉴权/校验 → RE 异步任务 → 轮询到终态。
4. 运行记录 `POST /api/detect/runs` 保存请求与结果；报告页展示净值/回撤/分组/IC/行业/指标。
5. 可将因子归档到用户库，或把报告指标/代码分享为社区草稿。

### 5.2 策略 → 回测 → 报告 → 广场

1. 在 `/strategy/library` 选择内置策略（82 个）或用户策略，发起检测/研究项目。
2. `/strategy/research/:projectId` 配置模式、代码、股票池、区间、成本和过滤。
3. `POST /api/backtest/strategy` → RE 同步执行 → 前端保存运行记录（大结果 blob + PG 摘要）。
4. 报告页查看收益/回撤/持仓/成交/AI 解读。
5. 发布到策略广场（标题/正文/指标/曲线/代码快照）或在社区分享。

### 5.3 AI：搜集 → 假设 → 因子草稿 → 回测 → 评价

1. `/ai/gather` 输入研究问题，选择资讯/研报/论文/帖子来源，得到 EvidencePack。
2. `/ai/idea` 基于证据包生成研究假设（含引用、置信度、建议窗口）。
3. `/ai/factor` 将假设转成平台可回测的单函数因子。
4. `/ai/factor-backtest` 调用 RE 回测，展示 10 项指标。
5. `/ai/factor-eval` 给出规则化“人工复核/不建议入库”结论，不自动写库。

### 5.4 资讯/社区 → 研究资产

- 资讯详情可跳转关联证券行情。
- 社区帖子中的因子/策略代码可克隆到因子检测或策略研究项目。
- 因子面板/检测报告/策略报告可生成社区分享草稿，携带 `platform_ref` 指标快照。

## 6. 当前实现中值得注意的事实

以下不是规划，而是代码/运行实例已经表现出的行为，使用前应知晓：

1. **计算全部依赖 RE**：因子/策略回测、行情、目录、AI 生成均无本地备用引擎；RE 不可用时研究功能明确失败。
2. **行情列表有硬编码 fallback**：RE 故障时 `/api/market-data/symbols` / `indices` 会返回内置 12 只证券和 5 个指数，与“无伪造结果”的原则不一致。
3. **策略回测是同步接口**：RE 只有 `POST /api/backtest/strategy`；SVQuant 的 GET/DELETE 转发路由对当前 RE 会 404，前端按同步结果处理。
4. **RE 任务结果保留 60 秒**：因子回测和批量任务的完成态在内存中只保留 60 秒，之后任务 ID 查询返回 404；批次历史在 SQLite 中仍可查。
5. **因子目录 `primary` 快照可能滞后**：前端用 `all=1`；运行实例的 `primary` 仍是 2026-08-13 的旧数据。
6. **面板刷新是重任务**：管理员“刷新指标”只重算当前股票池/周期/过滤组合，但仍是数十分钟级；每日调度跑完整 12 组约 10–12 小时。需要后端进程持续存活；进程中断会留下 `running` 状态。
7. **客户端提交的结果不被验证**：检测运行、策略运行、策略广场快照、社区 `platform_ref` 都由客户端提交，服务端不验证是否来自 RE。
8. **KnowledgeHub 仅管理员**：没有个人/团队知识库隔离；检索无向量索引；摄取同步阻塞请求。
9. **单进程假设**：限流、缓存、因子队列、面板任务、KH 进度、审计去重都在内存；多 worker/多实例会失效或重复。
10. **限流只覆盖登录/注册**：社区、AI 对话、语音、回测、广场发布、知识库写操作均无速率限制。
11. **直接 AI 对话/语音不扣额度**：Agent 额度只覆盖 `/api/agent/*` 和 Agent 流水线；直连 `/api/ai/chat` 不记用量。
12. **无迁移框架**：所有表运行时创建/加列；启动时 schema 失败多数被捕获并打印，服务可能带部分表启动。
13. **安全/稳健性缺口**：策略运行 `run_id` 参与 blob 路径拼接未清洗；社区正文服务端不清洗；KH 供应商密钥明文存储；CORS 未包含 PATCH 但存在 PATCH 路由。
14. **演示/静态内容**：首页“优质回测”和两张主图、资讯指数条/热门主题/投资日历、部分种子数据为静态或合成样例；分享/广场演示种子可能生成随机曲线。
15. **不可达/遗留代码**：`FactorCustomPage.tsx`、若干旧社区页面、`PlaceholderPage.tsx` 存在但未挂路由。

**文档结论**：当前代码已经跑通“行情展示 → 因子研究 → 因子检测/面板 → 策略研究/回测 → 报告 → 社区/广场分享”的主链路，以及“资讯/社区 → AI 搜集/假设/因子草稿 → 回测 → 评价”的 AI 辅助链路。核心研究计算完整落在 ResearchEngine；SVQuant 是产品层、资产层和展示层。已实现的交易层能力是日终模拟盘（账户/持仓/订单/成交/净值/自动调度）；尚未实现的是商业化能力（套餐/组织/计费）和实时/实盘，以及若干深化研究能力（参数优化、归因、基本面/分钟数据、团队知识库、RE 认证与沙箱）。
