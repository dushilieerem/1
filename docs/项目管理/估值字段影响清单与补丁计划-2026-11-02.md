# 估值字段影响清单与补丁计划

> 日期：2026-11-02  
> 触发：`derived.valuation_daily.total_mv` 实际映射 iFinD `ths_current_mv_stock`（流通市值），不是总市值  
> 状态：**仅影响清单与计划，不合并、不部署**；等 -17 切换后的下一个窗口执行  
> 相关：数据平台 `docs/PE-REPLACEMENT-IMPACT.md`、`docs/data_contract.yaml` revision 2026-11-02e

---

## 1. 结论

当前 `valuation_daily` 的市值/PE 语义：

| 字段 | 实际来源 | 实际含义 | 问题 |
|---|---|---|---|
| `valuation_daily.total_mv` | iFinD `ths_current_mv_stock` | **流通市值** | 列名与语义不符 |
| `valuation_daily.float_mv` | 免费 `valuation.float_mv` | 流通市值 | 与 total_mv 重复，但来源不同 |
| 免费 `valuation.total_mv` | 免费 valuation | 真总市值 | 未进入 `valuation_daily` |
| `valuation_daily.pe_ttm` | iFinD `date_sequence` | 报告期 TTM，有 1–3 个月前视 | 不是严格 PIT |

已实测：

- PG `md_valuation_daily` 中 601939.SH @2016-11-23：`total_mv=518.06 亿`、`float_mv=518.06 亿`；真总市值约 1.35 万亿。
- 免费 compat `valuation.total_mv` @2016-11-23：601939.SH = 1.35 万亿，600519.SH = 3,931 亿。
- 因此：任何把 `valuation_daily.total_mv` 当总市值做规模排序、权重、估值分母的消费者都会偏；H5 目前把它显示为“流通市值”，标签恰好正确，但依赖错误列。

## 3. 兼容与命名方案

### 3.1 `current_mv` 不立即改名

用户策略代码已经使用 `self.current_mv`，直接改名会破坏存量策略。采用两阶段：

**阶段 A（兼容）**

- `FUNDAMENTAL_FIELDS`：
  - 保留 `current_mv`，标签改为“流通市值（兼容名）”；
  - 新增 `float_mv`，映射同一 iFinD 列，标签“流通市值”；
  - 新增 `total_mv`（数据到位后）映射免费 valuation 真总市值；
- `/api/market-data/fundamentals` 同时返回 `current_mv`、`float_mv`、`total_mv`（后者在数据未到位前为 null）；
- `transcription_validation` 接受 `float_mv`/`total_mv`，保留 `current_mv`；
- 文档与字段目录标注 `current_mv` 为兼容别名。

**阶段 B（清理）**

- 新样例与新文档只用 `float_mv`/`total_mv`；
- `current_mv` 保留到 -18 数据切换上线 + 一个消费者发布周期；建议期限为 **2026-11-16 或下一次 contract revision，取较早者**；
- 期间 API 同时返回 `current_mv`/`float_mv`/`total_mv`，文档标注；
- 不删除、不改存量策略，除非有迁移脚本与用户公告。

### 3.2 H5 字段

- `invest_stocks.market_cap` 语义固定为**流通市值**（亿元）；
- 如未来需要总市值，新增 `total_market_cap` 字段，不改变 `marketCap` 现有含义；
- 搜索/同业排序继续用流通市值，页面文案明确。

### 3.3 PG 列

不重命名现有列，避免破坏 SQL 与历史数据：

| 列 | 当前 | 下一版后 |
|---|---|---|
| `total_mv` | 流通市值（错误） | 真总市值 |
| `float_mv` | 流通市值 | 流通市值 |
| `ifind_current_mv` | 无 | 新增，保留 iFinD `ths_current_mv_stock` 原值 |

迁移顺序：

1. 视图/契约先提供 `ifind_current_mv`；
2. loader 增加该列写入；旧行先以 `total_mv` 回填 `ifind_current_mv`；
3. 新视图切换后重载 valuation：`total_mv` 变真总市值、`float_mv` 保持、`ifind_current_mv` 保留；
4. 校验 601939 @2016-11-23：`total_mv≈1.35 万亿`、`float_mv≈518 亿`、`ifind_current_mv≈518 亿`。

## 8. RE 对齐结论（2026-11-02）

- **SMB / MKT 改用真总市值**：RE 确认 Fama-French 的 SMB、市值加权 MKT 与聚宽 `market_cap` 都是总市值口径；切换会改变历史 SMB/MKT/HML 序列与归因，RE 按“口径变更”登记，不悄悄改。
- **字段命名**：新增 `total_mv` / `float_mv`；`current_mv` 保留为 `float_mv` 的兼容别名，并标注“实为流通市值”；RE 在一个发布周期内迁移消费者后下线别名。
- **PE**：RE 公司策略对账读 free PIT `valuation.pe_ratio`，不受 `valuation_daily.pe_ttm` 影响；但 RE 因子/风险模型路径读 `date_sequence` 的 iFinD `ths_pe_ttm_stock`，存在 1–3 个月前视，属既存问题，需单列任务。
- RE 的 `total_mv` 字段切换单独开任务，不阻塞 -17 切换。
