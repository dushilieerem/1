### 0.2 修正原因与约束

1. **参数以真实工具能力为准。** horizon 为 1–20 个交易日，groups 为 2–5 且每层至少 2 只证券，rebalance 为 1–60 个交易日，top_n 不超过数据版本证券数，单边综合 cost_bps 为 0–200。界面由能力接口和所选数据版本限制；服务端再次校验。目标原型的范围不是引擎承诺。
2. **研究复用不等于人工登记。** 计算完成、硬检查通过的资产自动成为探索资产，可直接用于下游研究。未达候选条件的实验仍留档。只有达到候选条件的当前任务版本才能送审；人工通过后增加已审核标记。均为 research_only。
3. **独立验证不能用研发对照冒充。** 70% / 30% 时间切分可反复查看，属于研发诊断；真正的独立留出、试验记账、多重试验控制、封存访问权限仍属后续需求。
4. **任务版本与证据绑定。** 修改输入生成新版本；历史输入、实验和报告保留。旧报告不能送审新版本。正在计算或当前版本送审时禁止覆盖输入。并发写入采用 revision 检查，冲突返回 HTTP 409。
5. **避免重复计算。** 同一任务版本在排队、运行或成功后重试，返回同一个 run_id；失败或取消后可重新运行。任务快照、数据发布摘要、数据内容摘要与计算源码摘要保存在报告中。
6. **人工与 AI 同工具。** AI 填表只返回建议，人工采纳才保存；AI 执行模式可保存当前步骤字段或调用该步骤开放的工具。工具参数与人工入口使用同一校验。模型无权审批、修改预算或下单。
7. **异步状态真实可查。** 页面显示模型选用工具、工具输入、返回证据、耗时、错误、取消、用量。不是模型私有思维链，也不是预制的进度动画。
8. **审批边界真实。** 目前采用回环监听 + SSH 隧道的内部研发工作区，操作人记为研究责任人。尚未接入公司统一身份，不提供前端身份切换伪装权限。正式多用户发布前必须接入机构身份与独立审批。
9. **主观投资保持独立。** 本期不合并同事主观投资产品。前端沿用机构紫白样式，不复制同事业务。

### 0.3 首期候选筛选规则

规则版本 research-screen-v1。规则固定并随送审快照留存；不能由助手在一次实验后自行放宽。它仅减少人工审阅数量，不能代表机构已认可策略质量。

| 类型 | 条件 |
| --- | --- |
| 全部 | 实验成功，硬检查无失败，任务与报告版本相符 |
| 因子 | 有效 IC 至少 60 天，绝对平均 Rank IC 至少 0.02，覆盖率至少 80%，返回的研发分段 Rank IC 与全区间方向一致 |
| 策略 / 组合 | 至少 60 个收益观察日，扣费后夏普大于 0，最大回撤绝对值不超过 35% |

固定 16 股样本具有选择偏差，阈值通过也不能代表统计显著、全市场有效或可实盘。该规则应在后续接入更完整的数据、基准与独立验证后重新评估。

## 1. 产品定位与本次交付

面向本公司机构量化团队，提供一套可以人工完成研究、也可以委托 Agent 执行的专业工作平台。以业务模块组织页面，以任务、版本和研究资产连接模块，以明确的授权和证据决定能否推进。

平台包含五个业务模块：数据资源、因子工厂、策略研究、投资组合与执行、运行监控与风险。管理驾驶舱、审查中心、Agent 管理是跨模块公共入口。

本次交付：五个模块的 30 个业务步骤页面、18 个逻辑 Agent 角色说明、共享资产复用、任务和版本交互、Agent 执行记录预览、审查交互、方法配置与运行计划，以及本需求文档。所有示例报告、收益曲线、风险判断和工具调用记录都明确标为场景数据。

原型源代码位于公司服务器的 institutional-workflow/workbench/prototype-v3；构建产物位于 workbench/web/assets/prototype-v3。旧工具工作台继续独立提供原有已接通能力。本次没有改动另一聊天维护的自主研究版本，也没有接入主观投资产品。

### 1.1 用户问题与设计回应

| 用户问题 | 产品回应 | 验收表现 |
| --- | --- | --- |
| 一进去不知道有哪些模块、各自推进到哪里 | 总览显示五个模块、当前任务、待审事项、风险事件 | 一次点击进入任务当前步骤；总览计数来自任务状态 |
| 页面堆满工具，却不知道如何完成工作 | 每个模块有六个步骤；步骤直接就是操作页面 | 每步同时有输入、操作、结果与 Agent；无单独必读流程页面 |
| 只有 AI 按钮，无法人工完成 | 人工表单与确定性工具操作是完整入口 | 无模型连接也能查看、编辑、验证、执行已有工具 |
| Agent 是否真在做事看不出来 | 展示任务输入、工具调用、反馈、产物、错误与耗时 | 运行列表可追到每次调用；不以打字动画代替证据 |
| 研究员被串行岗位审批锁住 | 共享资产与任务解耦 | 因子库已有资产即可新建策略；不等待新一批因子 |
| 所有实验都送人审批，负担太大 | 实验自动留档、规则筛选、候选评估、重要决定人工审批 | 不合格候选停留档案；人工待审列表只保留满足政策的候选 |
| 角色越拆越细，工程越复杂 | 18 个逻辑职责可由可配置的一个或多个执行器承担 | 业务步骤、Agent 角色、工具接口分别定义；不以角色数决定进程数 |
| 团队需要持续工作，不想逐次创建目标 | 研究计划保存授权范围、触发器、预算、停止条件 | 目标需求是一次授权后按计划调度；原型仅预览计划配置 |

### 1.2 范围与明确不承诺的事项

- 先服务本公司，使用固定五模块和固定责任身份。当前不开发多租户组织编排器或任意拖拽 Agent 网络。
- 数据范围、算子、股票池、频率、成本模型和研究方法由实际数据与工具能力约束；界面选项不代表服务已经支持。
- 原型没有真实 AI 调用、自动采集、独立样本外验证、模拟撮合或实盘连接。资金、收益、回撤、IC 等场景值不能作为投资判断。
- 后续真实系统的发布、资金审批、风险处置、实盘开关必须由服务端控制；原型的“预览身份”只是展示权限差异。
- 主观投资由同事作为独立产品开发，本版保留未来资产与报告接口边界，不放入主观岗位或辩论工作流。
- 不建设新品牌。色彩、导航、卡片、表格沿用 Sunvalley 机构端的紫白风格。

## 2. 用户、责任与权限

“身份”表示责任和权限集合，同一个人可以承担多个职责，不要求客户为每个 Agent 招聘一个人。Agent 不拥有独立超越委托人的权限。

| 身份 | 主要工作 | 重要权限边界 |
| --- | --- | --- |
| 研究员 | 因子、策略探索；编辑输入；运行工具；检查报告；整理候选 | 可研究和留档；不授予资金、实盘或风险恢复权限 |
| 数据负责人 | 接入配置、数据质量、版本发布、维护工单 | 发布必须通过质量与版本检查；不能静默覆盖历史数据 |
| 研究负责人 | 研究政策、优质候选审查、试验资源协调 | 决定共享研究准入；研究准入不等于资金或实盘许可 |
| 投资负责人 | 资金目标、组合方案、资金授权及已授权方案部署 | 审批绑定版本、环境、范围和期限；不得绕过独立风险硬限制 |
| 风控负责人 | 独立风险规则、事件分级、处置与恢复复核 | 风险保护不因研究负责人同意而解除；恢复需证据与授权 |
| 平台管理员 | 工具注册、模型接入、方法版本、评测发布、运行配置 | 管理平台不自动获得投资决定权限；密钥不进入浏览器或 Git |

正式系统需求：对象级 RBAC、任务与资产作用域、操作者审计，以及按机构政策配置的复核人分离。原型暂按身份模拟关键按钮门槛，不能用来验证后端安全性。

### 3.2 步骤工作页面

每个步骤包含：

1. 任务上下文：任务名称、模块、输入版本、切换任务、新建任务。
2. 六步导航：每步名称、当前选择、未开始 / 运行中 / 已有产物 / 需补证 / 需重跑。点击导航只浏览，不把步骤自动标为完成。
3. 人工工作区：业务表单、输入说明、约束、当前缺少的必要证据、人工执行按钮。
4. 结果区：产物摘要、指标与明细、输入快照、版本、生成时间、导出和下一步入口。
5. Agent 区：AI 填写建议、AI 执行本步、运行记录、补充要求、对话、方法配置入口。

页面不要求员工先看完整架构图才能操作。鱼骨图放在“流程说明”和全图入口，供汇报、培训和追查职责时查看。

“AI 填写”只生成参数建议；“AI 执行本步”使用当前确认的输入调用业务能力。正式系统中两者可组合，但填写不等于执行成功，执行成功不等于研究证据合格。

## 4. 业务流程与模块关系

五模块不是每次必须从头走到尾的流水线。数据、因子、策略和组合形成版本化资产，任务引用已有资产独立发起。步骤先后描述单个任务的证据依赖，不要求全公司研究同步经过同一批次。

| 模块 | 六个步骤 | 主要交付 |
| --- | --- | --- |
| 数据资源 | 需求与来源 → 采集与归档 → 清洗与加工 → 质量与时点核验 → 发布与服务 → 维护与变更 | 已发布数据快照、质量报告、血缘和维护记录 |
| 因子工厂 | 资产复用 → 研究假设 → 工程计算 → 研发检验 → 独立验证 → 资产与准入 | 因子定义、可计算表达式或代码、实验报告、冻结候选与研究资产 |
| 策略研究 | 研究方案 → 信号与规则 → 成本回测 → 研发优化 → 独立复核 → 模拟跟踪与准入 | 可执行策略、版本与参数、回测证据、跟踪结果与策略资产 |
| 投资组合与执行 | 目标预算 → 策略选择 → 配置方案 → 风险与审批 → 部署执行 → 调整退出 | 版本化资金方案、授权、部署回执、订单与对账记录 |
| 运行监控与风险 | 运行巡检 → 异常分级 → 风险处置 → 复核恢复；归因分析 → 复盘改进并行 | 事件、保护措施、恢复证据、归因报告与改进任务 |

模块内功能和字段详见附录 A；角色职责与工具详见附录 B；公共入口详见附录 C。编号用于跟踪需求，不对应固定的服务实例数。

### 4.1 数据资源需求

- D1 记录数据用途、来源、授权范围、频率、字段、质量与时点要求。凭据通过服务器密钥引用配置，禁止放入提示词、报告或普通表单返回。
- D2 支持历史与增量任务、断点续传、重试、幂等入库、原始批次归档。先保留来源与采集时间，再处理加工结果。
- D3 人工与 Agent 都调用同一规则引擎，支持字段映射、去重、缺失处理、异常标记、复权与实体对齐。无法合理补齐的数据应隔离，不能让模型编造。
- D4 验证完整性、唯一性、跨源一致性、时效、历史可用时间和授权。历史可用时间需要真实来源依据，不能由 LLM 猜测。硬失败阻止发布。
- D5 发布不可变版本与服务契约；快照有来源、处理规则、内容校验和、质量报告和可用范围。
- D6 监控更新延迟、来源变化、质量漂移和服务异常；支持补采与修复新版本，明确受影响的下游任务，保留旧版可复现性。

### 4.2 因子工厂需求

- F1 查询因子库和失败案例，支持从已有资产复现；用户也可直接建立新研究。
- F2 写清经济或行为假设、表达式、预测目标、频率、研发与独立验证范围、试验预算和预先约定的筛选条件。
- F3 使用受控表达式算子或隔离代码执行，记录数据版本、预处理、计算环境和输出。AI 可以修复计算错误，但不能为了通过结果任意修改检验规则。
- F4 产生 IC / Rank IC、覆盖、分组、衰减、稳定性、成本和重复性证据；保存所有试验、失败与参数选择路径。原型阈值是交互示例，正式默认值需结合数据规模和研究政策校准。
- F5 冻结候选后由独立验证职责使用隔离权限生成证据。作者不能读取封存数据并反复针对同一封存结果优化；失败后新试验计入尝试记录，并按政策安排新的验证。
- F6 普通实验自动留档。硬条件和候选评价通过后，才送研究负责人决定共享研究用途。入研究库不自动授予资金或实盘权限。

### 4.3 策略研究需求

- S1 可选已有因子，不依赖正在运行的因子任务。支持选择研究资产进行探索，但记录其准入状态与使用限制。
- S2 将特征转换为预测或排序信号，定义组合规则、调仓规则、交易约束、风险暴露与可执行策略。因子值是特征，策略还需要明确怎样形成决策和交易规则。
- S3 调用可复现回测服务，显式提供费用、滑点、交易规则、基准、区间、数据与代码版本。不支持的成交约束不能用默认零值掩盖。
- S4 在研发范围内优化参数、模型或规则，记录搜索预算、所有试验、选择方法和稳健性检验。不得将看过的验证结果仍作为“未见样本”。
- S5 冻结策略、环境和预处理，独立验证泄漏、过拟合、成本、压力和实现一致性。报告明确样本规模与测试边界。
- S6 模拟跟踪达到政策约定后整理候选。未达到观察要求继续跟踪；满足要求并不自动证明可实盘，仍需组合与资金授权。

### 4.4 投资组合与执行需求

- P1 定义预算、账户与环境、风险目标、集中度、流动性和容量限制。
- P2 从已获相应用途准入的策略版本中选择，检查重叠持仓、风险暴露和共同失败来源。
- P3 产生策略权重与现金配置，检查总额、集中度、交易可行性与风险约束。预算与权重可以手动计算，优化器是可替换工具。
- P4 独立风险检查后提交固定版本资金方案。人工审批包含环境、上限、有效期与允许行为；硬风险失败不能靠普通审批覆盖。
- P5 只执行获得授权且版本一致的方案；先完成部署前检查，再生成目标持仓和订单意图；有幂等键、回执、部分失败处理与对账。原型只模拟部署回执，不发送订单。
- P6 调整和退出都形成新版本与变更说明。超授权范围重新审批，重大异常进入风险路径，不用编辑已审批记录的方式改变授权。

### 4.5 运行监控与风险需求

- T1 监视数据、任务、模型调用、策略、订单和账户；这些监控应由服务端采集，不依赖用户开着页面。
- T2 去重和关联事件，确定等级、影响对象和证据不足之处；根据预设政策触发保护。
- T3 在授权范围执行暂停、限额、补采或调查。紧急硬限制由确定性规则执行，不能等待模型回复或普通审批队列。
- T4 复测、核对措施回执后申请恢复；确认收到告警和真正解除风险是两种操作。
- T5 归因与日常盘后核算并行进行，不因某个风险事件未结束而完全阻塞；残差、对账差异必须明确展示。
- T6 把有证据的发现转成数据、因子、策略或方法改进任务，附责任人和验收标准，避免自动生成无人处理的建议堆积。

## 5. Agent 设计与人机协作

### 5.1 三层设计

业务步骤定义输入、输出和准入条件；Agent 角色定义可承担的任务与可用工具；执行器负责计划、调用、反馈、重试和交付。三者通过版本化契约关联。

一个业务步骤可由多个角色协作，同一角色也可服务多个步骤。18 个角色是便于评审的逻辑职责：数据 4、因子 3、策略 3、组合 3、运行 3，加上跨模块独立验证与候选评估 2 个。独立验证的隔离要求不能仅靠换一个角色名实现。

常规路径由业务约束规定。Agent 可以在授权步骤内检索、提出假设、选择工具、比较结果、有限重试或提出返工请求。它不能自行扩充数据权限、突破预算、跳过独立验证或把研究批准解释成交易授权。

### 5.2 标准 Agent 执行契约

| 对象 | 必须包含 |
| --- | --- |
| 输入 | 任务 ID、步骤 ID、输入版本、目标、资产版本、预算、权限、停止条件 |
| 方法 | 逻辑角色、Prompt 版本、Skill 版本、知识引用版本、模型配置引用 |
| 计划 | 本次目标、拟调用工具、需要的前置证据、预计停止位置 |
| 工具调用 | 调用 ID、工具与版本、参数摘要、幂等键、起止时间、状态、输出引用 |
| 输出 | 结构化产物、可复现文件、证据引用、失败与不确定性、建议下一步 |
| 审计 | 操作者或委托来源、输入版本、资源消耗、取消和人工修改记录 |

记录可核验的动作和证据，不要求显示模型私有推理过程。简要决策依据与来源足以解释“为什么用了这个工具”和“结果是否满足条件”。

### 5.3 人工介入规则

- 人可以纯人工完成表单和工具操作，也可以随时让 Agent 填写、执行或解释，不强制选择互斥的“人工 / 辅助 / 全自动模式”。
- AI 填写以任务输入版本为基准；若运行期间人已修改，显示冲突，保留人工内容，等待明确应用建议。
- 同一任务同一时间只执行一个有写入影响的步骤。用户可停止后续调用；已完成调用留下记录，不伪装成已撤销。
- 工具异常显示真实错误与可重试范围，不伪造成功报告。重试产生新执行记录；需要幂等的操作复用明确幂等键。
- 重要人工决定保留理由、身份、版本与时间；退回附补充要求，原任务继续修订。
- 自动留档与候选评分均能追溯政策版本。AI 评价不能把未通过硬条件的候选提升为正式批准。

### 5.4 方法维护

岗位用户可编辑草案 Prompt、Skill 装配和已授权知识引用，保存为新版本；可以提交公司共享库。共享内容需要来源、适用工具版本、样例、测试与维护人。

平台团队负责工具适配、权限隔离、执行框架、评测集、发布与回滚。微调、模型更换和多 Agent 架构变化通过离线评测与灰度发布，不能作为每位岗位人员无约束的在线操作。

原型支持方法草案、Skill 选择、版本变更、场景评测和发布门槛。场景评测仅检查示例配置完整性，不衡量实际模型能力；正式评测服务是后续开发项。

### 5.5 持续研究计划

真实调度需求：用户一次设置模块范围、触发条件、单次与累计预算、并发上限、候选队列上限、工具和数据授权、失败重试上限和停止条件。调度器按计划自动产生任务，自动筛选，只将合格候选送审。

触发器可包含定时、数据新版本、已发布资产、风险反馈和人工补充目标。无目标时必须有已批准的研究范围与资源政策，不能无限制地“自行赚钱”。

计划停止、模型额度不足、数据不可用、权限不足或候选队列积压时，显示具体等待原因；后台服务重启后从持久状态恢复，不重复采集、提交候选或部署。

本次原型仅保存各模块计划配置，并明确“不会启动后台研究”；真正的调度器、预算账本和恢复策略不在本次已完成功能内。

## 6. 任务、版本与审批状态

### 6.1 核心对象

| 对象 | 核心字段 | 不可混淆的边界 |
| --- | --- | --- |
| ResearchTask | module、id、name、currentStep、revision、owner、status | 页面步骤选择不等于任务完成 |
| InputRevision | taskId、revision、values、upstreamRefs、createdBy | 参数修改产生新版本 |
| Execution | runId、inputRevision、methodVersion、toolCalls、status | 执行成功不等于证据合格 |
| Artifact | id、version、inputRevision、contentHash、evidence、status | 上游变化后不能悄悄沿用旧证据 |
| ResearchAsset | familyId、assetId、version、sourceTask、usage、status | 研究留档、共享准入、资金用途分别控制 |
| Candidate | frozenVersion、hardChecks、aiAssessment、evidenceRefs | 低质量实验不是人工待审候选 |
| Review | candidateId、version、type、reviewer、decision、reason | 决定绑定提交时版本 |
| FundingAuthorization | proposalVersion、environment、limits、expiresAt | 研究准入不能替代资金授权 |
| Deployment | authorizationId、version、idempotencyKey、receipts | 已部署不等于所有订单成交 |
| RiskEvent | source、severity、affected、hardLimits、actions、resolution | 知悉、处置、复核和恢复不同 |
| MethodVersion | role、prompt、skills、knowledge、tools、eval、published | 编辑草案不覆盖线上版本 |

### 6.2 状态约定

| 对象 | 正常推进 | 异常或修订 |
| --- | --- | --- |
| 任务步骤 | 未开始 → 运行中 → 有效产物 | 执行失败、取消、中断、需补证、输入变化需重跑 |
| 因子与策略 | 探索留档 → 候选 → 共享研究准入 | 自动留档、退回、否决、暂停使用 |
| 审查 | 待审 → 通过 / 退回 / 不采纳 | 参数变化导致待审申请失效 |
| 方法 | 草案 → 评测 → 发布 | 编辑后旧评测失效；失败保留旧发布版本 |
| 风险事件 | 开放 → 限制与调查 → 复测 → 恢复或继续限制 | 缺证不能恢复；恢复申请与恢复结果分别记录 |

正式系统按依赖图失效下游证据。原型按模块步骤和输入版本做保守失效：修改本步或上游参数后，本步及后续输出标记为旧证据，待审申请失效；即使参数未改，上游产物重算也会重新检查下游证据。审查弹窗显示提交时固定快照，Agent 历史记录打开当次产物。审批通过的历史记录保留，但不能授权新版本执行。

同一资产新研究产生新版本，旧版本、报告、审批和下游引用必须可继续读取。审查查看提交快照，不能只显示当前编辑表单。

## 7. 关键场景与验收口径

### 7.1 因子研究闭环

研究员从已有因子复现或建立新任务，设定假设和表达式，执行工程计算与研发检验。未通过筛选的实验自动留档；通过的候选冻结后进行独立验证，整理报告。研究负责人查看固定版本证据并决定是否允许共享研究。批准后策略研究可引用该版本。

验收：人工和 AI 入口共用输入与工具契约；全部试验有记录；F4 失败不能继续 F5 正式验证；没有有效 F5 不能正式送审；F6 普通留档不强制领导审批；审批前修改输入使申请失效。

### 7.2 直接复用资产

策略研究员从因子库选一个已有因子，立即创建策略研究。组合研究员从已准入策略发起配置。数据隔离版本不能成为新研究输入。使用探索因子构建策略仅代表研究允许，不代表策略或组合可直接部署。

验收：即使没有正在进行的因子任务也可以启动策略任务；引用记录包含资产 ID、版本和用途。

### 7.3 资金审批与执行

配置权重、现金和预算；总权重与集中度检查通过后提交风险材料和资金方案。投资负责人审查固定版本。只有该版本获批且执行前检查满足时，才能进入模拟部署。真实系统的实盘开关与账户权限另行开发与验收。

验收：错误身份不能审批；权重合计不等于 100% 不能提交配置；缺独立风险材料不能送审；修改获批方案后不能用旧授权部署；重复部署请求不产生第二次同义执行。

### 7.4 数据与风险事件

数据负责人完成质量核验后发布新版本，隔离版本不能发布为正常可用数据。运行风险团队接到延迟或成本异常事件，确定影响、执行保护、复测并提交恢复复核；日常归因可以并行进行。

验收：质量未通过不能发布；不能覆盖历史版本；硬风险事件不能仅以“继续观察”解除限制；缺复测和回执不能恢复；审批恢复后事件状态才变化。

### 7.5 Agent 与方法

Agent 执行可查看参数与逐次工具回执；取消停止后续调用；失败可重试。人工在填写建议运行中修改参数时保留人工内容。方法修改后，旧评测结果不能授权新草案发布。

验收：运行记录来自执行事件；不得提前显示成功；页面刷新不能把中断作业伪装成继续后台运行；AI 产物必须能回到来源任务。

## 8. 工程接入与已有能力复用

### 8.1 当前事实与目标分开

| 能力 | 当前可复用基础 | 后续研发要求 |
| --- | --- | --- |
| 数据查询 | 独立数据服务和已发布研究快照查询接口已有基础 | 完整采集、加工、质量、版本维护与 Data Agent 仍需接通、验证 |
| 因子计算 | ResearchEngine 有受限表达式与部分计算、评价能力 | 原型表达式和所有指标必须逐项核对算子支持；严禁把场景值当引擎结果 |
| 策略回测 | 现有 SVQuant / ResearchEngine 能力可按契约适配 | 完整费用、成交约束、容量、PIT 与独立验证不能凭接口联通宣称完成 |
| 模型接入 | 旧工作台保留模型配置与工具调用边界 | V3 原型不读取密钥、不调用模型；正式执行器需接入真实运行记录 |
| 任务和资产 | 旧真实工作台有自己的记录 | V3 浏览器场景记录不写入旧业务数据库；迁移需明确映射 |
| 组合与风险 | V3 完整展示目标交互 | 真实风险引擎、资金授权、执行网关与对账尚不是本原型能力 |

现有研究环境的数据范围与计算能力仍受限制，包括既有固定样例股票池和基础行情字段。正式验收需要以服务端返回的能力清单为准；不能因为表单出现“财务”“独立验证”或“实盘”就认定后端已经支持。

### 8.2 推荐接入结构

前端通过业务 API 操作任务和资产；人工按钮与 Agent 调用相同的领域服务。Agent 不能通过模拟鼠标填写页面实现核心业务自动化。

执行器从持久任务状态领取已授权步骤，读取固定版本输入和方法配置，调用工具适配器，将结构化事件与产物写回。前端通过事件订阅或轮询展示，页面关闭不影响已授权后台任务。

对现有服务使用适配层，复用 SVQuant 业务能力、ResearchEngine 计算能力与 sunvalley-data 数据能力。先核对接口、分支、工作树、端口与运行数据隔离；不在共享工作树中切换分支影响另一版。

### 8.3 待实现 API 契约建议

以下是产品所需的接口契约草案，不代表现有服务已提供这些 URL；实现时优先复用现有接口，不强制照搬命名。

| 接口族 | 请求要点 | 响应与检查 |
| --- | --- | --- |
| GET /v3/capabilities | 用户、空间、工具版本 | 可用字段、算子、数据、操作与限制；前端按能力禁用不支持项 |
| POST /v3/tasks | module、name、upstreamRefs | taskId、revision；校验资产用途和权限 |
| PATCH /v3/tasks/{id}/draft | expectedRevision、changes | 新版本和受影响产物；冲突返回 409 |
| POST /v3/tasks/{id}/runs | stepId、inputRevision、mode、idempotencyKey | runId、状态；同任务互斥与授权检查 |
| GET /v3/runs/{id}/events | cursor | 有序工具事件、重连游标、脱敏输入与产物引用 |
| POST /v3/runs/{id}/cancel | reason、expectedState | 停止后续调用；明确已完成外部副作用 |
| GET /v3/assets | kind、usage、version、status | 可复用资产及版本；禁止引用隔离数据 |
| POST /v3/candidates | frozenVersion、evidenceRefs、policyVersion | 自动筛选或待审；保留失败原因 |
| POST /v3/reviews/{id}/decisions | expectedVersion、decision、reason | 服务端角色、硬条件、版本检查与审计 |

| POST /v3/plans | scope、triggers、budgets、limits、stopConditions | 计划版本与授权记录；真实调度另行验收 |

## 9. 非功能需求与质量目标

以下是工程验收目标，未作为本次原型实测性能结论。

- 可复现：产物绑定数据、代码、参数、环境、方法和政策版本；记录随机种子及外部依赖。无法复现必须显示原因。
- 稳定性：任务状态持久化；幂等采集、候选提交和部署；可断点续接；错误不静默消失。
- 性能：在确认的基准环境中，普通页面和列表交互 P95 目标小于 1 秒；长计算异步返回 runId，前端显示进度而非阻塞。
- 可观测性：请求与执行统一关联 ID；展示排队、执行、等待证据和等待审批的真实差别；模型费用与工具消耗独立统计。
- 安全：密钥只存服务器安全配置；输入白名单、表达式解析与隔离执行；日志脱敏；无授权时不得扩大工具或数据范围。
- 研究质量：时间切分、数据时点、交易可行性、试验选择偏差和独立复核有明确证据要求；报告披露限制。
- 可访问性：键盘可导航、表单有名称、状态不只依赖颜色、错误靠近输入、对话框能关闭；窄屏不产生全页横向溢出。
- 数据保存：正式系统有审计与保留政策、备份恢复验证；原型仅保存一个专用浏览器键，重置只清除本原型场景。
- 成本：单次、模块与空间预算都要检查；额度不足进入可解释等待状态，不自动调高用户授权额度。

## 10. 开发优先级

| 优先级 | 开发范围 | 完成标准 |
| --- | --- | --- |
| P0 | 因子闭环、已发布数据选择、任务与产物版本、Agent 执行事件、候选审查 | 在真实数据与受控算子上完成至少一个可复现实验；失败、取消、版本变更、重复提交均有验证 |
| P1 | 数据采集维护闭环、策略回测与独立验证、方法评测、持久研究计划 | 自动任务可恢复且有预算；真实候选筛选不堆积人工队列；完整接入报告 |
| P2 | 组合风险、模拟部署对账、运行风控与复盘闭环 | 授权、风险保护、幂等执行和故障恢复通过隔离环境测试 |
| 独立准入 | 真实资金与交易账户 | 另行完成接口、权限、风控、交易规则、审计与运行验收后决定，不随原型上线自动开放 |

原型把最终产品的五模块完整表达，工程优先跑通因子工厂的一条真实纵向闭环。不能通过先做五套空页面或先堆 18 个模型调用，替代可复现结果和失败处理。
